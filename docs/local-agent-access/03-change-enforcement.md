# 功能变更与 Agent 接入同步维护规范

日期：2026-10-24；完整门禁设计。依据：[主规范](../../AGENT_ACCESS_SPEC.md)。登记/生成/影响确认子集已实现；本篇其余自动检查仍是目标。实际脚本和覆盖边界见[交付台账](05-a0-a1-minimal-delivery.md)，不能笼统宣称全部门禁已经阻断。

## 1. 交付原则与生效顺序

用户需要的是长期同步维护，而不是每次功能完成后再补一份接入文档。接入影响判断应与节点协议、日志影响检查一起进入设计、实现、审查和发布。

建议 A0 分两步生效：先把影响检查和明确禁止项纳入 AGENTS.md 与变更模板，再以自动门禁保护已迁移模块；A1 起任何新增关键业务能力不得只走 UI 私有路径。历史未迁移能力保留明示状态与计划，不能为了通过门禁将新缺口伪装为历史欠账。

没有对外接口变化的纯样式、静态文案或内部等价重构允许“不涉及”，需要可核对的理由，不要求机械修改所有接入文件。公共处理逻辑已有契约覆盖且无需改 Schema 时，应引用既有测试并补适用回归；不能要求每次变更无意义地升版本。

## 2. 变更类型与同包要求

| 变化                        | 必须同步处理                                                                    | 可接受的不涉及依据                                       |
| --------------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 新增用户业务能力            | 能力项、公共 handler、Schema、支持入口、错误、日志、测试与说明                  | 明确 UI 专属且没有可调用业务语义，登记 excluded 理由     |
| 新增节点                    | NodeAccessSpec 与 Active 集合一致；可编辑字段、配置 Schema、动作/执行状态、测试 | 不允许无声明；可将执行动作标 planned/excluded 并说明原因 |
| 节点配置/正文/动态字段变更  | 配置与端口派生、旧值默认、序列化、CLI/MCP描述、保存重开                         | 仅可视排列改变、业务字段完全不变                         |
| 端口/Schema/基数/必填性变化 | contractVersion 判断、连线迁移、固定资产/输入准入、输出投影、兼容测试           | 无端口与输出语义变化，有对比证据                         |
| 执行/模型/工具行为变化      | 公共 executor、NodeAccessSpec 限制、任务状态、重试、取消/恢复及桌面一致性       | 同义实现优化，有等价回归证据                             |
| 项目保存/复制/导出变化      | 公共服务、revision/事务、重映射、凭据剥离、幂等与故障验证                       | 纯 UI 布局，不改变调用参数/提交顺序                      |
| 新增人工步骤/审核/状态关系  | waiting 类型、可执行动作、身份/修订校验、不可冒充人工                           | 只是提示文字，已有门禁语义未改                           |
| 业务故障修复                | 找到所有入口调用的公共根因，同包验证外部入口的同类故障                          | 仅 UI 指针/渲染缺陷，接入语义不变                        |
| 删除/停用能力               | Registry、工具目录、CLI help、能力状态、旧客户端明确错误和迁移                  | 不允许保留幽灵工具                                       |
| 日志变化                    | 允许字段、唯一终态拥有者、关联传播、脱敏、覆盖清单                              | 仅设计文档，未改变实际诊断行为                           |

每次变更填 [检查模板](../templates/AGENT_ACCESS_CHANGE_TEMPLATE.md)，可以粘贴在原任务记录/PR说明，无需人为生成大量空文档。

## 3. 三个公共事实来源

| 事实来源（待实现或扩展）           | 权威内容                                                         | 派生内容                                     |
| ---------------------------------- | ---------------------------------------------------------------- | -------------------------------------------- |
| 现有 NodeTypeSpec + NodeAccessSpec | 类型、版本、端口、配置/正文与动作能力                            | 节点目录、参数说明、逐节点测试夹具与覆盖报告 |
| Operation Registry                 | operationId/version、Schema、handler、效果、限制、入口、日志策略 | MCP tools、CLI命令/JSON帮助、可选HTTP契约    |
| 能力验证账本                       | implemented/verified/excluded/planned、入口、环境、证据和限制    | 发布覆盖报告、人工阅读矩阵                   |

手工 Markdown 用于解释产品边界；可机器判断的类型、端口、版本和工具目录应由同一 Registry 导出。`generated/` 如需重新引入仅用于契约产物，必须明确是新架构产物，不能恢复旧执行宿主。

建议机器源为 `src/shared/agent-access/operations.ts` 与 `node-access.ts` 中的TypeScript/Zod声明；节点端口直接引用现有Spec/共享契约。生成方向固定为“机器声明 → JSON Schema、工具/帮助、覆盖快照 → Markdown表格片段”，不反向解析本篇长文作为运行权威。兼容diff输入是基线/当前规范化Schema快照及人工行为影响声明；路径扫描只要求提供声明，不能自动判定全部语义影响。

## 4. 自动门禁设计

下列脚本名是建议名，A0 实现时可以调整；调整后同步文档，不把不存在的命令写为本轮已执行。

| 门禁                                  | 机器检查内容                                                                 | 阻断例子                                         | 边界                             |
| ------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------ | -------------------------------- |
| `verify:agent-access` / G1 登记完整性 | Active 集合与 NodeAccessSpec 一一对应；operation唯一；handler/schema引用存在 | 新增节点但无 access 声明；声称支持无 handler     | 不判断能力是否好用               |
| G2 暴露面一致性                       | 每个入口暴露集合是 Registry 的授权子集；项目导入/任意IPC不可出现             | 手写 MCP 工具绕开公共操作；CLI多出隐藏命令       | 能力声明不代替运行保护           |
| G3 生成一致性                         | 在临时目录重新生成 Schema/工具/帮助，与提交产物比较                          | config 增字段但CLI仍旧参数                       | 不通过直接覆盖文件掩盖差异       |
| G4 兼容差异                           | 与明确基线比较 operation/节点/config/输出版本；限制收紧/删除字段有迁移记录   | 删除必填输出但版本不变；节点端口破坏性变化未升版 | Schema diff 不能判断所有语义变化 |
| G5 变更影响                           | 受保护业务路径有影响声明、涉及的operation/node和处理结论                     | 改导出实现却声称只改样式                         | 路径清单/“不涉及”仍需审查        |
| G6 桌面与外部一致性                   | 共用业务fixture跑UI公共入口/CLI/MCP，比较规范化结果与保存事实                | 正文清空、many丢项、产物只在API可见              | 不能只比较HTTP成功码             |
| G7 状态与故障                         | 幂等、并发、unknown、取消、保存失败与恢复不重放                              | 断线后换key自动重生成；未落盘假成功              | 真实供应商行为需另验收           |
| G8 日志与脱敏                         | 接入上下文贯穿；唯一业务终态；日志拒写不影响结果；包/日志无禁项              | CLI把完整请求写stderr；包带密钥                  | 幂等账本故障与日志故障分别验收   |

G1–G5、相关快速测试在每次 verify 和 CI 执行；G6–G8 按已迁移能力和适用真实桌面路径加入现有 `verify:checks`。发布不能用快速检查替代完整 `npm run verify`。构建后的安装包另做 CLI/MCP 启动、依赖和版本匹配检查。

CI 基线必须明确：PR 使用 merge-base；本地显式基线或上一次发布契约；不能随机选择最近提交作为兼容判断依据。静态产物和运行时能力摘要都带契约摘要，防止旧 CLI 连接新应用时误用参数。

## 5. 影响声明与保护路径

建议保护范围包括节点 Spec/配置、shared types/schema、公共 engine/executors、Agent Flow 准入与任务、project/library/media/transfer、网关、preload/IPC、保存恢复和接入适配器。

影响声明采用结构化字段：变更标识、基线、受影响路径、operation/type集合、行为变化、版本结论、各入口处理、兼容迁移、日志检查引用、验证结果、未覆盖项。无需把用户提示词或模型回复写进声明；fixture 使用隔离样例。

代码审查要问：

1. 新的 UI 行为是否有可调用的公共业务入口？若没有，是否确实 UI 专属？
2. 外部 Agent 以旧参数或旧节点版本调用，会得到什么确定结果？
3. 操作失败、取消、断线、超时和崩溃时是否仍能核对原意图？
4. 外部修改是否会覆盖用户尚未保存的画布？
5. 能否在桌面看见并继续使用同一成果，重开后仍一致？
6. 声称支持的状态是否有本次适用验证，还是仅引用旧证据？

## 6. 版本与兼容规则

- API envelope 版本、operationVersion、node contractVersion、configSchemaVersion、结果Schema、项目包版本与 MCP 协议版本分别维护。
- 增加可选字段且旧默认行为完全保持，可以兼容升级；删除/改名、类型/单位/基数变化、错误或副作用语义变化需评估不兼容。
- 破坏性操作接口使用新 major；旧版保留适配或稳定 `UNSUPPORTED_CONTRACT` 与迁移指引，不静默解释为新行为。
- 节点端口版本继续遵循现有 NODE_CONTRACT_SPEC；单纯增加可选配置不机械提升节点端口版本，但仍更新配置Schema与快照。
- 客户端连接先取应用/操作/节点能力版本；不支持时停止依赖该能力，不用猜参数或直写项目文件补救。
- 每次发布附兼容表：应用版本 × CLI版本 × MCP协议/客户端 × 支持operation版本。没有实际验证的组合标“未验证”。

## 7. 历史欠账和例外

允许历史能力按 A1–A4 迁移；登记具体动作和入口，不能笼统写“此节点不适合Agent”。例如导演台可开放配置读取和准备，但人工发布受限；状态机可以编辑定义，但独立执行当前未支持。

例外记录原因、影响、当前替代方式、责任模块、截止阶段和验收条件；仅能对历史迁移或非关键边界使用。密钥泄露、任意文件访问、伪造成功、unknown自动重放、项目导入排除和人工身份门禁不得豁免。

若某功能已经对外验证，后续UI变化不能把它默默退回planned；必须同包修复或发布明确的兼容/退役变更。新功能不能先宣称支持，再无限期挂“以后适配”。
