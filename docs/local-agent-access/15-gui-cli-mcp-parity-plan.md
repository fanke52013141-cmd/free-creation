# 全软件 GUI／CLI／MCP 一致能力开发计划

日期：2026-11-07。状态：可执行开发方案，业务能力尚未因此新增。基线：`3b1f2ab`，另有未提交工作区修改，不能视为已发布能力。

目标由用户明确提出：人使用 GUI 操作软件；Agent 使用 CLI 或 MCP 操作同一个软件；能建立多个画布、创建和连接各类节点、执行任务、取得并复用结果，保存后人在 GUI 中继续操作。最终范围是全软件业务能力，不止32类节点或当前25项接口。

配套：[强制一致性规范](../../AGENT_PARITY_SPEC.md)、[32类节点动作表](16-node-action-coverage.md)、[现有25项能力](14-current-capabilities.md)。本计划接续并扩展原 A0–A4，不再用早期最小包或项目导入排除条款定义最终交付。

### 1.2 GUI 与内部执行已有的基础

- `ACTIVE_NODE_TYPE_IDS` 当前32类，定义在 `src/shared/types/index.ts`，包含后加入的时间线。旧文档中的31类为历史计数。
- 节点定义和端口分布在 renderer 的 NodeTypeSpec、共享 Schema、配置解析器和输出投影中；它们尚不是完整的外部节点 API。
- 多数节点有共享 executor；Agent、状态机、审核另有专门实现。内部建图 catalog 已包含文本模板、生图、P图、视频、语音与克隆等有限能力，不是任意32类建图。
- 内部 Flow 有命令账本、租约、固定资产、审核、恢复及部分目标适配，可以扩展给外部调用主体；“有内部适配”不等于“外部已可调用”。
- GUI 的画布编辑、节点库、素材导入、资源库、历史、模型配置等有 IPC/业务基础；复杂编辑器还有 React 私有事件路径，需要抽取公共动作。

上轮38项本地接入测试通过，包含真实 CLI 子进程及 MCP stdio 安装/查询；类型检查、定向 lint、构建通过。新增 Skill 绑定的主流程用受控桌面替身验证，真实 Electron 画布和安装包尚未验收。全仓 verify 与全局影响声明检查因其他进行中修改未通过，见[交付13](13-chat-skills-node-library.md)。

## 2. 最终产品使用方式

### 2.1 必须通过的完整场景

Agent 在没有人代点 GUI 的情况下完成：

1. 连接指定本机应用；若应用未启动，按显式配置启动并等待就绪。
2. 创建“角色素材”“视频剪辑”“配音”三个独立项目画布，分别取得稳定 ID。
3. 查询节点类型、端口、参数和可用模型，不靠节点标题猜类型。
4. 在各画布批量创建节点，设置内容/参数/位置，连接明确端口。
5. 导入指定文件、引用资源库素材、给对话节点绑定命名 Skill。
6. 运行单节点、局部子图或工作流，取得 taskId，观察进度和状态。
7. 读取文本/JSON/图片/视频/音频正式结果，选定版本，继续连接或保存资源。
8. 进行时间线编辑、截取、抽帧、声音调整、复杂工作区发布等适用操作。
9. 保存节点/组合到节点库，按名称再次插入另一张画布，重映射节点/媒体/连线。
10. 保存全部项目，关闭并重启应用；人在GUI打开，图、参数、素材、结果和可继续编辑状态一致。
11. 重复请求、发生冲突、断线或某任务失败时，不覆盖其他画布、不重复计费、不伪造成功。

### 2.2 “多个画布”的明确落地口径

当前主要业务按一个项目的一张工作画布组织，图收集大量使用 `getCurrentPageShapes()`。底层编辑库有 page 概念，不代表产品保存/执行已支持多页。

- **本计划必交**：创建任意多个独立项目画布；每张图有多个节点；Agent 不依赖前台窗口切换；最终支持至少两张图同时运行，更多画布按可配置资源上限排队。
- **先完成串行**：保持一张图一个权威宿主，外部显式 acquire/attach、flush、release。下一张图不能偷走上一张图的运行上下文。
- **再完成并发**：同一应用管理多个独立后台宿主或等价会话，按项目隔离 editor、保存协调器、模型任务、临时媒体及诊断；前台仍可查看其中任意画布。
- **项目内多画布**：如果后续需要同一项目多页，新设 canvasId/分页索引、迁移、GUI导航及所有页的保存/恢复/执行协议，单列追加包。不能把切换 tldraw 当前页当作多画布支持，也不把这个新增产品功能偷塞为本轮前置。
- 外部目标模型预留 canvasRef；当前一个项目只有一个合法主画布，不接受任意伪造 canvasId。不在尚未定义的不同页之间隐式连线。

## 4. 技术落地方案

### 4.1 共享业务层与契约层

保留现有本地传输；扩展 `src/shared/agent-access` 的 Registry、操作版本、错误和响应。将NodeTypeSpec中的环境无关元数据、默认配置、端口派生与可编辑字段整理为共享契约，再由 renderer 组合 UI。不是把整个 TSX 注册表搬进 main。

新增 NodeAccessSpec/action 声明，统一以下事实：

- 类型、契约/配置版本、参数Schema、正文Schema、端口生成和结果投影。
- 可用业务动作、公共handler、适用模型/模式、环境要求、是否可暂停/恢复。
- GUI入口、CLI命令、MCP工具、确认、成本、幂等与持久化提交点。
- 开发状态、各入口验证状态、证据路径。功能状态和运行时依赖不足分开。

以声明生成两入口帮助/工具和文档。共享节点创建服务调用公共注册、默认值和端口规则；编辑服务复用GUI图命令；执行服务复用现有runner/executor/网关/正式输出。不得在外部接口写32类私有switch重做节点行为。

### 4.2 读取与修改协议

`graph.get` 提供有界、可分页的一致版本视图；区分 latest（权威宿主当前状态，含未保存编辑）和 persisted（磁盘正式版本）。读取返回 graphVersion/semanticRevision、保存状态及分页版本。版本变化时游标失效，不拼接不同版本的半张图。包含正文的读取显式选择字段，目录默认不泄漏内容。

`node.get` 返回配置、正文、端口、实际引用与可用动作；结果和大媒体通过引用/分页读取。`graph.patch` 接收有限的 typed add/update/remove node/edge/group/layout 操作，不接收整份tldraw快照。临时客户端引用映射为正式ID，支持一次创建多个节点并连线。

提交顺序：预检 → 校验图版本及占用 → 核准完整patch → 记持久意图 → 宿主作为一组编辑应用 → 保存屏障 → main读取并核对 → 回执。提交前失败不改图；应用后失联返回unknown，按确定ID和意图核对，不盲目重放。业务正文/配置与运行结果/审核记录严格分离，客户端不得写运行事实。

### 4.3 执行与任务协议

现有外部响应以 completed/failed/unknown 为主；不能把长任务“已受理”塞成“已完成”。F3先定稿一个版本化任务提交输出：completed表示本次提交命令已经持久受理，同时明确 runId 和运行状态，最终成果只由 run.get 返回的终态判定；也可独立升级envelope，但必须保留旧客户端兼容，不能同名变义。

执行必须显式指定 node/selection/workflow 范围、输入版本、上游策略、是否复用结果和模型成本限制。启动前固定所需输入和能力；任务提供排队/运行/等待人工/暂停/成功/失败/取消/结果未知等可解释状态。取消请求与取消确认分开；不支持远端取消时明确说明，后续结果不能误记用户仍想要的成功。

统一runId、父子任务、每次节点执行、远端任务ID和正式输出版本；可持续查询，不把聊天流事件当任务权威。订阅断开后按游标恢复；MCP进度/资源与CLI JSON事件只作展示适配。不得因断线重发收费请求。

### 4.4 素材、结果与跨图复用

媒体先经公共导入/登记取得受控ID，再交给节点；绝对路径是导入请求，不是任意存储写口。读写大小有界。产物落盘、校验、写入正式输出和保存完成后，才称结果可用。

跨项目复制/实例化须重映射节点、边、媒体及配置/输出中的声明引用；不同画布不能误用另一个项目的相对路径。节点库区分纯结构预设与含资产的资源包，必要附件由明确打包策略处理，不能静默丢失；任何包都不携带密钥。恢复已有产物不触发重新生成。

### 4.5 确认和高交互能力

普通文件对话框以路径/媒体ID替代；有副作用的确认以预检与短期意图令牌/授权委托替代。Agent可以代表用户完成已委托的业务操作，不能伪造必须由真人签署的审核或设备证明。

3D的同步输入、场景编辑、渲染、发布分别声明；保留当前manual-publish时，明确等待合法发布授权，再走同一发布服务。不能调用普通node.execute伪造已发布。代码和脚本复用受控执行环境，时间/内存/网络/文件能力声明；现有隔离是否足够须专项核验。

本计划覆盖合法配置和使用授权材料的协作流程，不新增绕过许可证、签发授权或返回原始秘密的接口。若某GUI业务确实要求不可委托的人工动作，必须在覆盖报告中列出等待/继续路径和未达到的无人值守边界，不能悄悄剔除分母。

### F1：统一契约、确认与调用边界

- 从TSX抽取共享节点定义，迁移GUI引用，避免三份Schema漂移。
- 扩展Operation/NodeAccessSpec；两入口从相同声明生成；增加动作级状态、运行依赖、默认值、兼容说明及查询能力。
- 将外部调用身份接入已有命令/租约机制，明确与内部Agent身份不同；定稿图操作、任务受理与版本协议。
- 实现确认/委托、事务意图与unknown查询骨架，CLI文件/stdin输入及统一退出码；MCP参数、结构化结果与错误对应。
- 将当前`validateAccessRegistry`和目录测试中对名称含import的统一排除，改成按明确能力范围/阶段判定；F7未验收前仍不开放导入，不能因新目标直接取消全部输入边界。
- 补齐适合Agent自纠错的字段级校验原因和可执行下一步；不得回显秘密/正文。图分页、patch操作数、事件保留、媒体体积设上限，批量超限返回可分块方案，不用任意JSON绕过。
- **验收**：同一个测试业务动作在GUI/CLI/MCP校验和结果一致；非法参数、错误实例、过期授权/版本、重复请求和目录漏项正确拒绝。旧25项客户端行为保持兼容。

### F2：先让Agent真正控制画布

- `graph.get/validate/patch`、`node.get/create/update/clone/delete`、`edge.list/create/update/delete`及批量图服务；实际动作可由graph.patch承载，薄命令共用实现。
- 支持位置、尺寸、标题、分组、排列、层次、连接/重连/多输入顺序、断线与删除关联；动态端口变更先列影响，不能静默删除用户连线。
- 明确最新/已保存读视图与flush；每组编辑一个可撤销记录，返回节点ID映射和保存版本。
- 复用应用创建后台或托管画布宿主，串行操作多个项目；能力不足返回host/busy，不由Agent模拟点击。
- **验收**：一个脚本创建A/B/C三个项目，每张图批量创建10个适用节点并连线；修改其中一张不会改变其他图。GUI同步显示并能继续编辑；保存重启后图一致。混入一个非法端口时整批不留半图；用户未保存内容不被覆盖。

### F3：打通可运行的第一张图

- 先实现通用执行、run.get/list/wait/events/cancel/reconcile、output.list/get/select/export；需要暂停/恢复的动作按实际能力声明，不虚设。
- 文本、JSON、结构数据、数据处理、分镜板等确定性节点优先；读取型素材节点也要有正确可用输出，不强制假跑一次模型。
- 选择运行范围、固定输入、复用已有结果、输出投影和保存同源。输出类型不从标题猜，不把所有结果变成字符串。
- **验收**：GUI、CLI、MCP分别创建并执行同一确定性图，规范化参数、连线、端口值和保存重开一致；CLI停止与真实任务终态一致，失联后可查原run而不重跑。

### F4：图片能力逐项接入

- 媒体登记/探测/读取/替换/导出先成公共服务；图片素材、生图、P图、裁剪、拆分逐类接入。
- 全量参数、参考图顺序、提示词/结构化引用、遮罩及适用编辑数据进入Schema；UI编辑器做参数视图而非唯一业务拥有者。
- 结果版本/选中结果/节点物化、资源捕获与跨图引用复用正式输出。
- **验收**：横竖/透明图片、参考图上限、失效文件、取消、部分多产物失败和保存故障；真实供应商最小预算验证，未验证模型组合明确标注。不能把一款模型成功等同全部生图模式通过。

### F5：视频、音频与时间线

- 视频素材、生成各模式、抽帧、截取、深度/白模；音频素材、声音调整、语音合成、克隆、音色设计逐类接入。
- 时间单位、帧边界、流保留、编码/采样率、音画同步、参考音频/视频/图片顺序及供应商能力完整描述。
- 时间线提供轨道、片段、源入出点、起始位置、层级、音量/静音、当前GUI具有的编辑操作、预览和渲染参数。不是只暴露最终合成按钮。
- 本地ffmpeg/Python/GPU能力查询、排队、进度、取消清理；远端任务持久化和恢复与现有机制合并。
- **验收**：媒体探测与GUI一致，截取/抽帧边界一致，时间线修改在GUI可继续编辑；重启后接续原远端任务，不重复生成；资源不足/不可取消行为明确。

### F6：对话、Skill及复杂节点

- 完整会话/消息/附件/模型设置/流式/重生成/取消/压缩协议；继承已有Skill命名安装、绑定和版本不可变规则，补齐真实桌面验收。
- 网址节点暴露当前GUI的打开/编辑及实际具备的读取/输出动作；不凭名称承诺已有网页抓取，依赖和网络策略单独声明。
- 代码节点覆盖多参数/动态端口/多输出，循环覆盖循环体/项身份/预算/取消与恢复；不沿用内部target只有单输出的限制冒充完整GUI能力。
- 导演台暴露已有场景、对象、机位、镜头、连线素材同步、预览、图像/视频发布等业务动作。离屏渲染如缺WebGL/GPU须稳定失败或等待可用桌面宿主，不能伪造文件。
- **验收**：会话与附件保存重开一致；两种入口技能助手可复用；代码隔离/超时与循环中断真实有效；3D发布记录、版本和正式输出与GUI一致。

### F7：库、历史和项目传输

- 所有类型/组合的节点库CRUD、命名、保存策略、实例化、跨画布复制；保留当前skill助手预设的旧语义，新增通用接口或版本，不静默改旧接口。
- 资源库完整资源/组件/分类/文件夹/集合/版本/归档/批量操作、项目素材捕获、物化与包传输。
- 快照、恢复副本、撤销重做、项目与结构包导入导出复用原服务；导入暂存、媒体重映射、密钥剥离、失败清理必须独立验收。
- 批量部分失败按每项回执返回；用户可查完成情况，不因重试再次删除/导出成功项。
- **验收**：Agent导入图片/音频/视频/文本资源并分类、批量导出/删除；保存组合并插到另一张图；导出后重新导入的项目可编辑可执行，媒体不跨项目串用。

### F8：内部Agent与多画布并行

- 将建图预览/提交、角色与工具绑定、启动/观察/暂停/继续/停止、协作输入、固定资产、审核/返工和状态机事件开放为命令。
- 继续复用现有Flow声明、任务账本、审核与固定版本，不让外部Agent伪造内部运行身份或改写任务成功。
- 管理多个项目宿主、资源调度和项目租约；放宽当前LocalAccessService单个mutating标志时，改成明确锁顺序的按项目并发，保护应用级资源写入。
- **验收**：至少两张独立画布同时运行，第三张可排队；停掉A不影响B，重启后每张图核对自己的任务/结果；前台手动编辑与外部写冲突可见，不丢数据。审核不通过/人工等待/返工耗尽均不越过门禁。

### F9：补齐全软件余项并阻止新缺口

- 模型连接/定义/绑定/发现/验证、受控凭据配置、登录协作；环境安装/探测、节点可见集和业务设置、诊断查询/导出。
- GUI独有文件选择/确认/系统交互逐项落实等价输入或等待/继续协议。历史节点读取/迁移、发行版差异和人工步骤单列验收。
- 落实能力声明、三入口目录、Schema/行为兼容、逐动作证据、漏项审查与发布门禁。版本标签和清单与实际安装包一致。
- **验收**：全软件动作表逐行关闭缺口；没有“GUI能做但外部入口没有表达方式”的未说明业务项。已委托操作不需额外手点，确需真人的动作可查询/等待/继续，最终无人值守限制如实报告。

### F10：面向用户的最终交付

- 干净机器/安装目录、独立数据目录、真实CLI与目标MCP客户端，跑完多画布/32类节点/全软件场景。
- 定向、契约、持久化对照、故障恢复、全仓verify及接入门禁全部通过；以可复现证据替代口头声明。
- 付费供应商按已确认预算分组验收；本地GPU、代码、3D、音视频依赖分别验证。Windows为本次工作环境，其他操作系统在实际验收前不标支持。
- 提供命令/工具说明、示例图配方、连接与Skill使用说明、版本兼容表、迁移/回滚说明、剩余限制清单。
- **验收**：同一业务场景GUI/CLI/MCP保存的规范化业务数据及正式结果一致；人接手继续操作无额外转换；全动作覆盖达标。仍有planned项就不得发布“全软件已打通”。

## 7. 验证方法与完成口径

### 7.1 四层证据

1. **契约测试**：输入/默认值/版本/动态端口/结果Schema/两个入口集合一致；不写只复述实现的测试。
2. **业务一致性测试**：相同起始项目和操作意图分别走GUI、CLI、MCP，规范化比较内容、布局、端口、引用顺序、结果投影和保存重开。ID、时间戳等允许差异必须有显式映射。
3. **故障测试**：占用、版本冲突、无效参数、取消、网络断开、磁盘失败、保存后回执丢失、应用崩溃/重启及跨画布隔离。验证正式状态和无副作用重放。
4. **发布测试**：干净检出构建、真实安装包及客户端、真实模型/本地依赖；不把源码开发模式成功当安装包成功。

### 7.2 必测场景

| 场景 | 成功判据 |
| --- | --- |
| 三画布批量建图 | 项目/节点/边身份独立，GUI实时查看，重启一致 |
| 32类逐动作 | 创建、配置/正文、连接、执行/发布、结果及专有编辑动作都有证据 |
| 人与Agent交替 | 手动未保存内容不丢；冲突明确；可在GUI撤销适用图编辑 |
| 多输入/动态端口 | 顺序、基数、输出Schema一致；变更影响可预检 |
| 多模态与复杂工作区 | 图片/音视频/时间线/3D/代码/循环/对话都覆盖，不以普通文本替代 |
| 同名/重复请求 | 同名资源不误删；同幂等键只发生一次副作用；不同意图冲突 |
| 崩溃与未知 | 查回原任务和产物，不自动重复模型请求或发布 |
| 多画布并行 | 取消、诊断、媒体、版本及保存按项目隔离 |
| 模板/包迁移 | 媒体与引用完整重映射，无密钥泄漏，导入失败不留假项目 |
| 升级与发行版 | 旧参数/项目可迁移或明确拒绝，合法能力集合在三入口一致 |

### 7.3 报告必须展示的数字

- 软件业务动作总数、GUI/CLI/MCP分别实现与实测数。
- 32类节点每类适用动作数/已实测数，不能只报32/32类型登记。
- 分母中的人工协作、环境限制、发行版限制和旧节点兼容项单列；不能通过删除难项提高比例。
- 仍为planned、implemented但仅mock、真实客户端未测的项分别列出。
- 当前25项是已发布接口数量，不换算为全软件百分比；完整分母F0审计后确定。

## 8. 后续每次功能变更的固定流程

1. 需求阶段：给业务动作ID，写GUI/CLI/MCP意图、输入/输出和保存结果。
2. 设计阶段：确定公共实现、Schema、确认/幂等/版本、任务/结果、旧客户端兼容。
3. 开发阶段：同包迁移GUI并实现两入口；新增节点附全部专有动作，不只创建/执行两个空接口。
4. 验证阶段：定向一致性/故障测试、真实适用依赖、保存重开、日志脱敏及全仓门禁。
5. 发布阶段：同步机器目录、参数说明、示例、逐动作覆盖与版本兼容；未完成不能宣称同等可用。

[AGENT_PARITY_SPEC.md](../../AGENT_PARITY_SPEC.md)是维护要求，AGENTS入口和检查模板需指向它。现有`verify:agent-access`保留，逐步增加真实业务/入口/兼容/发布检查；具体脚本名在实施时确定，不能把设计中的脚本写成已经运行通过。

## 9. 风险、决策和交付边界

| 已识别问题 | 处理方式 | 所属阶段 |
| --- | --- | --- |
| TSX注册与UI私有逻辑 | 共享契约抽取，GUI同包迁移，不由外部客户端复制实现 | F1/F2 |
| 当前图与多画布宿主耦合 | 串行先行，多宿主再并行，显式目标与占用 | F2/F8 |
| 手动运行与内部Agent身份不同 | 新外部主体适配正式准入，不伪造内部任务 | F1/F3 |
| 提交后失联/计费任务重复 | 持久意图、未知状态和对账，分阶段提交 | F3/F5 |
| 复杂工作区缺结构化动作 | 时间线/3D/对话逐字段审计，完整编辑与发布 | F5/F6 |
| 导入/设备凭据/授权 | 正式服务、重映射与合法协作，不返回或绕过秘密 | F7/F9 |
| 当前验证基线有进行中改动 | 先复现干净版本，各模块确认自己的影响，不能批量刷hash | F0 |
| 规范比门禁先进 | 新增要求立即用于开发审查，机器门禁分阶段实现并记录状态 | F1/F9 |

本次文档变更不改变运行契约、存储、模型请求或日志事件；日志影响“不涉及”。不会新增或宣称上述计划接口已可用，也没有替后续业务开发执行完整验收。文档的完成检查是本地链接、32类覆盖、阶段依赖、现状/计划分离和规范入口一致性。
