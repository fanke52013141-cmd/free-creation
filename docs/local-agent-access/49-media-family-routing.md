# F5/F4 动作路由：把"GUI 就是节点执行"的动作映射到外部路径（并挡掉两处不诚实映射）

日期：2026-11-08。基线：117 项操作、F4/F5 共 26 项计划项。本轮把它们逐项定性：
**23 项映射到既有外部路径，2 项明确留在计划阶段，5 项排除并写理由**。F4/F5 计划项从 26 → **2**。

## 1. 判定依据（不按名字猜，按 GUI 入口的事实）

`action-coverage.json` 里每个动作的 `gui` 字段已经写明 GUI 入口是什么。例如
`ipc.media.imageCrop` 的 GUI 入口就是「image-crop 节点执行」——那么外部等价路径必然不是
"再造一个裁剪命令"，而是 `node.execute`（执行该类型节点）+ `output.get`（读正式产物）。
这就是本轮映射的全部逻辑，并且**加了机器校验**（见第 4 节），不允许拍脑袋。

## 2. 映射结果

| 组 | 数量 | 外部路径 | 证据等级 |
| --- | --- | --- | --- |
| 本地确定性节点执行（裁剪/拆分/抽帧/截取/声音调整/时间线合成） | 6 | `node.execute` + `output.get` | **真实桌面里程碑逐动作验收** |
| 付费生成节点（生图/P图/视频/语音合成/音色设计/声音复刻/本地 IndexTTS） | 7 | `node.execute` + `run.get/wait` + `output.get` | **仅接线级**，真实供应商从未实测 |
| 任务控制（视频任务查询/取消、转换取消、批量取消） | 4 | `run.get` / `run.wait` / `run.cancel` | 服务级测试 |
| 环境与导入（IndexTTS 检测、缓冲导入） | 2 | `environment.local` / `media.import` | 已有测试 |
| 纯预览/内部维护 | 5 | 排除 | — |

**留在计划阶段的 2 项（不硬凑）**：`ipc.media.videoConvertDepth`、`ipc.media.videoConvertClay`。
它们需要本机 Python + CUDA 推理环境（先经 `environment.videoEngine.install` 安装），且
`video-depth`/`video-clay` 的执行**从未实测**。环境未就绪时 `node.execute` 只会如实失败，
所以不把它们标成"已开放"——这是被本轮测试抓出来的，不是自查发现的。

**排除的 5 项及理由**：媒体元数据探测（导入登记时已返回 kind/mime/size）、视频探测（导入时已完成）、
视频缩略图与音频波形（纯预览呈现，不产生正式产物）、项目文件检查（内部维护/自检路径）。

## 3. 诚实边界（写死在映射说明里）

- 付费族的 note 逐条写明"付费/供应商执行从未实测，用户要求语音克隆/音色设计/视频生成由本人自测"；
- 本地确定性族的 note 写明"已由真实桌面里程碑逐动作验收"；
- 任务控制的 note 写明"取消请求与确认分离，终态由 run.get 读账本事实，不把 unknown 报成成功"。

## 4. 机器校验（`test/media-family-routing.test.ts`，7 项通过）

本测试不是复述实现，而是**专门用来抓不诚实映射**的：

1. GUI 入口为"节点执行"的动作必须全部已映射且带 `nodeType`；
2. 依赖 CUDA 且未实测的两项必须留在计划阶段、不得声明外部映射、note 必须写"未实测"；
3. 每条 `nodeType` 必须指向**当前 Active、可创建、且有契约快照**的节点类型
   （借 `node.type.get` 的契约目录校验，防止映射到已退役或不存在的类型）；
4. 映射到 `node.execute` 的类型，其矩阵 N5（执行）必须**要么已验收，要么明确声明未实测**——
   两种谎言都不放过：执行未验收却写成可用、或已验收却仍写 planned；
5. 付费族 note 必须含"未实测/自测/未验收"字样；
6. 被排除的预览/维护动作必须有理由且不声明外部映射；
7. 任务控制必须映射到任务族且 note 说明"取消≠成功"。

这条测试在本轮实际抓出 3 个问题（depth/clay 误标、付费 note 缺声明、历史 excluded 条目
把理由放在 `reason` 而非 `note`），全部已修。
