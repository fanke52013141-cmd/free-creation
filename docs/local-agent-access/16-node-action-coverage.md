# 32类节点的外部动作覆盖与验收计划

日期：2026-11-07。基线类型：`src/shared/types/index.ts` 的 `ACTIVE_NODE_TYPE_IDS`；版本来自 `nodes/specs/index.tsx` 与 `agentFlow.tsx`。本表是开发清单，不是已支持声明。新增类型或契约版本变更须同包更新机器清单和本表。

## 1. 每类节点必须核对的公共动作

| 编号 | 适用业务动作 | 必须验收 |
| --- | --- | --- |
| N1 | 查询类型、默认值、字段、端口、可用动作与依赖 | GUI/CLI/MCP同源；发行版与环境状态正确 |
| N2 | 创建、读写标题/位置/尺寸、克隆、删除、组合与排列 | 批量ID映射、单组撤销、删除影响和保存重开 |
| N3 | 配置、正文、素材、模型及节点专有字段读写 | 严格Schema、默认/旧值、单位、敏感信息边界 |
| N4 | 创建/修改/删除连线及动态端口 | 类型、基数、必填性、多输入顺序、引用投影一致 |
| N5 | 执行、显式发布、作为素材输出或其他适用动作 | 复用正式执行/发布规则，不强制把所有节点视为生成任务 |
| N6 | 结果、版本选择、输出投影、物化、预览、导出 | 正式持久产物，GUI能继续操作，不丢类型或引用 |
| N7 | 状态、任务、取消、暂停、继续、核对与恢复 | 按实际支持声明；不适用有依据，不伪造取消/恢复 |
| N8 | 节点库保存/实例化、资源捕获、跨画布复用 | 配置和声明的媒体依赖完整重映射，聊天历史等按明确策略处理 |

N1–N4的公共骨架在F1/F2交付，N5–N7在下表专包验收，N8在F7统一完成。类型字段存在或执行器已注册不等于N1–N8完成。最终按“节点×业务动作×模式×入口”记录证据，不按“节点类型数量”计算全部接通。

## 3. 非节点但必须同步的动作

32类表不覆盖软件全部能力。项目/画布、模型配置、素材管理、资源库、节点库、Skill管理、历史/恢复、应用业务设置、环境安装/探测、诊断及合法确认协作均在[计划第3节](15-gui-cli-mcp-parity-plan.md#3-全软件业务范围)单独登记。

GUI中的“替换”“抽帧”“截取”等快捷入口可能调用同一个节点/媒体能力。必须登记入口映射并复用公共实现，不为了API计数重复创造有不同语义的实现。

## 4. 历史类型和发行版

`script`、`video-audio`、`vocal-separate`、`group`、`compose` 为当前 Legacy 清单。不得恢复其新建入口；以当前GUI实际读取、迁移及适用执行行为为对照制定兼容验收，不能对不具备executor的历史类型伪造可执行能力。

发行版裁剪及工作区可见集需F0核对正式构建结果。Active是协议全集，不代表每个发行版都能新建全部32类；三入口应用相同版本/授权/依赖策略。代码中存在但未打包、仅隐藏UI或在进行中分支修改的节点，不能凭源文件就标安装包可用。

## 5. 每一行关闭缺口的记录格式

每个动作记录：`nodeType + contractVersion + actionId + mode + operationVersion + GUI/CLI/MCP状态 + 环境 + 证据 + 限制 + 负责人模块`。

关闭前必须有：

1. 默认、有效、无效、旧配置的真实业务校验；适用时包含所有动态端口与模式。
2. 三入口得到等价的配置、正文、端口、连线、正式结果和保存重开状态。
3. 合理的取消/依赖不足/版本冲突/占用/恢复边界，不支持的控制明确拒绝。
4. 结果能被下游按正式协议消费；预览记录、模型文字、UI标签不代替产物。
5. 节点库/资源引用/跨画布迁移不丢数据、不含密钥；日志有适用阶段及脱敏证据。
6. 安装包/真实客户端与适用供应商或本地依赖验收。未做实测的组合单列，不扩大为全部支持。

本次只建立人工开发矩阵；逐动作机器清单、自动差异检查和发布报告在F1/F9落地。当前32类目录仍主要标planned，这一事实不能被本文的完整表格掩盖。
