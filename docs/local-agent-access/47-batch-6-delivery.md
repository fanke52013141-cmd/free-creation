## 二、受控凭据写入（`570eeb4`）

这是"Agent 能不能自己配模型"的关键——不能配模型，所有生成能力都用不上。但凭据是敏感面，
`AGENT_PARITY_SPEC §6` 要求受控写入、不得回传明文、不得绕过设备密钥与授权。做法：

| 动作 | 状态 | 说明 |
| --- | --- | --- |
| 连接创建/更新（含 API Key） | ✅ | 复用 GUI `saveConnection`（设备绑定密钥库 + 授权守卫） |
| 密钥是否存在 / 指纹 | ✅ | 只回 `present + sha256:12 指纹`，不回明文/端点/请求头 |
| 连接删除（连带模型定义） | ✅ | 回执给 `deletedModels` |
| 模型定义增删 | ✅ | 不涉及凭据 |
| 功能默认绑定 | ✅ | **只在模型该操作已验证时成立**（宿主强制），未验证返回 `MODEL_NOT_VERIFIED` |
| 模型发现 / 模型验证 | ❌ 不开放 | 会向供应商发请求（可能计费/限流）。因此外部**无法自行验证模型**，验证仍是 GUI/人的步骤 |
| 读明文 / 导出凭据 / 密钥库绕行 | ❌ 永不开放 | 安全红线 |

关键证据（8 项测试）：回执与诊断事件都不含明文标记、密钥库密文列不含明文；同密钥指纹稳定、
省略 apiKey 保留原值、换密钥指纹改变；连接事实变化标记 `invalidatedBindings`（宿主会清除验证
与绑定）；删除后查询如实 NOT_FOUND；幂等重放只有一条连接。

一个必须说清的副作用：保存连接时若改动协议/地址/请求头/密钥，宿主的既有行为是**清除该连接的
验证与功能绑定**——回执用 `invalidatedBindings` 如实告知，不会让调用方误以为还能用。

## 三、环境探测与安装（`0ae5f6d`）

- 新增 `environment.videoEngine.install`：完全复用 GUI `installVideoEngine()`（下载源/权重/
  SHA-256 固定，外部**不能**指定 URL/镜像/路径，没有新写下载器）。
  * 必须 `confirmInstall:true`，否则 `INSTALL_CONFIRM_REQUIRED` 且安装实现 **0 次调用**；
  * `started` 语义如实：false = 已就绪或已在安装（不谎报"已开始"）；
  * 只受理启动，进度/终态由 `environment.videoEngine.status` 读取；
  * 缺 Python → `PYTHON_REQUIRED` + GUI 同一句提示；
  * 幂等三层（dispatch 账本 + 并发去重 + 实现内护栏），并发第二个请求按全局写锁 `RESOURCE_BUSY`。
- `environment.local` 输出追加：FFmpeg/FFprobe 可选 `version`、`videoEngine.phase`
  （ready/installing/python-ready/python-missing/unsupported-platform），文案抹除本机路径。
  这是**输出追加式**变更，已用 `--accept-contract-change` 显式接受并写明兼容结论。
