# 铁律：功能变更必须同包同步 Agent 对接

状态：**立即生效**（2026-11-08 用户明确要求）。本文件是行为规则，不是建议。
上位规范：[AGENT_PARITY_SPEC.md](../../AGENT_PARITY_SPEC.md)。执行入口：`npm run guard:agent-parity`。

---

## 0. 一句话铁律

> **凡是改动了"用户能做的业务动作"，就必须在同一次提交里把 CLI / MCP 的对接一起改完并验证；
> 不允许出现"人能做、Agent 不能做"或"Agent 以为能做、实际做不到"的任何缺口。**

违反这条的提交视为不合格，不得合入、不得发布。

---

## 1. 什么算"改动了业务动作"（触发条件）

命中任意一条，就必须走本流程：

| 类别 | 具体例子 |
| --- | --- |
| 新增/修改 IPC 通道 | `src/main/ipc/*.ipc.ts` 里新增 handler、改参数、改返回值、改错误码 |
| 新增/修改节点类型 | 新增 `NodeTypeSpec`、改端口声明、改 `contractVersion`、改默认配置、改动态端口规则 |
| 改业务默认值/参数语义 | 分页上限、超时、默认分辨率、默认预设、必填项变化 |
| 改权限/确认/人工门禁 | 新增"必须人确认"的动作、新增计费闸门、改授权前置 |
| 改持久化语义 | 保存时机、版本推进、冲突判定、恢复副本、事务边界 |
| 改错误语义 | 新增/重命名错误码、把"失败"改成"unknown"、改重试语义 |
| 删除/停用功能 | 删 handler、退役节点类型、下线入口 |
| 改运行/任务行为 | 取消语义、恢复、重放、并发占用、产物落位 |

**不算**（写明"不涉及 Agent 对接"即可）：纯样式、纯静态文案、注释、纯内部重构且对外行为与契约不变。

---

## 2. 同一次提交必须包含的 6 件事

缺任意一项都算不合格：

1. **契约**：在 `src/shared/agent-access/ops/*.ts` 登记/修改操作（输入 Schema、输出 Schema、description 写清边界）。
2. **实现**：在 `src/main/agent-access/*-ops.ts` 给出实现；**复用 GUI 同一业务函数**，不另写执行器、不直写数据库/项目文件。
3. **覆盖声明**：`docs/local-agent-access/action-coverage.json` 里该动作的状态/映射/理由同步更新（新增 IPC 通道不更新会让 `audit-business-actions` 直接红）。
4. **节点矩阵**：涉及节点时，`node-actions.ts`（N1–N8）与 `node-contracts` 快照同步；新增节点类型不登记会让节点契约漂移测试红。
5. **测试**：同包至少一条能复现"该动作经外部入口可达"的服务级测试；涉及桌面握手/人工确认的，补一条"未满足前置时必须拒绝"的断言。
6. **文档**：交付台账写清：动作 → 外部路径 → 证据等级（真实桌面实测 / 仅接线 / 未实测）→ 未覆盖边界。

## 3. 三道门（提交前必跑）

```powershell
npm run guard:agent-parity      # = 契约快照 + 动作分母 + 日志门禁，任何一项红都不许提交
npm run typecheck               # 类型
npm run test -- --run           # 全仓（或至少受影响的族）
```

涉及外部入口的改动，再跑：

```powershell
npm run build
node scripts/verify-acceptance.cjs --fast     # 真实 MCP 协议层 + 优化验证（约 3 分钟）
```

改了具体业务族，跑对应验收（否则"测试绿"只证明没坏，不证明能通）：

```powershell
node scripts/verify-acceptance.cjs family1 families-4-5-6-9
```

## 4. 例外流程（唯一合法的"不同包改"）

只在同时满足以下三条时才允许：

1. 该能力**尚不可发布**（在非发布分支，或功能开关后关闭）；
2. 用户**明确接受**范围与期限（记入下方例外清单，含日期与过期时间）；
3. 提交信息与台账显式写 `AGENT-PARITY-EXCEPTION: <原因> <到期日>`。

未满足三条的"先上 GUI，Agent 以后补"= 违反铁律。

### 例外清单

| 日期 | 动作/范围 | 原因 | 期限 | 责任人 |
| --- | --- | --- | --- | --- |
| 2026-11-08 | `video-depth` / `video-clay` 的真实转换 | 需本机 CUDA 环境安装后才能验收（代码已接通） | 环境就绪后 | 待定 |
| 2026-11-08 | 付费生成（生图/视频/语音/音色）真实调用 | 需预算授权，且用户要求自测 | 用户自测后 | 用户 |

## 5. 为什么定成铁律（都是真实踩过的坑）

| 事故 | 后果 | 现在由什么防住 |
| --- | --- | --- |
| 外部建项目默认用 `general` 预设（24 类），GUI 用 `all`（32 类） | 用户"新建项目后少了 8 类节点入口" | 节点矩阵 + `allWorkspaceProfile()` + `edition-node-parity` 测试 |
| `flowAgent.cooperate` 缺任务返回 `unknown` | 调用方分不清"没发生"和"不确定"，只能放弃 | 稳定错误码 + 对应验收断言 |
| `providers.repo.toSummary` 用旧逻辑判断 `hasApiKey` | 明明有密钥却报"没有"，Agent 会重复写凭据 | 读侧校正 + 根因修复 + 验收断言 |
| `group.create` 不回传 groupId | 组合后永远无法解组（能力单向缺失） | 回执补 `groups[{ref,groupId}]` + 验收 |
| 验收脚本写死"34 个工具" | 操作数一涨，脚本必红，最终没人跑 | 改为从门禁读真值 + `verify:acceptance` 统一入口 |
| 旧版 `DISTRIBUTION_HIDDEN_NODE_TYPES` 隐藏 13 类节点 | 发行版"人看不到但 Agent 能建" | 清单清空 + `edition-node-parity` 测试锁死 |

结论：这类缺口一旦发布，后续每加一个功能都要回头补，成本是当时的数倍。所以必须**同包**。

## 7. 例外之外的硬红线（永不放开）

- `license.*` 8 项（授权签发/挑战/证明/策略导入）不得对外开放——授权门禁的意义就在于此；
- 不得为"让 Agent 通过"而伪造运行事实、伪造人工确认、或绕过计费/授权前置；
- 不得用"仅 mock 通过"或"仅文档登记"计入完成。
