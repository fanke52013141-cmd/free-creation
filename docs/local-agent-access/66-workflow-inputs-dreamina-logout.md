# 即梦账号切换与选区运行补输入

## 用户路径

在模型设置的即梦通道中可以登录和退出。退出调用本机 CLI 的 `logout`，随后可重新发起设备授权。应用不读取 OAuth token。浏览器如果还保留即梦网页会话，可以在授权页选择要使用的账号。

框选节点后点击运行，系统沿原连线按顺序执行。执行到缺少必填输入的节点时，弹窗显示节点名和端口名，按端口类型提供文本、JSON 或素材选择。空文本源和空图片源也能在运行中补齐。同一个源节点只补一次，沿原连线向各分支输出。文本和素材引用仅作用于当前运行，上传文件按原有导入规则进入项目素材。取消弹窗终止本次运行，已经完成的节点保留其结果。

AI 处理有连接到下游的实际输出时，直接把本次验证过的文本、Markdown 或 JSON 放进原图的输出映射。独立使用时仍可以创建文档产物。生图应连接 AI 处理的文本输出到提示词端口，结构化输出需匹配接收端口的 Schema。

## 全局规则与边界

- 运行范围按目标节点和真实上游闭包确定。固定配置与已产出的上游值优先，临时输入不能覆盖已有连线。若上游已连接却失败或输出类型不匹配，运行记录指向原节点和端口。
- 在执行到缺口时补值，适用于无法在启动前判断的输入。当前入口是框选与组合运行。全画布运行、循环项级补值、应用重启后的运行恢复可沿同一端口和值模型扩展。重启恢复需要单独的保存和人工继续规则。
- `node.execute` 的 `subgraph` 可传可选 `inputs`。每项包含 `nodeId`、`portId` 和类型化 `value`，媒体仅接受当前项目的 `mediaId`。空图片源用 `out-image` 指定本次来源。旧请求格式保持兼容。外部调用缺少可补值时由任务返回缺失端口，调用者可提交新请求。`dreamina.logout` 使用 `confirmLogout: true`。CLI 和 MCP 均经现有操作目录和同一宿主实现。
- 诊断复用运行及导入的阶段事件。只登记等待补值、端口数量、任务结果和账号操作阶段，不记录输入正文、文件内容、授权码或 CLI 原始回显。

## 验收

浏览器使用本地模型夹具实际框选并运行文本 → AI 处理 → 生图，验证成图、保留空文本源、没有多余中间文本卡。另验证空图片源上传、参考图传递及取消停止。外部服务测试验证临时输入转交桌面、单节点模式拒绝临时输入、未显式确认的退出请求被拒绝，以及临时正文不入诊断。模型夹具未调用计费服务，真实账号退出未对当前登录状态执行。

构建、接入门禁与 MCP 快速验收通过（协议 90 项、优化 9 项）。全量 verify 在现有 activate-dev-license.cjs 和 license-tool.cjs 的 lint 报错处停止，本次修改文件的定向 lint 已通过。

## 后续统一到整张画布的顺序

1. 将端口缺口检查提到运行计划阶段，先列出确定缺失的输入，再对依赖上游输出的端口保留运行时补值。
2. 将等待输入登记为明确的运行状态，区分尚无输入、上游执行失败、端口不匹配。运行中心可定位到对应节点。需要接管失败分支时，由用户明确选择是否补值并从断点继续。
3. 用本次运行 ID 固定已完成步骤和正式产物。在支持重开恢复前验证提交回执、取消和模型任务核对，避免恢复时重复提交已经受理的生成请求。循环项按各自批次登记输入与产物。
