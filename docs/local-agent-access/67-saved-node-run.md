# 保存节点运行与画布输入预检

节点库按保存名称或内部节点标题搜索。卡片的「运行」会把模板实例化到当前画布，沿原连线执行，正式产物留在画布。旧连线无法恢复时停在插入阶段，供检查后再运行。取消补输入会停止执行，已插入的节点可通过画布撤销。

桌面在整张画布、选区、组合与节点库运行前补齐可确定的缺项，运行中仍按真实端口和上游结果校验。等待与补值共用原有节点输入诊断，正文与素材内容不入日志。

CLI 和 MCP 使用同一操作链。`node.library.search` 按名称查找，`node.library.get` 查看模板构成，`node.library.insert` 返回实例节点 ID 和图版本，`node.get` 查看实例实际输入输出端口。将端口值作为 `node.execute` 的 `subgraph` 模式 `inputs` 提交，使用 `run.wait` 与 `output.get` 查看结果。素材引用使用当前项目的 `mediaId`。每一步独立返回结果，插入成功而执行未开始时可用已有实例继续。

跨重启断点续跑仍需运行账本、产物引用及供应商回执的持久化设计。

CLI 和 MCP 插入模板后可调用 node.runPlan，传入实例节点 ID 获取整个上游闭包中可确定的缺项。预检读取当前打开画布，返回节点 ID、端口 ID、显示名及类型，并与 GUI 使用同一缺项判定。上游实际产物仍由执行时验证。
