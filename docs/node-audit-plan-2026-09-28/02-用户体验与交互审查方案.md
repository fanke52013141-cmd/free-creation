# 方案二：用户体验与交互审查方案

目标：让用户能判断节点做什么、需要什么、运行到了哪里、结果是什么、失败后怎么办。以 [执行总览](./00-执行总览.md) 为范围，用 [方案一](./01-全面代码测试方案.md) 的相同素材与契约作为结果真值。

本方案检查可理解性和真实操作。自动化点击成功只是证据之一；后台字段正确但用户看不懂，仍应登记体验问题。

**一、参与者、环境和记录方法**

- 先由熟悉产品的测试者逐项走查，再建议安排3名不了解实现的人，每人独立完成下方任务。暂时找不到新用户时标记“专家走查”，不声称完成用户研究。
- 新手只获得目标和素材，不预先讲节点名/端口规则；记录首次尝试。卡住后再给提示，分别记录“无帮助完成”和“提示后完成”。
- 主环境：实际Electron桌面包；1366×768/100%DPI、1920×1080/125%或150%DPI，至少一个高分屏；画布缩放50%/100%/150%，左栏/右栏开闭分别检查。
- 同一任务同时保存：录屏或关键步骤截图、点击路径、耗时、误操作、求助次数、用户原话、最终端口/资产证据。涉及模型等待，扣除纯供应商等待后再比较操作时间。
- 控制台报错、异常toast、未处理promise另建技术缺陷；使用者不需要读开发者工具才能恢复。

每个节点体验卡：

```text
节点/模式/供应商：
任务目标与起点：
发现入口：用了多久，搜什么词，是否找错节点
理解输入输出：用户的解释；实际协议；误解在哪里
关键操作：总步数、误点、撤销、滚动、切面板次数
状态与结果：能否判断正在运行/失败/旧结果/新结果
恢复：是否自行完成纠错和继续执行
结论：完成情况、严重度、截图时间点、改进建议、复测标准
```

**二、所有核心节点共用的走查步骤**

每节点依次做“发现→创建→空状态→配置→连接→运行→查看→修改复跑→错误恢复→保存重开”。将下列编号与节点名组合记录，例如 `UX-C05/image-crop`。

| ID | 实际操作 | 用户应当看见/理解 | 典型缺陷 |
|---|---|---|---|
| UX-C01 | 从创建菜单、搜索、常用入口寻找节点，尝试用户习惯词 | 标签一致；“P图/图片编辑”“结构数据/数据结构”等常用词可合理找到；退役节点不混入新建 | 名称/分类不一致、重名难区分、搜索只认内部ID |
| UX-C02 | 新建节点，不填配置，尝试运行；打开概览 | 一句用途说明、最小输入要求、下一步；不可运行原因可见 | 空白卡、置灰无原因、无输入却假成功 |
| UX-C03 | 打开输入输出面板，悬浮端口，再连一条合法/非法边 | 类型、必填、单值/多值、真实来源可读；拒绝原因能指出哪个端口 | 颜色是唯一信息、错误只显示“失败”、端口被遮挡 |
| UX-C04 | 编辑卡片和详情中的同一参数，切换节点，再返回 | 同一参数值同步，主编辑入口清楚；输入草稿不丢失 | 两套值互相覆盖、失焦丢字、默认值伪装已设置 |
| UX-C05 | 卡片运行、详情运行、多选运行；观察范围说明 | 用户可预知执行当前节点还是包含上游；运行入口语义一致 | 单选意外重跑付费上游、多选跑无关分支 |
| UX-C06 | 运行长任务，双击运行，再取消，等待迟到响应 | 立即反馈；重复点击受控；取消状态不被成功覆盖；异步阶段可解释 | 永久转圈、假百分比、按钮不可恢复、重复扣费 |
| UX-C07 | 成功后找到结果、预览、接下游，再运行一次 | 新产物位置可发现；操作节点仍可配置；历史产物与最近输出区分清楚 | 产物在视口外无提示、操作节点变资产、结果互相覆盖 |
| UX-C08 | 成功后制造失败，查看卡片、运行面板、下游 | 旧成功结果标识明确；本次失败原因及修复入口可找到 | 旧图仍在导致误以为成功，下游用旧结果无说明 |
| UX-C09 | 长标题、长文本、多结果；缩小窗口/画布；滚轮/触控板 | 标题不挤运行按钮；内滚动和画布缩放合理区分；内容可到达 | 滚轮吞事件、整张画布飞走、端口/弹层裁切 |
| UX-C10 | 双击重命名，Enter/失焦；单击选中；Esc关闭菜单；撤销重做 | 名称保存，单击不误编辑；键盘行为一致；撤销范围可预测 | 输入时触发画布快捷键、标题影响业务身份 |
| UX-C11 | 聚焦文字输入按Delete；选边按Delete；混选节点和边再删 | 输入只删文字，选边只删边，混选一次删除所选对象及关联边 | 误删节点、必须多次删除、撤销无法恢复 |
| UX-C12 | 打开多个菜单/下拉/Tooltip，点外部关闭，靠窗口边缘操作 | 菜单层级和退出方式一致，弹层不被卡片裁切 | 多层遮挡、焦点跑丢、点击穿透执行 |
| UX-C13 | Tab/Shift+Tab、Enter、空格、Esc；不依赖颜色判断状态 | 关键按钮有名称、焦点可见、可键盘操作；状态有文本/图标辅助 | 无焦点、图标无可读名称、错误只靠红色 |
| UX-C14 | 保存→关闭进程→重开；切项目；复制节点；从节点库插入 | 配置/结果符合保存承诺；无重复媒体/旧运行任务；恢复后下一步清楚 | 恢复永久running、复制结果串引用、模板带入旧密钥 |

视觉依据首先采用 `NODE_CONTRACT_SPEC.md` 的强制规则及真实产品任务；`docs/NODE_UI_STANDARD.md` 当前标注讨论稿，作为审查参考。两者冲突时登记决策项，不能仅凭讨论稿把现有功能判错。

**三、逐节点任务审查**

每行的“修改/失败恢复”都要独立走一次，不能只录成功页面。所列步骤是测试脚本；给新手只读“任务”，不提前告诉操作路径。

| ID / 节点 | 给用户的任务 | 观察步骤与通过标准 | 修改/失败恢复 |
|---|---|---|---|
| UX-T01 文本 | 输入两段不同来源说明，送给下一节点 | 找到正文、知道两源如何合并；多行/中文输入顺畅，来源可见 | 断一条线、改文本、撤销；不重复累加旧内容 |
| UX-T02 网址 | 保存并打开一个参考网址，把地址交给下一节点 | 名称与URL入口好找；用户知道它是链接；点击打开与选择/重命名不混淆 | 错误协议/空地址能修复；不误导为“自动读取网页” |
| UX-T03 文件 | 导入一份含“甲组-731”的文件并询问内容 | 拖入/上传后看到文件名、解析状态、正文预览；能够发现out-text并接对话 | 扫描PDF/损坏文件显示不可解析；知道换文件或提供文字，不以空回答掩盖 |
| UX-T04 AI 对话 | 两轮询问文件内容，然后建立新会话 | 发送、换行、停止、上下文来源清楚；卡片与工作台会话同步；长回复可读 | 取消/失败重发不重复消息；切会话不串结果；重开历史可继续 |
| UX-T05 AI 处理 | 将文本分别转为摘要、Markdown、两条镜头JSON | 模式/模型/指令入口可理解；用户区分对话与一次性处理；有效输出口清楚 | 错JSON提示字段/结构，不只给技术栈；切模式后旧边有可理解反馈 |
| UX-I01 图片资产 | 导入透明图并接裁剪 | 缩略图和大图一致；透明背景易辨；资产入口与生图节点区分 | 缺文件可定位原因；复制/删除不隐式破坏原素材 |
| UX-I02 裁剪 | 取右下区域，再做四角透视裁剪 | 控制点易抓取；预览比例可信；矩形/四角模式、重置/确认可发现 | 拖出边界或自交有反馈；关闭工作台是否保存明确；缩放不改坐标含义 |
| UX-I03 拆分 | 拆为2×3，只用第4格，再批量处理全部 | 行列含义、顺序、面积百分比明确；当前图与图片集合两输出能区分 | 超64格时显示实际限制；切选中格下游预览同步；不将25%误当边长比例 |
| UX-I04 生图 | 用提示词和两张有序参考图生成图片 | 模型可用状态和提示词来源清楚；参考顺序可辨；用户知道结果去哪里 | 缺模型、参考超限、下载失败、取消后可以恢复；不只显示远程生成成功 |
| UX-I05 P图 | 标出蓝色区域要求改红，然后只改遮罩内区域 | 原图/标注/遮罩/输出区别明确；工具、撤销、笔刷大小、反选易发现 | 放大缩小不移位；不支持遮罩模型有可操作错误；原图可找回 |
| UX-V01 视频素材 | 导入片段、预览，连接抽帧和截取 | 时长、播放/暂停、静音、当前时间清楚；不把预览移动当正式配置 | 无音轨/坏文件反馈正确；源视频与生成视频入口区分 |
| UX-V02 抽帧 | 取首帧、尾帧、2.34秒画面 | 时间输入、预览定位和确认关系清楚；毫秒/秒单位一致 | 超范围提示或钳制可见；尾帧不会点出空结果；拖动不触发无数次抽取 |
| UX-V03 视频截取 | 截2–5秒，再仅提取这段声音 | 起止/时长关系可读；输出模式提示对应输出端口；区分播放头和区间 | 起止反转可恢复；无声视频提音有明确原因；人声选项能力可见 |
| UX-V04 深度视频 | 把短片转为近白深度图视频 | 环境就绪/GPU/模型状态可见；首次准备与转换进度分开；远近颜色解释简单 | 环境未装/显存不足知道下一步；取消不阻塞其他节点 |
| UX-V05 白模视频 | 生成灰白浮雕效果，再改变光方向和强度 | 预览帮助理解参数；用户知道是深度着色效果；新旧结果可比较 | 不把真实3D能力写进提示；改参数后需重新运行的状态清楚 |
| UX-A01 音频资产 | 导入、试听、连接声音调整 | 播放/暂停、时长、波形、音量不冲突；上传点击区域不过大 | 卡片其他区域点击不弹文件框；离开后播放策略明确 |
| UX-A02 声音调整 | 将10秒音频改成5秒并降低音量，再处理视频 | 倍率/目标秒数切换易懂；输出类型跟源一致；参数单位清晰 | 两种源同时连有明确提示；无声视频调声量被解释；0%与静音一致 |
| UX-A03 语音合成 | 输入台词，选音色并合成；更换供应商 | 文本、音色、速度/音调层次清楚；高级参数不过度占卡片；可直接试听结果 | 后端切换后字段/端口同步；失效音色不会悄悄换默认；字幕开关有意义 |
| UX-A04 语音克隆 | 用机器语音参考创建音色，并读一句新台词 | 用户理解输出是音色档案；创建成功后有可发现的“接语音合成”路径 | 样本要求在上传前可读；重复上传/删除易恢复；ID不是唯一成功反馈 |
| UX-A05 音色设计 | 描述“沉稳清晰的旁白”，试听，再合成另一句 | 描述与试听文本区分；试听音频和可复用音色来源明确 | 空字段、试听失败、ID缺失分别提示；复用无需手工猜拷哪些字段 |
| UX-D01 数据处理 | 从JSON取user.name，再套入一句模板 | pass/pick/template用途有简单示例；知道只接一个值；结果真实类型可看 | 缺字段能定位路径；不支持数组索引时有说明，避免无效试错 |
| UX-D02 JSON | 粘贴JSON并格式化，修正一处语法错误 | 编辑区域、格式化/运行差别可理解；错误位置可定位；大JSON可滚动 | 两种输入同时接的优先级可见；格式化不丢未提交编辑 |
| UX-D03 结构数据 | 选“分镜列表”模板并把上游文字填入字段 | JSON与结构数据职责不同；schema预设和实例端口同步；占位符有例子 | 缺字段/错类型指向具体位置；重跑仍保留模板，占位符不消失 |
| UX-D04 分镜板 | 编辑2个镜头台词，新增、排序并送给下游 | 表格行序、ID、画面/台词/时长易读；单元格编辑不拖动画布 | 删除/撤销能找回内容；重开顺序一致；错误数据不突然清空整表 |
| UX-D05 循环 | 将3项列表逐项处理，第2项失败后继续，最后重试失败项 | 当前第几项/总数、成功/失败/待处理分开；失败条目可定位；能找到结果集合 | 暂停/取消/续跑语义清楚；成功项复用有标记；修改列表后告知失效范围 |

**四、用户完整任务与跨节点理解**

| ID | 任务说明 | 完成标准 | 初始操作目标（扣除计算/供应商等待） |
|---|---|---|---|
| UX-F01 | 从文件得到两条分镜并修改第二条台词 | 文件→对话/AI处理→结构验证→分镜板；能指出正文与结构来源 | 熟悉者≤8分钟；新手记录首次基线 |
| UX-F02 | 生成一张图、局部修改、裁剪成六格，处理指定一格 | 发现当前格和完整集合区别；可找到全部中间资产 | 熟悉者≤10分钟，无覆盖原图 |
| UX-F03 | 截取片段、抽帧、生成深度和白模效果 | 四类输出均能预览；明白本地环境准备与视频生成无关 | 熟悉者≤8分钟，不含环境安装 |
| UX-F04 | 创建一个新音色并配音，再把时长减半 | clone/design→speech→sound-adjust完整闭环 | 熟悉者≤6分钟，不需要手工修改工程JSON |
| UX-F05 | 批处理3个条目，停止后只补未完成项 | 能说明哪些已复用、哪些重跑，结果逐项对应 | 熟悉者≤8分钟，无意外付费重跑 |
| UX-F06 | 在已有大画布只运行某一分支并修复断线 | 用户准确预判范围，找到缺输入端口并恢复 | 不运行无关分支；最多一次错误尝试后自行恢复 |
| UX-F07 | 保存工作流到节点库，在新项目插入并继续 | 配置/结构复用清楚；缺素材可解释；不误以为媒体自动全复制 | 插入后无幽灵连线，能完成重新绑定 |
| UX-F08 | 关闭运行中的项目，重开并继续任务 | 有明确的取消/恢复状态和入口；用户不会盲目连点生成 | 不依赖开发者工具或重建整张图 |

时间是建议目标，第一次执行后按真实任务复杂度校准；不能以牺牲输入确认和错误提示来压缩步骤。

**五、状态、误操作和信息一致性专项**

1. 建立状态截图组：未配置、就绪、等待上游、排队、提交、生成/处理中、下载、落盘、成功、失败、已取消、旧成功结果。实现没有的状态不要求凭空添加，但长任务需要能解释正在等待什么。
2. 对同一节点同时对照卡片、概览、输入输出、设置、运行面板、独立资产，检查是否同一轮结果/相同参数。任何一处滞后都要记录触发步骤。
3. 运行中改参数：用户必须知道本轮采用旧参数还是新参数；不能展示新参数却将旧请求产物无标识归入新设置。
4. 所有删除和快捷键测试先在QA项目；重点覆盖文本输入焦点、多选混合、节点库删除和资产删除的区别。
5. 连接手势覆盖输入→输出反向拖线（按支持情况）、多源→many、移动节点、画布缩放、拖线到无效目标、取消拖线；临时线不能留成幽灵依赖。
6. 上游多结果：用户切换拆分当前格、从独立历史资产接线、从操作节点最近输出接线，必须能理解两条路径的差异。
7. 当前模型/功能绑定要可追踪：用户看到的可用模型应与实际请求一致；切换供应商导致字段不支持时反馈明确，不能隐式忽略。
8. 报错面向用户表达“什么失败、影响哪个结果、如何修复”；运行面板可以保留脱敏技术细节，主流程不堆协议实现细节。

**六、评价方法、门禁与改进排序**

每节点五项0–2分：可发现、可理解、可操作、状态清晰、可恢复。0=无法完成/误导，1=需要提示或绕行，2=独立完成且结果可判断。10分满分，建议≥8；核心任务任一0分仍是缺陷，不能被均分掩盖。

核心体验门禁：所有核心任务至少一遍无技术人员介入完成；没有误删、误连、范围不明导致的重复付费；没有结果落盘成功却无法找到；没有错误后无法继续。3名新手样本只用于发现问题，不用于宣称统计显著的可用率。

改进优先级：先修错误操作/数据损失/重复付费，再修任务阻断与结果误判，然后减少重复编辑、滚动和面板切换，最后调整视觉细节。每项建议说明具体位置、期望行为与验收，不只写“体验优化”。

**七、执行工具与回归**

现有 `test:browser-ui`、`test:browser-panel-sync`、`test:browser-media-import`、`test:browser-storyboard` 可复用定位UI回归；真桌面使用 `test:node-matrix` 和手动任务记录。命令与前置条件见方案一。不能把浏览器mock生成成功当作桌面产品或真实模型已验收。

每次修复选一个相关用户任务复测，并覆盖影响到的共同外壳：标题、主按钮、端口、滚动、弹层、焦点、保存。涉及共享组件时抽查文本、图片、视频、声音、结构类各一个节点；涉及契约或运行器则同时回到方案一的相关用例。

最终交付：逐节点体验卡、完整任务结果、关键状态截图组、按严重度排序的问题、可执行改进清单与复测记录。明确哪些来自新手观察，哪些是测试者的专业判断。
