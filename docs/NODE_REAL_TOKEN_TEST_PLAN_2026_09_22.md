# 文本、图片、音频节点真实 Token 测试计划

## 目标与边界

目标是验证桌面应用的真实调用链，而非 mock、浏览器演示或裸 HTTP：节点选择的供应商/模型必须实际进入 Electron 主进程、读取本机安全存储的 API Key、调用上游并将结果写回画布与媒体库。

本轮范围仅包括文本、图片和音频；视频节点、视频联合流、视频计费任务均不执行。

## 总体执行规则

1. 每个远程用例先过配置前置校验，再以最小有效输入真实调用一次。
2. 文本调用使用短提示词；图片默认尺寸、每个高成本变体最多一次；音频文本不超过 80 字。
3. 一项用例失败即停止其依赖用例，记录上游原始错误摘要、供应商、模型、节点和运行记录；不使用其他供应商“掩盖”失败。
4. 密钥不写入测试文档、日志或仓库。只记录“已配置/不可用/被拒绝”等状态。
5. 每项成功同时核对：节点状态、输出端口、运行记录、产物入库（图片/音频）以及保存重开后的引用。

## Phase 0：开测前置校验

| 编号 | 检查                       | 通过标准                                                        | 失败后的处理                                       |
| ---- | -------------------------- | --------------------------------------------------------------- | -------------------------------------------------- |
| P0-1 | 桌面应用启动并进入当前项目 | Electron 主进程已运行、模型供应商列表可打开                     | 请求用户启动桌面快捷方式                           |
| P0-2 | 文本连接验证               | 已配置文本模型；“测试”通过或最小对话成功                        | 停止文本关联流，反馈 Base URL、模型 ID 或 Key 问题 |
| P0-3 | 图片连接验证               | 已配置图片模型；最小文生图成功                                  | 停止图片关联流，反馈供应商响应                     |
| P0-4 | 音频连接验证               | 已配置语音合成/音色设计模型；最小合成成功                       | 停止相关音频流，反馈协议或模型参数问题             |
| P0-5 | 节点选择一致性             | 节点下拉显示已配置模型，选择后运行记录中的供应商/模型与 UI 一致 | 记为产品模型解析缺陷，先修复后重测                 |

## Phase 1：单节点真实测试

### 文本

| 编号 | 节点                         | 真实输入                                       | 验收                                                                       |
| ---- | ---------------------------- | ---------------------------------------------- | -------------------------------------------------------------------------- |
| T-01 | 对话 chat                    | 两轮短对话；第二轮要求引用第一轮中的唯一关键词 | 流式回复完整；第二轮确实保留上下文；`out-markdown` 可用                    |
| T-02 | AI 处理 ai-process（文本）   | 100 字以内摘要任务                             | 产生 `out-text` 与 `out-markdown`；节点运行记录成功                        |
| T-03 | AI 处理 ai-process（结构化） | 让模型只返回 2 条镜头 JSON                     | `out-json` 通过 Schema；非法 JSON 时有可操作错误                           |
| T-04 | 对话记忆边界                 | 自动化填入 20 轮短消息，再完成第 21 轮         | 前 20 轮不生成摘要且原文完整；第 21 轮后仅压缩早期消息，最近 20 轮原样保留 |

### 图片

| 编号 | 节点                     | 真实输入                                                   | 验收                                         |
| ---- | ------------------------ | ---------------------------------------------------------- | -------------------------------------------- |
| I-01 | 生图 image-gen           | 纯文本提示词：单一蓝色立方体                               | 返回真实图片资产，落盘并可预览               |
| I-02 | 生图 image-gen（参考图） | I-01 产物接入 `in-images`，补充“改为红色”提示              | 上游图片被识别为参考图；新资产不覆盖原图     |
| I-03 | P 图 image-edit          | I-01 产物 + 简短编辑提示词；若节点要求遮罩则补一处最小标注 | 调用编辑端点成功，原图保留、编辑结果新建资产 |
| I-04 | 图片节点链路保存         | 保存、关闭并重开当前项目                                   | 图片引用、节点状态与预览仍可用               |

### 音频

| 编号 | 节点                  | 真实输入                          | 验收                                                      |
| ---- | --------------------- | --------------------------------- | --------------------------------------------------------- |
| A-01 | 配音 speech           | 不超过 80 字的中文旁白            | 真实音频资产入库、可播放、格式与时长合理                  |
| A-02 | 音色设计 voice-design | 音色描述 + 不超过 80 字试听文本   | 返回 `voice_id` 与试听音频；voice_id 可被后续语音合成选择 |
| A-03 | 指定音色语音合成      | 使用 A-02 voice_id 合成一句短文本 | 合成成功且运行记录包含正确模型来源                        |
| A-04 | 音频节点保存          | 保存、关闭并重开当前项目          | 音频资产、voice_id 与节点引用不丢失                       |

语音克隆需要上传参考音频，可能涉及个人生物特征数据。本轮不自动上传任何用户音频；如需测试，将在上传前单独请求确认，并使用你指定的非敏感样本。

## Phase 2：节点联合真实测试

| 编号 | 流程                                     | 覆盖点                          | 通过标准                                         |
| ---- | ---------------------------------------- | ------------------------------- | ------------------------------------------------ |
| E-01 | `chat → ai-process(结构化)`              | Markdown 文本输入、真实模型串联 | AI 处理消费对话输出并得到合法 JSON               |
| E-02 | `chat → speech`                          | 文本输出进入音频节点            | 朗读内容来自对话输出，不是静态默认文案           |
| E-03 | `ai-process(文本) → image-gen`           | 文本提示词串联                  | 生图请求使用上游文本，产物成功入库               |
| E-04 | `image-gen → image-edit`                 | 图片资产与编辑提示词联合        | 编辑节点消费指定上游图片，原图与结果并存         |
| E-05 | `voice-design → speech`                  | voice_id 资源复用               | 新音色能被语音合成引用并成功生成                 |
| E-06 | `chat → ai-process → image-gen → speech` | 文本、图片、音频的完整非视频链  | 全图运行顺序正确，每一步有成功运行记录与对应输出 |

## Phase 3：异常与回归处理

| 异常                         | 立即动作                           | 需要向用户确认的信息          |
| ---------------------------- | ---------------------------------- | ----------------------------- |
| API Key 无效或不可解密       | 停止该供应商后续调用，保留错误摘要 | 是否重新输入对应 Key          |
| Base URL / 模型 ID 不兼容    | 记录实际 HTTP 错误和节点模型选择   | 供应商要求的准确端点与模型 ID |
| 上游限流、余额不足、内容审核 | 停止重复重试，避免额外费用         | 是否等待、换模型或调整提示词  |
| 产物生成成功但节点未落盘     | 记为 P0 产品缺陷，先修复再回归     | 无需用户提供 Key              |
| 需要上传个人参考音频         | 停在上传前                         | 指定样本及上传授权            |

## 结果记录模板

每个用例记录：`编号`、执行时间、节点/联合流、供应商、模型、真实或本地、输入摘要、运行状态、输出资产/端口、错误摘要、截图或运行记录位置、是否可回归。

最终交付分为：已通过、外部阻塞、产品缺陷、未执行（含原因）四类；不会把“模型下拉能选”当作真实调用成功。

## 已落地：无界面真实验收器

桌面 UI 自动化不可用时，仍可从项目根目录执行以下命令。验收器运行在 Electron 主进程，复用桌面端相同的安全存储、供应商目录和生产网关；不会打印或写入 API Key。

```powershell
# 构建后验收所有已配置的文本、图片、音频模型（不测视频）
pnpm model:smoke:build

# 仅复测文本模型，不会额外创建图片、音频或音色设计任务
pnpm model:smoke:text
```

每一项使用最小真实输入，图片和音频成功产物会写入独立的 `model-smoke-<run-id>` 媒体目录作为证据；报告逐项即时写到 `%APPDATA%\canvas-studio\data\model-smoke-reports\`，某个供应商超时也不会丢失此前结果。报告只含供应商名、模型 ID、耗时、脱敏错误摘要与媒体资产信息。

当前验收器有意不执行视频与语音克隆：前者不在本轮范围内；后者需要上传可能含生物特征的真人参考音频，必须由用户单独指定样本并授权。
