# 节点画布呈现与关系交互规范

> 状态：**强制规范 v1.0**；P0、P1 已实现并通过验收，P2、P3 为后续完善项。
> 适用范围：画布中的全部可创建节点、端口、数据边、框选、多选、分组、节点内输入预览及动态内容。
> 配套规范：[节点输入输出契约规范](../NODE_CONTRACT_SPEC.md) 定义“能否连接、传什么、怎样执行”；本文只定义“如何呈现、怎样操作、怎样保持几何一致”。两者必须同时满足。

## 0. 目标与不可违反边界

本规范要让用户始终能在画布上回答四个问题：

1. 此节点正在接收什么、来自哪里、会输出什么；
2. 连线是合法数据依赖、运行产物追溯，还是当前尚未提交的拖拽预览；
3. 节点因内容、结果或状态变化后，为什么以及如何改变尺寸；
4. 多个节点是否能作为一个临时选择集合一次性接到目标，以及这次操作实际会创建哪些边。

不得用视觉便利破坏下列规则：

- 不得按节点标题、UI 文案或上游节点类型猜测输入；所有连接仍以 `nodeId + portId` 和端口契约为准。
- “批量连接柄”和“组合框”是瞬时 UI，不是节点、端口或持久化数据；释放后必须只留下普通真实边。
- 节点内的引用预览只能读取目标输入端口的已解析值 / 已持久化输出投影，不能扫描画布猜测上游。
- 任何一键连接必须**全成或全不成**。不能有部分成员连上、其余静默遗漏。
- 新的视觉或手势能力不得新增隐藏业务输出；若数据语义改变，按 `NODE_CONTRACT_SPEC.md` 新增节点或提升契约版本。

### 1.2 已有能力，不应推倒重做

- 所有可创建节点的标准初始尺寸已由节点契约固定为 **340 × 260 px**。
- 端口具有类型、Schema、必填性和基数；真实数据线由 `DataEdgeLayer` 统一绘制，底层 tldraw Arrow 仅持久化绑定关系。
- 同构多选已经支持：多张相同类型、相同输出端口的节点可由公共圆形端口连接到 `many` 输入，最终创建普通数据边。
- 节点卡片已有底部类型色条、标题栏、状态灯、端口、执行遮罩和 ResizeObserver 驱动的“只向下扩容”机制。
- 分组（持久化 tldraw group）与框选（临时虚线框）已区分；不得把它们合并为业务“组合节点”。

## 2. 三层模型：契约、呈现、手势

### 2.1 契约层（唯一事实来源）

`NodeTypeSpec` / capability 中的端口声明、Schema、`projectOutputs`、已保存的边与节点结果是唯一业务事实。它决定：

```text
输出端口值 → 已保存 edge(nodeId, fromPort, toPort) → 目标输入端口值
```

呈现层不得直接按“左边有一张图片节点”显示引用。输入预览、端口摘要、运行前校验和右侧契约面板都必须经同一输入解析服务取得：

```ts
resolveConnectedInputs({ editor, targetShapeId, targetPortId })
  -> Array<{ edgeId, sourceNodeId, sourcePortId, value, producedAt }>
```

排序规则为：先按已保存 edge 的稳定创建顺序，缺失时按 `edgeId`；绝不能依赖 DOM 顺序或当前缩放后的屏幕位置。

### 2.2 呈现层（只解释事实）

提供统一的 `ConnectedInputPreview`，由目标端口声明和已解析值驱动。它属于画布基础组件，不属于任何单个节点的私有“扫描上游”逻辑。

| 输入类型 | 卡片内呈现 | 尺寸 / 文案 | 点击行为 |
| --- | --- | --- | --- |
| `image` / `image many` | 图片缩略卡；`many` 以横向单行列表显示，最多 4 张，超出显示 `+N`。 | 缩略图 `72 × 54 px`；保持来源画幅，`object-fit: cover`；下方一行名称，省略但 `title` 展示全名。 | 单击仅选中当前节点；双击或显式预览按钮打开媒体预览。 |
| `video` | 带播放标识的封面缩略卡。 | `96 × 54 px` 16:9；下方名称。 | 同上。 |
| `audio` | 音频胶囊，包含类型图标、名称、时长（可用时）。 | 高 `32 px`。 | 预览操作必须显式，不自动播放。 |
| `text` / `markdown` | 来源标签 + 首行摘要；多个输入以可换行列表呈现。 | 单项最大两行，超出省略；显示来源节点名。 | 点击来源标签选中来源节点；不改变连接。 |
| `json` / `camera` / `iteration` | 类型标签 + Schema / 字段摘要。 | 高 `32–48 px`；Schema 版本不可省略。 | 显式“查看”打开右侧契约面板。 |

通用规则：

- 所有引用块必须显示**源节点名称、输入端口显示名、顺序（当为 many）**，不能只显示“已连接 2 张”。
- 空端口显示端口名与简短行动提示；不可把空态伪装成已绑定的默认素材。
- `one` 输入只展示一个已解析值；若发现多个边，属于数据完整性错误，显示错误态并阻止运行。
- `many` 输入的“添加”只能引导用户拉真实连线或用批量连接手势，不能在卡片内偷偷复制资产。
- 预览不保存业务状态；结果/来源仍只写 `meta.nodeResult` 和普通 edge。

### 2.3 手势层（临时、可解释、可撤销）

框选、组框、悬浮、拖线和吸附只创建用户可预期的显式操作。每次拖拽应有 `ConnectionPlan`：

```ts
type ConnectionPlan = {
  sourceNodeIds: TLShapeId[]
  entries: Array<{
    sourceNodeId: TLShapeId
    fromPortId: string
    targetPortId: string
  }>
  reason?: 'no-compatible-plan' | 'cardinality-conflict' | 'cycle'
}
```

它只存在于连接拖拽的 session store。放下时校验全量 entries；全部合法才在一个 undo point 中创建边，任何一项失败则 0 条边写入并展示具体原因。

## 3. 节点几何与视觉 token（强制）

### 3.1 唯一 token

以下值必须集中在 `ui-foundation.css`（或一个等价的单一 token 文件）中；`app.css`、`ui-surfaces.css` 和各节点 Body 只消费 token，不再二次覆盖：

| Token | 值 | 用途 |
| --- | ---: | --- |
| `--node-default-w` | `340px` | 可创建节点初始宽度。 |
| `--node-default-h` | `260px` | 可创建节点初始高度。 |
| `--node-min-w` | `280px` | 用户缩放的最小宽度。 |
| `--node-min-h` | `200px` | 用户缩放的最小高度。 |
| `--node-radius` | `12px` | 卡片与内部输入框的外层圆角基准。 |
| `--node-header-h` | `28px` | 悬浮标题条总高度（2026-09-12 修订：标题为悬浮于卡片上方的单行条，卡外上方留 6px；原 42px 为旧"卡内标题栏"骨架值，决策记录见审查报告 F-TEXT-03）。 |
| `--node-body-pad-x/y` | `10px / 10px` | 通用节点正文安全内边距。 |
| `--node-gap` | `8px` | 正文纵向区块间距。 |
| `--node-color-bar-h` | `8px` | 仅位于底部的类型识别条高度。 |
| `--node-action-h` | `32px` | 节点内标准次级/主操作最小高度。 |
| `--node-port-size` | `18px` | 端口直径。 |
| `--node-port-outset` | `16px` | 端口圆心距卡片边缘。 |
| `--selection-handle-size` | `9px` | 四角视觉点直径。 |
| `--selection-handle-outset` | `6px` | 四角视觉点圆心距虚线角点的外移距离。 |

允许类型色、媒体画幅和业务内容不同；不允许每个节点自行改变标题高度、底部色条位置、正文默认边距或端口尺寸。

### 3.2 节点固定骨架

```text
┌────────────────────────── 340 px ──────────────────────────┐
│ （悬浮标题条 28px，位于卡片上边缘外 6px，不占用卡内高度）      │
├──────────────────────────────────────────────────────────────┤
│ 输入摘要（存在连接时）                                       │
│ 设置行（高频且不超过两行）                                   │
│ 主内容 / 主编辑区（占用剩余可用高度）                         │
│ 底部操作栏（需要时，距色条上沿 10 px）                        │
├────────────────────────── 类型色条 8 px ────────────────────┤
└──────────────────────────────────────────────────────────────┘
```

- **标题为悬浮式**（2026-09-12 修订）：标题条绝对定位在卡片上方（`top` 偏移 = `-(标题高度 + 6px)`），
  全宽单行省略，不占用卡片 260px 初始高度；分组框上内边距 44px 即为避让此悬浮标题。
  标题中的操作区使用固定宽度；标题只占余下空间并单行省略。
- 色条只承担节点类型识别，固定在卡片底部；不承载运行状态、可用性或错误。
- 主按钮若存在，必须位于底部操作栏，按钮底边至色条上沿为 **10 px**，左右随正文内边距对齐；不得漂浮在正文中间。
- 默认正文文本为 `14px / 1.6`；多行输入框内部 padding 为 `8px 10px`，最小可编辑高度 `96px`。节点可变高时输入框可增加，不能以内部滚动条替代必要扩容。
- 原生 `<select>` 禁止直接露出；全部采用 `AppSelect`，高度 `32px`、圆角 `8px`、统一下拉面板、深浅色主题、键盘焦点与 `aria` 标签。

### 3.3 生图 / 生成型节点专用骨架

生图、视频、配音、AI 处理等“编辑输入后执行”的节点使用同一纵向分配：

1. 已连接输入摘要；
2. 一行模型与核心参数；
3. 主提示词 / 正文编辑区，`flex: 1`，最小 `112px`；
4. 运行按钮固定在底部操作栏。

以生图为例：模型和画幅在第一行；参考图片使用上节的图片缩略卡；提示词区不再固定 `rows=3`，而是填满第 3 区；“生成图片”是唯一底部主按钮。种子、尺寸等低频参数进入右侧详情，不和主输入争抢高度。

## 4. 连接与连线呈现规范

### 4.1 三种线的语义

| 线 / 状态 | 语义 | 样式 |
| --- | --- | --- |
| 正式数据边 | 已保存、可执行的 `fromPort → toPort`。 | 中性实线 `1.5px`，端口颜色只用于端点 / 交互反馈，不给整条线染成强业务色。 |
| 拖拽预览边 | 尚未保存；显示当前拟创建的连接计划。 | `1.5px` 虚线 `6 5`，不透明度 `0.9`；合法为品牌蓝，非法为错误红。 |
| 运行产物追溯线 | “本节点产生了该资产”，不是输入依赖。 | 中性细线 `1px`、不透明度 `0.35`，标签/Tooltip 明确“追溯，不参与执行”。 |

正式边悬浮为 `1.8px`，选中为 `2.2px` + 低半径辉光；当线从节点下方穿过时允许遮挡段淡化，不能把整条线改成另一种业务语义。曲线控制点从端口绝对屏幕坐标计算，随缩放严格同比例。

### 4.2 单节点连接

- 从输出端口按下：只显示与该输出类型 / Schema / 基数兼容的目标输入端口。
- 放下前必须显示目标节点名、目标端口名与 `one/many`；非法目标不创建边。
- `one` 输入已有边时，默认拒绝并说明“此输入仅允许一个来源”；替换必须是用户明确的“替换连接”动作，不得静默删旧边。
- 连线成功后，目标节点立即通过 `ConnectedInputPreview` 显示接收的具体值；不是只改变端口颜色。

### 4.3 同构多选连接（保留并标准化）

当至少两个选中节点具有同一 `outPortId`、同一类型和同一 Schema 时，选框右侧外沿显示一个批量连接柄。它只能落到声明为 `many` 的兼容输入，释放后为每个源节点建一条同端口真实边。

公共柄规格：直径 `28px`，位于选框右边外 `12px`、垂直居中；显示成员数；默认中性描边，悬浮后实线品牌蓝。它不使用类型色，避免暗示“集合是 image/text”等不存在的业务类型。

### 4.4 异构多选连接（新增）

当选区中存在不同输出契约，但它们可以共同满足某个目标的不同输入时，显示“组合连接柄”。它是用户所说的选框外“大节点”，但必须是**临时手势柄**，不能伪装成新的业务输出节点。

适用例：`文本.out-text + 图片.out-image → 生图.in-texts(many) + 生图.in-images(many)`。

交互：

1. 框选后，求每个选中节点的可输出端口以及目标可接收端口，生成一份或多份候选 `ConnectionPlan`。
2. 只有存在完整、无循环、无 `one` 基数冲突的计划时显示组合连接柄；不能连时不显示柄，并在多选工具栏显示“没有共同可连接目标”。
3. 拖到目标节点时，目标边框高亮，所有将被写入的目标端口显示虚线预览；若有多个可行分配，弹出小型分配菜单（例如选择“作为参考图”或“作为首帧”），不猜测。
4. 放下时做一次事务校验：全部边创建成功才提交一个历史点；失败则一条也不创建，并指出哪个源端口 / 目标端口导致失败。
5. 成功后 toast 明确列出数量与关系，例如“已连接：文本 → 提示词；图片 → 参考图”。

源节点既可以是临时框选，也可以是持久化 group 的全部直接 node-card 子项；不得递归吞入嵌套 group 中未被用户明确选择的节点。

## 5. 框选、选中与分组

### 5.1 几何唯一来源

选中框、四角视觉点、四角命中点、批量连接柄和分组外框必须通过同一个 `SelectionGeometry` 计算：

```ts
type SelectionGeometry = {
  screenRect: { left: number; top: number; width: number; height: number }
  zoom: number
  corners: { topLeft: Pt; topRight: Pt; bottomRight: Pt; bottomLeft: Pt }
}
```

- `screenRect` 由 `editor.getShapePageBounds()` + `pageToScreen()` 得到，再以 host rect 转为容器局部坐标。
- 视觉圆点的圆心为 `corners` 沿对角线向外偏移 `--selection-handle-outset`；无论缩放、分组嵌套、窗口滚动或 DPR 如何变化，都不允许相对边框漂移。
- **禁止**再对 tldraw 原生 `.tl-corner-handle` 写 CSS `transform` 来修位置。若原生命中区无法与视觉点完全一致，保留其命中区但由统一 overlay 绘制视觉点；命中区的实际坐标必须由测试验证。
- 节点单选框使用实线品牌轮廓；临时多选框使用细虚线；持久化 group 使用实线低对比容器与组名。这三者不得复用颜色、线型或标签文案。

### 5.2 组框

- 持久化 group 只表达成员的移动 / 组织关系，不改变数据流，也不自动连接成员。
- 组框的标签置于左上角外 `26px`，标题为“组名 · N 个节点”；背景保持低对比。
- 组框内边距：左右 `12px`，上 `44px`（避开节点悬浮标题），下 `12px`，均随 canvas zoom 同比例变化。
- 分组、重命名、移动、取消分组均应是一个独立的可撤销历史点。

## 6. 节点状态与动态高度

### 6.1 状态模型

状态来自 `props.exec`、`meta.nodeRun`、`meta.nodeResult` 与输入契约校验，不从按钮文本、图片是否存在或 CSS 颜色猜测。最低视觉状态如下：

| 状态 | 卡片表现 | 内容区行为 |
| --- | --- | --- |
| idle / ready | 标题状态点中性 / 可运行色；不抢占内容。 | 保留最近有效输入预览。 |
| running | 标题状态点与执行遮罩；遮罩显示动作和可理解进度。 | 禁止重复执行，允许查看已持久化旧结果。 |
| success | 状态点成功色；新结果在结果区置顶并显示生成时间。 | 输出端口标记可用。 |
| failed | 状态点错误色；摘要显示可操作原因、重试入口。 | 不清除上一次成功结果；新的失败不得伪装成输出。 |
| blocked | 缺少必填输入 / 不兼容配置。 | 标出缺失端口，并给出“连接输入 / 打开设置”动作。 |

### 6.2 高度变化规则

节点高度只能由以下事件改变：

1. 用户手动 resize；
2. 内容自然高度超过当前可用 body 高度；
3. 结果集合、预览网格或错误详情被用户明确展开。

统一算法：

- 首次内容溢出时只向下扩，不压缩用户手调高度。
- 每次自动扩容最少 `16px`，最大高度为 `960px`；超过最大高度的集合使用节点内部滚动区。
- 异步图片加载、拆分网格行列改变和详情折叠/展开都必须重新测量。
- 不能因为状态点、Tooltip、悬浮按钮或临时连接预览改变持久化节点尺寸。
- 拆分等集合节点的高度变化必须保持卡片底色条始终在新的最底部，端口按新高度重新分布，边路径同帧重算。

### 6.3 动态节点验收示例

图片拆分从 2×2 切换到 4×4：结果网格完整可见；节点向下增长而不是裁掉底行；已有连线端点仍贴住更新后的端口圆心；撤销恢复到切换前的配置、尺寸和连线几何。

## 8. 全局 UI 显示与排版基线

本文的节点规范不能脱离整体工作台。下表是所有画布页面必须复用的布局约束；它避免节点、菜单、Dock、Tooltip 和侧栏各自挤占画布，造成“同一个画面没有主次”。

| 区域 | 规则 | 验收方式 |
| --- | --- | --- |
| 顶栏 | 顶栏是全局项目动作区，不与卡片、菜单或选中框重叠。创建节点和相机恢复后的可视安全区为顶栏底边 + `12px`。 | 连续创建 5 个节点，所有卡片标题和操作均在顶栏下方可点击。 |

### 8.1 视觉代码边界

当前代码审计发现卡片色条、文本 padding、选择框等存在基础样式与表面样式重复覆盖。此后按下列边界维护：

- `ui-foundation.css`：颜色、字号、间距、尺寸、z-index、焦点和基础控件 token；
- `ui-surfaces.css`：NodeCardShell、InputPreview、ActionBar、PortRail、DataEdge、菜单和面板的唯一外观实现；
- `app.css`：页面组装与业务组件局部布局，**不得**重定义 NodeCardShell / PortRail 的 token 几何；
- 节点 Body：只使用公开 class / CSS variables，不用 `position: absolute` 抢占标题、端口或底色条，不用裸 `z-index`。

任何例外必须在组件 API 中声明变体及理由；“为了某个节点看起来合适”不是覆盖公共几何的理由。
