## 6. 关键实现细节与坑（务必先看）

### 6.1 运行语义分支

`compositeRuntimeVersion(manifest)`：
- 缺省 → 1；
- `runtimeVersion: 2` → 新文本合并/输出映射。

**不要**把旧 manifest 静默改成 2；历史发布版本必须保持旧运行语义。若 W2 决定“编辑旧组合后发布新版本自动升级到 2”，必须先写兼容结论和测试，再改。

### 6.2 文本节点正文可满足必填输入

`validate.ts` 的 `hasContractFixedInput` 允许：
- `text` 节点 `in-text` 有非空正文；
- 资产节点有 `mediaRefs` 匹配媒体端口。

如果为了“更严格”删掉它，会让「只有正文、没有公开输入」的文本组合无法发布。删改前先跑 `test/composite-manifest` 和桌面验收。

### 6.3 同版本发布不可变

- 旧行为（2026-11-10 裁决）允许覆盖；W1 已改为拒绝。
- 旧数据不迁移；已绑定实例仍读旧行。
- 不要恢复覆盖逻辑；如果需求变化，先和任务发起人确认。

### 6.4 `graph.patch` 的 composite 插入

- `node.create` 的 `nodeType` 联合类型允许 `composite`；
- `graph-patch.ts` 只在 `config.manifest` 是对象时放行；
- **不要**把 `composite` 加到节点面板/`ACTIVE_NODE_TYPE_IDS` 的可创建入口；
- 外部可传任意 manifest 快照，当前未校验发布版本存在性；W3 若改为引用解析，需要同步 CLI/MCP 契约。

### 6.5 迁移与恢复测试

- M28 是 `ALTER TABLE composite_runs ADD COLUMN ...`。
- `test/recovery-contention.test.ts` 的 v16 夹具回退列表必须包含 M25–M27 的 `DROP TABLE`；以后新增迁移要同步补回退，否则并发迁移用例会假失败。

### 6.6 契约快照

任何受保护源码变化（`src/shared/agent-access`、`src/shared/engine`、`src/main/agent-access`、`db-migrations`、`observability` 等）后：

```powershell
node scripts/check-agent-access.cjs --write --accept-contract-change --reason "说明兼容结论，至少 12 字"
node scripts/audit-business-actions.cjs --write
npm run guard:agent-parity
```

`--accept-contract-change` 只用于已审查的加性变更；必须人工检查 `contracts.json` diff，不能不看内容。

### 6.7 `composite.upgrade.preview` 例外

`scripts/audit-business-actions.cjs` 的 `EXTERNAL_ONLY_OPERATIONS` 目前包含该操作，因为 W1 只交付公共预检、GUI 升级 UI 在 W3。
如果 W2/W3 增加了 GUI 升级入口，应把它从例外移除并映射到实际动作，否则审计会报 `STALE_EXCEPTION_MAPPED`。

### 6.8 日志

- 事件必须先在 `src/shared/observability/events.ts` 注册，否则 producer 丢弃。
- 运行终态只由 `finishCompositeRun` 真正改变状态时记一次；不要重复。
- 失败只记稳定 code/phase；不要传 `error.message` 或正文。
- `npm run verify:logging` 必须通过；新增数据库/文件路径也可能触发日志门禁。

### 6.9 桌面验收授权

`qa/w1-desktop-acceptance.cjs` 会复制本机已激活的 `security` 目录到临时数据目录（不伪造签名）。
没有授权文件时会失败并提示；不要在测试里绕过授权门禁。
