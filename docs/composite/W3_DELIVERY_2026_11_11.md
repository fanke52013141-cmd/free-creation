## 1. 本批完成项

### 1.1 W3-A 实例升级 UI 与外部操作

- 新组件 `CompositeUpgradeDialog.tsx`：主画布右键「升级节点流」→ 选择已发布目标版本 →
  与 CLI/MCP 同一份升级预检（`composite.upgrade.preview`）→ 展示接口差异与阻断项 →
  「确认升级」以固定版本引用更新实例（config 写 `{capabilityId, version, contentHash}`，
  快照缓存 `meta.compositeManifest`），兼容连线保留；取消、预检失败或读取失败不改变原实例。
  复用既有 `composite-modal` / `composite-publish-preview` 设计语言与主画布 `.run-btn` 主按钮，未新增控件类型。
- 新外部操作 `composite.upgrade.apply`（GUI/CLI/MCP 同源）：携带 `expectedGraphVersion`，
  兼容升级写入引用形态并返回新图版本；不兼容阻断且原实例不变。
- `scripts/audit-business-actions.cjs` 的 `EXTERNAL_ONLY_OPERATIONS` 移除
  `composite.upgrade.preview` 例外，映射到 GUI 升级入口（W1 交接 §6.7 要求）。

### 1.2 W3-B 多类型与多端口

- 图片/JSON/多值/多输出/媒体资产逐类验收：`test/composite-w3-types.test.ts`（19 项）覆盖
  各类型输入规划、媒体空间收集、资产固定引用、运行写回与媒体投影；
  桌面验收含「JSON 与多输出节点流运行并收集全部公开输出」「媒体资产节点流运行：
  output.get 投影含可下游消费的图片产物（nodeExtra 来源）」。
- 组合公开端口允许多输入/多输出同类型（`src/renderer/src/nodes/registry.tsx` 与 code 节点同口径，
  每个端口仍有独立稳定 ID）；`test/composite-multiport-registry.test.ts`（3 项）覆盖。
- 媒体公开输出同时写 `nodeExtra`（下游按公开端口直接消费）与 `nodeResult`
  （缩略图/资产索引保持旧呈现）；历史版本运行语义不变。

### 1.3 W3-C 嵌套运行守卫

- 运行期递归/深度/展开预算与发布校验同口径拒绝：`RECURSIVE_COMPOSITE`、
  `DEPTH_EXCEEDED`、`EXPANSION_BUDGET_EXCEEDED`（`checkCompositeRunBudget`，
  每层运行按 parentContext 链判定），拒绝写入运行台账（failurePhase=runtime）。
- 桌面验收以真实 Electron + CLI 触发三类拒绝（互相引用快照、超限嵌套、超限节点数）。

### 1.4 W3-D 引用保护与归档/删除

- 新外部操作 `composite.references`（只读）：列出各项目画布绑定实例（含固定版本）
  与其他节点流发布版本的嵌套依赖。
- 新外部操作 `composite.delete`：先做同一引用检查，存在画布实例或嵌套引用返回
  `CAPABILITY_IN_USE` 且不改动数据；无引用时物理删除（发布版本+草稿+能力行）。
- 归档不阻断引用：`composite.archive` 隐藏默认发现入口，固定版本仍可读、可恢复；
  已绑定实例不受影响。`test/composite-reference-protection.test.ts`（9 项）覆盖服务层。

### 1.5 W3-E 固定版本引用 + 仓库解析（解除 64KiB）

- 实例 config 只存 `{capabilityId, version, contentHash}` 引用，manifest 快照缓存
  `meta.compositeManifest`，不再受 `graph.patch` 64KiB config 上限约束。
- `graph.patch` 由 main 进程预解析发布仓库（`service.ts` 核对 contentHash），
  解析失败返回 `COMPOSITE_REF_NOT_RESOLVED`；执行器在 meta 缺失时经宿主回退解析并核对摘要。
- **存量兼容（不迁移）**：历史内嵌 manifest 快照实例继续按旧路径运行（执行器优先读
  `config.manifest`）；升级路径（`composite.upgrade.apply` / GUI 升级）把实例转换为引用形态。
  无新增数据库迁移（M28 之后无变化），旧数据不重写。

### 1.6 本批过程修复的真实缺陷

| 缺陷 | 根因 | 修复 |
| --- | --- | --- |
| 嵌套外层运行 `INTERNAL_EDGE_INVALID`（GUI 外层「标题整理」运行失败） | 隔离执行编辑器创建内部 composite 节点只带 props 不带 meta；引用形态 config 使 `resolvePorts` 推导不出公开端口，内部连线/输入绑定失败 | `run-composite.ts` 运行前预解析引用形态内部节点的固定版本快照并写入 `meta.compositeManifest`（与 graph.patch 同口径）；解析失败定位 input 阶段 `COMPOSITE_REF_NOT_RESOLVED` |
| 升级对话框 lint 错误（`react-hooks/set-state-in-effect`）与 busy 卡死隐患 | effect 内同步 setState；取消的 fetch 在 finally 不复位 busy | 重构为带请求键的单一异步状态 + 派生失效（busy/preview/error 全部派生），无 effect 内同步 setState |
| 桌面验收 `MCP_DELETE_NOT_BLOCKED` | 脚本 MCP `composite_delete` 漏传幂等键，协议层 `INVALID_INPUT` 先于引用保护分支 | 脚本补 `idempotencyKey`（与 CLI 助手同口径）；产品行为正确，未改 |
| GUI 固定版本检查读旧口径 | 引用形态下 `config.manifest.version` 不存在 | 改为 `config.version` + `contentHash` 与已发布 1.0 记录双重验证 |
| GUI 升级后检查与异步保存竞态 | 对话框关闭即读 `node.get`，画布防抖保存未落盘 | 显式 Ctrl+S + 有界轮询落盘后的 config |
| 桌面验收嵌套外层只发布未运行（覆盖缺口） | W1 起嵌套真实运行仅 GUI 覆盖 | 桌面验收新增引用形态内部节点的外层实例插入 + 真实运行 + 输出断言 |

回归证据：嵌套外层真实运行同时进入桌面验收（CLI 第 20 项）与 GUI 验收（第 10 项），
修复后两者均通过；升级对话框重构后 GUI 第 12 项复跑通过。
