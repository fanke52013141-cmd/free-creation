# 发给执行 Agent 的任务指令

以下内容可直接转发。详细规则和 W1 的逐步验收见[节点流执行方案](WORKFLOW_IMPLEMENTATION_PLAN.md)。

---

在 `free-creation` 仓库实施「节点流（Workflow）」优化的第一批 **W1 文本调用闭环**。节点流是可编辑的内部画布，发布后有稳定的端口和固定版本，可以被普通节点和其他节点流调用。先交付一条可实测的文本路径。

**开始前**

1. `git fetch origin`，检查 `git status -sb`，在最新 `origin/main` 上建立独立分支或工作树。保留现有工作区、用户改动和 stash。读 `AGENTS.md`、本目录执行方案及交付备注、`NODE_CONTRACT_SPEC.md`、`LOGGING_SPEC.md`、`AGENT_PARITY_SPEC.md` §0、`AGENT_ACCESS_SPEC.md` 和能力矩阵。核对手头基线与历史交接的差异。
2. 先复现并记录四个现状：文本值如何送达 `in-text`、草稿与发布是否分开、同版本发布是否会覆盖、嵌套是否解析到固定版本。分别记录 GUI、CLI、MCP 的已验证范围。

**本批实现**

1. 复用现有 `composite` 节点、manifest、仓储和执行宿主。公开端口保存稳定 ID、方向、类型、Schema、必填性、基数与精确映射。首尾仅生成首次候选。后续编辑保留已确认接口，映射失效时标出原节点和端口，发布前处理。全图校验必填缺口。
2. 让外部文本进入契约声明的 `in-text`，沿用普通文本节点的合并与投影规则。验证可选空值、多值顺序和内部正文。正式输出取本次运行的映射结果，必需输出缺失应有可定位的失败。对未验证类型给出明确结果，兼容存量版本已有行为。
3. 实现或补齐保存草稿、显式发布不可变新版本、固定嵌套引用。测试并发冲突、同版本覆盖拒绝、失败保留草稿和版本升级预检。保留旧版本、旧模板和项目内已绑定的实例，使用隔离数据完成迁移回归。
4. 给 W1 提供可实际操作的 GUI 路径。同包补齐 CLI/MCP 公共契约、入口、测试和文档，复用同一业务实现，继续遵守版本、占用、确认、持久化和人工门禁。登记日志开始与唯一终态、失败阶段、父子调用及脱敏证据。禁止记录密钥、提示词或原始请求响应。

**验收与回报**

用「文案整理 `1.0`」及引用它的「标题整理 `1.0`」验证普通节点传入和接收、节点流嵌套、草稿重开、发布 `2.0` 后外层仍使用 `1.0`、不兼容升级被拦截。用固定样例在 GUI、CLI、MCP 核对输出和失败。涉及窗口使用明确标识的隔离测试项目，测试退出后清理。

运行受影响测试、`npm run guard:agent-parity`、`npm run verify:agent-access`、`npm run verify`。更新覆盖清单、交付台账和兼容结论。回报格式为「完成项 / 改动文件 / 实测路径与证据 / 未通过或未验证项 / 下一批建议」。若基线门禁红，记录复现证据并区分基线与本次回归。任何自动检查结果均按实际状态回报。

本轮完成 W1 即交付审查。统一页面改版、全量类型、持久等待和重启恢复按 W2–W4 推进。提交、推送和发布按任务发起人给出的授权执行。
