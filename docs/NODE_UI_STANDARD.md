# 节点 UI 统一规范

> 版本：v0.1 讨论稿（2026-09-23）  
> 范围：画布中的全部可创建节点；历史节点继续使用同一外壳。  
> 目的：规定信息放置、卡片层级、尺寸、状态与例外。本文是布局与呈现规范；端口、数据来源、执行与持久化仍以 [`NODE_CONTRACT_SPEC.md`](../NODE_CONTRACT_SPEC.md) 为准。

## 1. 现状与本规范要解决的问题

项目已经有节点外壳、端口契约、右侧详情面板和不少逐节点决定，但这些规则分散在代码、测试、审计报告和历史提案里。当前实现的共同外壳包括：画布外侧标题行、统一的 340 × 260 默认卡片、真实连线输入预览、类型化节点正文、外置端口和运行遮罩。标题行承担通用运行入口；具体配置和动作仍有不少由各节点 Body 自己决定。

旧版 [`NODE_UI_SPEC.md`](./NODE_UI_SPEC.md) 同时保留了早期 footer、固定尺寸和 CSS 重排提案、后续已落地决定以及未完成项。它不能单独回答新增或修改节点时的关键问题：正文放什么、设置放哪、主操作在哪、超出空间后怎么处理。本文件把这些决定收成一套可逐节点执行的规则。

## 2. 设计目标

画布节点在不打开详情时，应让人快速回答四件事：

1. 这个节点是什么，当前是什么状态？
2. 它实际收到了什么输入？
3. 当前最重要的内容或结果是什么？
4. 下一步的主要操作是什么？

画布卡片是工作流的快速阅读、轻量编辑和运行表面。完整配置、契约、运行日志、长文本和完整历史由右侧详情面板或专用工作台承载。

### 不可破坏的原则

| 原则 | 规则 |
| --- | --- |
| 一个信息一个归属 | 同一份来源、状态或配置只在一个主要位置展开；卡片与详情只允许摘要和详情的关系，不重复放两份可编辑控件。 |
| 真实关系优先 | 输入摘要来自真实连线和当前有效输出。不能根据节点类型、标题或旧结果推断输入。 |
| 一张卡一个主操作 | 可执行节点的运行入口固定在标题行的主操作位；节点正文不再另放一个等价的“运行/生成/应用”按钮。 |
| 卡片先摘要 | 卡片优先保留高频内容、最重要的参数和最新结果；长尾设置、历史列表和日志进入详情。 |
| 同一顺序 | 有输入的节点按“输入 → 主要编辑/控制 → 最新结果”组织。无输入的源节点从主要内容开始。 |
| 例外必须登记 | 只有媒体编辑器或专用工作台确实需要大画布空间时，才允许替换通用输入摘要；例外仍要显示真实来源，并且不能重复呈现同一输入。 |

## 3. 节点卡片解剖

```text
节点标题行（卡片外）
[序号] [类型图标] [可编辑名称] [说明] [摘要/计数] [状态] [主操作]

节点卡片（默认 340 × 260）
┌──────────────────────────────────────────┐
│ 输入摘要：真实上游的媒体缩略图、文本或结构摘要 │  可无
├──────────────────────────────────────────┤
│                                          │
│ 主要内容：正文编辑器、关键参数、预览或结果     │
│                                          │
│ 可选的一行状态/结果摘要                      │
└──────────────────────────────────────────┘
 左侧输入端口                              输出端口右侧
```

### 3.1 标题行

- 固定放置：序号、节点图标、节点名称、节点说明入口、状态、单一主操作。
- 名称始终来自节点 Spec 的同一个 label 来源；用户可重命名，但不能让节点类型与画布创建菜单使用两套名称。
- 状态摘要和字数等小计数可以占用标题行的弹性空隙；不得挤压节点名称或主操作。超长名称省略显示，完整文本通过 tooltip/详情可读。
- 主操作位按节点能力呈现一个有语义的动作：执行器节点为运行；手动发布型节点为发布；不可执行的素材源不显示运行按钮。
- 主操作不可用时保留按钮并置灰；不可用原因由标题 tooltip、缺失端口状态或一行阻断摘要说明。
- 标题行不放模型下拉、配置表单、第二个执行按钮或长说明。

### 3.2 卡片正文

正文按以下区域从上到下排列，按节点类型省略不适用区域，不得改变顺序：

1. **输入摘要**：真实上游数据的紧凑摘要。无已解析输入时不占空白高度；必填输入缺失由端口和简短状态呈现。
2. **主要工作区**：该节点唯一的主要编辑对象，或最常用的一至两个参数。文本、提示词、裁剪范围、拆分行列、时间范围等可在此轻量编辑。
3. **最新结果/预览**：有结果时展示当前有效结果或清楚标记为旧结果的最近成功结果。媒体以预览为主；结构数据以 schema、规模和少量字段摘要为主。
4. **对象级操作**：只针对正文中某一条素材、某个字段或某个结果的操作，贴近对象放置。

卡片正文不承担完整设置页面。正文中可见的配置控件最多两个（不含主要正文编辑区）；低频、高复杂度或随供应商变化的字段进入“设置”。

### 3.3 右侧详情与工作台

右侧详情沿用现有四个分区：

| 分区 | 内容 |
| --- | --- |
| 概览 | 节点作用、当前就绪/阻断状态、输入输出摘要。 |
| 输入输出 | 完整端口名称、类型、Schema、基数、必填性和真实连接情况。 |
| 设置 | 完整配置表单，包括低频参数、供应商/模型高级选项、长 JSON 或代码配置。 |
| 运行 | 运行/运行至此操作、最近运行状态、失败原因、耗时、日志与历史记录。 |

需要大画布操作（如图片标注、裁剪工作台、对话）的节点可以从卡片进入专用工作台。工作台负责复杂编辑；卡片保留结果摘要、来源、状态和入口，不再复制工作台中的整套控件。

## 4. 信息放置裁决表

| 信息/操作 | 固定位置 | 卡片显示上限 | 不应放置 |
| --- | --- | --- | --- |
| 节点序号、类型、名称 | 标题行 | 一行 | 正文重复节点全名 |
| 执行状态 | 标题状态点；运行时正文遮罩；阻断/失败时一行摘要 | 一种当前状态 + 一条短原因 | 多处重复状态徽标和长日志 |
| 输入端口与输出端口 | 卡片左右外缘 | 由契约定义 | 正文手画第二套端口或假连接图标 |
| 已连接输入 | 正文顶部的统一输入摘要，或登记过的专用媒体输入面 | 默认最多 12 项，超出显示 `+N`；many 输入显示顺序 | 只写“已连接”而不展示真实内容；在卡片和工作区重复展示同一完整预览 |
| 主要正文/提示词 | 正文主要工作区 | 一份主要编辑对象；长内容可滚动或打开工作台 | 再放一份同步不可靠的侧栏副本 |
| 高频关键参数 | 正文紧邻主要工作区 | 最多 2 个 | 把所有低频字段排成密集表单 |
| 供应商细节、长尾参数 | 右侧“设置” | 卡片最多显示当前值的只读摘要 | 同一字段同时在卡片与面板各有可编辑副本 |
| 最新生成/处理结果 | 正文主要预览区 | 当前结果优先；历史列表不超过摘要 | 结果详情压到卡片外下方或侧边散落 |
| 单项预览、复制、移除、重命名 | 对象行内，统一微按钮 | 每行最多 2 个图标操作 | 把全节点动作伪装成对象操作 |
| 运行/生成/发布 | 标题行主操作位 | 每个节点最多 1 个 | 同时在标题行和正文放等价的主执行按钮 |
| 导入/选择源素材 | 源节点空态或素材预览区 | 一个明确入口 | 空态同时摆多个并列主按钮 |
| 错误详情、调用参数、运行日志 | 右侧“运行” | 卡片最多一行可操作的错误摘要 | 让错误堆栈占满卡片正文 |
| 引导和解释 | 首次空态的一句事实说明；详细说明在概览/tooltip | 空态一行，tooltip 短句 | 长段教学、重复端口操作说明 |

### 4.1 输入摘要规则

- 数据必须来自真实 Arrow binding、端口契约和当前有效输出投影。
- 图片用缩略图；视频/音频/文件用类型图标和来源名；文本显示短摘要；JSON 显示类型/schema 或短结构摘要。
- 多值输入按真实连线顺序显示序号。超出可视量折叠为 `+N`，展开后在正文内滚动。
- 当前 `image-crop`、`image-split`、`video` 使用专用输入表面；保留这些差异时，必须遵循同一输入摘要组件的密度和来源语义，不能成为新的私有布局模板。
- 需要显示“等待上游”时，使用事实状态，不添加拖线教程。若输入缺失是可选状态，不以红色错误呈现。
- 对媒体工作台采用“输入摘要”的紧凑/展开同一组件；同一来源不得在通用输入栏和工作台素材列表中重复出现。

### 4.2 按钮规则

- **节点级动作**：运行、生成、应用、发布等改变整个节点结果的动作，统一使用标题行唯一主操作位。
- **工作台入口/设置入口**：放在主要内容附近，最多一个明显入口；必要时另一个次要操作进入详情或菜单。
- **对象级动作**：放在对象行右侧；使用 20–22 px 图标按钮，必须有 tooltip 和 aria-label。
- **源素材导入**：只在无素材空态显示一个主 CTA；有素材后转为预览和替换/导入入口。
- 任何节点正文不能定义第二份运行 readiness，也不能出现另一套“是否可执行”的条件判断；沿用契约派生状态。

## 5. 尺寸、间距与溢出

| Token | 规范值 | 用途 |
| --- | ---: | --- |
| 默认宽度 | 340 px | 新建节点默认宽度；用户可手动调整。 |
| 默认高度 | 260 px | 新建节点默认高度。 |
| 自动档位 | 260 / 320 / 380 / 440 px | 内容确实需要额外空间时逐档增长，不接受任意像素自动高度。 |
| 自动高度上限 | 440 px | 超出后由正文内滚动或转入详情/工作台。 |
| 推荐手动高度上限 | 720 px | 不强制裁切；手动 resize 必须优先于自动布局。 |
| 标题行 | 28 px 基线 | 所有节点同一标题结构。 |
| 卡片圆角 | 12 px | 由 UI token 单一维护。 |
| 图片引用缩略图 | 48 × 36 px | 保留现有已确认决定；点击预览，hover 查看全貌。 |
| 间距 | 4 px 基数；常用 8 / 12 / 16 px | 组件间距走统一间距阶梯，禁止节点私造任意边距。 |
| 常规控件 | 28–32 px 高 | 下拉框、短输入、常规按钮。 |
| 对象微按钮 | 20–22 px | 单项复制/移除/预览等。 |

自动高度在空态、连接变化、预览加载或结果删除时都应重新计算固定档位，并能回到较小档位；一旦用户手动 resize，自动布局不覆盖用户尺寸。实现时必须能区分自动尺寸与用户尺寸。历史尺寸迁移不得覆盖用户手动调整。

正文容器必须 `min-height: 0`，超长文本、代码、JSON、结果列表和多图集合在正文内部滚动；不得靠无限撑高节点。所有控件和文本必须支持窄卡片，控件允许收缩，禁止横向溢出。滚轮在可滚动正文内先滚正文，到边界后交给画布；Ctrl/Command + 滚轮继续缩放。

## 6. 字体、控件与颜色

- 节点标签使用简短的人类可读名称；内部 port ID、Schema ID、媒体路径、MIME 和供应商 wire 值不能直接作为主界面文案。
- 卡片标签/辅助文本保持紧凑，正文重要值比说明文字突出一级。卡片控件字号不得低于现行 11 px 下限；标题以既有画布层级为准。
- 同一类控件共享 `AppSelect`、通用输入和按钮样式；每个 Body 不重复实现边框、聚焦环、禁用态、按钮高度和菜单材质。
- 类型色只表示节点家族身份，状态色只表示运行状态，数据类型色只服务已连端口和连线候选。不得用节点色表示成功/失败，也不得只用颜色表达必填或阻断。
- 类型色标识保持轻量（现有左上角切角和图标色）；卡片主体不再额外叠加整圈类型色边框。
- 空态用一个图标/缩略图、节点对象名称和一行事实状态。仅在用户必须采取动作时出现一个 CTA；不再叠加教学段落。

## 7. 状态规范

| 状态 | 标题行 | 正文 | 操作 |
| --- | --- | --- | --- |
| 空闲/就绪 | 安静状态点 | 显示输入摘要和主要编辑对象 | 主操作可用 |
| 缺必填输入/阻断 | 阻断状态点；tooltip 给出原因 | 仅当原因不明显时显示一行简短状态 | 主操作保留但置灰；对应必填端口用缺口语义呈现 |
| 排队/运行中 | 状态点变化 | 统一执行遮罩覆盖正文；进度只在有可信进度时呈现 | 主操作显示运行中状态且不可重复触发 |
| 成功/缓存 | 成功/缓存状态点 | 展示当前有效结果；旧结果不被失败覆盖 | 可再次运行 |
| 失败 | 失败状态点 | 仍保留最近一次有效结果；正文可显示一行原因摘要 | 运行详情、日志与完整错误在“运行”页 |
| 已取消 | 中性状态点 | 保留取消前有效结果 | 可重新运行 |

颜色不可单独承载状态：状态还必须能通过标题 tooltip、文本或端口形态获取。运行错误不能污染旧结果；若旧结果仍展示，要从状态上能分辨它不是本次失败生成的结果。

## 8. 节点家族模板

| 家族 | 正文顺序 | 卡片可留的设置 | 详情/工作台负责 |
| --- | --- | --- | --- |
| 素材源 | 素材预览 → 名称/简短元信息 | 导入、替换等单一素材动作 | 完整文件信息、文本抽取详情、资源管理 |
| 文本/提示词 | 上游文本摘要 → 可编辑正文 → 字数/有效性 | 主文本编辑对象 | 长文档、查找、契约与运行历史 |
| 媒体处理 | 原始媒体摘要/预览 → 高频处理参数 → 最新结果 | 最多两个直接影响当前结果的参数 | 时间轴、精细蒙版、透视参数、输出选项等复杂编辑 |
| 内容生成 | 提示词/输入参考 → 少量高频参数 → 结果预览 | 提示词、常用比例/数量/模式 | 供应商、模型细节、质量、高级配置 |
| 结构/数据 | 输入摘要 → 操作/schema 摘要 → 校验结果/输出摘要 | 当前操作和少量字段摘要 | 完整 JSON/代码、schema 编辑、端口动态配置 |
| 对话 | 上游上下文摘要 → 最近一轮对话摘要 | 最近答复与会话入口 | 完整消息、记忆、会话切换与高级设置 |
| 批量/流程 | 列表来源、项目数 → 当前范围/结果数量 | 当前批次、简短进度 | 完整集合、运行历史与异常明细 |
| 预演/导演台 | 分镜/参考来源摘要 → 当前预览/发布状态 | 当前镜头摘要和发布动作 | 完整工程编辑、相机参数和发布差异 |

## 9. 逐节点呈现表

以下表格规定每个节点卡片首屏的内容归属。节点可按需要省略一行，但不能把另一栏的完整表单搬进卡片。右侧详情和工作台复用现有面板，不复制第二份可编辑表单。

| 节点 | 卡片首屏应有 | 详情/工作台放完整内容 |
| --- | --- | --- |
| 文本 `text` | 上游文本摘要、正文编辑区、字数 | 长文本编辑、输入输出契约、运行信息 |
| 图片 `image` | 图片预览、资产名称；空态提供导入 | 资产详情、契约与运行记录 |
| 裁剪 `image-crop` | 原图来源/预览、比例或裁剪摘要、最近结果 | 精细裁剪/透视工作台、复杂参数 |
| 拆分 `image-split` | 原图、行列数、拆分预览/结果数量 | 高级布局、完整结果列表与输出说明 |
| 生图 `image-gen` | 提示词、参考图、常用画幅/数量摘要、最新图片结果 | 供应商/模型高级项、质量选项、完整历史 |
| P 图 `image-edit` | 原图、编辑说明摘要、标注入口、最新结果 | 标注工作台、遮罩/模型高级配置、历史 |
| 视频生成 `video` | 参考媒体、提示词、关键生成模式、最新结果 | 供应商/模型、质量与其他高级参数 |
| 视频素材 `video-asset` | 视频预览、素材名称；空态提供导入 | 文件详情、契约与运行记录 |
| 抽帧 `video-frame` | 源视频预览、取帧时刻、最新帧 | 精细时间选择与输出历史 |
| 视频截取 `video-clip` | 源视频、截取范围、产物摘要 | 时间轴工作台、格式与完整结果 |
| 截音频 `video-audio` | 源视频、音轨提取状态、最新音频结果 | 输出细节和运行历史 |
| 人声分离 `vocal-separate` | 输入音频、分离模式、最新人声结果 | 质量/引擎参数与完整输出记录 |

## 10. 允许的例外

以下例外须在新增节点时写入本表或同等的逐节点说明，并解释为什么通用卡片不足：

1. **大画布工作台**：图片标注、精细裁剪、对话等需要空间的编辑器可以独立打开。卡片中只留摘要、状态和入口。
2. **媒体主对象占满卡片**：素材源或预览节点可让媒体预览成为主体；导入/替换属于素材对象动作，不视为重复运行按钮。
3. **专用输入面**：裁剪、拆分、视频时间轴等媒体操作允许使用展开的输入预览，但要复用统一输入数据和样式，不重复通用输入条。
4. **行内对象动作**：只有对某个具体字段、素材或历史条目执行的动作才能保留在对象行。

其他“空间不够”情形按此顺序处理：删除重复信息 → 把低频控件移到设置 → 缩短摘要 → 让正文内部滚动/分页 → 最后申请节点专属例外。不得再把任意信息堆到卡片下方、侧边或浮动文本上。

## 11. 新增或修改节点的交付检查

- [ ] 标题行字段与其他节点相同；节点名称和说明来源唯一。
- [ ] 首屏能看出节点状态、真实输入和主要内容/结果。
- [ ] 正文顺序符合家族模板；未复制第二套输入来源或配置。
- [ ] 卡片最多两个普通配置控件；长内容和低频高级项进入详情/工作台。
- [ ] 每个可执行节点只有一个主运行入口；空态最多一个 CTA。
- [ ] 对象级操作确实作用于单个对象，并有 tooltip 和可访问名称。
- [ ] 260/320/380/440 档位下没有横向溢出；更长内容由内部滚动承载。
- [ ] 所有状态同时有形状/文本语义，不依赖颜色；失败不覆盖旧有效结果。
- [ ] 例外已登记并说明原因；正文组件没有私自重定义节点外壳样式。
- [ ] 输入展示只读真实连线投影，端口/schema/必填性仍服从节点契约。
