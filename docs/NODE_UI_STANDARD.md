# 节点 UI 统一规范

> 当前布局裁决见 §19 v1.3；与其冲突的 §18 强制说明、单按钮和操作占位规则已废止。

> 版本：**v1.2 强制规范**（2026-10-05：统一图标、说明、底部按钮和高度边界）。
> **当前入口：先读 §18。** 本轮规则已定稿，界面整改尚未完成。§18 是节点几何、身份区、说明、主按钮与滚动的唯一现行裁决；§13–§17 中的旧实现数值与历史验收不能证明符合 v1.2。
> v0.1 讨论稿（2026-09-23）的全部布局裁决经实测核对后升级为正式规范；**§13–§17 为本轮新增的实施细则**：样式令牌与权威层、滑动样式、按钮实现规格、引用关系与高度变化、统一记录。
> 范围：画布中的全部可创建节点；历史节点继续使用同一外壳。
> 目的：规定信息放置、卡片层级、尺寸、状态与例外。本文是布局与呈现规范；端口、数据来源、执行与持久化仍以 [`NODE_CONTRACT_SPEC.md`](../NODE_CONTRACT_SPEC.md) 为准。
> 参考样式：以本文现行规则为准；现有截图用于发现偏差，不能反过来成为豁免规范的依据。

## 1. 现状与本规范要解决的问题

项目已经有节点外壳、端口契约、右侧详情面板和不少逐节点决定，但这些规则分散在代码、测试、审计报告和历史提案里。当前实现的共同外壳包括：画布外侧标题行、统一的 340 × 260 默认卡片、真实连线输入预览、类型化节点正文、外置端口和运行遮罩。标题行承担通用运行入口；具体配置和动作仍有不少由各节点 Body 自己决定。

旧版 [`NODE_UI_SPEC.md`](./NODE_UI_SPEC.md) 同时保留了早期 footer、固定尺寸和 CSS 重排提案、后续已落地决定以及未完成项。它不能单独回答新增或修改节点时的关键问题：正文放什么、设置放哪、主操作在哪、超出空间后怎么处理。本文件把这些决定收成一套可逐节点执行的规则。

## 2. 设计目标

画布节点在不打开详情时，应让人快速回答四件事：

1. 这个节点是什么，当前是什么状态？
2. 它实际收到了什么输入？
3. 当前最重要的内容或结果是什么？
4. 下一步的主要操作是什么？

画布卡片是工作流的快速阅读、轻量编辑和运行表面。完整配置、契约、运行日志、长文本和完整历史由右侧详情面板或专用工作台承载。

### 不可破坏的原则

| 原则 | 规则 |
| --- | --- |
| 一个信息一个归属 | 同一份来源、状态或配置只在一个主要位置展开；卡片与详情只允许摘要和详情的关系，不重复放两份可编辑控件。 |
| 真实关系优先 | 输入摘要来自真实连线和当前有效输出。不能根据节点类型、标题或旧结果推断输入。 |
| 一张卡一个主操作 | 生成类节点以正文“生成”按钮为主操作，标题行运行为次级图标；数据处理类以标题行为主操作。两者必须调用同一执行器，不新增隐藏输出。旧版“所有运行只放标题行”条款已失效。 |
| 卡片先摘要 | 卡片优先保留高频内容、最重要的参数和最新结果；长尾设置、历史列表和日志进入详情。 |
| 同一顺序 | 有输入的节点按“输入 → 主要编辑/控制 → 最新结果”组织。无输入的源节点从主要内容开始。 |
| 例外必须登记 | 只有媒体编辑器或专用工作台确实需要大画布空间时，才允许替换通用输入摘要；例外仍要显示真实来源，并且不能重复呈现同一输入。 |

## 3. 节点卡片解剖

```text
节点标题行（卡片外）
[序号] [类型图标] [可编辑名称] [说明] [摘要/计数] [状态] [主操作]

节点卡片（默认 340 × 260）
┌──────────────────────────────────────────┐
│ 输入摘要：真实上游的媒体缩略图、文本或结构摘要 │  可无
├──────────────────────────────────────────┤
│                                          │
│ 主要内容：正文编辑器、关键参数、预览或结果     │
│                                          │
│ 可选的一行状态/结果摘要                      │
└──────────────────────────────────────────┘
 左侧输入端口                              输出端口右侧
```

### 3.1 标题行

- 固定放置：序号、节点图标、节点名称、节点说明入口、状态、单一主操作。
- 名称始终来自节点 Spec 的同一个 label 来源；用户可重命名，但不能让节点类型与画布创建菜单使用两套名称。
- 状态摘要和字数等小计数可以占用标题行的弹性空隙；不得挤压节点名称或主操作。超长名称省略显示，完整文本通过 tooltip/详情可读。
- 主操作位按节点能力呈现一个有语义的动作：执行器节点为运行；手动发布型节点为发布；不可执行的素材源不显示运行按钮。
- 主操作不可用时保留按钮并置灰；不可用原因由标题 tooltip、缺失端口状态或一行阻断摘要说明。
- 标题行不放模型下拉、配置表单、第二个执行按钮或长说明。

### 3.2 卡片正文

正文按以下区域从上到下排列，按节点类型省略不适用区域，不得改变顺序：

1. **输入摘要**：真实上游数据的紧凑摘要。无已解析输入时不占空白高度；必填输入缺失由端口和简短状态呈现。
2. **主要工作区**：该节点唯一的主要编辑对象，或最常用的一至两个参数。文本、提示词、裁剪范围、拆分行列、时间范围等可在此轻量编辑。
3. **最新结果/预览**：有结果时展示当前有效结果或清楚标记为旧结果的最近成功结果。媒体以预览为主；结构数据以 schema、规模和少量字段摘要为主。
4. **对象级操作**：只针对正文中某一条素材、某个字段或某个结果的操作，贴近对象放置。

卡片正文不承担完整设置页面。正文中可见的配置控件最多两个（不含主要正文编辑区）；低频、高复杂度或随供应商变化的字段进入“设置”。

### 3.3 右侧详情与工作台

右侧详情沿用现有四个分区：

| 分区 | 内容 |
| --- | --- |
| 概览 | 节点作用、当前就绪/阻断状态、输入输出摘要。 |
| 输入输出 | 完整端口名称、类型、Schema、基数、必填性和真实连接情况。 |
| 设置 | 完整配置表单，包括低频参数、供应商/模型高级选项、长 JSON 或代码配置。 |
| 运行 | 运行/运行至此操作、最近运行状态、失败原因、耗时、日志与历史记录。 |

需要大画布操作（如图片标注、裁剪工作台、对话）的节点可以从卡片进入专用工作台。工作台负责复杂编辑；卡片保留结果摘要、来源、状态和入口，不再复制工作台中的整套控件。

## 4. 信息放置裁决表

| 信息/操作 | 固定位置 | 卡片显示上限 | 不应放置 |
| --- | --- | --- | --- |
| 节点序号、类型、名称 | 标题行 | 一行 | 正文重复节点全名 |
| 执行状态 | 标题状态点；运行时正文遮罩；阻断/失败时一行摘要 | 一种当前状态 + 一条短原因 | 多处重复状态徽标和长日志 |
| 输入端口与输出端口 | 卡片左右外缘 | 显示契约声明的全部端口；悬浮可读名称与类型 | 隐藏未连接的附加端口；正文手画第二套端口或假连接图标 |
| 已连接输入 | 正文顶部的统一输入摘要，或登记过的专用媒体输入面 | 默认最多 12 项，超出显示 `+N`；many 输入显示顺序 | 只写“已连接”而不展示真实内容；在卡片和工作区重复展示同一完整预览 |
| 主要正文/提示词 | 正文主要工作区 | 一份主要编辑对象；长内容可滚动或打开工作台 | 再放一份同步不可靠的侧栏副本 |
| 高频关键参数 | 正文紧邻主要工作区 | 最多 2 个 | 把所有低频字段排成密集表单 |
| 供应商细节、长尾参数 | 右侧“设置” | 卡片最多显示当前值的只读摘要 | 同一字段同时在卡片与面板各有可编辑副本 |
| 最新生成/处理结果 | 正文主要预览区 | 当前结果优先；历史列表不超过摘要 | 结果详情压到卡片外下方或侧边散落 |
| 单项预览、复制、移除、重命名 | 对象行内，统一微按钮 | 每行最多 2 个图标操作 | 把全节点动作伪装成对象操作 |
| 运行/生成/发布 | 生成类正文主按钮、标题次级图标；处理类标题行 | 每节点一个主要位置 | 两个入口各自维护执行逻辑或不同运行状态 |
| 导入/选择源素材 | 源节点空态或素材预览区 | 一个明确入口 | 空态同时摆多个并列主按钮 |
| 错误详情、调用参数、运行日志 | 右侧“运行” | 卡片最多一行可操作的错误摘要 | 让错误堆栈占满卡片正文 |
| 引导和解释 | 首次空态的一句事实说明；详细说明在概览/tooltip | 空态一行，tooltip 短句 | 长段教学、重复端口操作说明 |

### 4.1 输入摘要规则

- 数据必须来自真实 Arrow binding、端口契约和当前有效输出投影。
- 图片用缩略图；视频/音频/文件用类型图标和来源名；文本显示短摘要；JSON 显示类型/schema 或短结构摘要。
- 多值输入按真实连线顺序显示序号。超出可视量折叠为 `+N`，展开后在正文内滚动。
- 当前 `image-crop`、`image-split`、`video` 使用专用输入表面；保留这些差异时，必须遵循同一输入摘要组件的密度和来源语义，不能成为新的私有布局模板。
- 需要显示“等待上游”时，使用事实状态，不添加拖线教程。若输入缺失是可选状态，不以红色错误呈现。
- 对媒体工作台采用“输入摘要”的紧凑/展开同一组件；同一来源不得在通用输入栏和工作台素材列表中重复出现。

### 4.2 按钮规则

- **节点级动作**：生成类以正文生成为主，标题图标为次级入口；处理类以标题行运行为主；专用工作台的应用/发布用于提交编辑结果。全部入口复用同一执行器与运行状态。
- **工作台入口/设置入口**：作为节点主要动作时放在固定底部操作区，最多一个主按钮；次要操作进入详情或菜单。具体尺寸见 §18。
- **对象级动作**：放在对象行右侧；使用 20–22 px 图标按钮，必须有 tooltip 和 aria-label。
- **源素材导入**：只在无素材空态显示一个主 CTA；有素材后转为预览和替换/导入入口。
- 任何节点正文不能定义第二份运行 readiness，也不能出现另一套“是否可执行”的条件判断；沿用契约派生状态。

## 5. 尺寸、间距与溢出

| Token | 规范值 | 用途 |
| --- | ---: | --- |
| 默认宽度 | 340 px | 新建节点默认宽度；用户可手动调整。 |
| 默认及最低高度 | 260 px | 新建节点默认值，也是手动缩小的下限。 |
| 自动档位 | 260 / 320 / 380 / 440 px | 内容确实需要额外空间时逐档增长，不接受任意像素自动高度。 |
| 自动高度上限 | 440 px | 超出后由正文内滚动或转入详情/工作台。 |
| 手动高度上限 | 440 px | 与自动上限一致；超出内容在正文滚动，完整操作进入工作台。历史超限节点按 §18.5 迁移。 |
| 标题行 | 28 px 基线 | 所有节点同一标题结构。 |
| 卡片圆角 | 12 px | 由 UI token 单一维护。 |
| 图片引用缩略图 | 48 × 36 px | 保留现有已确认决定；点击预览，hover 查看全貌。 |
| 间距 | 4 px 基数；常用 8 / 12 / 16 px | 组件间距走统一间距阶梯，禁止节点私造任意边距。 |
| 常规控件 | 28–32 px 高 | 下拉框、短输入、常规按钮。 |
| 对象微按钮 | 20–22 px | 单项复制/移除/预览等。 |
| 节点主操作底边距 | 8 px | 正文内主操作按钮到卡片底边的留白。 |

自动高度在空态、连接变化、预览加载或结果删除后重新计算固定档位，可回落；输入中不自动缩小。所有节点记录自动/手动模式，手动高度限制在 260–440px。迁移与收缩时机以 §18.5 为准。

正文容器必须 `min-height: 0`，超长文本、代码、JSON、结果列表和多图集合在正文内部滚动；不得靠无限撑高节点。所有控件和文本必须支持窄卡片，控件允许收缩，禁止横向溢出。滚轮在可滚动正文内先滚正文，到边界后交给画布；Ctrl/Command + 滚轮继续缩放。

## 6. 字体、控件与颜色

- 节点标签使用简短的人类可读名称；内部 port ID、Schema ID、媒体路径、MIME 和供应商 wire 值不能直接作为主界面文案。
- 卡片标签/辅助文本保持紧凑，正文重要值比说明文字突出一级。卡片控件字号不得低于现行 11 px 下限；标题以既有画布层级为准。
- 同一类控件共享 `AppSelect`、通用输入和按钮样式；每个 Body 不重复实现边框、聚焦环、禁用态、按钮高度和菜单材质。
- 类型色只表示节点家族身份，状态色只表示运行状态，数据类型色只服务已连端口和连线候选。不得用节点色表示成功/失败，也不得只用颜色表达必填或阻断。
- 类型色标识保持轻量（现有左上角切角和图标色）；卡片主体不再额外叠加整圈类型色边框。
- 空态统一使用图标、名称、两行说明槽和固定底部 CTA。所有节点均需简短功能说明；有内容时转为紧凑说明区，见 §18.3。状态提示不替代功能说明。

## 7. 状态规范

| 状态 | 标题行 | 正文 | 操作 |
| --- | --- | --- | --- |
| 空闲/就绪 | 安静状态点 | 显示输入摘要和主要编辑对象 | 主操作可用 |
| 缺必填输入/阻断 | 阻断状态点；tooltip 给出原因 | 仅当原因不明显时显示一行简短状态 | 主操作保留但置灰；对应必填端口用缺口语义呈现 |
| 排队/运行中 | 状态点变化 | 统一执行遮罩覆盖正文；进度只在有可信进度时呈现 | 主操作显示运行中状态且不可重复触发 |
| 成功/缓存 | 成功/缓存状态点 | 展示当前有效结果；旧结果不被失败覆盖 | 可再次运行 |
| 失败 | 失败状态点 | 仍保留最近一次有效结果；正文可显示一行原因摘要 | 运行详情、日志与完整错误在“运行”页 |
| 已取消 | 中性状态点 | 保留取消前有效结果 | 可重新运行 |

颜色不可单独承载状态：状态还必须能通过标题 tooltip、文本或端口形态获取。运行错误不能污染旧结果；若旧结果仍展示，要从状态上能分辨它不是本次失败生成的结果。

## 8. 节点家族模板

| 家族 | 正文顺序 | 卡片可留的设置 | 详情/工作台负责 |
| --- | --- | --- | --- |
| 素材源 | 素材预览 → 名称/简短元信息 | 导入、替换等单一素材动作 | 完整文件信息、文本抽取详情、资源管理 |
| 文本/提示词 | 上游文本摘要 → 可编辑正文 → 字数/有效性 | 主文本编辑对象 | 长文档、查找、契约与运行历史 |
| 媒体处理 | 原始媒体摘要/预览 → 高频处理参数 → 最新结果 | 最多两个直接影响当前结果的参数 | 时间轴、精细蒙版、透视参数、输出选项等复杂编辑 |
| 内容生成 | 提示词/输入参考 → 少量高频参数 → 结果预览 | 提示词、常用比例/数量/模式 | 供应商、模型细节、质量、高级配置 |
| 结构/数据 | 输入摘要 → 操作/schema 摘要 → 校验结果/输出摘要 | 当前操作和少量字段摘要 | 完整 JSON/代码、schema 编辑、端口动态配置 |
| 对话 | 上游上下文摘要 → 最近一轮对话摘要 | 最近答复与会话入口 | 完整消息、记忆、会话切换与高级设置 |
| 批量/流程 | 列表来源、项目数 → 当前范围/结果数量 | 当前批次、简短进度 | 完整集合、运行历史与异常明细 |
| 预演/导演台 | 分镜/参考来源摘要 → 当前预览/发布状态 | 当前镜头摘要和发布动作 | 完整工程编辑、相机参数和发布差异 |

## 9. 逐节点呈现表

以下表格规定每个节点卡片首屏的内容归属。节点可按需要省略一行，但不能把另一栏的完整表单搬进卡片。右侧详情和工作台复用现有面板，不复制第二份可编辑表单。

| 节点 | 卡片首屏应有 | 详情/工作台放完整内容 |
| --- | --- | --- |
| 文本 `text` | 上游文本摘要、正文编辑区、字数 | 长文本编辑、输入输出契约、运行信息 |

## 10. 允许的例外

以下例外须在新增节点时写入本表或同等的逐节点说明，并解释为什么通用卡片不足：

1. **大画布工作台**：图片标注、精细裁剪、对话等需要空间的编辑器可以独立打开。卡片中只留摘要、状态和入口。
2. **媒体主对象占满卡片**：素材源或预览节点可让媒体预览成为主体；导入/替换属于素材对象动作，不视为重复运行按钮。
3. **专用输入面**：裁剪、拆分、视频时间轴等媒体操作允许使用展开的输入预览，但要复用统一输入数据和样式，不重复通用输入条。
4. **行内对象动作**：只有对某个具体字段、素材或历史条目执行的动作才能保留在对象行。

其他“空间不够”情形按此顺序处理：删除重复信息 → 把低频控件移到设置 → 缩短摘要 → 让正文内部滚动/分页 → 最后申请节点专属例外。不得再把任意信息堆到卡片下方、侧边或浮动文本上。

## 16. 存在引用关系时，高度如何变化（实施细则）

> 本节仅保留旧实现记录，不得用于新增实现。引用布局、间距与增高以 [节点引用呈现规范](./NODE_REFERENCE_SPEC.md) 为准；其余高度规则以 §19 为准。旧版逐条换行、只增不减、860px 兜底及仅 image-gen 记录手动尺寸均已废止。

引用关系 = 上游连线进入本节点。视觉与高度按以下顺序自动变化，节点代码不介入：

1. **连线瞬间**：除 `image-crop`、`image-split`、`video`（专用输入面）外的节点，在 body 顶部插入 `ConnectedInputPreview`：每条连线一行 **28px** 输入条（gap 5px）；图片引用渲染 **48×36 白底缩略图**（与 §5 尺寸表一致）。
2. **端口变色**：已连接输入端口继承上游节点色，空闲端口用本节点色；产物溯源点继承生产者色。
3. **高度跳档**：新增输入行使 body 溢出 → fitHeight（`NodeCardView.tsx`）提升到最低可容纳档（260→320→380→440）。**只增不减**：断线后卡片保持当前档位，不回落（防输入抖动）。
4. **运行产生结果后**：单结果渲染 `.node-media` 预览（`object-fit:contain`，随档位撑高）；多结果渲染 `.media-result-grid`——自然高度参与跳档，超过 440 档容量后网格转内滚（860px 兜底）；底部追加续接动作条。
5. **循环节点**：进度条固定 6px 高，计入 fitHeight。
6. **手动尺寸优先**：`nodeHeightMode:'manual'`（仅 image-gen 经 resize 记录）时自动量高完全退出，溢出转内滚；历史尺寸迁移不得覆盖用户手动调整。

实现要求：节点 Body 不做任何自身高度管理（不设固定 height、不自行撑卡）；提供语义容器与内容，高度一律由 §5 档位机制裁决。

## 18. v1.2 统一节点呈现协议（2026-10-05，当前权威）

### 18.1 审计结论与适用边界

用户截图及源码确认：文本/AI 身份图标采用 88px 容器，文件/媒体另有 76px，网址为 48px；按钮既有居中跟随正文又有底部布局；文件有说明而多个身份卡没有；网址用“双击打开设置”文字代替按钮；生成按钮存在被局部样式削弱为文字的情况。现有颜色验收只证明身份色正确，没有证明节点整体布局一致。

文档也有冲突：本文件旧 §5 与 §16 分别要求回落和只增不减；旧 §15 主按钮为 28px，其他记录为空态 32px；呈现规范旧 §6.2 保留 960px 上限；代码 `manualMax=720` 只是推荐值，生图自动高度还使用连续像素计算。这些均列入待整改，不能标注“已统一”。

本节适用于全部 28 个可创建节点和历史节点外壳，覆盖空态、编辑、有结果、缺输入、运行、失败、重开项目。统一的是结构、尺寸、说明和动作位置；图标图形、身份色与业务内容按节点职责变化。大图标仅用于空态/工作台入口，不要求在已有媒体预览上额外叠大图标。

### 18.2 唯一尺寸表与卡片骨架

所有数值以画布 100% 缩放的 CSS px 计；缩放后等比例测量。卡片高度指卡体，不含悬浮标题及其 6px 间隔。

| 最低/最高卡体高度 | 260 / 440px，自动和手动均受约束                          |
| 自动高度档位      | 260 → 320 → 380 → 440px                                  |

| 空态图标图形      | 32 × 32px，线宽 2px，容器内正中，100% 不透明             |

                 与卡体相隔 6px
┌─────────────────────────────┐

底部操作区是卡片的固定布局行，不放进正文滚动容器，也不以 absolute 覆盖正文。空态身份组在正文可用区域中居中，功能说明槽高度固定，因此相同高度节点的图标、名称、说明和按钮基线一致。生成型节点用编辑区替代身份组，但共享相同底部操作区。

用户手动改变宽度时按钮宽度为 `min(200px, 可用正文宽度)`，禁止溢出。不能因按钮文字更长改变高度或节点宽度；文字省略，完整名称可通过提示及可访问名称获取。

### 18.3 每个节点都必须有功能说明

1. 每个节点声明一份用户可读的短说明，优先复用 `NodeTypeSpec.description`；详细能力/限制进入详情。不要在各 Body 再写同义但不同的文案。
2. 空态在名称下方展示；内容态在正文顶部以同一两行说明组件展示。内容态说明随正文滚动，底部按钮固定。
3. 说明只回答“处理什么、得到什么”或关键格式限制。最多两行，超出末尾省略；一行说明仍保留两行槽位，不让按钮和图标跳动。
4. 完整说明通过标题说明入口可点击/键盘打开；hover 提示作为补充。不得只依赖原生 `title` 让触屏或键盘用户无法读取。
5. “双击打开设置”“点击这里”“请拖入节点”属于操作教学，不作为功能说明。缺输入、失败、运行进度放独立状态位置；完整错误可以在详情读取，不能被两行说明规则截断后无处查看。
6. 名称使用主题主文字色，说明使用主题次级文字色；两种主题均验证可读性。禁止给说明整段染身份色。

建议文案：文本“输入或编辑文本，供下游节点使用。”；文件“导入文件；支持的文档可提取文字。”；网址“保存网址名称与链接，快速打开网页。”；AI 对话“结合输入内容与 AI 对话。”；AI 处理“按任务说明处理输入内容。”；图片“导入图片，供下游编辑或生成使用。”；生图“根据提示词和参考图片生成图像。”具体格式支持以真实文件处理能力为准，不编造支持格式。

### 18.4 所有节点共用主按钮

- 每张卡保留一个固定底部主动作：输入、导入、配置、打开工作台、生成、运行或查看结果；根据业务状态选择，不用“确定”“操作”等空泛名称。
- 全部采用真实 `<button type="button">`，左图标右文字；按钮有可见填充和描边，正常态即能识别。禁止纯文本、可点击 span、只能双击的伪按钮，禁止仅 hover 后显现。
- 统一表面：背景 `--card-hover`，描边 `--line`，文字 `--txt`；hover 使用公共交互高亮，focus-visible 使用独立清晰焦点环。禁止逐节点改变高度、宽度、圆角或使用私人渐变。
- 单击或 Enter/Space 触发；按钮事件不得同时触发卡片拖动、双击或两次执行。卡片双击可保留快捷方式，但不得作为唯一入口。
- 不可用时按钮仍保留同样位置、尺寸和图标，显示明确原因；运行中保留宽度，改为“生成中…”等状态文案并阻止重复提交。执行条件复用已有 readiness，不另写一套判断。
- 对象上的复制、替换、删除等操作仍放对象附近，不冒充第二个主动作。标题运行是次级快捷入口，与底部运行复用同一执行器和状态；数据处理类也需明确底部“运行处理”或“配置处理”主动作，替代旧“只放标题行”裁定。
- 若有结果预览，底部动作可保持“再次生成”或切为“打开工作台/查看结果”；具体状态映射在节点定义中明确，不能因渲染分支丢失操作区。

### 18.5 高度与滚动的完整规则

1. 所有节点创建尺寸从 260px 开始。仅含身份入口的空态组及动作区必须在此高度容纳，不因长说明或不同图标自动变高。直接展示配置表单、参数列表或预览的节点属于内容态，按实际控件自然高度进入自动档位；所有节点最低高度均为 260px。
2. 内容态需要的高度 = 正文自然高度（含说明、输入引用、间距）+ 正文上下留白 + 48px 操作区。取不小于需求的最小档位，上限 440px；禁止按固定 `rows`、当前带滚动的容器高度或单节点特殊公式推断。
3. 只有正文内容确实溢出才升档。到 440px 后正文 `min-height:0; overflow-y:auto`，操作区不滚动。禁止滚动整张卡、让主按钮滚走、正文盖住按钮或继续撑到 720/860/960px。
4. 默认只设一个纵向正文滚动区。长文本、代码等确需独立编辑器时由编辑器承担该段滚动，禁止同一区域出现两条嵌套纵向滚动条。Ctrl/Command + 滚轮保持画布缩放，普通滚轮沿现有正文优先路由处理。
5. 自动模式：新增输入、预览加载、执行结果就绪时重新量高；删除内容、移除结果或断线后允许回落。输入法组合期间及持续键入期间不自动缩小，失焦或明确删除操作结束后再回落，避免光标跳动。
6. 手动模式：任意节点手动拖高后记录 `nodeHeightMode:'manual'`，高度可在 260–440px 连续调整，内容变多只内滚，不覆盖用户选择。提供“恢复自动高度”入口。禁止仅生图具备手动模式。
7. 调整高度必须同步端口与连线锚点；不缩放正文文字及控件。临时 hover、tooltip、状态点与拖线候选不触发持久化高度变化。
8. 历史节点：原始数据保留，加载时仅对显示高度夹取到 260–440px，不改正文/媒体/配置；保存时才记录有效显示尺寸。迁移需保留原尺寸元数据用于回溯，并验证重开和撤销行为，不静默删除超出部分内容。

## 19. v1.3 按内容布局协议（2026-10-05，当前权威）

### 内容与操作

- 节点卡片不自动展示 `NodeTypeSpec.description`；职责、端口、实现约束留在标题的“查看输入输出说明”入口。
- 没有实际引用时不渲染引用区域，不预留高度，不补图片/端口解释。实际引用只显示真实缩略图或摘要。
- 提示文案仅用于必要的操作状态、错误或格式限制；按需显示，最多两行，缺省不占位。不得把内部契约文案当成用户操作提示。
- 底部可以没有动作、一个主动作或多个业务动作。只能由 Body 显式提供，不自动补“配置图片/配置裁剪/配置拆分”。
- 图片空态为导入按钮；有图为裁剪、拆分、生图、P 图、生视频、替换及已有文件操作。保留原回调和真实连线，不合并成无意义的配置按钮。
- 裁剪保留精细框选和裁剪图片；拆分直接编辑行列及面积，使用标题运行入口，无底部配置按钮。

### 新增节点与验收

先声明空态、输入、引用、编辑/预览和实际操作，再接入公共外壳。复用 NodeIdentity、NodePrimaryButton 或 NodeFooterActions；无动作不创建占位按钮。按有/无引用、有/无资产及单/多/无操作分别验收，不再断言每张卡必须恰好一个按钮和一份说明。重点验证图片多操作回调、默认拆分无滚动、生图输入框填满、缩放后间距和历史高度模式。


### AI 处理结果呈现修正（2026-10-05）

成功结果直接在节点正文框显示完整文本、Markdown 原文或格式化 JSON，取消配置/查看结果切换按钮。短结果最低 260px，长结果自动增长到 440px，超出由公共正文滚动区承载；不截断内容。配置保留右侧面板入口。仅修改读取已有输出投影和呈现，不改变执行器、结果持久化及日志路径，无新增日志事件。浏览器门禁验证自动显示、完整末尾、440px 上限与可滚动。


### AI 结果阅读与格式（2026-10-05）

AI 处理卡片只显示输出，取消通用输入预览。点击正文选中节点并允许选文，阅读滑块拖动不启动节点拖动；选中后的滚轮使用公共正文外壳，边界不传递到画布。Markdown 输出用已有 ReactMarkdown/GFM 渲染，禁用原始 HTML；纯文本保持换行和字面符号。仅改呈现与滚轮路由，不变更执行、持久化和请求路径，无新增日志事件。


### 初始设置入口与引用增长（2026-10-05 补充）

AI 处理尚无输出时显示“配置处理设置”底部按钮，打开现有右侧设置页；已有输出时按钮隐藏，直接显示结果。

自动高度必须把实际显示的引用视为新增内容：先计算无引用正文所需高度，最低按默认 260px，再加单排引用区 36px 和 8px 分隔间距，向上取 260/320/380/440 档。例如默认 260px 正文加引用，应升到 320px，不能用缩小输入框来吞掉引用。整个引用区只显示一排，多项溢出通过 +N 浮层查看，不继续增加卡片高度；删除全部引用后按自动高度规则回落，手动模式保留用户尺寸。

此规则仅计算真实可见引用，不因有连线就盲目增加高度。AI 处理输入保持不显示；裁剪/拆分以主预览承载上游素材，不再重复引用；这些场景不额外增加引用高度。

### 侧边面板材质

所有侧边面板（节点详情、资产、节点库、历史、运行、AI 对话及资源详情）必须使用完全不透明的背景。深色与浅色主题均不得使用带透明度的背景渐变、整体透明度或背景模糊；面板打开后不得透出画布内容。阴影和边框可保留透明色，不影响面板背景的不透明要求。

### 视频缩略预览与高度增长原因

视频资产及已有视频结果的节点默认保持 260px 高度。导入、替换或选择视频不会因为视频的像素尺寸、比例或缩略预览而增长节点高度；预览保持比例并适应剩余空间，双击打开完整播放器。输入框或长文本结果确实需要更多空间、顶部真实引用新增内容时，才按档增长并封顶滚动。媒体缩略图、空白空间和装饰不属于高度增长原因。手动高度继续尊重用户选择。

工具栏采用统一线性图标：水平/垂直分布为等距矩形，组合为完整边界中的多个元素，拆分为断开的边界与分离元素，流程模板为连接步骤，节点库为叠放卡片。任务状态显示运行/等待图标与数量，并保留悬停文字及无障碍名称。

### 引用位置与详情预览

所有引用遵守 [节点引用呈现规范 v1.0](./NODE_REFERENCE_SPEC.md)：整个区域只显示一排、统一高 36px，位于正文最顶部，沿用 12px 左右内边距，下方间距 8px。文字单行省略，多项超宽显示 +N，通过统一悬浮详情查看完整内容。类型格式、来源、媒体预览、键盘交互及迁移验收以该文档为准；无引用时不占位。

声音调整节点直接展示按倍率/按目标秒数、对应数值及声量输入，底部保存参数；不再展示无操作价值的倍速摘要和右侧设置提示。音色设计默认连接点为音色档案 out-json，可接 MiniMax 语音合成 in-voice；试听音频仍保留独立输出，朗读文本接 in-text，不按文本内容猜测音色 ID。

数据处理不显示无连接的引用状态。数据类型和处理方式均有标题，类型下拉不占满整行；JSON 输入（任意、对象或数组固定值）可提取字段，文本输入使用字符串模板。新节点默认提取字段，显式保存的旧原样传递配置保留。输出区呈现真实运行结果，示例只放在输入占位提示中。

### 任务浮层与拖线候选

顶部任务状态及其浮层必须高于画布节点和画布工具栏，展开时可直接编辑任务额度。拖线候选兼容多个端口类型时，优先沿用目标已有兼容连接点，否则使用声明顺序中的默认兼容连接点；不得仅因上游为任意类型就展开全部可兼容类型。真实已连接端口、用户动态端口及明确的单类型候选仍按端口协议展示。
