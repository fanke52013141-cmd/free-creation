## 核心决策

1. 产品定位为通用的人机协作 Agent Flow 工作台。短视频、写作、设计等是领域模板。
2. 通用任务独立声明输入、参与方式、执行方式、上下文、交付要求和完成条件。
3. 人工是流程中的正式执行者；多轮交流、直接编辑、上传替换、版本选择都是正式操作。
4. 主 Agent 负责理解与协调；执行系统维护真实状态、依赖、预算和恢复。
5. 流程经由版本化产物交接。聊天记录、任务完成、产物确认分别建模。
6. 领域适配需要 system content、Skill、工具、上下文及产物契约共同配置；只换提示词不能补足缺失的工具能力。
7. 现有基础节点与契约继续复用，任务阶段通过可展开子图组合，避免巨型业务节点。
8. 三期顺序：通用协作闭环 → 可配置编排与复用 → 主 Agent 辅助规划与持续优化。

## 三期概览

| 阶段 | 核心目标 | 主要交付 | 进入下一期的条件 |
|---|---|---|---|
| 第一期 | 一个通用任务流可靠地运行、协作、交接和恢复 | 项目配置、任务配置、三种参与方式、会话隔离、正式产物、串行执行、人工待办、持久化、状态总览 | 两个不同领域共用同一套机制；通过协作、恢复和兼容性验收 |
| 第二期 | 复杂任务可以编排、复用和局部修正 | 条件/并行/批处理、子流程、Agent / Skill 配置中心、模板包、上下文检查、版本影响分析 | 失败与修改只影响对应范围；复杂流程可恢复；模板可导入导出 |
| 第三期 | 主 Agent 帮助创建、解释和调整流程 | 对话生成流程草案、受约束委派、变更预览、纠偏建议、评估与复用经验 | AI 提案均经契约校验；自主范围可控；跨领域方案可重复执行 |

## 边界与使用说明

- 保持本地单用户 Electron 产品形态。登录、团队权限、云端协作不属于三期范围。
- 本包是实施建议，没有宣称相关功能已经开发完成。
- 当前交付仅新增方案文件；未修改应用逻辑、安装依赖或运行测试。
- 文件内的接口、目录及数据库表为建议设计；标注为“现有”的内容来自仓库核对。
- 验收清单用于后续实施，不代表本次已执行或通过。
- 工作量是待校准估算，不是工期承诺。每期先完成入口评审，再逐项实施。
- 后续产品变更先更新本文档，再更新任务计划与契约，避免三份文档相互漂移。
