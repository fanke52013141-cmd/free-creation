# 通用 Agent Flow：三期实施与验收计划

版本：v1.0 · 2026-09-26

## 1. 计划口径

三期均交付可使用的增量版本。先保证通用协作的正确性，再扩展流程复杂度，最后增加主 Agent 的规划和协调能力。

下文是待执行工作包。验收场景未在本次文档编制中运行。每个工作包实施时需要同步设计、契约、代码、迁移和说明，不能只完成界面。

“人日”表示熟悉当前 Electron/TypeScript 工程的开发人员投入，包含开发、代码评审与对应验证；各期另列设计/集成和发布预算。估算不含新增复杂媒体算法、外部工具采购、任意插件市场或云端团队能力。先完成一期技术验证，再调整其余估算。

## 2. 第一期：通用协作闭环

### 2.1 用户最终能做什么

创建一个项目，选择工作台和简单流程模板；配置每个任务由人、AI 或人机共同完成；在某个任务内充分交流；整理并确认产物；进入下一个任务；退出后重新打开继续处理。

提供项目状态总览，呈现未来主 Agent 需要使用的状态信息。第一期不让主 Agent自主生成或修改流程。

### 2.2 范围

- 项目级节点显示配置、新建项目弹窗、兼容空白画布。
- 通用任务定义、配置校验、串行任务依赖。
- 人工、AI 自动、人机协作三种参与方式。
- 单次调用与多轮会话；复用已有节点执行。
- 独立 Session、显式提炼草稿、编辑/上传、确认与交接。
- 通用产物身份、版本、来源、固定输入引用。
- 持久化任务状态、暂停/取消、重启对账与继续。
- 串行流程的修订提示与选择性重做。
- 两个不同领域的配置模板。

不包含条件并行编排器、复杂子流程、任意工具循环、自动生成流程、团队协同、完整视频后期工具链。

### 2.4 推荐实施顺序

1. 先做 P1-01；未证明可恢复与现有契约兼容前，不扩展 UI。
2. 完成协议与存储，确定真实状态唯一来源。
3. 先贯通“输入 → AI 单次任务 → 产物 → 人工确认 → 下一任务”。
4. 再加入多轮协作、人工上传、工作台与任务编辑。
5. 最后做修订恢复、双领域模板、发布验证。

工作台配置 UI 可在协议确定后独立开发；关键路径为 P1-01 → P1-02 → P1-03 → P1-05 → P1-07 → P1-08。

### 2.5 验收清单

| 编号 | 场景 | 可观察的通过条件 |
|---|---|---|
| A1-01 | 新建两个不同领域项目 | 使用相同任务类型与运行器，仅配置/Schema/工具组合不同；无硬编码领域判断 |
| A1-02 | 隐藏某节点 | 新建入口一致隐藏，旧图仍能打开、查看和执行 |
| A1-03 | 人工完成任务 | 上传或编辑结果，类型校验通过并确认后，下游可读取对应版本 |
| A1-04 | 多轮协作 | 至少完成 5 轮修改与一次草稿提炼，未确认草稿不会释放人工确认型下游 |
| A1-05 | 会话隔离 | 两个任务分别交流，实际发给模型的消息不含另一任务未授权对话 |
| A1-06 | 重复确认 | 重复发送同一个确认命令只形成一次有效决策和一次后续执行 |
| A1-07 | 陈旧版本确认 | 在旧页面确认已被替换的版本，返回冲突，不批准最新版本 |
| A1-08 | 人工等待时退出 | 重开后待办、会话、草稿及输入版本一致，可继续完成 |
| A1-09 | 确认后立即崩溃 | 重启后 outbox 可恢复；不丢确认、不重复创建业务产物 |
| A1-10 | 外部调用状态未知 | 显示待对账/结果未知；没有自动发起第二次付费请求 |
| A1-11 | 修改上游 | 展示受影响的后续任务，当前运行仍绑定原版本；重做需明确选择 |
| A1-12 | 停止后结果晚到 | 结果保留来源但不自动完成已取消任务、不触发下游 |
| A1-13 | 桌面与新宿主一致性 | 同一节点输入下，多输出、错误、取消和媒体引用语义一致；确定性节点内容一致，模型节点用固定响应验证协议 |
| A1-14 | 老项目兼容 | 旧项目无需迁移聊天为产物即可打开；现有节点和执行语义不变 |

### 2.6 阶段出口

所有 A1 场景达到预期，关键数据丢失与重复副作用问题关闭，两个模板可连续完成。若运行框架仍存在重复调用或恢复歧义，一期继续收敛，二期只开展独立的设计准备。

## 3. 第二期：可配置编排与复用

### 3.1 用户最终能做什么

把一个专业流程配置成可复用模板；为每个环节选择 Agent、Skill、工具和确认方式；运行并行与批量任务；集中处理待办；修改部分成果后只重做受影响部分。

### 3.2 范围

- 条件、并行、Join、ForEach、子流程与结构化修订。
- Agent 与 Skill 配置中心、版本发布与依赖检查。
- 工具目录和受限工具循环，复用节点执行协议。
- 上下文来源预览、预算和摘要管理。
- 产物比较、依赖影响图、单项重试与局部重做。
- 可移植模板包与项目产物导入导出。
- 运行诊断与待办聚合。

### 3.3 工作包

| ID | 任务 | 具体开发内容 | 依赖 | 交付/完成标志 | 人日 |
|---|---|---|---|---|---|
| P2-01 | 编排模型与静态校验 | 控制结构 Schema、Join 规则、变量作用域、循环边界、缺失输入检查 | 一期出口 | 非法流程运行前明确报错 | 4–6 |
| P2-02 | 并行与批处理运行 | itemKey、并发限制、单项 attempt、部分失败策略、恢复与取消 | P2-01 | 成功项不重复、失败项可单独继续 | 6–9 |
| P2-03 | 子流程与画布编辑 | 入口出口、展开折叠、内部定位、模板节点映射 | P2-01 | 复用子流程且契约可追踪 | 5–8 |
| P2-04 | Agent / Skill 中心 | profile 编辑、指令变量、Skill 版本、工具依赖、样例调试 | 一期协议与存储 | 多项目引用配置，运行固定快照 | 5–8 |
| P2-05 | 工具目录与受限循环 | 从共享契约形成工具规格、参数校验、调用预算、错误返回与中断 | P2-04 | Agent 仅能调用已配置能力 | 4–7 |

| P2-07 | 版本比较与影响 | 依赖反查、受影响闭包、文本/结构对比、媒体并排预览、选择性重做 | P2-02 | 修订仅传播到真正依赖项 | 5–8 |
| P2-08 | 模板包与项目转移 | manifest、依赖检查、版本迁移、引用重映射、无密钥导出 | P2-03、P2-04、P2-07 | 在干净工作区导入可配置运行 | 4–6 |
| P2-09 | 待办与诊断 | 多任务待办筛选、失败路径、耗时/用量、上下文与产物来源跳转 | P2-02、P2-06 | 能定位为什么等待、失败或过期 | 3–5 |

开发工作包合计 **40–63 人日**；另预留设计、集成与发布 **6–10 人日**，二期合计 **46–73 人日**。

### 3.4 推荐实施顺序

编排语义与配置中心分别明确接口；先完成固定配置下的并行/批处理，再引入工具循环。子流程、影响分析和导入导出依赖稳定身份与版本，不应提前用临时 ID 赶 UI。

关键路径：P2-01 → P2-02 → P2-07 → P2-08。另一条为 P2-04 → P2-05 / P2-06。

### 3.5 验收清单

| 编号 | 场景 | 可观察的通过条件 |
|---|---|---|
| A2-01 | 一分支等待人 | 另一独立分支继续执行，Join 等待正确集合 |
| A2-02 | 20 项批处理中 2 项失败 | 只重试 2 项，已成功的 18 项不再次调用供应商 |
| A2-03 | 批处理输入重排序 | 对象身份与原结果保持关联，按 itemKey 而非数组下标匹配 |
| A2-04 | 条件分支未被选中 | 正确 skipped；必需下游输入缺失时阻止执行而非传空值 |
| A2-05 | 修改一份产物 | 只标记读取该版本的下游及其传递依赖；无关分支保持可用 |
| A2-06 | 更新 Agent / Skill | 已启动运行使用原快照，新运行可选择新版本 |
| A2-07 | 上下文超预算 | 硬约束和当前输入不静默丢失；显示缩减方案或明确阻止调用 |
| A2-08 | 工具调用越界 | 未配置工具、无效参数、超调用次数均在执行前被拦截并留痕 |
| A2-09 | 导入模板缺依赖 | 显示缺少节点/工具/模型配置，不丢失模板内容、不发起隐式调用 |
| A2-10 | 导入带产物项目 | 新 ID、文件路径、图引用及产物依赖全部有效，包中没有 API Key |
| A2-11 | 批处理等待与重启 | 每项状态和确认版本恢复，已处理待办不再次出现 |
| A2-12 | 子流程失败 | 可以定位内部具体步骤，重试不重新执行已确认的无关步骤 |

### 3.6 阶段出口

两个以上不同领域的模板可使用条件或批处理；产物依赖查询和选择性重做可靠；模板在干净工作区可导入。能力缺失必须作为模板依赖明确显示。

## 4. 第三期：主 Agent 辅助规划与持续优化

### 4.1 用户最终能做什么

在项目首页向主 Agent 描述目标；主 Agent 根据可用能力生成流程草案，明确每个环节由谁参与、产物是什么、哪里需要确认；用户修改后开始执行。过程中主 Agent 解释状态，给出处理异常、调整方案和局部重做的建议。

### 4.2 范围

- 项目首页的主 Agent 入口与目标澄清。
- 根据能力目录、模板和约束生成流程草案。
- 结构化变更提案与差异预览。
- 受限 Sub Agent 委派、动态任务计划与预算。
- 运行摘要、纠偏建议、主动呈现待办。
- 配置效果评估、模板对比和用户确认后的经验复用。

不承诺开放式自主执行任何任务，也不自动把历史对话写成所有项目共享记忆。

### 4.3 工作包

| ID | 任务 | 具体开发内容 | 依赖 | 交付/完成标志 | 人日 |
|---|---|---|---|---|---|
| P3-01 | 主 Agent 总控入口 | 目标澄清、状态摘要、待办定位、运行上下文选择 | 二期出口 | 用户可通过对话了解和进入当前任务 | 4–6 |
| P3-02 | 流程生成 | 模板检索、能力约束、结构化输出、静态校验、有限修复循环 | P3-01 | 生成可审阅而非直接执行的流程草稿 | 6–9 |
| P3-03 | 提案与变更预览 | 添加/替换任务、端口映射、预算影响、执行范围与用户选择 | P3-02 | 所有流程变更可查看差异并追溯 | 4–6 |
| P3-04 | 受限委派 | 子任务契约、Agent 绑定、递归深度/预算限制、上下文分配与回收 | P3-03 | 子任务有稳定身份，越界进入待办 | 5–8 |
| P3-05 | 纠偏建议 | 基于失败/过期/反馈提出重试、改配置、人工接管和局部重做方案 | P3-01、P3-03 | 建议说明证据、影响范围和预计动作 | 4–6 |
| P3-06 | 评估与版本对比 | 样例集、客观契约检查、人工评分、耗时/成本记录、配置比较 | P3-02 | 配置升级有可复查效果记录 | 4–7 |
| P3-07 | 经验与模板沉淀 | 用户选择将偏好写入项目约束或模板、版本化保存、来源与撤销 | P3-05、P3-06 | 经验可编辑、可拒绝、可回退 | 3–5 |

开发工作包合计 **30–47 人日**；另预留设计、跨领域评估与发布 **6–9 人日**，三期合计 **36–56 人日**。

### 4.4 推荐实施顺序

先让主 Agent 读懂和解释真实状态；再生成静态草案；再提供变更预览；最后开放受限委派。不要从“主 Agent 全自动跑整条流程”倒推补齐基础控制。

### 4.5 验收清单

| 编号 | 场景 | 可观察的通过条件 |
|---|---|---|
| A3-01 | 三个不同领域目标 | 通过配置生成任务图；结构契约有效；不新增针对领域名称的运行器分支 |
| A3-02 | 目标需要缺失能力 | 主 Agent 明确缺口，提出人工任务或替代流程，不虚构工具 |
| A3-03 | AI 生成错误端口 | 静态校验失败并可修复；未校验通过不能执行 |
| A3-04 | 修改已经确认成果 | 显示新版本及受影响任务，不原地覆盖用户确认内容 |
| A3-05 | 动态委派达到上限 | 停止继续派生，保留已有任务与结果，出现清晰待办 |
| A3-06 | 主 Agent 摘要与记录不一致 | UI 的完成/失败取持久化状态；可定位摘要引用，不被聊天覆盖 |
| A3-07 | 用户拒绝提案 | 当前定义和运行保持不变；拒绝记录可供本次修订参考 |
| A3-08 | 复用历史偏好 | 只有用户选定并保存的规则进入新模板；原始对话不默认全量带入 |
| A3-09 | 配置效果比较 | 固定输入与版本，展示质量评分、成本、耗时、人工修改次数；不只比较 token |

### 4.6 阶段出口

主 Agent 的规划和动作均可追溯，用户能检查、修改和拒绝；跨领域样例可以重新执行；AI 生成的流程遵守与手工流程相同的契约与恢复机制。

## 5. 总体资源与排期建议

| 阶段 | 含阶段集成的估算 | 可单独发布的结果 |
|---|---|---|
| 第一期 | 44–68 人日 | 通用人机协作任务流 |
| 第二期 | 46–73 人日 | 可配置、可复用的复杂流程 |
| 第三期 | 36–56 人日 | 主 Agent 辅助规划和协调 |
| 合计 | 126–197 人日 | 三期核心范围 |

若由两名熟悉工程的开发者持续投入，并有产品/设计/验收支持，可将 **约 16–24 个有效开发周**作为最初排期窗口，另考虑实际人员可用性与反馈等待。该窗口只是按人日和串行依赖推算的起点；一个开发者不能简单沿用该日历工期。核心运行适配失败、需求增加或新增媒体工具会改变估算。

建议按两周一个迭代排任务，每期结束单独演示和验收；一期 P1-01 完成后重新估算全部计划。按工作包和出口条件管理，不按“页面数量”计算完成率。

### 5.1 角色分工

- 产品/设计：任务抽象、关键交互、模板内容、人工决策体验及验收样例。
- 运行与存储开发：状态、契约、持久化、恢复、执行器、工具适配。
- 前端开发：画布视图、协作面板、配置中心、产物与事件展示。
- 验收责任人：恢复/重复命令/兼容性检查、真实模型样本与交付质量。

同一人可以兼任，交付责任需明确。涉及存储和副作用的变更必须经过独立代码评审。

## 6. 持续优化指标

| 指标 | 含义 | 如何使用 |
|---|---|---|
| 流程交付率 | 满足交付条件的运行占比 | 与失败原因共同分析，不能隐藏人工退出 |
| 人工修改次数与耗时 | 从草稿到确认的协作成本 | 用于改善任务与上下文配置，不把人参与多直接判为坏事 |
| 首次接受率 | 未重新生成即确认的产物占比 | 按领域与任务类型分组，配合质量评分 |
| 恢复正确性 | 中断后状态、输入、决策保持一致 | 数据正确性问题作为发布阻断 |
| 重复副作用 | 非用户意图的重复外部调用 | 对可去重路径要求为零；未知结果显式待处理 |
| 局部重做命中 | 修改后实际重跑是否匹配依赖范围 | 发现过度重跑和漏跑 |
| 上下文可解释性 | 一次模型调用能否列出输入来源 | 定位串话、遗漏与信息过量 |
| 实际成本与延迟 | 模型/工具用量、端到端等待时间 | 展示估算与实际差异，未提供价格的数据不伪造 |

第一期先记录基线，第二期开始比较模板，第三期比较 Agent 配置。审美与专业质量必须保留人工评价，结构校验不能替代。

## 7. 风险与处理顺序

| 风险 | 后果 | 措施 | 最晚处理阶段 |
|---|---|---|---|
| 过度抽象成万能黑盒 | 难以校验与复用 | 通用任务层 + 明确基础节点契约 | 一期协议 |
| system content 被当作全部配置 | 缺工具、缺数据却继续运行 | 显式依赖、上下文和产物 Schema | 一期 |
| 同一动作被重复执行 | 重复扣费、重复结果 | 命令去重、调用对账、结果未知状态 | 一期 |
| 主 Agent 与运行器各管一套状态 | 假完成、恢复不一致 | 唯一运行后端，UI/Agent 读取投影 | 一期 |
| 人工协作退化为确认弹窗 | 无法发挥专业判断 | 多轮讨论、直接编辑、上传和版本选择 | 一期 |
| 任务切分过细丢失全局约束 | 成果互相矛盾 | 公共约束和相关产物固定引用 | 一期 |
| 修改触发全量重跑 | 成本和体验恶化 | 一期串行范围提示，二期依赖闭包 | 二期 |
| 框架与业务深度耦合 | 难以替换和迁移 | 业务协议自有、运行适配器隔离 | 一期 |
| 新 UI 打包后快捷方式仍指旧包 | 用户看不到新功能 | 发布版本可见、启动入口核对 | 每期发布 |

## 8. 交付清单与变更流程

每一期交付：可安装构建、源码提交记录、协议/迁移说明、已知限制、验收记录、演示模板、用户操作说明和回滚材料。

任何新增需求按以下流程处理：

1. 判断是通用机制、领域配置还是新工具能力。
2. 确认是否改变任务/产物/节点契约。
3. 更新对应文档与工作包，注明增加的人日及依赖。
4. 为新能力增加可观察的验收场景。
5. 若挤占当前阶段核心恢复与数据正确性工作，则延后可选功能。

## 9. 第一个迭代的建议清单

1. 将本包作为 v1.0 设计基线，确定一期两个示例模板。
2. 完成运行框架与执行宿主 ADR，列出必须遵循的旧节点行为。
3. 定义 Task、Run、Artifact、HumanTask、Session 的最小 Schema。
4. 贯通“单次 AI 处理 → 产物草稿 → 人工确认 → 下一个确定性节点”。
5. 在等待确认和确认后两个位置验证重启恢复，再开始扩展协作 UI。

该迭代的评审重点是流程能否可靠交接与继续，不以主 Agent 对话界面是否完整作为衡量标准。
