# 通用 Agent Flow：产品与交互方案

版本：v1.0 · 2026-09-26

## 1. 产品目标

让用户把复杂工作拆成可协作、可检查、可修改、可复用的流程。每个环节由人、AI 或人机共同完成，使用明确的输入，交付可继续使用的成果。

平台提供通用机制；垂类通过配置组合专业知识、工具和工作方法。短视频只是一个可安装的流程模板，不能成为底层任务、状态和运行器的固定概念。

核心用户价值：

- 用户能在执行过程中充分讨论和纠偏，保留审美与专业判断。
- 单个任务只获得必要信息，同时保留项目级约束和相关背景。
- 用户能知道每个结果来自哪里、哪些版本被采用、修改会影响什么。
- 已完成的工作可以被继续使用；失败或改动不必让整条流程重跑。
- 随项目扩展，工作台只呈现用户当前需要的工具和环节。

“更抽象”必须对应更稳定的职责与协议。不能把所有节点退化成一个任意输入、任意输出的黑盒。通用任务负责组织参与和交接，基础节点继续承担明确能力。

## 2. 抽象模型

### 2.1 八个基础对象

| 对象 | 负责什么 | 不负责什么 |
|---|---|---|
| 工作台配置 WorkspaceProfile | 显示哪些节点、常用模板、默认布局 | 改变已有图的执行逻辑 |
| 流程定义 FlowDefinition | 任务、依赖、输入输出映射、运行策略 | 存储某次运行结果 |
| 任务定义 TaskDefinition | 描述一个可交付的工作单元及参与方式 | 等同于一个模型调用 |
| Agent 配置 AgentProfile | system content、模型、Skill、工具、上下文规则 | 持有所有运行的聊天与结果 |
| Skill 定义 SkillDefinition | 可复用的专业指令、资料、过程与适用范围 | 自动授予工具或文件访问能力 |
| 运行 FlowRun / TaskRun | 保存一次执行的状态、输入快照与尝试记录 | 反向覆盖模板定义 |
| 会话 Session | 保存某一协作任务的多轮交流 | 自动成为正式产物 |
| 产物 Artifact / Version | 保存可交接、可追溯的成果 | 把日志和所有消息混成业务输出 |

人工待办 HumanTask、上下文快照 ContextSnapshot、工具调用记录 ToolCallRecord 为运行层配套对象。

### 2.2 任务的七项声明

每个通用任务定义：目标、输入契约、参与方式、执行方式、上下文规则、产物契约、完成条件。

**参与方式和执行方式正交：**

| 维度 | 选项 | 解释 |
|---|---|---|
| 参与方式 | 人工 / 人机协作 / AI 自动 | 谁负责完成工作 |
| 执行方式 | 手工编辑上传 / 单次模型处理 / 多轮会话 / 工具操作 / 子流程 | 工作如何发生 |
| 确认策略 | 人工确认 / 契约校验后自动提交 | 什么条件允许交给下游 |

配置器只提供合法组合。人工任务可编辑或上传；人机协作可多轮讨论或人工修订 AI 草稿；AI 自动可单次处理或受限工具循环。自动生成后再由人确认，也是一种合法组合。

“AI 自动”不要求每次都创建一个自主 Agent。确定性的格式转换、裁剪、合成依旧调用基础执行器。

### 2.3 主 Agent、Sub Agent 和任务

- 主 Agent 是项目协作入口，负责理解目标、解释进度、提出安排、定位待办。
- Sub Agent 是某项任务绑定的专业 Agent 实例。配置可复用，但运行、会话和结果按任务隔离。
- 一个任务可以使用若干基础节点组成的子流程。对子流程的折叠只影响显示，不改变真实节点契约。
- 同一 Agent 配置处理多个对象时，各对象独立建 TaskRun 和 Session。
- 主 Agent 读取运行系统的状态。完成、失败、暂停等事实必须来自运行记录与正式结果。

第一期先提供主 Agent 所需的状态总览与项目入口；专业任务先具备 AI 协作。第三期再让主 Agent 生成和修改流程，避免早期把调度权交给尚未建立恢复机制的对话模型。

## 3. 领域如何通过配置接入

一个领域包由下列配置组合：

1. 工作台预设：可见节点、常用工具和布局。
2. 流程模板：任务拓扑、人工参与位置、输出映射。
3. Agent 配置：角色目标、system content、模型和预算。
4. Skill 与专业资料：方法、规范、案例、检查项。
5. 输入与产物 Schema：需要哪些数据，如何校验与展示。
6. 确认标准：用户需要判断什么，哪些可以自动校验。
7. 工具依赖：领域实际需要的生图、检索、文件处理等能力。

只修改 system content 可以改变专业指令，但不能产生尚不存在的工具、数据结构或执行能力。依赖不足时，模板应明确显示缺失能力和替代路径。

### 3.1 三种场景映射

| 通用环节 | 文章创作 | 短视频 | 产品方案 |
|---|---|---|---|
| 明确目标 | 读者与主题讨论 | 风格与故事讨论 | 问题与约束讨论 |
| 形成草案 | 提纲、初稿 | 剧本、分镜 | 需求列表、方案 |
| 专业加工 | 事实检查、润色 | 资产与镜头生成 | 技术可行性分析 |
| 人工判断 | 编辑定稿 | 造型与镜头选择 | 方案取舍 |
| 交付 | Markdown / 文件 | 视频 / 素材包 | 说明文档 / 任务清单 |

同一任务和产物机制适配以上场景。第一期用文章创作和短视频前期策划两个模板验证，均只依赖已有能力，不把整条视频生产作为一期前置条件。

## 4. 新建项目与可配置工作台

### 4.1 新建弹窗

默认只显示：项目名称、工作台预设、可选流程模板。

展开“高级配置”后显示：启用节点、默认 Agent 配置、项目公共约束。用户可以选空白画布，不必先配置复杂 Agent。

创建后提供“工作台设置”和“流程设置”两个入口：前者调整可见工具，后者调整任务与参与方式。

### 4.2 必须遵守的行为

- 隐藏节点只影响新建入口，已有节点仍可查看和执行。
- 左侧节点库、右键菜单、搜索、快捷入口使用同一筛选源。
- 导入模板时列出缺失节点与工具，可启用或取消导入，不能悄悄丢节点。
- 工作台配置按项目持久化；全局默认仅影响之后新建的项目。
- 新增节点类型不自动挤入旧项目已选的工具列表。
- 保存为工作台预设时不带项目媒体、密钥、会话或运行记录。
- 用户修改正在运行的流程定义只创建新修订；当前运行继续使用自己的快照。

## 5. 工作台界面

### 5.1 布局建议

```text
项目目标 / 当前运行 / 暂停与继续 / 工作台设置
┌──────────┬─────────────────────────────┬───────────────────┐
│ 节点与模板 │ 任务卡片 + 产物卡片 + 真实数据依赖 │ 当前协作 / 产物 / 配置 │
│ 常用 Agent│ 可展开的基础节点子图             │ 明确显示会话所属任务  │
└──────────┴─────────────────────────────┴───────────────────┘
运行摘要：执行中 N 项 · 待你处理 N 项 · 异常 N 项 · 已交付 N 项
```

第一期优先复用现有画布与右侧面板，避免同时改造所有基础交互。任务与产物视图应按需切换，不必把全部运行事件显示成画布节点。

### 5.2 主 Agent 状态区

显示目标、正在处理的环节、待办、异常、下一步与资源消耗。进度以任务统计和实际交付为基础；动态流程尚未确定总任务数时不伪造精确百分比。

状态区由持久化状态驱动，主 Agent 的自然语言摘要可重新生成。某一任务等待人，不应阻塞不依赖它的其他分支。

### 5.3 任务卡片

默认显示任务名、参与方式、状态、当前输入版本、产物数量及主操作。复杂提示词、工具、重试和契约放在详情面板。

状态对应操作：

- 尚未开始：编辑配置、选择输入、开始。
- 执行中：查看进度、请求暂停、停止。
- 需要协作：进入会话、编辑草稿、上传、选择版本。
- 待确认：比较、确认、提出修改、继续讨论。
- 失败：查看原因、修正配置、重试本项。
- 已完成：查看产物、创建修订、查看下游影响。

主 Agent 与 Sub Agent 的管理关系保存在独立视图数据中。不能作为现有业务 edge 写入数据图；可提供“协作关系”图层展示。

## 6. 让人充分参与的协作流程

### 6.1 多轮交流

用户打开待办后进入对应任务会话。面板头部固定展示当前 Agent、任务、作用对象和输入版本。

交流期间可以查看参考产物、手动改草稿、针对选中段落或区域提出意见。新回复保存为会话内容；不会覆盖已确认的产物。

“整理为草稿”是显式处理步骤：提炼当前结论，记录来源消息范围并创建产物版本。需要结构化时调用声明契约的提取节点，校验失败继续保留原文与错误说明。

### 6.2 确认与交接

用户确认的是一个明确版本，界面显示将交给哪些下游任务。系统通过事务登记确认决策，再释放满足条件的任务。

自动确认仅用于模板明确允许、且已通过约定校验的任务。语法或字段校验通过不代表审美正确；需要人判断的环节仍保留人工确认。

### 6.3 人工接管与恢复

用户可以请求停止 AI，等待取消或当前原子操作结束后接管，避免两个执行者同时覆盖草稿。纯人工任务也可以之后切换为人机协作；变更作为新的任务配置修订记录。

用户直接上传或编辑的结果具有同等产物地位，来源标记为人工，仍需通过类型和必填校验。

### 6.4 修改已经交接的结果

创建新版本，展示受影响任务，允许：仅保存草稿、确认新版本暂不重做、选择范围重做。

运行中的下游固定使用启动时选定的版本，不能被后台静默替换。必要时停止这些任务，再创建修订运行。

旧结果保留且可查看。受影响状态与“执行失败”分开表示。

## 7. 产物与上下文

### 7.1 产物模型

支持 text、markdown、json、image、audio、video、file。二进制文件继续使用媒体或文件引用，元数据描述业务身份、版本、来源及审阅状态。

产物有稳定身份；每次内容提交形成新版本。业务标签可以是“剧本”“报告”“角色”，不应把这些标签硬编码为运行器分支。

正式版本保留内容摘要、内容哈希、输入版本引用、生产任务与执行尝试、Schema 版本及决策记录。尚在编辑的草稿可自动保存，发布版本后不可原地改写。

### 7.2 上下文规则

按以下来源组装，并保留引用清单：

1. Agent 的固定指令与选定 Skill 版本。
2. 项目公共约束，例如目标、语气、风格、术语。
3. 当前任务的输入和相关已确认产物。
4. 当前会话及必要摘要。
5. 本次反馈、工具结果与明确授权的资料。

超过预算时先压缩或剔除可选背景，不能静默丢弃硬约束、当前输入和关键反馈；无法容纳时显示原因并要求调整范围或模型。

第一期提供来源清单；第二期提供上下文预览、摘要版本和预算检查。不同任务默认不共享完整聊天；跨任务借用信息通过产物引用或用户显式选择完成。

## 8. Agent 与 Skill 配置页

第一期提供任务详情中的简化配置；第二期建设独立配置中心。

配置页分为：基础信息、system content、模型、Skill、工具、上下文、产物与完成条件、调试记录。

- system content 支持明确变量，如项目约束和任务目标；使用显式绑定，缺少变量时提示。
- Skill 具有版本、适用输入、依赖工具和资源清单，装载时检查兼容性。
- 工具配置引用现有稳定能力标识与契约版本；不能仅存工具显示名称。
- Sub Agent 配置引用可复用 AgentProfile；每次运行固定引用版本。
- 调试使用独立测试任务与样例输入，结果不能自动混入正式项目。
- 第一、二期采用配置式 Skill：指令和资料加受控工具引用。任意第三方可执行插件不是必要能力。

## 9. 基础节点如何演进

由 LibTV 对照发现的媒体能力需求，作为领域工具路线并行管理：

| 能力方向 | 与通用 Agent Flow 的关系 | 推荐时机 |
|---|---|---|
| 通用产物与确认 | 所有领域共同依赖 | 第一期核心 |
| 文本提炼与 Schema 校验 | 对话转正式交付的通用桥梁 | 第一期核心 |
| 图像 / 视频 / 音频引用与预览 | 复用已有媒体基础 | 第一期整合 |
| 素材版本、分镜状态和批量关联 | 借助通用版本和批处理扩展 | 第二期领域模板 |
| 视频合成导出、字幕和音频加工 | 独立媒体能力，补全短视频交付 | 按短视频模板需求单独排期 |
| 检索、外部资料接入 | 其他领域工具扩展 | 按明确用例排期 |

领域工具不应阻塞通用协作机制；尚未支持的操作可设置为人工任务导入结果。详细媒体工具开发不包含在三期核心人日中。

## 10. 三期用户体验结果

- 第一期：用户自己安排简单流程，可以在任何配置为协作的步骤充分交流，确认产物后继续；项目重开能恢复。
- 第二期：用户可配置复杂依赖、批量任务与专业 Agent，保存成模板，在不同项目复用；修改和失败可局部处理。
- 第三期：用户通过主 Agent 描述目标，获得可检查的流程草案；AI 在约定范围内协调执行，并提出纠偏和改进建议。

三个阶段均保留人工主导权。高级自动化应减少机械操作，让人把时间用在判断与创作上。
