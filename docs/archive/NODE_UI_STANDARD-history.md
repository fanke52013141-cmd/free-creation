## 13. 样式令牌与权威层（实施细则；**本节令牌表为 v2.2 之前的历史值**，现行几何令牌以 `src/renderer/src/canvas/node-ui-tokens.ts` 与 §22/§23 为准）

### 13.1 CSS 加载顺序与覆盖规则

`main.tsx` 依次引入三层全局样式，**同特异性下后者覆盖前者**，改动样式前必须先确认目标规则落在哪一层：

| 层 | 文件 | 职责 |
| --- | --- | --- |
| ① legacy 全量 | `assets/app.css` | 历史规则；其 `:root` 令牌值仅作兜底 |
| ② 基础 | `assets/ui-foundation.css` | **令牌权威**（`:root` 实际生效值）+ `.node-*` 外壳唯一权威 |
| ③ 表面 | `assets/ui-surfaces.css` | 面板/菜单/表单/浅色主题；头部元件的最终生效值 |

节点专属局部 CSS 与组件同目录（如 `bodies/video-ai.css`），只允许补充布局与内容样式，不得重定义全局令牌或卡片外壳。

## 14. 滑动样式（实施细则）

| 容器 | 行为 | 依据 |
| --- | --- | --- |
| `.node-body` | `overflow-x:hidden; overflow-y:auto; overscroll-behavior:contain` | ui-foundation.css |
| 所有滚动区域：文档、画布、卡内、卡外面板、弹窗、编辑器及 Portal 详情 | **保留滚动，始终隐藏横向和纵向滚动条**；悬停和聚焦也不得显示 | `assets/scrollbars.css`，§19 全局规则 |
| 卡片本体 | `overflow:hidden`，内容不得溢出卡外 | ui-foundation.css |

本节历史局部上限以 §19 的现行高度规则为准。新增滚动区域自动继承全局隐藏规则，不再维护节点选择器清单；不得通过改变 overflow 来实现视觉隐藏。

## 15. 按钮实现规格（实施细则）

### 15.1 头部（2026-11-20 校准：几何已被 §22 的 20px 中轴替代——序号/图标/名称统一 20px 中轴、图标 svg 17px、状态灯 6×6、标题行高 36px；本段保留按钮透明度与禁用色口径）

序号（19px/800 无底框）→ 节点图标 20×20（svg 17px）→ 标题 flex:1 省略号（15px/700）→ info 按钮 22×22 → 状态灯（现行 6×6，`node-visual-system.css`；旧文写 8×8）→ `action-float`（高 24px）内运行按钮 22×22（svg 16px，透明底 opacity .72，disabled `rgba(158,173,189,0.42)`）。JSX `Icon size` 必须与 CSS 强制值一致（node-icon 17、run 16、info 16）。

### 15.2 卡体内按钮（历史实现记录；现行规格见 §18.4）

| 角色 | 实现 | 规格 |
| --- | --- | --- |
| 主操作（生成/合成/安装等 busy 钮） | `.btn-generate`（唯一类） | 宽 100%、min-height **28px**、padding 5px 10px、r7、12px/600、底 `var(--card)` 描边 `var(--line)`；hover 青描边；disabled opacity .5 |
| 次操作/工具空态 | `.btn-ghost.small` | min-height 28px、padding 4px 10px、r7、11px/600 |
| 生图主钮布局 | `.gen-go` | image-gen 内 `margin-top:0; flex:0 0 auto`，其余 `margin-top:auto` 贴底 |
| 结果续接动作条 | `.node-media-next-actions` | 底部追加行 |

规则：一个节点内只允许一种主操作按钮材质（`.btn-generate`）；禁止节点私有覆盖（voice-design 的 42px/渐变/位移覆盖已删）；busy 态只做"文字替换 + disabled"，不加旋转动画。新按钮先查本表，没有就扩展本表，不得另起类名。

### 15.3 下拉与输入控件

唯一下拉实现为 `AppSelect`（Radix）：卡片内紧凑 **28px**，面板内标准 **36px**。调用保留 `<option>` 子元素 API；option value 会被字符串化，受控 `value` 必须同步 `String()`。**禁止新增原生 `<select`**（遗留仅 library 管理页，非节点 UI，迁移时一并替换）。文本输入/textarea 用 ui-foundation 的统一暗底与聚焦环。

## 16. 存在引用关系时，高度如何变化（实施细则）

> 本节仅保留旧实现记录，不得用于新增实现。引用布局、间距与增高以 [节点引用呈现规范](./NODE_REFERENCE_SPEC.md) 为准；其余高度规则以 §19 为准。旧版逐条换行、只增不减、860px 兜底及仅 image-gen 记录手动尺寸均已废止。

引用关系 = 上游连线进入本节点。视觉与高度按以下顺序自动变化，节点代码不介入：

1. **连线瞬间**：除 `image-crop`、`image-split`、`video`（专用输入面）外的节点，在 body 顶部插入 `ConnectedInputPreview`：每条连线一行 **28px** 输入条（gap 5px）；图片引用渲染 **48×36 白底缩略图**（与 §5 尺寸表一致）。
2. **端口变色**：已连接输入端口继承上游节点色，空闲端口用本节点色；产物溯源点继承生产者色。
3. **高度跳档**：新增输入行使 body 溢出 → fitHeight（`NodeCardView.tsx`）提升到最低可容纳档（260→320→380→440）。**只增不减**：断线后卡片保持当前档位，不回落（防输入抖动）。
4. **运行产生结果后**：单结果渲染 `.node-media` 预览（`object-fit:contain`，随档位撑高）；多结果渲染 `.media-result-grid`——自然高度参与跳档，超过 440 档容量后网格转内滚（860px 兜底）；底部追加续接动作条。
5. **循环节点**：进度条固定 6px 高，计入 fitHeight。
6. **手动尺寸优先**：`nodeHeightMode:'manual'`（仅 image-gen 经 resize 记录）时自动量高完全退出，溢出转内滚；历史尺寸迁移不得覆盖用户手动调整。

实现要求：节点 Body 不做任何自身高度管理（不设固定 height、不自行撑卡）；提供语义容器与内容，高度一律由 §5 档位机制裁决。

## 18. v1.2 统一节点呈现协议（2026-10-05；**几何与头部数值已被 §22/§23 替代**，本节保留交互归属与内容放置规则，阅读时几何一律以 §22/§23 为准）

### 18.1 审计结论与适用边界

用户截图及源码确认：文本/AI 身份图标采用 88px 容器，文件/媒体另有 76px，网址为 48px；按钮既有居中跟随正文又有底部布局；文件有说明而多个身份卡没有；网址用“双击打开设置”文字代替按钮；生成按钮存在被局部样式削弱为文字的情况。现有颜色验收只证明身份色正确，没有证明节点整体布局一致。

文档也有冲突：本文件旧 §5 与 §16 分别要求回落和只增不减；旧 §15 主按钮为 28px，其他记录为空态 32px；呈现规范旧 §6.2 保留 960px 上限；代码 `manualMax=720` 只是推荐值，生图自动高度还使用连续像素计算。这些均列入待整改，不能标注“已统一”。

本节适用于全部 28 个可创建节点和历史节点外壳，覆盖空态、编辑、有结果、缺输入、运行、失败、重开项目。统一的是结构、尺寸、说明和动作位置；图标图形、身份色与业务内容按节点职责变化。大图标仅用于空态/工作台入口，不要求在已有媒体预览上额外叠大图标。

### 18.2 唯一尺寸表与卡片骨架

所有数值以画布 100% 缩放的 CSS px 计；缩放后等比例测量。卡片高度指卡体，不含悬浮标题及其 6px 间隔。

| 项目              | 固定规则                                                 |
| ----------------- | -------------------------------------------------------- |
| 初始尺寸          | 340 × 260px；所有节点一致                                |
| 最低/最高卡体高度 | 260 / 440px，自动和手动均受约束                          |
| 自动高度档位      | 260 → 320 → 380 → 440px                                  |
| 标题行            | 卡外 28px 高，与卡顶间隔 6px；类型图标 17 × 17px         |
| 卡片圆角          | 12px                                                     |
| 正文水平内边距    | 左右各 12px；正文顶部 12px                               |
| 空态图标容器      | 72 × 72px，圆角 16px，1px 统一边框                       |
| 空态图标图形      | 32 × 32px，线宽 2px，容器内正中，100% 不透明             |
| 空态图标表面      | 统一主题卡面与轻量阴影；禁止节点私设渐变、蓝光或额外容器 |
| 空态名称          | 16px、600 字重、22px 行高；最多一行，超出省略            |
| 图标 → 名称       | 12px                                                     |
| 名称 → 功能说明   | 6px                                                      |

| 按钮到底边        | 按钮边框外缘距卡体底边严格 8px                           |
| 底部操作区        | 48px：顶部安全间隔 8px + 按钮 32px + 底部 8px            |

```text
[悬浮标题行：序号 / 类型图标 / 名称 / 说明入口 / 状态 / 次级运行]
                 与卡体相隔 6px
┌─────────────────────────────┐
│ 正文（可增长、可滚动）         │ ← 顶部与左右 12px
│ 空态：图标 → 名称 → 两行说明   │
│ 内容态：说明 → 输入 → 编辑/结果 │
├─────────────────────────────┤ ← 结构分区，不强制绘制横线
│       [图标  主操作文字]       │ ← 200×32px，水平居中
└─────────────────────────────┘ ← 按钮底边距 8px
```

底部操作区是卡片的固定布局行，不放进正文滚动容器，也不以 absolute 覆盖正文。空态身份组在正文可用区域中居中，功能说明槽高度固定，因此相同高度节点的图标、名称、说明和按钮基线一致。生成型节点用编辑区替代身份组，但共享相同底部操作区。

用户手动改变宽度时按钮宽度为 `min(200px, 可用正文宽度)`，禁止溢出。不能因按钮文字更长改变高度或节点宽度；文字省略，完整名称可通过提示及可访问名称获取。

### 18.3 每个节点都必须有功能说明

1. 每个节点声明一份用户可读的短说明，优先复用 `NodeTypeSpec.description`；详细能力/限制进入详情。不要在各 Body 再写同义但不同的文案。
2. 空态在名称下方展示；内容态在正文顶部以同一两行说明组件展示。内容态说明随正文滚动，底部按钮固定。
3. 说明只回答“处理什么、得到什么”或关键格式限制。最多两行，超出末尾省略；一行说明仍保留两行槽位，不让按钮和图标跳动。
4. 完整说明通过标题说明入口可点击/键盘打开；hover 提示作为补充。不得只依赖原生 `title` 让触屏或键盘用户无法读取。
5. “双击打开设置”“点击这里”“请拖入节点”属于操作教学，不作为功能说明。缺输入、失败、运行进度放独立状态位置；完整错误可以在详情读取，不能被两行说明规则截断后无处查看。
6. 名称使用主题主文字色，说明使用主题次级文字色；两种主题均验证可读性。禁止给说明整段染身份色。

建议文案：文本“输入或编辑文本，供下游节点使用。”；文件“导入文件；支持的文档可提取文字。”；网址“保存网址名称与链接，快速打开网页。”；AI 对话“结合输入内容与 AI 对话。”；AI 处理“按任务说明处理输入内容。”；图片“导入图片，供下游编辑或生成使用。”；生图“根据提示词和参考图片生成图像。”具体格式支持以真实文件处理能力为准，不编造支持格式。

### 18.4 所有节点共用主按钮

- 每张卡保留一个固定底部主动作：输入、导入、配置、打开工作台、生成、运行或查看结果；根据业务状态选择，不用“确定”“操作”等空泛名称。
- 全部采用真实 `<button type="button">`，左图标右文字；按钮有可见填充和描边，正常态即能识别。禁止纯文本、可点击 span、只能双击的伪按钮，禁止仅 hover 后显现。
- 统一表面：背景 `--card-hover`，描边 `--line`，文字 `--txt`；hover 使用公共交互高亮，focus-visible 使用独立清晰焦点环。禁止逐节点改变高度、宽度、圆角或使用私人渐变。
- 单击或 Enter/Space 触发；按钮事件不得同时触发卡片拖动、双击或两次执行。卡片双击可保留快捷方式，但不得作为唯一入口。
- 不可用时按钮仍保留同样位置、尺寸和图标，显示明确原因；运行中保留宽度，改为“生成中…”等状态文案并阻止重复提交。执行条件复用已有 readiness，不另写一套判断。
- 对象上的复制、替换、删除等操作仍放对象附近，不冒充第二个主动作。标题运行是次级快捷入口，与底部运行复用同一执行器和状态；数据处理类也需明确底部“运行处理”或“配置处理”主动作，替代旧“只放标题行”裁定。
- 若有结果预览，底部动作可保持“再次生成”或切为“打开工作台/查看结果”；具体状态映射在节点定义中明确，不能因渲染分支丢失操作区。

### 18.5 高度与滚动的完整规则

1. 所有节点创建尺寸从 260px 开始。仅含身份入口的空态组及动作区必须在此高度容纳，不因长说明或不同图标自动变高。直接展示配置表单、参数列表或预览的节点属于内容态，按实际控件自然高度进入自动档位；所有节点最低高度均为 260px。
2. 内容态需要的高度 = 正文自然高度（含说明、输入引用、间距）+ 正文上下留白 + 48px 操作区。取不小于需求的最小档位，上限 440px；禁止按固定 `rows`、当前带滚动的容器高度或单节点特殊公式推断。
3. 只有正文内容确实溢出才升档。到 440px 后正文 `min-height:0; overflow-y:auto`，操作区不滚动。禁止滚动整张卡、让主按钮滚走、正文盖住按钮或继续撑到 720/860/960px。
4. 默认只设一个纵向正文滚动区。长文本、代码等确需独立编辑器时由编辑器承担该段滚动，禁止同一区域出现两条嵌套纵向滚动条。Ctrl/Command + 滚轮保持画布缩放，普通滚轮沿现有正文优先路由处理。
5. 自动模式：新增输入、预览加载、执行结果就绪时重新量高；删除内容、移除结果或断线后允许回落。输入法组合期间及持续键入期间不自动缩小，失焦或明确删除操作结束后再回落，避免光标跳动。
6. 手动模式：任意节点手动拖高后记录 `nodeHeightMode:'manual'`，高度可在 260–440px 连续调整，内容变多只内滚，不覆盖用户选择。提供“恢复自动高度”入口。禁止仅生图具备手动模式。
7. 调整高度必须同步端口与连线锚点；不缩放正文文字及控件。临时 hover、tooltip、状态点与拖线候选不触发持久化高度变化。
8. 历史节点：原始数据保留，加载时仅对显示高度夹取到 260–440px，不改正文/媒体/配置；保存时才记录有效显示尺寸。迁移需保留原尺寸元数据用于回溯，并验证重开和撤销行为，不静默删除超出部分内容。

## 19. v1.3 按内容布局协议（2026-10-05；**几何数值已被 §22/§23 替代**，本节保留按内容布局协议、指针与滚动规则）

### 节点指针与输入编辑规则（2026-10-06）

空白、身份图标、名称、字段标题、说明与只读内容均属于节点表面：单击选中，按住拖动移动节点；不能因内层容器拦截指针而失效。Shift/平台多选修饰键、分组及撤销沿用画布机制。不得在整个表单或面板上使用事件拦截来保护其中几个控件。

卡片内的文本框、数字框与多行输入框首次单击只选中节点，并可以从该位置拖动节点；无拖动的双击才聚焦编辑。编辑后允许正常输入、选文及光标操作，失焦或 Escape 退出编辑，保留各节点原有保存/取消语义。键盘 Tab 可直接聚焦编辑，不强迫键盘用户双击。编辑态或外部弹窗的输入不能再次被卡片拖动接管。

下拉框、按钮、复选框、滑块、真实端口、裁剪画布等具备即时操作的控件保持自身交互；例外只作用于实际控件，不延伸到旁边标题和空白区域。JSON、结构数据、代码等只读正文保留双击进入编辑，媒体保留双击预览。工作台和弹窗即使通过 React portal 来自节点，也不参与画布拖动路由。

验收必须覆盖全部可创建节点的空态及关键内容态，实际点击图标/名称/标题/正文，并验证拖动后的坐标；不能只点击卡片左上角。所有可见输入框验证单击不聚焦、拖动、双击编辑、输入以及退出编辑，同时复验下拉框、媒体预览、裁剪和滚动。

### 文本编辑框与下拉外部关闭裁决（2026-11-02）

文本节点编辑态输入框为白底深字（背景 #ffffff、深色正文与光标），描边统一中性灰，不使用节点分类色；高度用 flex 填满正文剩余空间，底边落在底部操作条中保存按钮上方 8px 处。该填充高度属于版面自适应，不反算为自动高度的内容需求（沿用本节"空白 flex 空间不得反算为内容需求"），编辑期间高度只保持不回落，提交后按展示态内容重新计档。该规则仅作用于文本节点编辑框（`data-node-interactive="text-editor"`）；JSON 编辑框（`json-editor`）几何相同但材质不同，见下条；结构数据/代码等其他 `node-textarea` 使用方维持原样。

### JSON 节点空态与编辑态裁决（2026-11-02 第四批）

JSON 节点空态不再渲染 `code-toolbar`：工具栏只在有正文时出现，避免主按钮上方多出一条只有描边的空横线；主操作按钮经 portal 落在底部操作条，DOM 位置不影响呈现。
编辑态与文本节点同构：双击正文或底部按钮进入，编辑框填满正文，底边距底部「保存 JSON」按钮 8px；但**不使用文本节点的白底**（用户裁决：白色太突兀），改用视频描述框那种暗色字段——深底 + 8px 圆角，描边沿用本节「文本字段使用中性白色描边」。填充高度同样按名义高度（`NODE_UI.textEditor.naturalHeight`）参与自动高度测算，不随编辑逐档膨胀。

节点内下拉框（公共 `AppSelect`）在展开状态下，点击画布空白、其他节点、面板等任何外部位置必须立即关闭。画布与节点外壳会在 pointerdown 冒泡路径上 stopPropagation，下拉不得依赖 document 冒泡阶段的 dismiss 监听；公共实现须使用捕获阶段监听补齐外部关闭。验收覆盖：展开后点画布空白关闭、点另一节点关闭、点下拉内部不关闭、再次点触发器可关闭。

### 下拉框样式与生图选项行裁决（2026-11-02 第二批）

所有下拉框（`AppSelect` 触发器，含各节点与工作台内变体）聚焦、键盘聚焦及展开态一律不绘制选中边框、描边或光晕；展开状态由弹出的菜单本身承载，不另加边框提示。节点强调色聚焦描边规则仅适用于输入框/文本域/原生控件，不再覆盖下拉触发器。

- **分镜板**：空态提示语全部取消，只保留居中身份图标；"新增镜头"与"编辑 JSON"为两个均分底部主按钮；JSON 编辑态编辑框填满正文剩余空间（最小 220px）；默认尺寸 340×260 与其他节点一致，宽高随内容自适应增长且无上限（细则见分镜板专项规范）。
- **图标与颜色**：视频系六个节点图标按同一套线性语言区分（生成=播放卡片、素材=胶片条、截取=虚线裁切、抽帧=弹出帧、深度=层叠切片、白模=立体方块）；同分类内相邻节点颜色拉开区分度，具体色值以 `NODE_COLOR_SPEC.md` 为准。

AI 对话工作区的图片展示、预览、下载与分辨率设置遵守 [对话生图规范](./CHAT_IMAGE_SKILL_SPEC.md)。图片显示在对话消息内，不改变普通画布节点的默认尺寸；预览使用不透明背景，滚动条按公共规则隐藏。

白模视频的预设、质量、历史升级入口及特殊视觉验收遵循 [白模视频规范](./VIDEO_CLAY_RENDERING_STANDARD.md)，继续使用本节尺寸、间距、引用和隐藏滚动条规则。

### 全局滚动条与画布品牌入口（2026-10-05）

已提交文本/JSON 资产版本放到画布后，卡片是固定结果预览，显示 pinnedOutput 内容并提供“创建可编辑副本”；编辑副本沿普通文本/JSON 节点双击编辑规则，新版本须明确提交。图片/视频固定版本使用媒体预览与原生输出端口，不提供编辑副本；双击进入统一媒体查看，预览适应卡片空间。固定结果预览仍可从正文/空白单击选中及拖动，不在整个区域拦截指针。普通文本/JSON 文档的编辑行为保持不变。

所有应用内需要滚动的区域必须保留滚动能力，但始终隐藏滚动条轨道、滑块和箭头，横向、纵向及普通/悬停/聚焦状态均适用。范围包含文档根节点、画布、所有节点正文、文本框、代码/JSON 编辑器、侧栏、资产/节点库、弹窗、下拉列表、悬浮详情和未来新增区域。鼠标滚轮、触控板、键盘和触摸滚动沿用原路由；不能使用 `overflow:hidden` 或禁用指针来代替隐藏，不保留滚动条专属 gutter，也不创建自绘可见滑块。

公共实现唯一入口为 `assets/scrollbars.css`，在应用入口全局加载。旧版细滚动条、悬停显示及 AI 阅读滑块规则已废止；新区域无需登记专用选择器。验收同时确认计算样式隐藏和真实 scrollTop/scrollLeft 可变化，检查长内容末尾可达，不能只看截图。

所有画布左上角使用首页 Free Creation 的现有品牌图标，取消可见“项目”文字；保留“项目菜单”无障碍名称及项目管理操作，图标不得自行改色或另画一版。

本节取代 §18 中“每个节点必须有说明、单一按钮及固定说明槽”的要求。统一尺寸和间距，不强行统一业务结构。§18 的相关验收为历史记录，不再作为新增节点要求。

### 新增节点与验收

先声明空态、输入、引用、编辑/预览和实际操作，再接入公共外壳。复用 NodeIdentity、NodePrimaryButton 或 NodeFooterActions；无动作不创建占位按钮。按有/无引用、有/无资产及单/多/无操作分别验收，不再断言每张卡必须恰好一个按钮和一份说明。重点验证图片多操作回调、默认拆分无滚动、生图输入框填满、缩放后间距和历史高度模式。


### AI 处理结果呈现修正（2026-10-05）

成功结果直接在节点正文框显示完整文本、Markdown 原文或格式化 JSON，取消配置/查看结果切换按钮。短结果最低 260px，长结果自动增长到 440px，超出由公共正文滚动区承载；不截断内容。配置保留右侧面板入口。仅修改读取已有输出投影和呈现，不改变执行器、结果持久化及日志路径，无新增日志事件。浏览器门禁验证自动显示、完整末尾、440px 上限与可滚动。


### AI 结果阅读与格式（2026-10-05）

AI 处理卡片只显示输出，取消通用输入预览。点击正文选中节点并允许选文，选中后的滚轮使用公共正文外壳，边界不传递到画布；遵守全局滚动条隐藏规则，不呈现原生或自绘阅读滑块。Markdown 输出用已有 ReactMarkdown/GFM 渲染，禁用原始 HTML；纯文本保持换行和字面符号。仅改呈现与滚轮路由，不变更执行、持久化和请求路径，无新增日志事件。


### 初始设置入口与引用增长（2026-10-05 补充）

AI 处理尚无输出时显示“配置处理设置”底部按钮，打开现有右侧设置页；已有输出时按钮隐藏，直接显示结果。

自动高度必须把实际显示的引用视为新增内容：先计算无引用正文所需高度，最低按默认 260px，再加单排引用区 36px 和 8px 分隔间距，向上取 260/320/380/440 档。例如默认 260px 正文加引用，应升到 320px，不能用缩小输入框来吞掉引用。整个引用区只显示一排，多项溢出通过 +N 浮层查看，不继续增加卡片高度；删除全部引用后按自动高度规则回落，手动模式保留用户尺寸。

此规则仅计算真实可见引用，不因有连线就盲目增加高度。AI 处理输入保持不显示；裁剪/拆分以主预览承载上游素材，不再重复引用；这些场景不额外增加引用高度。

### 侧边面板材质

所有侧边面板（节点详情、资产、节点库、历史、运行、AI 对话及资源详情）必须使用完全不透明的背景。深色与浅色主题均不得使用带透明度的背景渐变、整体透明度或背景模糊；面板打开后不得透出画布内容。阴影和边框可保留透明色，不影响面板背景的不透明要求。

### 视频缩略预览与高度增长原因

视频资产及已有视频结果的节点默认保持 260px 高度。导入、替换或选择视频不会因为视频的像素尺寸、比例或缩略预览而增长节点高度；预览保持比例并适应剩余空间，双击打开完整播放器。输入框或长文本结果确实需要更多空间、顶部真实引用新增内容时，才按档增长并封顶滚动。媒体缩略图、空白空间和装饰不属于高度增长原因。手动高度继续尊重用户选择。

高度 32px 的按钮按可用正文宽度分配，图标入口沿用媒体文件操作的 32px 方形材质，分隔线、hover/active/
focus-visible 与深浅主题取同一套值。材质只在 `ui-surfaces.css` 的 `.media-action-toolbar` /
`.media-action-button` / `.media-action-divider` 定义一份，节点（含 `video.tsx`）不得再写私有操作条覆盖；
`app.css` 中退役的 `.node-video-action-group` 等规则由 `test/node-ui-decisions.test.ts` 守住。

工具栏采用统一线性图标：水平/垂直分布为等距矩形，组合为完整边界中的多个元素，拆分为断开的边界与分离元素，流程模板为连接步骤，节点库为叠放卡片。任务状态显示运行/等待图标与数量，并保留悬停文字及无障碍名称。

### 视频生成卡片的三段配置（2026-11-02）

视频生成节点只保留「生成配置 / 视频描述 / 输出参数」三个分组框，生成面板自身不再套外框：`border`、圆角、

`test/node-ui-decisions.test.ts` 守住这三条，并禁止让整条规则失效的孤儿选择器。

### 引用位置与详情预览

所有引用遵守 [节点引用呈现规范 v1.0](./NODE_REFERENCE_SPEC.md)：整个区域只显示一排、统一高 36px，位于正文最顶部，沿用 12px 左右内边距，下方间距 8px。文字单行省略，多项超宽显示 +N，通过统一悬浮详情查看完整内容。类型格式、来源、媒体预览、键盘交互及迁移验收以该文档为准；无引用时不占位。

声音调整节点直接展示按倍率/按目标秒数、对应数值及声量输入，底部保存参数；不再展示无操作价值的倍速摘要和右侧设置提示。音色设计默认连接点为音色档案 out-json，可接 MiniMax 语音合成 in-voice；试听音频仍保留独立输出，朗读文本接 in-text，不按文本内容猜测音色 ID。

数据处理不显示无连接的引用状态。数据类型和处理方式均有标题，类型下拉不占满整行；JSON 输入（任意、对象或数组固定值）可提取字段，文本输入使用字符串模板。新节点默认提取字段，显式保存的旧原样传递配置保留。输出区呈现真实运行结果，示例只放在输入占位提示中。

### 任务浮层与拖线候选

拖线预览与空白落点菜单的临时引线必须直接从真实节点端口延伸，不叠加起点圆点、黑色描边或起点装饰。分类菜单图标与文字整体左对齐，图标槽固定 20px，文字紧随其后，间距 8px；不得使用 space-between 把二者推到两端。

顶部任务状态及其浮层必须高于画布节点和画布工具栏，展开时可直接编辑任务额度。拖线候选兼容多个端口类型时，优先沿用目标已有兼容连接点，否则使用声明顺序中的默认兼容连接点；不得仅因上游为任意类型就展开全部可兼容类型。真实已连接端口、用户动态端口及明确的单类型候选仍按端口协议展示。

### 分镜板特殊尺寸规则

分镜板为 JSON 表格，默认 340×300（与 §22 standard 默认一致，`node-ui-tokens.STORYBOARD_UI`；2026-11-20 校准：旧文曾写 960×420 与 340×260，以实现值与本条为准），宽高随内容自适应增长；自动随列数、行高展开，手动调整后保留尺寸。详见 docs/STORYBOARD_TABLE_STANDARD.md。输入输出示例须在说明弹窗呈现。

单选节点必须提供真实可拖拽的尺寸控件，不得仅保留程序化 `onResize` 而关闭用户操作入口。普通节点手动高度边界以 §22 档位为准；分镜板不受此上限约束。多选继续使用现有组合操作，禁止通过组合缩放偷偷改变组内节点尺寸。验收使用真实鼠标拖拽，并检查手动模式和快照恢复。

尺寸控件的透明命中区不得遮挡浮动标题中的说明、状态和运行按钮；缩小画布后也必须保持按钮可点击。顶部边和角避让标题，用户通过侧边与底部控件调整尺寸。

### 审查整改补充（2026-10-06）

画布顶栏在画布之上、模态弹窗及全屏工作区之下；任务浮层高于画布的规则不意味着顶栏覆盖模态工作区。自动整理使用实际节点尺寸，自动取景给固定分类菜单及卡片外围端口留出安全边距；不能让“整理画布”后关键端口落到固定菜单下面。明确拖拽落点仍尊重用户位置。

数据处理使用真实连线值优先于固定值的有效输入校验。字段提取只接受 JSON，空路径、不存在路径或文本输入必须在运行前显示具体原因并阻止无效手动执行；切换字符串模板由用户决定，不静默修改模式。执行器须复用相同校验，不能只在卡片拦截。

顶栏保持 44px 单行，项目名称不足空间时截断，不在 1180px 以下自动增加标题行。顶部、左侧分类及底部工具图标统一 16px；标题/主操作文字 12px、分类文字 11px、底部标签 10px，品牌图标 28×22px。工具区不随画布缩放变化，节点内图标沿用节点规范。整理画布按左侧菜单、上方浮动节点标题和底部工具栏分别预留空间，不得把左侧菜单宽度作为上下留白；单个普通节点在可容纳时使用 100% 取景，多节点按剩余空间适配，最大自动缩放为 100%。此规则不改变用户手动缩放。

## 20. v1.5 卡片统一规范（2026-11-02）

用户裁决：节点卡片回到「一张卡 + 平面分组 + 中性灰 + 无装饰图标 + 底部固定动作」。本节与 §18、§19 的私有卡片皮肤冲突时以本节为准；§19 的指针、滚动、内容布局规则继续有效。

### 20.1 卡片与边框

- 所有节点卡面统一 `var(--node-surface)`（深色 `#20242a`，浅色 `#ffffff`），不得按节点类型改卡面底色或叠加径向渐变。**2026-11-06 起深色卡面改为 §23 的 `#1b202b→#151922` 纵向渐变，本条材质数值由 §23 覆盖。**
- 卡体外框统一 `1px solid var(--node-edge)`；输入/下拉/按钮描边统一 `var(--node-edge-strong)`；hover 用 `var(--node-edge-hover)`。禁止使用节点分类色作为卡片、分区、输入框或按钮的描边/底色/发光。**2026-11-06 起深色描边取值为 `--node-edge: #252b36`、`--node-edge-hover/strong: #333b48`，见 §23。**
- 卡内分组**不描边、不填底色、不加渐变**；只有输入框、下拉、媒体预览、结果卡可以有 1px 中性灰边框。
- 节点分类色只允许出现在：卡外标题栏类型图标、左上/右上类型切角、端口圆点与连线、空态中心身份图标、运行状态与危险操作。

### 20.2 标题与分隔线
