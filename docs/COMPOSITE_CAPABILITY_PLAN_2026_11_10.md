# 组合节点能力化实施计划

日期 2026-11-10。核查基线 `544ac25`。状态为待实施方案。

面向产品负责人及接手开发的 Agent。本文依据当前源码与交付记录制定，本轮只做静态核查和文档编制，没有重新执行历史测试。以下新增类型、接口、数据结构和阶段均为建议设计，不能当作现有能力使用。

## 1. 最终产品目标

用户将调试好的多个节点保存为一个可调用的组合节点。组合节点有名称、明确的输入输出和固定版本，既能在画布连线运行，也能由外部 Agent 通过 CLI/MCP 查找并调用，还能作为另一个组合的内部节点。内部流程始终可以打开查看、编辑草稿和诊断。

贯穿验收的例子是「人物设计」。输入「人物要求」文本，内部依次经过文本节点、AI 处理、生图节点，对外输出图片。Agent 查找「人物设计」，读取契约，提交人物要求，等待任务完成，拿到图片引用。用户无需了解内部节点 ID，也无需手工填入内部文本节点。

组合能力的扩展来自复用和嵌套。每次执行仍受资源、嵌套深度、节点数量、模型配额和人工门禁约束。发布成功表示契约及结构有效，真实模型运行是否成功由运行回执决定。

最终交付同时覆盖以下用户路径。

1. 框选节点，保存为组合，声明输入输出，验证后发布。
2. 从节点库拖入一个组合节点，直接与基础节点连接。
3. 点击运行，按输入类型补齐缺项，沿内部连线得到最终输出。
4. 将组合与其他节点再次组合，发布更复杂的能力。
5. Agent 按名称发现组合，用稳定 ID 和固定版本调用，查询结果或补输入继续。
6. 出错后定位内部节点，安全重试；应用重启后依据持久记录恢复或明确提示需要核对。

## 3. 核心设计决策

### 3.1 三个对象各有职责

| 对象 | 保存内容 | 生命周期 |
| --- | --- | --- |
| 组合定义 | 内部语义图、公开端口、映射、固定配置和依赖 | 草稿可改，已发布版本不可变 |
| 组合实例 | 组合 ID、固定版本、契约摘要、实例输入配置和画布位置 | 随项目保存，允许显式升级 |
| 组合运行 | 版本快照、有效输入、父子调用、进度、等待项、产物和错误 | 独立持久化，支持查询与受控恢复 |

画布 `props.config` 保存实例固定配置，`props.text` 保存适用的用户正文，运行事实和结果按项目现有 meta/账本协议保存。不要把新运行结果写回发布模板。

### 3.2 一个节点类型承载多种组合

新增静态 `composite` 类型并完成 Active 类型、Spec、自注册 executor 和 `projectOutputs`。不同组合通过固定 manifest 派生实例端口，不为每个用户保存的组合增加一个 TypeScript 静态类型。

端口解析、连线校验、输入表单、输出投影和 Agent Schema 都必须来自同一份已验证契约。`node.type.get` 返回通用类型说明，组合详情接口返回具体组合的实例契约。

### 3.3 第一阶段沿用桌面执行宿主

现有运行器依赖 renderer、注册表和画布形状。先抽出“给定语义图、运行上下文与输入，执行并返回端口输出”的公共服务，由桌面宿主管理执行。执行器继续使用现有 gateway、调度器、模型配置、媒体落盘和诊断入口。

内部图在组合编辑器中仍以画布表示。执行时从固定版本建立隔离的运行实例，不能把临时内部节点写入用户当前画布后再删除。公共运行服务负责隔离 ID、状态和输出，渲染仅订阅其状态。

P0 必须验证最小的 text → ai-process → image-gen 链能否通过该适配完成。若共享执行器仍有必须写全局 editor 的副作用，先改造受影响宿主接口并测试，再开放组合运行。第一版的契约明确要求桌面宿主可用；纯后台运行作为独立后续目标。

### 3.4 旧模板与新组合共存

旧条目保留原有展开方式。新增“保存为组合节点”和“转换为组合节点”，转换生成草稿，用户确认边界后发布。发布过程不得从节点名称猜测端口，也不得在损坏连线被跳过后声称转换成功。

## 4. 组合契约与发布规则

### 4.1 建议 manifest 字段

| 字段 | 含义 |
| --- | --- |
| `schemaVersion` | manifest 格式版本 |
| `capabilityId` | 稳定组合身份，重命名不改变 |
| `version` | 不可变发布版本，内部建议 SemVer |
| `name`、`description`、`tags` | 名称、简短用途和发现标签 |
| `inputs` | 公开输入 ID、标题、类型/Schema、必填性、基数、默认值、目标映射 |
| `outputs` | 公开输出 ID、标题、类型/Schema、基数、内部来源映射 |
| `graph` | 使用稳定内部 ID 的节点、显式端口连线和编辑布局 |
| `dependencies` | 内部节点契约版本、嵌套组合固定版本、固定资源引用及模型能力需求 |
| `executionPolicy` | 超时、深度及展开预算、输入等待、重试和已有人工门禁要求 |
| `contentHash` | 规范化内容摘要，用于完整性验证 |

组合格式版本、组合发布版本、基础节点 `contractVersion` 分别管理。UI 可把 `1.0.0` 显示为“1.0 版本”，接口和存储保留完整版本。日期沿用年月日时分秒。

### 4.2 边界提取

1. 从选区内节点、内部连线和跨边界连线生成候选契约。
2. 外部进入选区的边，提出公开输入及内部目标映射。缺少来源的必需输入也列为候选。
3. 选区内节点连向外部的边提出公开输出。用户可明确公开其他结果端口，包括内部有下游的中间结果。
4. 未被引用的输出可供选择，不能把所有悬空端口强制公开。发布至少有一个明确业务输出。
5. 单个公开输入可以广播给多个兼容目标。第一版每个公开输出绑定一个内部输出，聚合使用显式节点。
6. 映射必须保存稳定内部节点 ID 和端口 ID。数组下标只用于旧模板迁移，不作为新契约长期身份。
7. 已有固定文本、媒体或配置与公开输入冲突时，保存界面要求明确选择固定来源或公开来源。

输入优先级建议为外部连线、显式本次输入、实例默认值、组合默认值。外部连线与本次输入同时指定同一单值端口时返回冲突，用户明确断开或选择来源后继续，避免静默覆盖。多值端口采用已声明的顺序和基数，不能自动合并两种来源。

### 4.3 发布校验

校验内部类型/契约可用、映射存在、Schema 兼容、基数及互斥条件有效、输出可到达、必填来源已满足。Schema 兼容先支持项目已有可判定规则，遇到无法证明兼容的复杂 Schema 返回明确问题。

普通数据边保持 DAG，循环使用既有循环节点语义。嵌套依赖图禁止直接或间接递归，检查展开后的预算，防止只统计表面节点数量。

未支持 Agent 调度或需要人工工作台操作的内部节点必须在组合能力描述中明确标记。首个自动运行版本只允许通过完整适配验收的节点。受支持但需要人工门禁的组合应报告“需要人工参与”，不能静默绕过审核。

模型依赖记录能力和配置引用，凭据仍来自当前本机配置。发布和导入校验固定媒体依赖是否可用。测试运行记录单独保存，发布不自动触发付费模型调用。

### 4.4 人物设计契约示意

```json
{
  "capabilityId": "character-design",
  "version": "1.0.0",
  "name": "人物设计",
  "inputs": [{
    "id": "requirements",
    "label": "人物要求",
    "type": "text",
    "required": true,
    "targets": [{ "nodeId": "source-text", "portId": "in-text" }]
  }],
  "outputs": [{
    "id": "portrait",
    "label": "人物设计图",
    "type": "image",
    "source": { "nodeId": "generate-image", "portId": "out-image" }
  }]
}
```

此例只展示边界字段。实际 manifest 必须包含内部图、Schema、基数和依赖。实施时从真实节点 Spec 校验端口 ID，不能复制示例替代校验。若生图节点返回多张图片，公开输出须声明多值，或由显式选择节点产生一张。

## 5. 执行、补输入和恢复

### 5.1 正常调用

发现组合 → 解析固定版本 → 验证宿主/依赖/输入 → 创建持久调用记录 → 执行隔离内部图 → 校验并固定公开输出 → 完成父调用。

各内部节点继续调用公共 executor。结果直接沿声明端口传递，组合对外投影正式产物引用。产物展示可以使用已有结果组件，但下游数据来源必须是本次运行的真实输出，不能依赖新建结果卡片或旧 meta。

运行记录至少关联 `rootRunId`、父调用、组合实例、内部节点执行、固定版本和尝试次数。主进程拥有权威状态；GUI 和外部接口读取同一事实。

### 5.2 按类型补输入

| 输入类型 | GUI 控件 | CLI/MCP 值 |
| --- | --- | --- |
| 文本/Markdown | 多行输入 | 对应文本值 |
| JSON | 结构化编辑及 Schema 错误 | 符合 Schema 的 JSON |
| 图片/视频/音频/文件 | 选择项目素材或通过正式入口上传，显示预览 | 当前项目有效媒体 ID |
| 数字/布尔/枚举 | 由具体 Schema 派生的数字、开关、单选控件 | 当前值协议允许的 JSON 值 |
| 多值 | 可排序列表、增删和数量校验 | 有序列表，基数校验 |

当前值系统未独立声明的类型要通过明确 Schema 适配，不能仅增加 UI 控件而让底层无法消费。

能预检的缺项在启动前合并显示。运行过程中实际发现缺项时保存 `waiting-input` 和结构化输入请求，暂停依赖该输入的执行，保留已成功产物。空值允许性由 Schema 决定；上游执行失败应返回失败，不能一律转成补输入。

输入请求包含 `requestId`、修订、字段 ID、类型、必填性和内部目标路径。补交值必须校验请求仍有效、任务未取消、媒体属于当前项目。GUI 关闭弹窗保留等待，可在运行中心重新打开；“取消运行”才进入取消流程。

CLI/MCP 返回等待状态和缺项描述，Agent 可提交输入并继续。涉及人工授权或审核的等待沿用原有门禁，不让普通输入提交冒充批准。

### 5.3 状态与兼容

目标内部状态包括 accepted、running、waiting-input、completed、failed、cancel-requested、cancelled、interrupted/unknown。具体命名由现有账本映射确定，失败与未知必须区分。

现有外部状态枚举没有 waiting-input。新增接口应使用明确版本化 Schema，或通过经过兼容评估的可选等待详情扩展；不能直接给严格旧客户端返回它无法解析的枚举。恢复及补输入操作引用同一个运行 ID。

### 5.4 并发、重试和付费请求

每个调用持有独立图快照和输入，内部 ID 加调用作用域。两个实例并发运行不能覆盖彼此的正文、状态或结果。修改画布、升级组合及删除库条目不能修改已开始调用的快照。

外部调用携带幂等键。同项目、同键、同版本及有效输入返回同一调用，键相同但请求不同则冲突。恢复时复用已提交且有效的节点产物，只重新执行需要的节点。

模型调用的供应商回执、任务号和落盘状态写入权威记录。网络超时或进程中断后，先查任务回执；无法确认是否已收费/执行时进入 unknown 并提示核对，禁止自动重发。对不支持查询或幂等的供应商，不能承诺严格一次执行。

取消向所有正在运行的子调用传播，停止新任务派发。无法取消的远端任务晚到结果应登记，不能使已取消父调用变成成功。重试和恢复受总超时、预算和重试策略约束。

### 5.5 持久化与重启

沿用现有 SQLite 和运行账本边界，新增组合定义/版本/依赖及调用明细存储。具体表名由实施阶段决定，避免另建同等权威的执行系统。

必须落盘版本快照、有效输入或受控输入引用、等待请求、已完成节点输出、供应商回执及恢复判断。敏感正文进入受控业务存储，不进入日志，使用项目删除和数据清理生命周期。

重启后先恢复等待输入和已完成产物，再核对在途远端任务。不能恢复的执行明确标记 interrupted/unknown，提供受控重试。补输入前或恢复前再次验证媒体引用和依赖完整性。

运行结束、节点输出和产物引用的提交保持一致。媒体先暂存并校验，再在事务中提交引用，失败回滚并清理暂存文件。引用计数/依赖检查覆盖项目、已发布组合和未清理运行记录。

## 6. 版本、嵌套与迁移

发布版本不可修改，更新从旧版复制草稿。画布实例固定版本，库发布新版本后只提示可升级。升级先比较端口 ID、Schema、基数、默认值及内部依赖，预览对现有连线的影响，经用户操作才生效，支持撤销。

删除必填端口、改变类型或收紧输入约束视为破坏性变化。增加可选输入也必须检查下游 Schema 兼容；不能仅靠名称或版本号判断兼容。运行期间实例升级影响后续调用。

嵌套组合同样固定版本，发布时锁定传递依赖并生成摘要。已有循环节点与组合嵌套组合时需要单独验收取消、输出收集和预算。复杂控制关系未适配前在发布校验阶段给出具体不支持原因。

已被引用的版本通过归档退出发现列表，继续供既有实例使用。彻底删除须通过引用检查。跨项目导出携带必要定义、固定版本和受控媒体依赖，导入重映射媒体与项目 ID，校验摘要，并剥离凭据。相同 ID/版本但不同摘要必须报告冲突。

旧模板升级采用可重复的迁移和事务。迁移无法恢复的边列出来源、目标及原因，保留旧条目供修复。不得自动把缺少契约的全部历史条目标为可运行组合。

建议初始安全预算沿用当前模板 40 节点、120 连线的约束，并在 P0 明确外部执行 50 节点限制的作用域。嵌套深度可先设 5 层，展开总预算另行压测确定。这些是工程默认建议，最终值需记录测试依据，并由公共策略统一供 GUI/CLI/MCP 使用。

## 7. Agent 接口与一致性

建议新增 `capability.*` 业务命名空间，具体名字在 P0 与现有 registry 对齐。它通过现有本地接入注册和公共服务实现。

| 建议操作 | 行为 |
| --- | --- |
| `capability.search` | 名称/标签/输入输出类型查询，返回稳定 ID、版本和支持状态 |
| `capability.get` | 固定版本的用途、输入输出 Schema、依赖及执行限制 |
| `capability.draft.create/update` | 由选区或版本创建草稿并修改边界，带预期修订 |
| `capability.validate` | 返回结构化问题与对应节点/端口 |
| `capability.publish` | 事务发布不可变版本，防止重复提交及修订冲突 |
| `capability.insert` | 在目标项目插入一个组合实例 |
| `capability.runPlan/run` | 解析依赖与输入，创建任务并返回运行 ID |
| `capability.input.submit` | 按请求 ID/修订补值并继续 |
| `capability.instance.upgrade` | 校验并升级指定实例，处理连线影响 |
| `capability.archive` | 隐藏后续发现入口，保留被引用版本 |

任务查询、等待、取消、产物读取优先扩展既有 `run.get/run.wait/run.cancel/output.get`，确有兼容需求才增加版本化接口。发布、重命名、归档、转换、导入导出及升级等所有 GUI 业务动作都要有 CLI/MCP 对等操作。

Agent 按名称搜索可能获得多个候选，必须选定稳定 ID 和版本再执行，禁止静默运行第一个同名条目。对发现结果返回支持等级，例如自动可调用、需要人工参与、依赖缺失。接入保持现有本地凭据、范围、项目占用和预期修订检查。

采用固定的发现/详情/运行工具即可支持动态组合。首版无需为每个组合向 MCP 注册一个独立工具，避免工具列表随库增长失控。动态能力通过契约内容体现。

外部 Agent 与画布内 Agent 分别验收。画布 Agent 需新增 composite target adapter，进入现有命令、固定输入、审核和回执流程；不能因为外部调用成功就宣称内部 Agent 协同完成。

## 8. UI 设计任务

实施时调用 Stitch 输出关键界面，并映射为项目已有组件与 token。设计范围为保存/发布、组合卡片、按类型补输入、内部运行详情和版本升级。Stitch 不可用时记录阻塞或回退依据，不能声称已调用。

| 界面 | 规则 |
| --- | --- |
| 保存/发布弹窗 | 名称、公开输入、公开输出和校验结果分区；智能提出候选，用户确认映射 |
| 组合节点卡片 | 与基础节点统一标题/图标/动作尺寸，输入在左输出在右，正文突出用途和产物 |
| 节点库 | 名称及类型预览为主，支持单节点拖入、运行、编辑草稿及版本详情 |
| 补输入弹窗 | 从契约派生控件，只展示当前缺项和错误，统一底部运行/继续操作 |
| 内部详情 | 打开同一份组合画布，运行时定位实际内部失败节点和等待项 |
| 版本升级 | 展示输入输出及连线变化，确认后升级，不在运行中切换版本 |

视觉使用现有自由画布的深色底和克制主题色。侧边层沿用画布背景、轻阴影及顶部切分线，标题、图标、关闭按钮在同一中线上。选中底色沿用节点背景；图标无多余底块；正文移除重复解释。

沿用 `NODE_UI_STANDARD.md`、`NODE_COLOR_SPEC.md` 和 `NODE_REFERENCE_SPEC.md`。新类型按流程分类登记颜色，复用公共节点组件。滚动区域保持可滚动且隐藏滚动条。节点单击选中、拖动和双击编辑按公共协议执行。下拉菜单自适应视口，底部控件向上展开，避免截图中曾出现的屏外菜单。

## 9. 分阶段实施与完成门槛

每个阶段同时交付公共契约、GUI、CLI、MCP、日志和测试。阶段内技术基础可先合入未开放模块，但不得发布只支持某一个入口的业务动作。

| 阶段 | 实施内容 | 可验收结果 | 依赖 |
| --- | --- | --- | --- |
| P0 基线与执行可行性 | 复核当前 HEAD、规范、旧模板、宿主耦合、类型/基数和预算；最小内部执行原型；列出迁移范围 | 确定单一执行服务边界、状态兼容策略、首批可嵌入类型，记录事实和测试基线 | 无 |
| P1 契约与发布 | manifest、稳定内部 ID、数据库迁移、边界编辑、校验、版本发布/查询及归档 | 用户和 Agent 都能发布/读取人物设计 1.0；损坏映射无法发布；旧模板可继续使用 | P0 |
| P2 可运行组合最小闭环 | composite Spec/executor/投影、隔离内部执行、插入/运行、预检补输入、外部任务接口 | 画布只插入一个组合；输入人物要求后输出图片；Agent 按名称查到同能力并取得结果 | P1 |
| P3 等待输入与可靠恢复 | 持久等待、补交、父子运行、取消、幂等、并发隔离、供应商核对、重启恢复 | 运行中缺项可继续；重启保留等待和已完成结果；未知请求不会自动重复收费 | P2 |
| P4 嵌套与生命周期 | 组合内组合、依赖锁定、深度/展开预算、实例升级、导入导出和引用保护 | 人物设计组合接图片裁剪后再保存；双层运行、升级和跨项目迁移均可验证 | P3 |
| P5 画布 Agent 与整体交付 | composite target adapter、真实命令回执、人工门禁、能力发现及最终 UI 回归 | 内部 Agent 和外部 Agent 都能调用；三入口结果及错误一致；构建并加载可验证 UI | P4 |

P2 是可演示的最小闭环，P5 完成后才达到本文定义的完整目标。完整计划默认包含 P0–P5。具体工期在 P0 核实运行器改造规模后估算，按节点类型适配和恢复边界列工作量，避免用未经核实的天数承诺。

## 10. 验收矩阵

| 场景 | 通过条件 |
| --- | --- |
| 人物设计 GUI | 一个组合实例接收文本，内部 AI 结果传递给生图，图片输出可连接下游 |
| 人物设计 CLI/MCP | 名称发现、固定版本执行、查询和图片获取成功，结果结构与 GUI 一致 |
| 各类输入 | 文本、JSON、图片、视频、音频、文件、枚举和多值按 Schema 校验，错误可定位字段 |
| 缺项与互斥 | 必填、默认值、互斥组、单值冲突、多值顺序和运行中空输出按契约处理 |
| 旧模板转换 | 正常条目可转换；损坏连线阻断发布；取消不破坏原条目 |
| 输入隔离 | 连续或并发提交不同人物要求，内部文本、状态和图片各自归属正确 |
| 嵌套 | 两层组合输出可继续连接，递归与预算超限明确拒绝 |
| 版本 | 发布新版不改变旧实例；不兼容升级指出受影响连线；归档不破坏已引用版本 |
| 持久等待 | 关闭弹窗/应用后重新打开，可补原请求继续，重复补交或过期修订被拒绝 |
| 取消 | 停止父调用后不派发新子任务，晚到结果不能把父调用改成成功 |
| 重试 | 已成功上游复用有效结果；幂等调用不创建第二个任务；未知供应商状态不自动重发 |
| 故障注入 | 请求提交前后、媒体落盘前后、事务提交前后崩溃均可核对状态，无假成功 |
| 导出导入 | 新项目中版本/依赖/媒体完整，引用重映射，包内无凭据 |
| Agent 门禁 | 人工审核无法用普通输入提交绕过，内部调用保留父子命令和产物证据 |
| UI | 无屏外菜单、标题对齐、弹窗稳定、节点拖动选中有效、单节点预览与内部详情一致 |
| 日志 | 可沿一次调用定位内部失败，日志无正文/提示词/回复/密钥，日志失败不改变业务结果 |

新增测试应覆盖隔离、递归、恢复、幂等、迁移等具体回归风险。模型执行使用可控 mock 验证调度，再对已授权配置做最小真实链路验收，记录真实模型/账户的未测边界，不能用 mock 替代真实生成结论。

按仓库规范运行类型检查、相关测试、`npm run guard:agent-parity`、`npm run verify:agent-access`、`npm run verify:logging`、节点合规及完整 `npm run verify`。历史交付曾记录全量校验停在许可证脚本 lint；接手时重新核实，不预先认定该问题仍存在，也不能省略本次检查。

## 11. 交付记录与工程约束

开工前完整阅读 `AGENTS.md`、`NODE_CONTRACT_SPEC.md`、`LOGGING_SPEC.md`、`AGENT_PARITY_SPEC.md`、`AGENT_ACCESS_SPEC.md` 及相关节点 UI/协同规范。以当前有效规范和源码为准，发现旧文档与新代码矛盾要记录并修正文档口径。

每包提交应包含功能代码、契约及兼容说明、数据库迁移、对应测试、三入口操作台账、日志覆盖和阶段验收证据。受保护源码按仓库流程更新契约快照、`docs/local-agent-access/change-impact.json` 和能力矩阵，并说明实际影响。

业务开始、等待、补输入、恢复及终态复用现有诊断机制，关联根运行与子调用。不得把日志当成恢复数据库，不得记录原始输入或输出正文。同一终态只记录一次。

每阶段交付列出已实现、已验证、未支持和阻塞。最终提供实际截图、操作路径、CLI/MCP 调用记录、运行/产物 ID、构建版本和远程提交信息。性能数据用实测值，真实调用失败据实报告。

本轮为规划文档修改，日志影响和接入业务影响均不涉及。本轮未实施上述新增能力，也未重跑历史功能测试。
