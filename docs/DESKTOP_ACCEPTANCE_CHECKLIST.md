# Canvas Studio 桌面端验收清单

> 此清单补足自动化测试无法覆盖的 Electron / tldraw 实际交互。每次发布候选版本都应在干净本机目录完成一次，并记录版本、日期、结果和失败截图。

## A. 画布与本地持久化

- [ ] 创建文本、图片资产、生图、视频、音频、处理、JSON、结构数据、代码、分镜、迭代和导演台节点；双击标题/正文编辑，单击选中并拖动。
- [ ] 创建真实端口连线；尝试不兼容类型、第二条单值输入和循环连线，确认均被拒绝并给出原因。
- [ ] 框选两个节点分组，移动其中一项时组内节点随组移动；撤销/重做、右键菜单、保存重开均正常。
- [ ] 保存模板、重启应用、套用模板；保存/回溯/删除历史版本后重启，确认数据仍按项目隔离。

## B. 供应商与运行记录

- [ ] 编辑已有供应商时 API Key 留空并保存，重启后确认模型仍可用；界面、导出项目和运行记录均不显示 Key。
- [ ] 对话节点发送消息，确认卡片渲染 Markdown、`out-markdown` 可连线、右侧运行面板有成功/失败记录。
- [ ] 生成图片两次，切换当前候选；从资产中心定位来源节点和精确运行记录。
- [ ] 让一次生成失败，确认失败项不覆盖旧媒体；从运行中心“重试节点”后记录新增且旧产物来源不变。

## C. 批量与媒体

- [ ] 用“分镜→批量生图”模板以已配置模型完成 20 项，至少执行一次暂停、继续和只重跑失败项。
- [ ] 以 100 项进行一次串行压力回归，记录总耗时、失败数量和恢复结果；不得开启并发。
- [ ] 图片、视频、音频各生成或导入一次；重复生成后结果集合、当前选择、来源、运行 ID 与下游端口一致。
- [ ] 导入中强制退出后重新启动，确认残留 `.importing` 只会移入项目 `.recovery` 目录并被日志报告，绝不删除正式项目或媒体。

## D. 性能记录

- [ ] 导入 100 / 500 / 1000 节点演示包，记录画布首次渲染和连续拖动体验。
- [ ] 执行 `npm run benchmark:canvas`，保存结果；任何明显退化必须在发布前说明或修复。
