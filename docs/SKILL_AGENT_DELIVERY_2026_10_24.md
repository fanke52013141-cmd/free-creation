## 用户路径

对话工作区的「对话设置」内直接提供同一套 Agent 技能控件；上传和绑定不离开当前对话，不丢未发送草稿。

打开 AI 对话或 AI 处理节点的右侧设置，在「Agent 技能」上传 `.md` / `.json`，然后勾选启用。也可直接选择内置「内容分析」「内容整理」。一次绑定最多 8 个技能，正文与参考资源总配置最多 256 KiB；执行步数默认 6，允许 1–12。

安装进入现有 SQLite `flow_skill_versions`，同 ID/版本不可覆盖；已有 Flow Agent 的目录也能看到安装的包。对话与处理节点将选中包的完整内容固定在 `props.config.agent`，不随全局库升级静默改变。对话消息仍沿用原 `props.text` 会话格式；切换/新增会话不覆盖技能配置。项目保存、克隆和导出复用已有快照路径，无新数据库和第二份拓扑。

输入 → 按 Skill 自动处理 → 检查输出 → 有限修正 → 正式输出。运行中没有新增人工确认/继续入口。未绑定技能的旧节点保持原执行行为。运行器继续负责节点开始、取消、失败和下游阻断；不以中间协议回复作为正式结果。

## 执行与边界

- 纯内容任务使用公共 `runSkillAgent`：每步请求只接受 `read_resource` 或 `complete`，资源只能来自已绑定包的自有键；无任意文件读取。文本/Markdown 检查非空，JSON 还检查现有 Schema。校验反馈用于下一步，达到预算则失败，不发布结果。
- 对话生图保持原工具执行链：绑定技能的正文/资源自动加入上下文，仍沿原网关最多一次生图及产物落盘规则；工具步数受同一配置上限约束。显式生图也带入绑定技能，避免选择内容技能后丢失原生图能力。
- 不依赖模型原生工具调用的内容循环使用受校验的 JSON 动作协议；中间步骤只在本次执行内有效。崩溃后不伪造完成、不自动恢复未完成模型请求；用户重新运行会开启新运行记录。
- 本版支持内容和 Markdown 参考资源，不执行包内脚本、shell、网络程序或任意文件操作。`requiredTools` 未满足会拒绝启用/执行。现有 Flow 技能若依赖 `node.execute`，不能在内容节点冒充可用。
- Markdown 元数据当前支持单行 `name`、`description`、`version`，也可上传无元数据的正文。未声明版本按内容生成稳定版本标识；工具声明/多个参考资源使用 JSON 格式。文件上限 128 KiB，单条 instructions 最多 32768 字符。暂不支持 ZIP、目录导入、复杂 YAML 或远程市场安装。
- 本包不开放外部 MCP/CLI 的技能安装或节点执行。已有只读查询与节点能力发现不提升为执行支持；端口、输出类型和 contractVersion 不变。

## 日志影响检查

安装/列表复用 `skill.library.started/completed/failed`，同一操作由 store 产生唯一终态，IPC 不重复记录。非法窗口/子框架在存储前返回 `SKILL_SENDER_REJECTED`，记录失败阶段 authorize。包无效、版本冲突、存储失败和完整性失败有稳定错误码。

内容执行复用公共节点生命周期与 `ctx.trace` 的 execution/request/result 阶段；每个模型步骤生成新的请求诊断关联，经现有网关记录 `model.request.*`。日志只写技能数量、步数和固定状态，不写技能名称、正文、资源、模型回复或原始异常。步数有界，不记录逐字输出。已有网关失败/取消及 runner 负责终态，不重复发明 Agent 成功事件。

内存诊断收集测试验证安装开始/终态配对、假密钥/技能正文不入日志、logger 抛错不改变业务结果。真实供应商和跨进程诊断完整性仍需单独验收，不以 mocked 网关测试替代。
