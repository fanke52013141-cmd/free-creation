# 节点功能与体验审计

本文是新增或调整节点前的产品审查基线。它与 `NODE_CONTRACT_SPEC.md` 一起使用：
前者定义数据正确性，本文定义用户是否真的能完成任务。状态中的“可用”表示现有实现能完成
核心闭环，不代表所有模型或外部服务都必然可用。

## 审核标准

每个节点先回答四个问题：

1. 用户带着什么任务来；节点是否是完成该任务的最小单元？
2. 真实输入和真实输出是否都能通过端口解释，且不依赖标题、文件名或隐藏状态？
3. 需要用户调整的参数是否都能在右侧详情中看到、理解、预览并恢复？
4. 用户是否能在画布上看出“还缺什么、正在做什么、产出了什么、下一步能做什么”？

“附加功能还是新节点”按以下规则判断：只改变本节点的**操作参数**且不产生独立可复用数据时，
它是附加功能；一旦产生可被其他节点消费的新媒体、结构化数据或异步任务，就必须是新节点，
并通过正式输出端口交付。

## 2026-08-31 严格复核：按用户任务而非“代码存在”判定

本节是当前实现的正式审计结论，优先级高于上表中的历史措辞。已逐一核对 24 个注册
节点的 `NodeTypeSpec`、端口、执行器、配置 UI 与回归测试。判定含义如下：

- **可用**：核心任务、真实端口和失败路径均已实现；外部模型的可用性仍取决于用户配置。
- **条件可用**：功能正确，但依赖 FFmpeg、本地模型或已配置供应商；界面必须在运行前明确提示。
- **部分匹配**：能完成一部分任务，但现有入口、设置或输出表达会让普通用户误用。
- **退役**：仅保持旧项目读取能力，不能作为后续功能基础。

### 关键发现（按必须先修复排序）

1. **已落实 — 对话节点输入输出说明。** 对话节点不再被 `NodeContractPanel` 排除；它和其他节点一样可查看概览、真实端口、固定设置和运行记录。
2. **已落实 — 代码离线确定性。** Worker 策略拒绝网络、动态模块和非确定性 API；运行时关闭网络/动态执行入口，CSP 仅允许本地 blob Worker，时钟/随机数可复跑。它依然不是带权限边界的通用安全沙箱，不能扩展 Electron 或 Node 能力。
3. **已落实 — 分镜板逐镜编辑。** 新增、编辑、上/下移和删除都通过独立、不可变的数据模型写回 JSON；卡片采用固定尺寸与内部滚动，不再因镜头数量无限撑高。该模型已有新增/编辑/边界排序/删除回归覆盖。
4. **已落实 — 音频与语音克隆职责拆分。** `audio` 仅承接或导入音频资产；`speech` 仅以文本生成普通配音；`tts` 必须同时有参考音频与文本才执行语音克隆。资产节点不会再误触发模型调用。
5. **已落实 — 统一基础交互组件。** 高使用率模型下拉框接入 `AppSelect`，侧栏和顶部操作接入可翻转的 Portal Tooltip；连线、端口效果只保留 `ui-foundation.css` 一个基础样式源。正式连线统一中性灰，端口色保留类型提示，选中/拖拽才使用蓝色或类型色反馈。
6. **已落实 — 本机媒体依赖前置。** 取帧、截取、提音会在右侧设置面板显示 FFmpeg 状态；人声分离会分别检查快速模式的 FFmpeg 与高质量模式的 `audio-separator`。探测是提示，不替代执行时错误处理，也不会自动安装软件。
7. **P1 — 右侧设置不是所有节点的第一等 UI。** 24 个节点中仅裁剪、拆分、修改、取帧、截取、提音、人声分离共 7 个有专用设置面板；其余节点在“设置”页多是原始配置 JSON 或只能回到卡片里设置。应将高频字段转成统一表单，而不是扩大卡片。
8. **已落实 — 生图多参考能力。** 新增可见的 `in-reference-images (many)` 端口，最多收集 4 张真实上游图片并按连线顺序提交；旧 `in-image` 保留兼容，不在提示词里暗记图片名。仍需真实供应商回归各类参考图限制。
9. **P1 — 人声分离模型策略仍需明确。** 高质量模式可将 BS-RoFormer（包含 124 bands 检查点）作为首选候选，但它不是对所有音乐、对白、噪声场景都绝对最优；必须保留本地模型可替换、失败可解释和结果试听。快速模式仍只能称“人声增强”。

## 界面与交互审计

### 悬浮提示与下拉框

- 左侧节点栏与顶部高频操作已接入 Portal Tooltip，因此提示不会再被滚动容器裁掉；提示会在屏幕边缘自动翻转，并保留键盘焦点语义。
- 但全项目仍有不少原生 `title`。原生提示的延迟、字体、位置与主题不可控，因此页面仍会显得“拼凑”；下一轮应按高频程度继续迁移。
- 统一 Tooltip 应先覆盖：顶部运行/暂停/搜索、节点端口、结果卡操作、右侧面板关闭/运行、时间轴控制。长文本提示应支持最大宽度、换行、快捷键与禁用原因。
- 下拉框虽然有全局基础样式，但不同模块还额外定义了 `gen-select`、`csp-select`、资源筛选、运行筛选等局部变体。下一步要保留一个 `SelectField` 组件和两个密度（紧凑/标准），而不是继续新增类名。

### 连线为什么没有参考图中的优雅感

参考图的连线使用“默认中性、交互时强化”的层级：平时是细的灰白弧线，只在选中或连线时给轻微蓝色反馈。当前实现的数据语义是对的（端口、箭头绑定、删除、撤销都是真实依赖），并已完成以下收敛：

1. 正式边统一为中性灰；端口圆点保留数据类型色，拖拽中的临时线才继承源端口色。
2. `.conn-main-path`、`.conn-glow-path` 与 `.port-dot` 仅由 `ui-foundation.css` 定义；旧 `app.css` 的动画虚线、脉冲与重复规则已移除。
3. 默认边为 1.5–2px 柔和曲线，选中/悬停使用品牌蓝和极弱阴影；连线色彩服务于阅读顺序，而不是展示技术类型。

### 画板、节点与右侧详情

- 节点默认尺寸统一为 `340 × 260`，这是正确基线；复杂内容应使用内部滚动或右侧详情，不能靠自动变高破坏布局。
- 右侧详情的“概览 / 输入输出 / 设置 / 运行”信息架构正确；对话节点例外已移除，但多数设置仍缺少表单化 UI，应继续补齐信息，再做皮肤。
- 节点悬浮状态、端口可连接状态、结果历史和失败原因已有基础，但需要统一成三层：默认安静、悬浮可操作、选中/运行可识别；不可让所有边、端口和按钮同时发光。

2. **再做 P1 高频任务**：生图多参考图、图片修改预设/对比/历史已完成；继续把高频节点的设置迁入统一右侧表单，并做裁剪、视频时间轴、分镜板、迭代的桌面人工回归。

## 共性体验问题与优先级

### P0：阻止用户做错事

- 视频、图片生成中的 `@` 都必须创建真实边，提示文字只是辅助说明。
- 所有模型选项由能力表驱动；不支持的端口、比例或参数要在运行前说明原因。
- 右侧详情必须用“输入 / 输出 / 设置 / 运行”四段解释当前节点，不把技术端口 ID 当成主文案。
- 运行失败必须保留旧结果，不用失败结果污染现有资产。

### P1：让高频操作自然

- 裁剪选区可拖动、可缩放、可实时预览；固定比例优先，自由/透视不抢占主流程。
- 视频取帧/截取/提音共用一个时间轴预览模型，首帧、尾帧和自定义时刻都能直观看到。
- 统一结果卡：预览、重新运行、历史版本、下载、创建后续节点。
- 双击编辑、单击选中、直接按住拖动；拖动期间只做轻量预览，持久化合帧写入。

### P2：建立统一视觉语言

- 边采用同一条曲线与同一端口语义；默认中性，悬停或选中才强调，不让整条依赖链常亮。
- 节点只有顶部色带；色带向外包住圆角，正文不再出现四边颜色边框。
- 下拉框、提示、图标使用同一 Surface / Menu / Tooltip 组件；侧栏提示采用 Portal 渲染，不能再被滚动容器裁切。
- 默认节点采用统一基础尺寸；媒体预览和复杂表单在打开详情后展开，而非在画布上无限增高。
