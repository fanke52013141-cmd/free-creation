## 1. 本次交付

已完成独立的 `image-edit` 图片修改节点。它遵循现有节点契约，不把图片编辑藏进图片资产或生图节点。

```text
图片/生图/裁剪节点 out-image
             │
             ▼
    image-edit.in-image + image-edit.in-text
             │
             ▼
      image-edit.out-image（新的 MediaAsset）
```

### P0：契约与持久化

- 新类型：`image-edit`，`contractVersion: 1`。
- 输入：必填 `in-image`（单张图片）和可选、多值 `in-text`（修改说明）。
- 输出：必填 `out-image`（新的图片资产）。
- 固定配置位于 `props.config`：模型、尺寸、文字说明、标注列表；运行结果仍位于 `meta.nodeResult`。
- 节点规范已经升到 1.6，并说明标注不是隐藏数据端口。

### P1：右侧图片标注工作台

- 在右侧“设置”页显示与原图等比例的小画布。
- 支持箭头、矩形、画笔、文字标注，支持红/黄/橙颜色，支持撤销和清空。
- 节点卡片只保持预览和“调整修改”入口，避免破坏当前画布布局。

### P2：实际执行链路

- 主进程读取属于当前项目的 `sourceMediaId`，绘制临时标注参考图，再使用现有图片网关进行图生图。
- 模型产物经过统一 `saveBufferAsset` 入库，作为新的 `MediaAsset` 输出；原图不覆写。
- 图片资产与生图节点均提供“修改图片”快捷入口，入口只创建真实节点与真实边。

### P3：安全与失败边界

- 只允许当前项目的图片媒体；拒绝非图片、跨项目、路径无效或超过 100 MB 的输入。
- 解码源图上限为 6400 万像素；发送给模型的临时参考图限制为最长边 4096、最多 1600 万像素。
- 配置限制：最多 64 个标注、标注文本最多 500 字、节点说明最多 4000 字、最终模型提示最多 8000 字。
- 无图片、无模型、无说明且无标注、损坏标注都会明确跳过或失败，不会复用旧结果伪装成功。

### P4：测试与发布验证

- 新增 `test/image-edit.test.ts`：配置归一化、错误边界和执行器的真实输入/输出测试。
- 更新注册契约快照、连线矩阵、输出投影及版本测试。
- 自动化基线：42 个测试文件、525 项测试通过；新增主进程标注参考图渲染回归。
- `npm run typecheck`、`npm run lint`、`npm test`、`npm run build`、`npm run build:unpack` 都已通过。

5. 分别验证：未连原图、未选模型、空说明/空标注、供应商失败；它们应有明确失败信息且不产生新资产。

本次没有在桌面端调用真实供应商生成图片：自动化测试使用 mock，打包通过。实际模型的端到端验证必须使用操作者自己的已配置供应商，不提交密钥、样例媒体或生成文件。

## 4. 已知边界

- 当前使用一张原图作为模型参考图；没有承诺多参考图、分层合成或逐像素本地修图。
- 临时标注图是模型输入，不是单独资产，也不会暴露成输出端口。
- 不同供应商对图生图、尺寸及参考图格式的支持不同；失败应保留供应商返回的可读信息，不能在渲染端伪造兼容性。
- 画笔轨迹在右侧小画布绘制；不是新的无限画布，也不引入第二套 tldraw 状态。
- 失败运行会撤销本轮内存输出并抑制节点旧输出；历史结果仍保留在结果集合中供用户回看。
- `image-edit` 支持受控遮罩配置：在右侧选择“遮罩”并绘制区域，默认笔画区域转为透明重绘区；反选后透明区与笔画区相反。遮罩通过标准 `prompt.mask` 发送给所选模型，不根据模型名称预判能力；生成的 PNG 仅作为模型输入，不作为节点输出资产。

## 5. 后续开发方向（按优先级）

### 已完成的后续增量（媒体中心、模板与结构数据）

- 媒体结果卡统一支持两项结果并排对比；当前正式输出仍只由原有 `out-image` / `out-video` / `out-audio` 端口提供。
- 媒体结果卡支持删除非当前历史候选；删除只更新 `meta.nodeResult` 结果集合，不回收当前正式资产文件。
- 工作流模板保存并恢复节点 `config`，模型、Schema、代码动态端口等配置不会在套用时丢失。
- 处理节点保持 `in-value → out-value` 契约，新增原样传递、字段提取、字符串模板三种显式内部模式。
- 结构数据节点增加字段路径树，字段路径可复制，仍只通过声明的 `in-context` / `in-text` 输入进行映射。

对应回归覆盖结果集合删除/选择、模板配置保存、处理节点转换和结构数据契约；这些 UI 增量不改变任何既有端口 ID。

### D1：图片修改真实桌面回归与供应商能力记录（下一步，最高优先级）

先完成上节人工路径，并记录供应商对图生图、尺寸和透明遮罩的实际响应。供应商能力字段只能作为 UI 提示，不能按模型名称阻断运行；用户可选择任意已配置模型，是否支持由该次请求的真实响应决定。

验收：至少用一个真实 OpenAI 兼容图片端点成功完成“带文字+标注的图片修改”；不支持图生图或遮罩的供应商必须在运行时给出准确、可操作的错误，且不产生伪造输出。

### D2：图片修改的可复用创作模板（已完成）

已新增“图片修改→后续创作”模板：`图片资产 → 图片修改 → 裁剪 / 生图 / 视频`。模板先创建空的图片资产入口，用户自行导入原图后再运行；四条边均为真实的 `out-image → in-image` 连线，不复制媒体、不隐藏执行步骤。

验收：一键创建模板后，每一个输入、输出、原图和产物来源均可在右侧契约面板查看。

### D3：受控的区域修改能力（已完成第一版）

当前已将 `mask` 定义为 `image-edit` 的版本化配置能力：通过标准透明 PNG mask 请求局部重绘，供应商是否支持由实际响应决定，不独立输出资产。若未来遮罩需要被多个流程复用、版本化或单独编辑，再定义独立 `image-mask` 节点，契约为 `image + mask → image`。

前置条件：先扩展供应商能力契约和错误码；禁止为某个供应商在 renderer 里增加特例。

### D4：媒体节点统一回归与性能验收

以图片裁剪、图片修改、取帧、截取和提音为一组，补充实际桌面端的资产落盘、失败不污染旧结果、跨节点连接、保存重开、100/500 节点拖动基准。继续保持视频成片合成在专业剪辑软件中完成。
