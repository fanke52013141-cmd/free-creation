## 0. 2026-09-29 决策记录（已与用户确认）

以下决策已确认，正文相关条目按此执行；与正文冲突时以本节为准。

1. **多模态看图**：将接入一个多模态大模型（豆包·方舟或通义千问 VL 系列）。接入方式：复用已有 `doubao` / `qwen` 供应商模板，不新增供应商协议；模型模态新增 `vision`（识图）类别；扩展聊天链路支持随消息携带图片；vision 模型须通过真实看图验证，未验证的模型不可运行图片评审或参考图分析。
2. **字幕转写：不采用**。`audio-transcribe@1`、`subtitle-export@1` 及后续字幕烧录节点不再立项；现有 `voice.subtitle@1` 语音字幕输出保持不变。
3. **本地推理边界**：现有深度/白模节点的本地推理保留；"不接本地部署模型"约束解释为**不新增本地生成模型**。AI 超分仅考虑云端供应商方案——两个项目当前均无现成云端超分接入；启动时优先核查 ToAPIS 是否提供超分端点，其次火山。
4. **视频任务取消语义**：确认"取消＝不再关注（额度照扣）"。不验证上游取消接口，P1-02 的"上游取消成功"分支取消，界面按"本地停止观察"表达。
5. **不做自动更新**。P6-04 的更新器、代理与签名机制取消，仅保留手动升级的数据安全要求。
6. **成片剪辑**：确认维持"不在画布做成片剪辑"，最终成片在外部软件完成。
7. **P0 供应商真值表**固定为实际配置连接：minimax、seedance、volc-speech、toapis，加文本/多模态连接（豆包或千问 VL，按第 1 条接入）。
8. **P3-05 / P4-03 模板全部走现有 P 图节点**，不为此新增节点类型。

## 1. 目标与实施原则

用户最终可以完成三条更完整的创作链路：

1. 草图或参考图 → 提示词优化 → 生图/P 图 → 调色 → 对比选优 → 收藏进资源库。
2. 剧本 → 角色/场景/道具候选 → 分镜 → 批量任务表 → 逐项生成 → 修改失败项并续跑。
3. 视频素材 → 精确取帧/截取 → 深度或白模参考 → 视频生成 → 字幕转写与导出。

共同基础是任务可恢复、历史可回溯、媒体可追踪、模型能力可信，以及项目可以安全迁移。

- 保持本地单用户 Electron、SQLite、本地媒体资产、tldraw 和现有模型模块。
- 新处理能力用独立节点或明确的工作流模板表达。快捷入口负责创建真实节点和端口连线。
- 配置进入 `props.config`，用户正文进入 `props.text`，运行与正式结果进入 `meta.nodeRun` / `meta.nodeResult`。
- 既有项目继续可读。协议变化提升版本，并提供迁移与旧样本回归。
- 新节点保持 `340×260` 默认卡片；表格、绘图、报告、机位编辑进入右侧面板或专用工作区。
- 模型选择继续接入 `packages/model-contracts`、`packages/model-runtime` 与主进程网关，避免另建模型设置和密钥存储。
- 界面控件只编辑配置、展示结果或触发统一执行；模型请求由 executor 经主进程发起。
- 展示节点允许使用现有 `display-only` 模式。没有新产物的对比、查看行为不需要伪造输出。
- 数据库与文件系统无法组成普通 SQLite 原子事务；跨两者的写入采用暂存、提交记录、补偿和启动恢复。

## 5. P0：基线、样本与最终拆单

**用户价值：** 后续新增能力建立在当前真实实现上，避免把已完成工作重复建设。

1. 在实际开发起点重新锁定本项目提交与工作区改动；确认 28 类可创建节点和退役节点清单没有漂移。
2. 固定四套去敏项目：图片创作；20 项批量；含运行中视频任务；含资源库引用、历史版本和导演台发布结果的迁移项目。
3. 记录真实供应商支持，范围固定为实际配置连接：minimax、seedance、volc-speech、toapis 及文本/多模态连接（豆包或千问 VL，见决策记录）。逐项核对文本、多模态看图、生图、图片编辑、视频任务查询与取消语义；转写已确认不需要。未经真实调用验证的能力标“未验证”。
4. 测 100/500 节点场景、100 张视频封面、2000 条边的打开、平移、框选、预览与内存。记录电脑、媒体分辨率、窗口尺寸和渲染模式。

6. 对 P1 的媒体引用保护作专项调查：画布、节点历史结果、项目快照、导演台、资源库副本分别引用什么；删除入口何处拦截。当前已看到 `media.repo.ts` 删除原文件的路径，但尚未对所有调用方完成缺陷审计，不能直接认定所有入口都缺少保护。

**交付与验收：** 一张能力真值表、一份性能基线、四套可重新打开的测试项目；基线 `npm run verify` 结果留档。已存在的失败单独登记，不能写成新增工作的验收通过。

## 6. P1：任务恢复、错误和版本安全

### P1-01 错误模型与重试动作

在现有 `src/shared/upstream-error.ts` 和 gateway 错误出口上增加结构化信息：`category`、`stage`、`retryAction`、`requestId`、`providerTaskId`、`submissionCertainty`。错误类别至少包括配置/鉴权、额度、限流、审核、参数、网络、提交未知、结果下载失败、本地落盘失败、响应格式异常。

动作按阶段区分：修正配置、修改输入后新建尝试、继续查询原任务、重新下载原结果、重新提交。不能仅凭 HTTP 状态推断所有供应商都未受理请求；尤其不能将未知提交统一当普通失败自动重发。节点卡、运行中心、批量表消费同一个解释器，保留原始安全错误码，不展示敏感请求体。

**验收：** 使用模拟供应商覆盖 HTTP 200 业务错误、429、超时、5xx、下载得到 JSON 错误页；没有把“下载失败”变成新生成，也不将额度不足统一提示成等待重试。

### P1-02 延续既有任务恢复

保留现有视频任务表和恢复路径，增量补齐提交中、已受理、执行中、已完成待下载、已落盘待回写和提交状态未知的区分。状态先存在任务记录，由适配层映射到现有节点状态；若扩展节点状态，另做版本迁移。

每次尝试关联 `projectId/nodeId/runId/attemptId/providerTaskId`、连接配置指纹、协议版本及输出登记键。任务摘要与节点结果各有用途：主进程记录执行事实，节点 meta 保存可持久化展示和正式输出；通过幂等提交结果统一两者，避免两个来源各自推进状态。

供应商可查询任务时恢复原任务；不能查询的同步请求重启后标记中断/未知，不能自动重提。已知结果下载地址按敏感数据处理，导出诊断剥离签名参数。配置变化时明确停止恢复并提示选择。取消语义已确认为“不再关注（额度照扣）”：区分关闭观察与停止本地轮询的展示，不验证上游取消接口。

**验收：** 在任务提交后、下载中、资产写入后、节点回写前分别模拟进程退出；重启后同一结果仅登记一次，不覆盖已删除/更改输入的节点。找不到原节点时保留可领取结果，不偷偷重建节点。

### P1-03 快照和媒体引用保护

增强现有历史面板：只读预览 → 校验媒体 → 保存当前恢复点 → 应用历史 → 保存新版本。失败保留原画布；恢复动作不恢复“正在运行”的外部请求。自动快照仅在内容变化时创建，视口移动不触发内容版本；保留数量、间隔和固定版本策略可配置，开发时确定默认值。

统一媒体引用查询，覆盖当前画布、成功结果集合、历史快照、导演台发布引用与资源来源。删除在“取消当前引用”“移入待清理”“物理回收”之间有明确区分；先完成引用保护，再开放垃圾回收。导入新增引用字段时扩展 `media-reference-remap.ts`，验证所有 ID/相对路径均被重映射。

**验收：** 历史图仍可预览；恢复前内容可找回；模拟文件缺失、快照迁移失败和写入失败都不会产生半恢复状态；新旧导出包均可导入。

### P1-04 诊断与真实进度

扩展已有节点诊断导出，按项目/批次汇总任务阶段、协议/契约版本、环境能力、脱敏日志和关联 ID。导出前预览范围；默认排除正文、密钥、Cookie、签名 URL 参数和媒体本体。

进度遵循现有 `IMAGE_GENERATION_PROGRESS_PLAN.md`：真实任务事件优先，耗时估计明确标注估计；供应商排队未知时显示阶段与经过时长，不制造线性百分比。

**主要落点：** `src/shared/upstream-error.ts`、`src/shared/diagnostics.ts`、`src/main/gateway/`、`src/main/ipc/diagnostics.ipc.ts`、`src/main/store/`、`src/renderer/src/engine/`、`CanvasSidePanel.tsx`。

## 7. P2：本地图像节点、结果查看与轻量交互

### P2-01 图片调色

拟定 `image-color-grade@1`：`in-image(image, required, one) → out-image(image, required, one)`。配置首版仅亮度、对比度、饱和度、色相；后续曲线/LUT 要单独验证色彩与参数协议。

实时预览使用缩略图处理；点击运行后通过本地媒体服务生成新资产。预览与导出复用算子定义，并通过像素样本验证允许误差。原尺寸、透明通道、色彩空间处理需要明确；第一版可统一输出 sRGB PNG，但应在帮助中说明。不会照搬 BeefTV 到下游消费时才物化调色图的路径。

**验收：** 默认参数视觉不变；透明区域正确；配置重开可复跑；运行失败不产生可消费的新输出；源文件哈希不变。

### P2-02 图片尺寸调整

拟定 `image-resize@1`：图片单入单出。配置包括目标宽高/长边、锁定比例、重采样方式及是否允许放大。输出实际像素尺寸与文件格式。插值缩放明确称“尺寸调整”；真正的 AI 超分另列 P7，需选择和验证模型。

**验收：** 极端长宽比、1px 边长、透明图、过大目标内存限制、取消和写入失败；预览尺寸与输出元信息一致。

### P2-03 草图参考

拟定 `sketch@1`：无必填输入，`out-image` 为发布后的图片；使用 `manual-publish`。可选背景图走正式 `in-image`，笔画、画幅、背景和图层配置可恢复。优先复用 tldraw/现有绘图基础，不额外引入完整绘图产品。

编辑草稿与已发布图分离：修改草图不会悄悄改变下游，点击发布生成新图片资产。画布撤销与草图编辑历史边界明确；关闭面板后保留草稿。

**验收：** 草图发布 → 接生图参考 → 重开项目 → 修改再发布；旧发布图仍可追溯，资源包不遗漏草图引用。

### P2-04 对比、选优和继续创作

公共图片查看器增加并排、滑杆、同步缩放和来源信息；从结果集合或多选两图打开。不同宽高比默认完整显示并提示比较方式，不静默裁切。已有结果集合继续使用现行模型；选优动作明确只改变哪个输出投影，不能在失败运行中重新暴露旧结果作为本轮成功输出。

若需要画布固定展示，新增 `image-compare` 的 `display-only` 卡：单个 `in-images(image, many)`，运行/展示前校验恰好两项，配置固定 A/B 身份，禁止两个同类型单值输入绕过一般节点规则。无输出；仍注册空输出投影、执行策略及合规测试。

“继续调色/裁剪/P 图”复用统一动作注册，创建节点并连接真实输出。只打开预览不修改图数据。

### P2-05 已有工具完善与媒体加载

- 拆分增加常用宫格预设、格子选择和清晰序号；若改变输出数量语义，升级契约并迁移。
- 提示词提供放大编辑，保留草稿，切换节点不会把文本写错对象。
- 图片、视频、音频采用统一预览入口和关闭规则；缩略图失败可重试。
- 视频默认封面，悬停预览延迟和时长以实测决定；全局控制预览解码数量，拖动画布立即停止自动预览，手动播放优先。
- 空画布引导与工具栏共用节点创建注册表；沿用项目已选节点和现有搜索。
- 整理操作可撤销，区分“保留相对关系扩大间距”和“按依赖重新布局”，锁定节点不移动。

**主要落点：** `src/main/media/`、`src/renderer/src/nodes/specs/`、`src/renderer/src/engine/executors/`、公共媒体预览与画布动作组件；新增节点同步 active IDs、Schema、持久化与测试。

## 8. P3：AI 辅助与可复用视觉模板

### P3-01 多模态能力先验收

已确认现状（2026-09-29）：聊天链路仅发送纯文本。接入方式见决策记录第 1 条：复用 `doubao`（方舟 OpenAI 兼容）/ `qwen`（百炼 compatible-mode）供应商模板，新增 `vision` 识图模态，扩展聊天消息携带图片资产。

核验现有 `text.generate` 请求是否能稳定携带项目图片资产、使用何种内容格式、是否获得结构化响应。需要时扩展模型契约和适配器，记录“看图已验证”状态；不能按模型名称推断。没有通过该门槛的模型不可运行图片评审或参考图分析，但纯文本优化仍可用。

### P3-02 提示词优化节点

拟定 `prompt-optimize@1`：`in-text(text, one)` 与可选 `in-images(image, many)`，输出 `out-text` 及 `out-report(json, prompt.optimization@1)`。用户正文也可填写 `props.text`；端口是否 required 依现有正文兜底规范定稿，最终就绪检查要求至少一种正文来源。

首版包含扩展、精修、风格强化、结合参考四种模式；模型适配仅依据已验证参数，不能编造供应商语法。报告记录改动说明、假设、备选和规避内容。文本模型与目标生图/视频模型分别选择。

`prompt.optimization@1` 不能直接伪装成现有 `prompt.bundle@1`；先用 `out-text` 接生图文本口，后续需要结构化包时由显式转换模板生成。优化失败保留原稿；点击采用/连接才改变目标输入。

### P3-03 图片评审节点

拟定 `image-critique@1`：必填单图 `in-image`，可选 `in-text` 创作目标；输出 `out-report(json, image.critique@1)`。报告包含总结、优点、问题列表、建议、置信度和归一化定位；最多 5 个重点问题，0 个问题也是合法成功结果。

首版一次视觉模型请求加本地 Schema 校验；不采用最多九阶段的复杂分析流程。保存源资产哈希、模型与评审模板版本，输入改变后标旧报告过期。右侧原图上绘制标注，标注只是报告显示；如需导出标注图，新增明确的报告渲染节点/模板，不能按钮偷偷输出媒体。

用户选择建议后，通过显式转换节点生成修改说明并连接 P 图；原图仍经真实 `in-image` 连线进入 P 图。模型意见展示为建议，不把置信度伪装成客观审美分数。

**验收：** 多模态失败、非法 JSON、越界坐标、空问题、取消、源图更换、旧报告查看、重新打开；新输入不能消费旧报告作为本次结果。

### P3-04 显式素材引用

在节点提示词编辑器中，候选仅来自当前真实连接并通过类型校验的输入。显示名称可读，但持久身份包含来源 `nodeId + portId`、具体结果/媒体身份及目标输入口；显示别名不是数据寻址依据。

文本正文保留在 `props.text`，引用映射与配置分离保存。重命名不破坏引用；删线/媒体删除明确提示失效；重排参考图时在提交前显示真实发送顺序。跨项目导入、模板复制、节点复制都必须重映射引用。

一键识别“图1/角色名”只提出无歧义候选，用户确认后绑定稳定身份；普通数字不得被当引用替换。模型请求中最终引用与实际上传素材必须一致。

### P3-05 多角度、打光、人物质感、风格配方

先做模板而非每个预设增加一种节点：参考图片 + 参数化文本/结构数据 → 现有 P 图。多角度参数包括方位、俯仰、景别；打光包括方向、强度描述、色温意图；质感模板约束希望保留的身份和构图。参数 UI 修改的是显式模板节点配置/正文，运行仍走 P 图 executor。

每个模板固定版本、参数、生成的最终文本与使用的模型；用户可看见并编辑全部节点。多角度属于 AI 重绘，不承诺真实几何或严格身份一致；模板预览不能装成生成后的确定效果。

风格使用现有资源库不可变版本。运行前明确展示将追加的风格文本、引用图和待应用模型参数。需要替换用户参数时逐项选择应用；资源库新版本不会自动改变已完成项目。

**交付样例：** 多角度角色参考、人物质感微调、场景打光、分镜风格统一四套模板，每套有输入示例、能力需求、失败说明和可修改参数。

## 9. P4：批量生产、剧本资产与分镜协同

### P4-01 任务表与执行器分离

表格每行有稳定 `rowId`、启用状态、提示词、参考资产、参数覆盖、结果和尝试记录。表格可以选择/替换参考、重排行列、运行选中行、只跑未完成、只跑失败。全局提示词明确采用“覆盖”还是“追加”，运行前可看到逐行最终内容。

首版可扩展结构数据节点的表格编辑，或新增 `batch-input` 专用输入节点；推荐后者用于媒体逐格绑定，但它只输出 `list.items@1`，不在内部执行模型。行结构另用拟议 `batch.job@1` 校验，通用列表 Schema 不被误认为已经校验了所有行字段。

参考图片采用唯一 `in-images(image, many)`；行中绑定已连接资产身份，不能因列增加而创建多个同类型输入口。上传单元格时物化图片资产节点和真实边，表格保存引用映射；项目重开、复制和导入保持关系。

输出接现有循环节点。给循环增加显式行字段到循环体端口的映射：目标节点/端口固定，文本按字段映射，多图按数组逐项校验为图片值，所有注入经过相同输入契约校验。执行器不得自行扫描行里看似图片的字符串。

### P4-02 先串行闭环，再隔离并发

第一交付保留当前串行执行，完善每行恢复。`rowId`、内容修订、`itemRunId`、尝试 ID 独立；修改一行只使该行和其依赖结果过期。安全重试遵守 P1，限流可退避，提交未知不能盲目重发。

并发作为第二交付：先把每项输入/配置/输出与画布共享 shape 分离，运行过程中不轮流覆盖同一个循环体节点的 `meta.nodeResult`。各项结果独立持久化，选择一行时再投影显示。没有完成隔离和幂等输出登记前，不开放 5/10 路并发。

并发上限按供应商实例和本地资源分别限制，串行为默认；与 GPU 推理、媒体下载共用容量管理。限制必须来自已验证能力/用户配置，不能沿用 BeefTV 的选项数字当安全结论。

### P4-03 章节资产候选与分镜

以现有 AI 处理节点和结构化输出开始验证 `story.assets@1`：角色、场景、道具三个数组必须存在，可为空。需要专用预览/复跑能力时再固化 `story-assets-extract` 节点。先输出候选数据，用户选择后写入现有资源库，并显示重复候选；模型返回不能直接修改已有角色资源。

现有分镜板增加稳定镜头 ID、引用的固定资源版本、关联任务行和选用结果。新增字段通过 `storyboard.shots` 新版本迁移；旧分镜仍可读。镜头修改只使关联任务过期，完成片段可继续保留。

模板先交付“分镜批量生图”“同一角色多场景”“商品/人物批量换装”三种。每种都展开为真实节点与端口连线，没有隐藏生成阶段。

**验收：** 20 行真实小批次 + 100 行模拟压力；运行中暂停/退出、修改 3 行、失败 2 行后恢复，已完成且输入未变的行不重新提交。断线的单元格不能静默换成首张图。并发验收需证实结果不串行号、不串参考图、不覆盖其他项。

## 10. P5：视频、字幕与空间参考

### P5-01 全景查看与取景

图片查看器可提供球面/柱面查看方式；用户明确选择投影，不把普通图自动当全景。重型 WebGL 点击才加载，展开大窗口时释放原视图实例。

拟定 `panorama-capture@1`：必填 `in-image`，输出单张 `out-image`；配置投影、yaw/pitch/FOV、画幅与尺寸。界面取景是临时预览，确认参数保存，executor 或受控手动发布产生正式新图片。实现阶段需验证截图渲染与正式发布共用同一投影，不能只依赖组件某次屏幕像素。

四方向输出用四个节点或列表循环模板；不要把单图节点临时切成多图输出。该能力没有新增真实场景几何，不等同于 3D 重建。

### P5-02 导演台与视频审阅

增强现有 3D 预演台机位预设、镜头切换、发布前预览、镜头与分镜的关联提示。草稿和发布输出保持区分，继续使用已有帧、预演视频和机位端口。参考侧导演入口在该版本仍标开发中，不能作为成熟产品替代本项目实现。

抽帧/截取复用已有时间轴，改善帧定位、缩略图缓存、区间试听和时间码；深度/白模继续沿用现有两个独立节点。后续共享推理缓存按输入哈希、范围、模型/引擎版本、尺寸和参数寻址，不能把不同设定视为相同结果。

### P5-03 音频转写与字幕文件（不采用）

> 2026-09-29 决策：不需要字幕转写。本节仅作记录，`audio-transcribe@1`、`subtitle-export@1`、`video-subtitle-burn` 均不立项；现有 `voice.subtitle@1` 语音字幕输出不变。

拟定 `audio-transcribe@1`：`in-audio → out-subtitles(json, subtitle.track@1)`；视频通过现有截取节点的音频输出连接。先核实 `speech.transcribe` 已声明操作的具体适配器和真实模型能力，再开放创建/运行。

拟定 `subtitle-export@1`：字幕 JSON 单入、SRT/VTT 文件单出。新增 `subtitle.track@1` 时为已有 `voice.subtitle@1` 定义显式转换，不直接改写旧语音输出协议。字幕按毫秒保存，编辑需校验起止关系、重叠策略和源媒体版本。

首版做转写、编辑、侧挂文件导出。烧录视频作为后续独立 `video-subtitle-burn` 节点，需样式和音画同步专项验收；完整时间线成片编辑器仍暂缓。

### P5-04 局部表情编辑（能力门槛后的可选项）

采用独立 `image-expression` 节点时，明确输入原图、修改说明与归一化区域；如需额外角色参考，遵守单个多值图片口及显式角色映射规则。支持遮罩和多参考的模型须实测；否则该模式不可用，不能静默退化成全图重绘。

**验收：** 全景 0/90/180/270 度测试图方向正确；多次打开/关闭释放 WebGL；发布视频保留预期音轨与时长。

## 11. P6：资源应用、性能与桌面发布

### P6-01 资源库补齐

沿用现有资源分类、不可变修订、蓝图和 `.canvaslib`。优先增加收藏集管理、引用来源跳转、参数应用预览和失效引用提示。资源配方中的模型参数目前仅保存/展示；增加应用能力时，逐字段映射到已验证模型配置，未知参数不下发。

大文件走流式复制、哈希和进度/取消；不要直接放开当前大小限制后继续整包读内存。原有 128 MB 单文件、512 MB 资源包限制是否调整，以内存和迁移测试结果决定。回收先依赖 P1 引用保护，归档不能等价物理删除。

### P6-02 大画布与媒体预算

沿用 tldraw 的可见性机制，主要优化自定义节点的媒体和复杂面板：分级缩略图、延迟视频加载、3D 单实例/可释放、虚拟化批量表、按需载入报告。大幅缩小时显示摘要，不把所有视频元数据请求和解码同时启动。

建议验收目标（P0 后校准）：指定基准机的 500 节点/2000 边场景平移帧耗时 p95 不超过 33ms，普通选中反馈不超过 100ms；反复打开/关闭预览 20 次后，无持续增长的播放器/纹理实例。内存比较应在相同 GC/缓存条件和静置窗口进行，报告绝对值与基线变化，不能只给平均帧率。

性能模式是资源预算选择，不改变正式输出、运行顺序或项目保存内容。参考侧的阈值仅供设计参考，不直接复制成我们的节点数量上限。

### P6-03 模型适配和可控扩展

模型选择器统一显示已验证能力、参考图上限、可用参数和验证时间。修改 Base URL、协议或凭据后明确需要重新验证。先维护内置适配器注册点，按用户实际使用模型逐个加入；第三方提供商包数量不是验收指标。

以后开放插件时先限定声明式配置和受信任内置适配器。任意插件代码执行、权限管理、签名与迁移机制需单独方案，不以本轮创作功能为由增加通用脚本宿主。

### P6-04 手动升级数据安全（更新器已取消）

> 2026-09-29 决策：不做自动更新。更新器、网络/代理/签名机制取消，仅保留以下手动升级要求：升级前保存当前画布与各编辑器草稿；程序与用户数据分离；数据库迁移失败保留旧数据与恢复记录，不以“进程启动成功”判定升级成功；发行构建不携带工作区数据库、密钥、项目或素材；旧版真实数据升级与换目录导入纳入验收。

定义检查、可更新、下载中、校验、待安装、安装准备、失败重试等状态。启动可检查，下载与重启由用户选择；安装前保存当前画布和各编辑器草稿，有活动生成任务时提示其真实恢复能力。保存失败阻止退出。

Electron 主进程实现网络和校验。借鉴环境/系统代理优先级、bypass、重试重读设置；针对 Electron 实际使用的网络栈验证系统代理/PAC 行为，不能照搬 Go 静态代理解析并声称覆盖所有系统代理。测试重定向、无代理直连、代理不可达、校验失败和中断下载。

发布清单和安装包做真实性/完整性验证，支持的签名方式与打包机制在实施设计中明确。发行构建不得携带工作区数据库、密钥、项目或素材。程序与用户数据分离；回滚应用文件不等于数据库可降级，迁移失败保留旧数据与恢复记录，不能以“进程启动成功”判定完整升级成功。

**验收：** 干净 Windows 用户目录安装；旧版真实数据升级；保存失败不重启；损坏包不安装；代理改变后可重试；项目、资源、模型连接与历史均保留。涉及本机密钥的验证使用临时配置，正式凭据不进入样本。

## 12. P7：按使用需求选择的扩展

| 能力 | 推荐实现边界 | 启动条件 |
| --- | --- | --- |
| Eagle 素材连接器 | 主进程读取本地 API，选择后复制到本地资产并保留来源；首版不自动写回 | 用户确实有 Eagle 资料库；验证官方 API 后实现 |
| Markdown 展示 | 文本/Markdown 输入，`display-only`；共用已有 Markdown 渲染器 | 长文/提示词文档有稳定使用需求 |
| SVG 展示与导出 | 展示卡只预览；导出走显式 `svg-render`，输出图片或文件，禁止混淆两种输出 | 需要图标/示意图进入生成流程 |
| 图表节点 | JSON 表格 Schema + 明确 x/y/series 配置；导出图像另立正式节点 | 数据图表确实成为创作素材 |
| HTML 预览 | 受控沙箱、不暴露 Electron 能力，网络/脚本策略明确；仅展示 | 有代码可视化需求；不是导演台实现方式 |
| AI 超分/修复 | 独立节点，仅云端供应商方案，不引入本地权重；可取消/恢复 | 云端供应商效果验证通过（优先核查 ToAPIS，其次火山） |
| 视频延长/局部重绘/换主体 | 每项单独验证供应商能力、输入和错误语义；独立节点或显式模板 | 真实协议和模型能力可用；枚举名称不能视为支持 |
| 标注报告导出 | `image + critique JSON → image` 的正式渲染节点 | 用户需要分享评审图或作为 P 图参考 |
| 新旧结果差异统计 | 独立分析节点，输出版本化 JSON；视觉比较仍可独立使用 | 用户有一致性评估需求，指标含义明确 |

## 13. 拟议节点与协议清单

下表是设计起点，不能跳过注册校验、版本规则和实际端口兼容测试。所有新增节点都需 executor/展示执行策略、`projectOutputs`、失败路径和持久化测试。

| 节点/形式 | 输入 | 输出 | 主要配置与正式结果 |
| --- | --- | --- | --- |
| 图片调色 | image one required | image one | 配置四项调色值；结果保存新资产与来源 |
| 图片尺寸调整 | image one required | image one | 目标尺寸、比例、重采样；结果含实际尺寸 |
| 草图 | image one optional | image one，未发布时无结果 | 草图配置/文档版本；发布结果固定资产 |
| 图片对比（可选） | image many，恰好两项 | 无，display-only | A/B 明确绑定；滑杆位置可临时保存 |
| 提示词优化 | text one + image many optional | text + prompt.optimization@1 | 优化模式、模型；正式结果正文和报告 |
| 图片评审 | image one required + text one optional | image.critique@1 | 评审目标、模型；报告、源指纹、模板版本 |
| 批量输入（若独立） | image many optional | list.items@1 | 稳定行 ID、引用映射；逐行通过 batch.job@1 |
| 剧本资产提取（先模板） | text | story.assets@1 | 角色、场景、道具候选，独立审核入库 |
| 全景取景 | image one required | image one | 投影/机位/尺寸；取景图片 |

通用就绪判断复用 `deriveNodeReadiness`。必要的跨端口条件（例如至少一种正文来源）通过统一契约/配置验证明确表达，不能卡片和 executor 分别写不同规则。输入/输出单值、多值及 Schema 兼容必须在连接时和执行时都验证。

## 14. 测试、发布与回退门禁

每项能力的验收包含四层证据：纯函数/协议测试；SQLite 与真实文件的持久化测试；实际 Electron 界面操作；需要模型的真实供应商小样本。浏览器 mock 只能证明界面流程，不能代替真实落盘和模型效果。

- 所有节点修改运行 `test/node-compliance.test.ts` 和完整 `npm run verify`，补契约快照、连线、投影、错误、取消、重开与导入导出测试。
- 修改模型 packages 时另跑相关 package 的类型检查和测试；不要假定根目录 verify 已覆盖所有工作区包。
- 本地媒体算子使用固定图片/音视频夹具检验输出；图像算法和字幕精度容差提前写入测试说明。
- 有外部付费调用的验收采用配置好的测试模型和受控样本，保存脱敏请求 ID、结果元信息及人工检查结论；不把未调用的供应商写为通过。
- 存量节点、声音调整、视频截取、深度/白模、资源蓝图和导演台发布链路都纳入受影响回归，不能用新功能覆盖退役节点规则。
- 新 Schema/配置迁移保留旧读取器与样本；功能入口可关闭，但已保存项目必须仍可显示旧配置和结果。数据迁移回退不依赖卸载新版本。
- 分阶段发布依赖实测门禁，不按日期强行放行。高复杂度并发、AI 超分、外部连接器可以晚于核心版本发布。

建议使用三个验收项目演示阶段成果：

1. **图片精修项目（P1–P3）：** 草图 → 生图 → 调色 → A/B → 图片评审 → 选择建议 → P 图 → 资源收藏；中途模拟一次网络失败和一次重启。
2. **20 镜头项目（P4）：** 剧本 → 候选资产 → 分镜 → 批量表；改 3 行、失败 2 行后只重做受影响项目，证明参考图与结果行一一对应。
3. **视频参考项目（P5–P6）：** 视频取帧/截取 → 深度/白模 → 全景参考取景或导演台机位 → 视频生成；导出、换目录导入后继续打开。
