# 资源分类与节点蓝图：修订提案

状态：待产品讨论。本文修订资源库的核心模型，现有 `formPreset`、通用组件编辑器和单组件加入画布仍是已上线的第一版实现；下文的可配置分类与整组节点实例化尚未实现。

## 1. 核心结论

资源库保存的是**可反复放入画布的节点集合定义及其内容**。用户在库里看到的一份资源，放入画布后可以产生一个或多个现有节点。库中图片、提示词、声音等可使用内容，都必须有明确的节点类型、内容落点和使用规则。

同时区分四个对象：

| 对象 | 回答的问题 | 示例 |
|---|---|---|
| 资源分类定义 `ResourceCategory` | 这一类资源怎样填写、展示，放入画布时生成哪些节点？ | 用户创建“系列主角设定”，选择人物档案样式及图片、文本、音频节点 |
| 资源实例 `Resource` | 具体是哪一份可复用内容？ | “林青的角色设定” |
| 资源版本 `ResourceRevision` | 这份内容和分类节点蓝图在某一时刻是什么状态？ | v3 的正面图、描述和声音，固定使用分类蓝图 v2 |
| 收藏集 / 展板 | 怎样组织、对照多份资源？ | “短剧 A”收藏集、“暖色胶片参考”展板 |

资源分类具有用户可改的名称；人物、场景、风格只作为内置**分类模板**提供起点，不应是不可扩展的资源类型枚举。收藏集负责归档，不能替代规定节点结构的资源分类。一份资源属于一个分类，可以同时进入多个收藏集。

资源名称属于资源实例。分类名称是“系列主角设定”，资源名称可以是“林青”；生成的节点可分别命名为“林青 · 形象”“林青 · 描述”“林青 · 声音”。资源名称不必强行复制为每个节点的相同标题。

## 2. 用户创建分类时配置什么

创建分类使用三个步骤，并提供即时资源卡片和画布展开预览：

1. **基本信息**：分类名称、说明、图标、默认封面来源；可从人物、场景、风格、海报、提示词或空白模板开始。
2. **展示样式**：从档案卡、图片网格、列表、风格展板等受控布局中选一种；配置封面槽位、摘要槽位、字段顺序、预览大小和表单标签。“样式”只控制库内呈现和填写方式，不改变节点的执行语义。艺术风格本身仍是资源内容。
3. **节点蓝图**：选择已有可创建的节点类型，为每个节点指定稳定的槽位 ID、显示名称规则、内容字段、必填性和数量；可声明初始摆放与合法连线。

节点蓝图中的一个条目称为 `NodeSlot`，不是已经存在于项目中的节点。每个槽位保存：`slotId`、`nodeTypeId`、`contractVersion`、角色、标题模板、内容绑定、基数（单个/多个）、是否必填、默认配置和相对位置。分类还可以保存可选的 `EdgeTemplate`；仅当端口存在且类型兼容时才创建连线。多个图片若共用一个可重复槽位，放入画布时按资源中的图片数量展开成多个图片节点。

内容绑定明确“资源表单字段 → 节点数据的哪一处”，例如图片文件绑定图片节点的媒体引用，角色描述绑定文本节点的正文。分类编辑器只能选择该节点契约允许的落点，不接受任意属性路径、脚本或未经声明的执行逻辑。提示词配方可以提供变量预览；应用后的文本进入文本节点。模型参数只有在目标节点显式支持并完成契约校验时才能填入配置。

分类至少包含一个可实例化的节点槽位。节点类型与字段类型不兼容、必填内容无来源、端口连线不兼容时，保存前显示具体问题。分类样式可随时修改；更改节点结构时发布新的分类蓝图版本，已有资源版本继续固定旧蓝图。

## 3. 三个具体例子

| 分类名称与库内样式 | 节点槽位 | 一份资源放入画布后的结果 |
|---|---|---|
| “系列主角设定”／人物档案 | `portrait`: 图片节点 1～多；`bio`: 文本节点 1；`voice`: 音频节点 0～多 | “林青 · 形象（正面）”“林青 · 形象（侧面）”“林青 · 描述”“林青 · 声音”四个或更多节点；按蓝图排布为一组 |
| “海报灵感”／图片网格 | `poster`: 图片节点 1；`prompt`: 文本节点 0～1 | 图片必有；有提示词时再创建文本节点。资源名称可以是“红色骑行海报” |
| “胶片质感参考”／风格展板 | `references`: 图片节点 1～多；`stylePrompt`: 文本节点 0～1；`notes`: 文本节点 0～1 | 多张参考图和明确选中的提示词展开；展板布局用于库内观察，不暗示画布运行顺序 |

上述“人物”“海报”“风格”都只是模板示例。用户可以用同一批节点创建“品牌角色卡”“道具设定”或其他名称的分类。

## 4. 从库到画布的契约

用户可以选择**整份加入**或**选择槽位加入**。整份加入按蓝图生成所有有内容的节点；部分加入只生成选中的槽位及两端都存在的合法连线。整体加入的所有节点、素材复制和连线应组成一次可撤销操作，失败时不留下半份节点集合。

实例化过程：读取资源的固定版本和其分类蓝图版本 → 检查节点实现、契约版本、字段和媒体文件 → 生成预览和缺失项提示 → 复制文件到项目 → 分配新的节点、媒体与连线 ID → 写入节点内容和布局 → 记录来源。记录 `resourceId`、`revisionId`、`categoryId`、`categoryVersion`、`slotId` 和本次 `instanceId`，以后才能辨认“这个节点来自哪份资源的哪个部分”。同一资源可以多次放入画布，每次都是独立实例。

蓝图中的节点即使被项目工作台隐藏，使用资源时也需明确提示将加入哪些节点，并允许本次加入或同时显示其创建入口。缺少节点实现、契约不兼容或必填文件丢失时禁止静默跳过。资源实例化不会自动执行图像生成、视频生成等计算节点；若蓝图显式包含此类节点，它们以未运行状态加入画布。

库内资源名称可用作这组节点的标题；若画布提供视觉分组，则用非执行的分组/框架呈现整组。分组本身不冒充一个新业务节点。节点标题允许用户在项目内修改，来源关系仍以稳定 ID 记录，不通过标题推断。

## 5. 数据结构与现有代码的关系

目标结构可概括为：

```text
ResourceCategory(id, name, description, presentation, latestSchemaVersion)
CategorySchema(categoryId, version, fields, nodeSlots, edgeTemplates)
Resource(id, categoryId, title, tags, collections, latestRevisionId)
ResourceRevision(id, resourceId, categorySchemaVersion, contentBySlot, changeNote)
ResourceUsage(projectId, resourceRevisionId, categorySchemaVersion,
              instanceId, slotId -> materializedNodeIds, materializedMediaIds)
```

当前 `formPreset` 是写死的表单选择，`LibraryComponent.role/valueType` 只表述组件的用途和数据类型；它们没有稳定的节点槽位、节点类型、属性绑定及蓝图版本。当前选择器逐个组件创建节点，`library_usages.materialized_node_ids_json` 虽预留字段，但尚未形成整组节点的来源映射。因此不能把现有第一版称为“可配置节点集合”。

迁移时新增分类定义和版本表，将现有 `image/prompt/character/scene/style/custom` 映射到内置分类模板；旧资源内容按 `role/valueType` 映射到槽位。无法可靠推断的旧组件放入“未映射内容”，由用户手工指定节点槽位，绝不丢弃。保留现有资源、版本、收藏集、展板与文件 ID；旧项目已复制的素材和节点不被批量改写。导入导出包需要包含分类蓝图及其版本，并处理名称冲突和节点类型在另一台电脑不可用的情形。

## 6. 建议实施顺序与验收

1. **协议与迁移**：先定义槽位、内容绑定、蓝图版本和来源记录，补旧资源映射。此时现有资源仍可读取。
2. **分类编辑器**：支持名称、受控展示样式、节点选择、字段绑定、预览与版本发布。内置模板走同一套协议。
3. **整组放入画布**：支持全量/部分槽位、布局、可选连线、单次撤销、失败回滚和来源追踪。之后再做专用人物/风格表单的视觉优化。

验收用一份自建“品牌角色卡”分类：名称不等于任何内置类型，选人物档案样式，配置图片、文本和音频三个节点槽位；创建“林青”资源并上传两张图、一段描述和一段声音；整份加入画布后应准确生成对应节点，标题、内容、位置与来源可追溯；只选声音加入时仅生成音频节点。修改分类节点结构发布新版本后，旧资源版本和旧项目仍可正常打开。

## 7. 需要产品确认的两个语义

- 分类的“展示样式”是否需要自由排版？建议第一版只提供受控布局和字段配置；自由画板属于展板功能。
- 将整份资源放入画布时，是否默认建立视觉分组？建议默认分组，允许解组；分组不参与执行。
