# 资源节点蓝图 v1：实现与使用说明

更新：2026-09-26。对应本轮分类、资源填写与整组画布创建的实现。

## 使用路径

1. 项目首页打开“资源库”，点击“新建分类”。填写自定义名称，选择图片卡片、档案卡片或内容列表样式。
2. 为分类添加节点槽位。每个槽位有内容名称、节点类型、必填/可选、单项/多项和节点名称模板；可调整顺序、封面来源及画布网格/横向排列。保存前可以看到名称与结构预览。
3. 点击“新建资源”，选择分类。按槽位上传文件或填写文本；文本槽位可以保存带变量的提示词配方。图片槽位允许多项时，每张图对应一个图片节点。
4. 在资源详情中勾选内容，选择目标项目并点击“打开画布并创建节点”。画布显示待创建名称及配方变量，确认后一次创建。画布的“项目素材 / 资源库”入口也支持整份加入、加入所选和单项加入。
5. 多个节点自动用 tldraw 普通分组呈现，一次撤销或重做覆盖整个节点集合；不执行节点。复制到项目的媒体仍保留，供重做和项目素材复用。插入失败则补偿清理本次新复制媒体。

例如“品牌角色卡”分类包含形象（图片，多项）、描述（文本，单项）和声音（音频，可选）。资源“林青”上传两张图并填写描述，整份加入会创建两张图片节点和一个文本节点。单独选择第二张图加入时仍保留其原序号。

## 协议边界

协议源码：`src/shared/library/blueprint.ts`。

- 分类身份与名称分离：`id` 稳定，`name` 可修改，每次编辑发布一个新的 `version`。
- 分类保存 `presentation`、可选图片封面槽位、`blueprint.protocolVersion = 1`、排列方式和有序槽位。
- 槽位使用稳定 ID，明确 `nodeType`、`contractVersion`、`required`、`multiple` 和 `titleTemplate`。
- 名称模板支持 `{resource}`、`{slot}`、`{index}`，分别对应资源名称、内容名称、槽位内序号。
- 内容组件在 `metadata.librarySlotId` 记录绑定；主进程验证槽位存在、内容类型兼容、必填性和基数。
- 资源每个不可变版本保存完整分类快照。编辑分类不改写旧资源；编辑资源时可以选择新的分类版本。换分类时保留内容，无法确定的映射显示待选择。
- 当前明确适配 `text@3`、`image@3`、`audio@3`、`video-asset@2`、`file@2`、`json@1`。正文进入节点 `props.text`，媒体进入现有媒体引用字段。合规测试检查这些版本与真实节点注册表一致。
- v1 不提供任意节点配置路径、处理节点蓝图、自定义连线或执行代码。处理流程仍使用现有工作流模板；未来接入时需要明确节点适配器和端口契约。
- 分类最多 32 个槽位，单份资源沿用最多 100 个组件的限制。单文件与资源包大小限制维持原有规则。

## 画布创建与来源

`insertResource.ts` 在文件复制之前验证组件选择、变量及实际节点契约版本。主进程复制资源文件并校验哈希，返回组件到项目媒体的对应关系；渲染进程在一次编辑事务中创建所有节点及普通分组。

节点 `meta.librarySource` 保存资源 ID、资源修订 ID、分类 ID/版本、槽位 ID、组件 ID、本次实例 ID 和使用记录 ID。使用记录同时保存创建的节点 ID。每次插入使用新的实例和节点 ID，引用固定资源版本。项目工作台隐藏节点创建入口不影响显式使用资源，加入入口和预览说明这一行为。

开始写画布前检查页面是否仍打开；创建或分组失败时回退本次历史段，并清理本次物化的媒体和使用记录。正常撤销保留项目素材以支持重做。旧资源继续按原组件类型生成对应节点，不修改原数据；可编辑后归入新分类。

## 存储与迁移

SQLite M8 新增 `library_category_versions` 与 `library_revision_blueprints`，旧资源、组件、文件和项目不做破坏性重写。内置人物、场景、风格等仅为可编辑分类起点，新分类不受这些名称限制。

资源包升级为 v2，包含分类定义和历史版本、每份资源固定的分类快照及组件槽位。仍可读 v1 包。全库导出包含尚未创建资源的分类；选择资源导出只包含相关分类。导入重新映射分类 ID，避免同名分类覆盖；同一包内相同分类版本定义不一致时回滚导入。

## 验证

- `test/library-blueprint.test.ts`：多节点映射、部分选择的稳定序号、槽位约束、配方、JSON、旧资源兼容。
- `test/library-persistence.test.ts`：使用临时 SQLite 和文件目录验证分类冲突、版本固定、文件复制/哈希、补偿清理、导入导出。
- `test/library-insert.test.ts`：插入来源、历史段边界、分组失败、关闭画布及契约不匹配。
- `test/node-compliance.test.ts`：库适配器与真实节点契约版本一致。
- `scripts/test-browser-library.cjs`：隔离浏览器会话使用内存 IPC 测试数据，验证真实 React 表单和 tldraw 画布的“创建分类 → 上传两张图并填写描述 → 创建三个真实节点 → 整组撤销/重做”。它不替代 Electron 主进程持久化验证，后者由 SQLite 集成测试覆盖。

浏览器验收运行方式：启动 `pnpm dev:browser --port 5202 --strictPort`，再运行 `node scripts/test-browser-library.cjs`。可通过 `BROWSER_ORIGIN` 指向其他本地端口。
