# 视频深度与白模转换：技术选型

> 更新：本文件的接入方式和节点拆分已由 `../VIDEO_CONVERSION_FINAL_PLAN.md`（v2.0）替代。最终采用不依赖 ComfyUI、两个均直接输入原视频的独立节点。本文件保留为历史选型参考。

检索日期：2026-09-26。以下是选型与验证方案，不代表已在当前电脑完成推理。

## 1. 先明确三种结果

| 结果 | 表达内容 | 典型用途 | 能否获得真实三维模型 |
|---|---|---|---|
| 深度视频 | 用灰度/数值表示每个像素的远近估计 | 控制视频生成、空间结构参考 | 不能直接得到完整模型 |
| 白模质感视频 | 用白色材质、简化光照呈现可见表面 | 去除原纹理干扰、观察运动构图 | 近似方案通常只有当前视角的表面信息 |
| 可编辑三维场景 | 几何、相机、材质及可能的动画 | 改机位、重新布光、真实三维操作 | 需要额外重建、跟踪与人工修整 |

对白模暂按“保持原视频构图和运动、呈现白色无纹理形体”规划。灰度深度图不是白模渲染；将原视频去色也不等于白模。

现有导演台从已有空间与人物布置输出白模预演；本需求从外部视频估计结构，二者的输入条件和误差来源不同。

## 2. 候选实现

### 2.1 优先验证：Video Depth Anything Small

官方项目针对视频时序深度，提供灰度预览、NPZ 和 EXR 输出。建议先用 Small 做本地试验；官方把 Small 权重列为 Apache-2.0，Base/Large 列为 CC-BY-NC-4.0，发布时必须固定实际权重及其条款。官方 A100 测试中 Small FP16 的显存为 6.8GB（输入 1×32×518×518），不能把这个数值直接当作用户显卡的最低配置或速度保证。[官方仓库](https://github.com/DepthAnything/Video-Depth-Anything)

选择理由是任务匹配、可保留原始深度数据、可先做窄范围验证。是否作为正式默认后端，取决于本机样片效果、推理延迟及内存峰值。

已有社区 ComfyUI 封装，可作为快速实验入口；它不是模型作者的官方 ComfyUI 实现。接入时固定版本并核对节点输入、输出和权重来源。[封装仓库](https://github.com/yuvraj108c/ComfyUI-Video-Depth-Anything)

### 2.2 对照候选：DepthCrafter

该项目提供视频深度序列及 EXR 输出。其许可证明确限制为学术、研究和教育用途，并排除商业或生产用途，因此本方案不把它列为默认生产后端；另行获得适用授权前仅作为许可允许范围内的研究候选。[官方仓库](https://github.com/Tencent/DepthCrafter)、[许可证](https://raw.githubusercontent.com/Tencent/DepthCrafter/main/LICENSE)

### 2.3 白模研究候选：NormalCrafter

NormalCrafter 从视频估计时序法线，可用于评估表面方向与简化着色。官方示例列出约 6GB 显存对应 512×256、约 20GB 对应 1024×576。实际权重、基础模型及依赖的发布条件仍需分别核对，不能仅凭代码仓库的 MIT 标记推断整个模型链可自由分发。[官方仓库](https://github.com/Binyr/NormalCrafter)

法线结果本身不是完整白模视频；白色着色、光照、背景和边缘处理属于我们需要实现和验证的后续步骤。

## 3. ComfyUI 与直接接入如何选择

**建议：验证阶段允许使用 ComfyUI，产品暴露稳定的“视频深度估计”能力接口。** 用户不必为了日常转换去理解整张 ComfyUI 图。

| 路线 | 优点 | 工程代价 | 建议 |
|---|---|---|---|
| ComfyUI 适配器 | 快速对照不同工作流，已有封装可试用 | 依赖版本、节点包、模型与文件传输需管理 | 技术验证优先；已有环境的用户可选 |
| 本地 Python 推理进程 | 环境和输出更可控，易隐藏内部复杂度 | CUDA/PyTorch 环境与打包维护成本 | 验证后评估为默认后端 |
| 用户配置的远端服务 | 本机低显存也有机会使用 | 上传隐私、成本、认证、恢复与限额 | 后续可选，不作为首版必需 |

统一接口建议为 `estimateVideoDepth(input, config, signal)`，返回已登记的输出清单和执行元数据。前端节点不绑定某个 ComfyUI 节点类名。

ComfyUI 官方 API 提供 `/prompt`、`/history/{prompt_id}`、`/ws` 和 `/object_info`，可用于提交、查询、事件与能力检查。[官方 API 文档](https://docs.comfy.org/development/comfyui-server/comms_routes)

工程注意事项：

1. 固定可支持的工作流模板、模型与自定义节点版本，提前检查缺失依赖。
2. 官方通用图片上传接口不等于视频上传接口；本机后端可把视频复制到专属输入目录，远端需明确的视频传输适配。
3. 保存 prompt_id，断线先查询历史和队列，不直接重提。
4. 共享服务的中断可能影响当前运行的其他作业，不能盲用全局中断；先验证任务所有权和取消能力。
5. 不自动安装任意第三方节点、不把远端输出路径直接当成本机项目路径。
6. 结果完成后导入项目媒体仓库，校验文件、帧数与元数据，再把节点标记成功。

## 4. 白模近似方案

### 4.1 推荐原型链路

```text
原视频
  → 分镜头检测/按镜头处理
  → 时序深度估计
  → 深度数据清理与尺度约定
  → 从深度近似计算法线，或采用独立视频法线估计
  → 白色材质 + 固定虚拟光照
  → 边缘、遮挡与背景处理
  → 白模效果视频
```

这是拟实施的工程路线，不是某个现成模型已保证的一键能力。深度梯度/反投影可用于估计可见表面的方向；没有可靠相机内参时，应标记为近似结果。

优点是能尽量沿用原视频的像素运动与轮廓；局限包括遮挡边缘破碎、发丝/透明物体错误、未知背面、缺少真实投影阴影、尺度漂移。法线估计也可能在快速运动时闪烁。

首版产品名称建议“白模效果（实验）”，可调整光照方向、环境亮度、平滑与背景处理；仅在目标样片通过验收后开放。

### 4.2 另外两条路线

- 视频生成模型风格转换：可能得到更漂亮的白色模型外观，但会改动细节、动作或构图，不能作为可靠结构提取的替代承诺。若做，应是独立的风格转换能力。
- 三维重建后渲染：需要相机估计、几何重建，动态人物还涉及跟踪和动画；适合后续专项，不纳入本轮常规节点排期。

## 5. 节点与端口建议

### 5.1 视频深度估计

建议类型 `video-depth`，输入 `in-video: video(one, required)`。

固定输出：

- `out-video: video`：用于预览或兼容的视频控制图。
- `out-file: file`：深度数据包，包含高精度帧/数组和时间索引。
- `out-json: json(video.depth@1)`：模型、输入来源、尺寸、帧率/时间戳、近远方向、深度语义、归一化范围、数据包引用。

深度数据包在正式首版中应成为可靠输出，不仅保留 MP4。实现能力若不足，应明确缩减契约而非默默返回空文件。

固定配置包含后端、模型版本、输入分辨率、处理片段、帧采样策略、精度和输出编码。变化只改变参数，不改变端口含义。原文件保持不变。

### 5.2 深度白模渲染

建议类型 `depth-clay-render`：

- 输入 `in-file: file(one, required)`，对应完整的深度数据包。
- 输入 `in-json: json(video.depth@1, required)`，定义解释方式；与数据包哈希必须一致。
- 输出 `out-video: video`，生成白模效果视频。
- 输出 `out-json: json(video.clay-render@1)`，记录光照、法线推导、来源和近似标记。

最初实现采用深度推导的近似法线。独立法线模型应作为后续明确节点和数据契约接入，不在此节点隐藏一个任意模型调用。

对用户可提供“视频转白模”模板，一次插入深度估计与白模渲染两个节点及连线。这样简单入口和可展开流程兼容。

### 5.3 视频语义兼容

当前视频端口不能只靠文件扩展名区分 RGB、depth、normal。增加媒体语义元数据及下游 capability 检查：不支持深度控制的生成接口不能因为同为 video 就当作支持。

预览视频用于查看；数值计算读取高精度包。普通视频播放节点可以显示控制图，但不会自动改变其数学语义。

所有节点依照 NODE_CONTRACT_SPEC 建立类型、Schema、executor、projectOutputs、失败路径和持久化；React 只负责交互。

## 6. 时序与数值要求

- 记录输入时间戳，识别可变帧率；需要转恒定帧率时保存重采样映射。
- 逐镜头固定深度归一化策略，不每帧独立 min/max 拉伸造成亮度跳动。
- 明确相对深度/逆深度/度量深度，不把相对灰度标为米。
- 记录 nearWhite 或 nearBlack，转换时显式操作。
- 保留高精度线性数据；普通有损视频不承担测量用途。
- 输出帧数、时长、方向与原视频可对齐；旋转、裁剪和缩放记录为变换。
- 控制视频默认不携带声音，原视频及音轨仍保留；需要合成时由后续节点处理。
- 分块计算需处理边界和中间缓存，重试不覆盖已完整提交的原始素材。

## 7. 验证计划与发布门槛

先用每类 5–10 秒样片：静态场景移动镜头、人物运动、多人遮挡、快速运动、室内细节、强反光/透明、硬切多镜头。由用户选定一份“白模”目标样片作为视觉标准。

记录模型/权重哈希、后端版本、显卡/显存、尺寸、帧数、总耗时与峰值显存。官方数值只作选型参考。

深度检查：主结构远近、轮廓、帧间闪烁、遮挡、镜头切换、帧时间对齐。白模检查：去纹理程度、轮廓/运动保留、表面稳定、背景边缘与是否误解为完整三维。

发布条件：

1. 不破坏原视频；两次运行产生独立结果和来源。
2. 失败/取消可解释，无半成品被标记成功。
3. 深度包与预览可按帧对应，数值含义完整。
4. 缺少环境/模型或显存不足时在适当阶段明确报告。
5. 在目标显卡上记录实际可用档位，不承诺所有电脑本地运行。
6. 白模未达到视觉标准时，深度节点独立发布，白模保持实验状态，不用灰度视频冒充。

## 8. 选型结论

先验证 Video Depth Anything Small 的视频深度链路；ComfyUI 用于快速实验和可选后端。优先保留高精度深度结果与时序元数据，再开发近似白模渲染。NormalCrafter 用作法线质量研究候选，DepthCrafter 不直接进入默认生产方案。
