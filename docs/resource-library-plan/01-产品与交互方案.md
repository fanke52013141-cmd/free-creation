# 产品与交互方案

## 1. 产品目标与整体结构

让用户持续积累创作材料、提示词和生产经验，并在任意项目中查找和使用。一次生成的优秀图片可以成为参考图，一套有效提示词可以持续迭代，一个角色可以积累不同视角和声音，一组风格可以被整理成长期参考展板。

资源库保存可重复使用的内容与使用方法；画布继续负责生产。保存资源不依赖 Agent，也不要求用户理解节点内部协议。

```text
全局资源库
  ├─ 单份资源：图片 / 提示词 / 音频 / 视频 / 文件
  ├─ 组合资源：人物 / 场景 / 风格 / 自定义资料包
  ├─ 收藏集：手工归类，同一资源可属于多个收藏集
  └─ 展板：收藏集的视觉排布，展示固定版本的图与说明
             ↓ 搜索、选组件、选版本、插入
项目工作台 → 基础节点与真实连线 → 生成结果
             ↑                  ↓
             └──── 收藏、迭代、保存新版本 ────┘
```

## 2. 项目复制

### 2.1 入口和交互

- 首页项目卡片新增“复制”操作，可收进更多菜单，但不能只有隐藏快捷键。
- 项目内部的项目菜单也提供“复制当前项目”。
- 点击打开小弹窗：项目名称，默认“原名称 · 副本”；复制方式；复制后是否打开。
- 默认“完整副本”：包含布局、节点、连线、分组、配置、正文、素材、结果及对话内容。
- 可选“仅结构与配置”：用于复用生产结构，不带媒体、运行结果、历史对话；保留用户编写的固定提示词和节点参数。
- 显示复制进度和失败原因，大项目可取消；完成之前新项目不出现在可打开列表中。

“完整”复制的是用户可继续编辑的内容快照，执行中的任务不克隆为新后台任务。历史运行可作为来源记录保留，副本中的活动运行状态统一归于未运行/已中断的明确状态，不自动继续请求模型。

### 2.2 行为要求

1. 从当前项目复制前，先等待保存完成并固定 graphVersion；如果源图持续变化，复制同一个已提交版本，不能混合不同时间的内容。
2. 创建独立项目和媒体标识；节点、边、分组、导演台等内部引用成套重映射。
3. 复制后的文本、图片、配置可以独立修改，删除原项目不使副本丢文件。
4. 已使用资源固定的版本和本地副本继续保留，不因复制项目而在全局库新增一套重复资源。
5. API Key 属于本机供应商设置，不写入副本或导出包；保留模型配置引用，缺少模型时提示设置。
6. 仅结构复制完成后列出待补素材，不通过清空隐藏字段制造“看起来可运行”的残缺图。
7. 复制失败或取消清理暂存产物，不影响源项目。

## 3. 创建项目时选择节点

### 3.1 统一新建弹窗

首页与画布项目菜单使用同一个组件。默认显示：

```text
新建项目
项目名称：____________
工作台预设：通用 / 图像 / 视频 / 音频 / 自定义

节点选择                       搜索节点…
基础输入   [✓ 文本] [✓ 图片] [✓ 文件]
图像       [✓ 图像生成] [✓ 图像修改] [  图片切分]
视频       [  视频生成] [  视频取帧] …
音频       [  配音] [  音色克隆] …
处理       [✓ AI 处理] [  循环] [  代码] …

可选：初始工作流模板
已选 N 类节点      保存为我的预设
                     取消 / 创建项目
```

选择决定哪些创建入口可见，不自动把所有选中节点铺到画布。模板决定初始图，两者分别配置。

### 3.2 后续修改

项目菜单提供“工作台节点设置”，打开同一选择器。用户随时增加或隐藏节点类型。

- 隐藏只收起创建入口，不删除已有节点、不禁用既有连线或运行。
- 节点库、搜索、右键菜单、快捷创建按钮使用同一配置源。
- 对隐藏节点进行导入、资源展开或模板插入时，显示将添加的类型，允许本次插入或同时设为可见。
- 缺少某类型的实现与“用户隐藏该类型”分别提示；缺少实现不能执行。
- 项目复制继承设置；“保存为预设”影响后续新建项目，不回写其他项目。
- 旧项目缺少该字段时兼容现有行为；首次配置后固定已选列表，新功能通过“新增能力”提示让用户自己选择。
- 基础查看和节点设置入口始终可达，避免全部隐藏后无处恢复。

## 4. 资源库的抽象：内容、组合、组织、配方

### 4.1 基础资源

一个可独立查找和使用的条目，可只有一张图片、一个名称，或只有一段提示词。不能强制每份资源必须同时有图片和提示词。

通用信息：名称、封面、说明、标签、收藏集、来源、创建/更新时间、版本、使用记录。

来源允许未知；收藏外部海报时，不把后来补写的提示词当成原始生成参数。提供“原始配方 / 我推测或整理的提示词 / 暂无提示词”区分。

### 4.2 组合资源

由具备角色的内容槽组成。例如 referenceImage、description、voiceSample、prompt。类型和角色明确，但一个角色可有多项；同一个资源可以拥有多种组件。

人物、场景和风格使用同一底层组合模型，通过不同表单预设引导填写。以后新增产品设定、品牌规范或道具包，优先增加配置，不复制一套表和业务逻辑。

### 4.3 收藏集与展板

收藏集负责分类，一个资源可以加入多个收藏集，不复制文件。可分层，但先限制复杂嵌套，避免形成难以查找的文件夹迷宫。

展板是收藏集的一种视图：自由排列图片、资源封面和说明，支持缩放与对照。展板项默认固定资源版本，原资源更新时提示有新版本；更换版本由用户选择。

“赛博朋克参考集”可以包含很多互不依赖的图片；“某套稳定风格资源”则是一份组合资源，包含指定参考图、风格说明和提示词。二者可以互相引用和整理，但不能混成一个对象。

### 4.4 生产配方

保存一次可复用的生成方法：提示词版本、参考图、变量、节点类型/契约版本、模型与关键参数、结果样例。

配方是资源中的可选组件，调用时填入节点配置。工作流模板另外保存多节点执行结构；资源不隐式藏一条自动执行流程。

种子和模型名称不足以保证完全复现，记录供应商、模型版本（若可获取）、参数和时间；不能获取的值标记未知。

## 5. 用户关心的几类资源

| 表单预设 | 必要内容 | 可选内容 | 使用方式 |
|---|---|---|---|
| 图片/海报收藏 | 名称、图片 | 提示词、来源、用途说明 | 作为参考图或加入展板 |
| 提示词 | 名称、正文 | 变量、参考图、结果样例、适用模型 | 插入文本、带图应用、保存新版本 |
| 人物 | 名称，至少一个有效组件 | 形象多视角、描述、声音样本、角色约束 | 选择所需组件，组合使用 |
| 场景 | 名称，至少一个有效组件 | 多张场景图、场景说明、光照/时间信息 | 图片与描述共同引用 |
| 风格 | 名称，至少一个有效组件 | 参考图集、风格 prompt、反向约束、配方与效果样例 | 风格参考、批量生产起点、视觉展板 |
| 自定义组合 | 名称与组件 | 自定义用途与字段 | 通用资料包 |

### 5.1 人物资源的填写

用户看到“人物名称、人物说明、形象、声音”等自然表单，可以拖入多张图片并标记正面/侧面/服装等用途；声音可以试听并附转录与备注。

底层转换成可复用组件。放入画布时才生成图片、文本、音频等现有资产节点及分组。用户不用先手工创建三个节点才能收藏人物。

声音样本与供应商 voiceId 分开保存：前者是音频资源，后者是带供应商及模型作用域的可选绑定。不同模型不一定能复用同一个 voiceId。

### 5.2 风格资源的填写

最简只需名称和参考图。需要生产时可逐步补充：风格说明、可复用 prompt、可变主体、构图建议、不希望出现的元素、适用模型和结果样例。

例如提示词包含 `{{主体}}`、`{{场景}}`，使用时填写“红色自行车”“雨后的街道”。变量由用户显式定义，未填写必填变量时不提交运行。

把“风格固定部分”和“本次任务内容”分别显示，应用时预览最终文本。不要默认拼接所有描述、标签和注释，避免污染提示词。

### 5.3 系列剧情

建立“系列 A”收藏集，加入人物、场景、风格等资源。每个项目采用各资源的明确版本，库里有新版本时可以选择升级；历史镜头不跟着变。

角色换服装、不同年龄等可以保存为新资源并记录派生关系；修正同一套设定则保存为新版本。这样版本历史不会混入完全不同的人物变体。

## 6. 资源库界面与入口

### 6.1 全局入口

首页增加“资源库”，无需打开项目即可整理；画布侧栏提供“项目素材 / 资源库”切换。

资源库主界面：左侧收藏集和类型，顶部搜索和排序，中间网格/列表/展板，右侧资源详情。详情包含预览、组件、提示词、版本、来源及使用方式。

资源卡片突出封面、名称、类型、标签和版本。纯文本提示词显示摘要；人物显示主图及声音标记；组合资源显示组件数量。

### 6.2 收藏入口

- 项目素材卡片：“收藏到资源库”。
- 图片/文本/音频节点：“收藏此内容”。
- 多选节点：“保存为组合资源”。
- 文本编辑器：选中文字保存为提示词。
- 资源库：导入图片、粘贴文本、新建人物/风格。
- 生成结果：“收藏结果与本次配方”。

多选保存时识别能直接读取的已完成内容，让用户选择组件用途。计算节点的未执行配置不能伪装成素材；只保存生产结构时引导到工作流模板。收藏不自动执行节点。

### 6.3 搜索与节点调用

所有节点统一提供资源搜索入口。搜索范围覆盖名称、说明、标签和提示词正文，可按类型、收藏集和最近使用筛选。

首版做可预测的中文关键词搜索；图像相似搜索、向量检索和自动风格分类作为以后可选能力，不阻塞积累。

选中资源后展示“可用组件”：

- 图像输入位置：选择参考图片，并遵守单张/多张基数。
- 文本输入位置：选择说明或 prompt，预览替换/追加的具体内容。
- 音频输入位置：选择声音样本；显示目标模型是否支持参考音频。
- 无兼容输入：仍可查看或放到画布，不自动接线。

对于已有连线的输入，明确选择替换或追加；单值端口不能静默接入多项。一次批量插入应作为一个撤销操作，失败时整批回滚。

“应用人物资源”时可选择只用形象，或形象加描述，声音不用被强行送入生图节点。

## 7. 版本与积累闭环

### 7.1 版本规则

- 资源具有稳定 resourceId；发布内容有固定 revisionId。
- 编辑草稿可以自动保存；点击“保存新版本”形成不可变修订。
- 内容组件、prompt、配方和版本说明进入修订；普通收藏标记、个人排序不必形成内容版本。
- 默认展示最新发布版本，但节点引用固定 revisionId。
- 回退以旧内容创建新版本，保留历史；也可选择让某项目重新采用旧版本。
- 发布组合资源时固定其组件引用的具体版本；不得让人物 v1 随某个声音资源更新而变化。

### 7.2 同一版本内的对应关系

参考图、结果样例和 prompt 应记录角色与对应关系。例如样例 A 来自 prompt v2，不能因为 prompt 升为 v3 就把样例 A 显示为 v3 的实际效果。

保存修改后的 prompt 后，应显示“尚无本版本生成样例”；用户后续运行再把结果关联到这个版本。

### 7.3 项目局部修改

从库使用后，用户可以在当前项目修改文本或替换图片。此时标记“基于资源 v2，项目内已修改”，不覆盖全局资源。

用户可以明确选择：保存为原资源新版本、另存为新资源、仅留在项目。发布时对 baseRevision 做冲突校验，防止两个编辑窗口覆盖彼此。

## 8. 文件生命周期

收藏时由资源库持有文件副本或经过引用管理的独立 blob，不能只保留源项目路径。使用时把选中组件导入项目本地素材，附加资源版本来源。

采用该策略后：删除源项目不损坏库；归档库资源不损坏已经使用它的项目；项目导出仍可自包含。

资源删除默认进入回收站。收藏集删除只解除组织关系。文件去重按内容哈希进行，垃圾回收只删除无人引用且超过保留期的 blob；没有完成引用管理之前宁可保留重复文件。

全局指当前本机应用的数据工作区，不暗含云同步。资源库备份和迁移需要包含目录、组件、版本及文件；普通项目导出只携带该项目实际使用的内容。

## 9. 与后续能力的衔接

资源库对外提供稳定的查询、读取版本、选择组件和记录使用接口。以后 Agent 可以调用这些接口，但现在的资源创建、搜索、版本和插入均由普通 UI 完成。

生成深度视频、白模参考视频等结果也可以被收藏为资源，附带转换模型及参数。它们沿用同一个内容/版本模型，无需专门再建一个视频参考库。
