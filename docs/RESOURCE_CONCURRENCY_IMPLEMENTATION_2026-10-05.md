# 节点端口与资源并发优化（2026-10-05）

## 本次行为

- 点击/拖动蓝色输入端口不会重排绿色输出锚点。端口卡片和溯源线都计入 artifactProducerPortId，端口槽位按完整声明计算，候选显示仅改变可见性。
- 手动运行、工作流中的节点以及节点测试共享资源队列。同一 projectId/nodeId 在运行或排队时不能重复执行；节点测试与真实执行互斥。
- 不同节点按资源池额度并行。默认模型任务总额度 2、本地 GPU 1、媒体处理 2、其他本地任务 4。生成视频与生成图片共享模型总额度；本地深度/白模视频用 GPU 池，不占模型池。
- 额度不足进入 FIFO 队列，同资源按提交顺序唤醒；不同资源互不阻塞。任务面板提供运行/排队数量、额度调整和逐任务取消。
- 排队取消立即移出队列，不调用执行器。运行取消使用执行器已有 signal：资源在执行器实际返回后释放，避免请求尚未结束就启动更多任务。额度下调不会终止已有任务。
- 每个手动任务有自己的 RunControl、runId、traceId、输出 Map 和运行记录，不再使用“仅生图可与深度/白模并行”的例外规则；完成不会清空另一个工作流的状态。
- 工作流内部仍按拓扑顺序运行，循环体逐项执行；循环体启动前检查占用，避免重置正在独立执行节点的结果。全图/子图的确认与暂停仍由前台工作流入口管理，重复提交工作流仍被防重。

## 使用

顶部“任务”菜单查看任务，输入额度可调整 1–64。取消某个工作流中的当前节点会停止其所属工作流；其他独立任务继续运行。单节点取消只影响该节点任务。

## 边界

额度为当前 renderer 会话中的总资源上限，不是供应商账户的实时剩余额度；不同供应商暂时共用一个模型池。额度和队列不跨重启持久化，也不跨桌面窗口共享。已有主进程 GPU 串行及视频同节点防重复请求保护继续保留。已提交的远端任务能否立即停止依赖供应商能力；此版不承诺停止后退费。

## 验证与审查

- resource-queue：满额排队、同节点防重、取消不执行、运行取消后保留额度、释放唤醒、资源池独立、升降额度。
- manual-run：两个独立任务在额度 1 下排队，重复提交被拒绝，取消排队节点，前台工作流状态不被清空。
- node-port-stability：候选显示前后所有端口 offset 不变，同类型端口共享锚点。
- 浏览器 mock 回归：绿色 out-audio 端口与溯源线偏差约 0.17px，输入按下前/中/后不变；运行入口不再因别的节点运行直接拒绝。本验证未请求真实付费模型。
- 五维自审：检查取消/释放幂等、输入和输出契约、上下文隔离、无敏感日志、按资源唤醒；不引入项目文件/媒体格式变化。
- 验证必须在仅包含本次提交的隔离副本运行，原工作区其他改动存在 lint/类型问题，不随本次提交发布。
- npm run verify 在当前环境因 pnpm 自动切换版本的路径缺失中断；改用 npm --prefix 执行同样的两项模型类型检查，模型 runtime 测试使用原 Vitest 配置执行（补齐隔离副本的工作区依赖链接）。其余门禁按原命令执行。
- 隔离提交验证：lint、node/web 类型检查通过；129 个测试文件通过，共 1479 通过、1 跳过；模型包类型检查及 2 个 runtime 用例通过；日志旁路、优化浏览器门禁和 Electron 生产构建通过。
