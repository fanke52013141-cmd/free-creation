# 节点选中、拖动与输入编辑审查（2026-10-06）

## 结论与原因

截图中 JSON 空态图标/名称区、数据处理的「数据类型」「处理方式」标题区确有事件路由问题：内部容器拦截了 pointerdown，旧公共逻辑只补选中，没有把后续拖动交给画布。保护下拉框的容器也把旁边无操作的标题一起拦住。历史门禁主要点击卡片角落，不能证明内部区域可用。

修复放在公共卡片层，覆盖全部 28 类可创建节点：按实际控件判断指针归属，无功能区域交给 tldraw 的公开指针接口；只读正文、身份图标及名称可以选中和移动。JSON、结构数据、代码、分镜单元格及音频预览显示区补齐双击入口或表面标记。输入框首次单击选中节点并允许拖动，双击聚焦编辑，失焦/Escape 退出；原有节点保存/取消逻辑保留。下拉框、即时按钮、滑块、真实端口和裁剪手势保持自身操作。

同时移除第二次 mousedown 提前打开编辑器/对话的桥接，改为完成 dblclick 后按坐标恢复命中目标，修复连续单击后拖动被误当双击的问题。转发的非可信 dblclick 不再次桥接，React portal 弹窗不参加节点指针路由。

规则已写入 [节点 UI 规范 §19](./NODE_UI_STANDARD.md#19-v13-按内容布局协议2026-10-05当前权威) 和 [AGENTS.md](../AGENTS.md)。

## 实测结果

新增真实浏览器指针门禁 `scripts/test-browser-node-pointer.cjs`，已纳入 `npm run verify`。每类节点至少检查一个非控件内部区域，单击必须选中，拖动必须产生坐标变化；输入框验证单击不聚焦、拖动、双击、实际输入及 Escape 退出。长表单字段先滚动到可见位置再检查。

28 类节点共 **101 个内部区域、20 个可编辑输入框通过**。详细可追溯清单：[results.json](../qa/node-pointer-2026-10-06/results.json)。额外通过：

- JSON、结构数据的空态及内容态选中/移动，双击进入编辑。
- 已加载音频的图标/名称选中和移动，双击打开音频预览。
- 数据处理下拉框即时切换、多选修饰键、拖动撤销。
- 现有引用、隐藏滚动条与滚轮、分镜尺寸、节点缩放/布局、对话生图等 13 支 UI 门禁，加本支共 14 支通过。
- 全量 `npm run verify` 成功：140 个测试文件；1531 项通过、1 项原有条件跳过；model-runtime 另 2 项通过；lint、类型检查、日志门禁及 production 构建通过。新增指针策略单元测试 4 项通过。

## 五维审查与边界

| 维度 | 审查结果 |
| --- | --- |
| 正确性 | 按实际 DOM 控件划分路由；公共接口保留多选/分组/撤销语义；实测内部区域及编辑态，双击完成后才触发操作。 |
| 可读性 | 指针归属集中到 `node-pointer-policy.ts`；节点只声明必要的表面/双击标记，未逐节点复制路由。 |
| 架构 | 沿用 tldraw 公共 dispatch/getPointerInfo，业务控件仍用原回调；不改变端口、executor 或节点数据协议。 |
| 安全 | 不增加网络/模型请求、不持久化输入内容或点击日志；portal 不被卡片路由接管，转发事件有递归保护。 |
| 性能 | 判定只在交互时运行，不为每个节点注册全局定时器或 pointerup 监听；既有渲染路径保留。 |

本次是交互验收，不等同于每个供应商/模型/媒体解码器的运行验收。音频夹具用于验证预览手势，不验证真实音频质量。条件跳过的原有真实媒体用例没有改成虚假通过。

日志影响：复用画布撤销与项目保存链路，节点执行/媒体/模型的诊断保持原样，不新增逐指针日志，也不记录输入值；见 [日志覆盖清单](./LOGGING_COVERAGE.md)。
