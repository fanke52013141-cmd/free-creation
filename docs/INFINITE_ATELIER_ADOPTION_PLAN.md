# Infinite Atelier 借鉴计划

> 状态：决策草案
>
> 更新日期：2026-08-28
>
> 参考项目：[GuiYi-Xi/infinite-atelier](https://github.com/GuiYi-Xi/infinite-atelier)
>
> 本文的目标不是复制参考项目，而是把值得借鉴的交互和功能拆成可验收的开发切片。节点输入输出契约、Electron 本地数据安全和 executor 架构优先级高于视觉相似性。

## 1. 使用方式

每一项借鉴都按以下顺序处理：

1. 锁定参考仓库的具体 commit，记录对应目录、组件或交互证据。
2. 判断该能力是否符合本地单用户产品边界。
3. 判断该能力能否用现有节点组合表达；只有不能清晰表达时才新增节点。
4. 明确是否改变端口、Schema、配置或运行结果语义。
5. 先写自动化测试，再实现 UI 或执行逻辑。
6. 按本文验收标准进行桌面端回归。

当前环境无法稳定读取 GitHub 页面，因此本文把结论分成三类：

- **已确认**：本仓库已有实现或 `REFERENCE_INFINITE_ATELIER.md` 已明确记录。
- **可借鉴**：从参考项目定位和现有交互记录推导出的候选方向，接入前必须锁定 commit 实测。
- **不采用**：与节点契约、本地数据安全或产品边界冲突。

## 2. 总体结论

我们与 Infinite Atelier 不是同一个功能集合：

```text
视觉和交互方向：部分相似
基础 AI 节点能力：有较大重叠
节点协议和执行架构：我们更严格，不能复制参考项目的数据流
媒体结果和资产工作流：我们有基础，但体验还不完整
批处理恢复能力：双方都需要进一步确认，我们当前明显不足
真实 3D / 图片转模型：当前不属于已完成能力
```

当前已经借鉴的内容：

- 节点卡片的参数摘要和低噪声信息层级。
- 节点状态、选中态、关联高亮和悬浮操作。
- 从连线末端快速创建兼容节点。
- 多媒体结果预览和单项操作的方向。
- 资产面板、历史面板和画布定位的方向。
- 导演台的镜头列表、资源区、预演区和时间线层级。

尚未完成的高价值借鉴：

- 生图/视频多结果网格、结果对比和结果选优。
- “基于此结果继续创作”“设为参考图”等短路径操作。
- 资产按类型、来源、节点、时间和状态筛选。
- 运行历史和失败任务的检索、重试、定位。
- 处理节点的字段映射和常用数据变换。
- 迭代节点的暂停、恢复、只重试失败项和断点续跑。
- 更完整的节点快捷操作和键盘工作流。

### 3.3 明确不采用的 UI/架构方向

- 用无端口连线表达“流程关系”。
- 通过上游节点标题或类型猜测输入。
- 把多个业务阶段折叠为一个巨型节点。
- 使用浏览器 `localStorage` 作为项目库。
- 使用 iframe 作为导演台核心架构。
- 在节点组件内直接调用模型或写入隐藏输出。
- 通过快捷按钮产生未声明的业务输出。

## 6. 分阶段实施计划

### IA-0：参考基线锁定

目标：把候选借鉴从“印象”变成可引用证据。

任务：

1. 固定 Infinite Atelier 的参考 commit 和许可证信息。
2. 建立节点、结果卡、资产面板、工作流模板、快捷操作、导演台的截图/代码索引。
3. 将本表中“可借鉴”条目改成“已确认/不适用/待决策”。
4. 不把参考项目代码复制进本仓库。

验收：每个要实现的借鉴点都能指向参考 commit、目录或截图，并有采用理由。

### IA-1：节点卡片和结果卡统一（第三批完成）

目标：先提升每天都会使用的交互，不改变节点协议。

任务：

1. 统一节点卡片标题、状态、端口、摘要和错误区域。
2. 统一图片/视频/音频结果卡的预览、来源、重试、定位和继续创作动作。
3. 增加图片/生图/视频/音频多结果展示和选优状态。
4. 结果集合限制为最近 12 项；支持清空历史候选并保留当前输出。
5. 快捷操作只创建真实节点、真实连线或更新已声明输出引用。

当前进度：

- 图片资产和生图结果已增加“继续生图”和“生成视频”快捷入口。
- 快捷入口会创建真实下游节点，并建立 `out-image -> in-image` 端口连线。
- 连线失败会删除刚创建的节点，不留下孤立节点。
- 媒体结果的来源摘要沿用现有 `meta.nodeResult`，未引入新的隐藏输出。
- 图片、生图、视频、音频结果卡已接入统一的来源摘要组件。
- 四类媒体结果卡均提供一致的本地文件操作：定位、复制路径、系统打开。
- 四类媒体结果卡均支持结果集合；图片/视频/音频可切换当前结果，音频以轻量占位缩略图展示。
- 结果历史具备数量上限，清理历史不会改变当前媒体资产或正式输出端口。
- 统一结果操作区不改变上传、重新生成、播放和预览的节点专属逻辑。

尚未完成：跨节点统一的运行状态徽标、结果并排对比和单项删除 UI。单项删除纯函数已具备，待在结果卡交互中确定删除确认与资产回收策略。

验收：任意媒体结果都能看懂来源、状态、下一步动作；重复生成会追加到结果集合；切换结果后下游仍只读取原有 `out-image` / `out-video` / `out-audio`；自动化验证输出端口没有变化。

### IA-2：资产与运行中心

目标：让用户能从结果反查输入、节点和项目位置。

任务：

1. 资产面板增加类型、来源节点、生成时间、项目位置和状态筛选。
2. 增加“定位到节点”和“定位到运行记录”。
3. 增加跨节点运行历史查询，保留敏感信息脱敏规则。
4. 失败任务提供重试、查看输入和回到节点三个动作。

验收：从一个媒体资产可以反查产生它的节点、运行 ID、输入端口和本地路径；不显示 API Key。

### IA-3：处理和结构化数据体验

目标：补齐参考项目轻量操作与我们严格 Schema 之间的空白。

任务：

1. 处理节点增加字段提取、字段重命名、字符串模板、数组过滤和数组映射配置。
2. JSON 节点增加字段树、字段路径复制和结构模板。
3. 代码节点增加安全模板、运行预览和错误行定位。
4. 所有新增动作仍写入 `props.config`，不把运行结果写回配置。

验收：每个变换都有明确输入/输出说明；非法结构在运行前被拒绝；契约快照和执行测试通过。

### IA-4：迭代节点可恢复执行

目标：把批量创作从“一次性运行”提升为可恢复任务。

任务：

1. 为每个列表项建立独立运行 ID 和产物引用。
2. 增加暂停、恢复、取消和只重试失败项。
3. 增加断点续跑和并发数配置；默认保持串行。
4. 迭代结果面板显示每项输入、状态、错误和输出资产。
5. 测试失败项不会覆盖成功项的运行记录或媒体。

验收：20–100 项任务可暂停恢复；只重试失败项；重新打开项目后仍能识别已完成项。

### IA-5：模板和快捷入口

目标：缩短常用工作流，但不隐藏业务步骤。

任务：

1. 建立“文本→AI 处理→分镜”“分镜→迭代→生图”“分镜→导演台”等模板目录。
2. 模板套用时展示将创建的节点、端口和连线。
3. 支持保存用户模板、命名、复制和删除。
4. 增加从结果卡创建下游节点的快捷入口。

验收：模板创建的每条边都指向真实端口；模板恢复、保存和导入导出有测试。

### IA-6：桌面端体验验收

目标：确认借鉴后的交互在本地 Electron 中稳定。

任务：

1. 新建项目完成节点创建、连接、运行、结果选择和资产定位。
2. 保存、关闭、重开后验证配置、正文、运行结果和媒体引用。
3. 离线启动验证画布、资产和已落盘结果可用。
4. 窄屏验证面板、结果网格、资产筛选和错误提示不溢出。

验收：自动门禁全部通过，并完成 `INTERACTION_ACCEPTANCE.md` 对应人工路径。

## 7. 节点新增门槛

本计划默认不新增节点类型。只有以下情况才允许新增：

- 现有节点组合无法清晰表达该能力。
- 输入/输出可以独立定义并通过 Schema 表达。
- 执行器、投影、失败路径和持久化都能独立测试。
- 新节点不会只是把多个隐藏步骤塞进一个配置对象。

候选的新节点只有在 IA-3 或 IA-4 验证后仍无法表达时再评估，例如独立的模型资产节点或图片转模型节点；它们不属于本轮 UI 借鉴的默认范围。

## 8. 验收和发布门禁

每个借鉴切片必须通过：

```powershell
npm run lint
npm run typecheck
npm test
npm run build
git diff --check
```

涉及节点时还必须通过：

```powershell
npm run test:contract
```

涉及媒体时必须额外验证：

- 结果落盘为 MediaAsset。
- 结果来源和运行 ID 可追踪。
- 失败和取消不会产生旧输出。
- 导入导出会重映射媒体 ID 和相对路径。
- 导出包不包含 API Key。

## 9. 当前唯一推荐顺序

```text
IA-0 锁定参考基线
→ IA-1 节点卡片和结果卡
→ IA-2 资产与运行中心
→ IA-3 处理和结构化数据
→ IA-4 迭代可恢复执行
→ IA-5 模板和快捷入口
→ IA-6 桌面端验收
```

导演台和图片转模型暂不作为本计划的前置工作。等上述通用体验完成后，再单独评估真实 3D 模型资产是否值得进入产品主线。
