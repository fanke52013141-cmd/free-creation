# C3.3 自动审核与有界返工验收

日期：2026-10-14。状态：C3.3 文本/JSON 首批范围验收完成，下一步 C4。保护现有模型接入、手动流程和不可变任务/资产；媒体、并行及任意节点建图不在本次完成范围。

交付路径：专业 Agent 通过授权能力节点交付固定文本/JSON → 主控通过显式控制关系触发公共审核 executor → 拒绝时固定原始任务输入、被拒版本、规则及报告身份 → 创建独立返工任务 → 新版本复审 → 通过后释放下游。

- 纯 AI：主控在原权限范围创建并启动新任务，旧任务和回执保留。
- 人机协作：负责 Agent 显示反馈，新返工任务准备后等待人明确启动/继续；讨论和目标修订不隐式执行。重开等待不重复派发。
- 纯人工：文本/JSON 负责节点显示反馈，人保存并明确提交新资产版本，主控明确继续后复审。只允许本次待修订正文变化，配置、模型、端口、关系和权限变更仍拒绝。

第一批只接已适配的文本/JSON 与数据处理能力。Agent 可以选择其已授权的修订能力节点；不向未适配 executor 偷塞反馈或隐式改配置。主控必须声明审核控制关系和工具权限；普通旧图不自动加入返工循环。审核模型只提供结论，调度、预算、状态和完成事实由可信宿主决定。

验收包括三类返工、停止策略、质量轮次/总预算、技术失败无结论、旧批准失效、去重、跨进程人工等待、同输入旧任务不改写、未知结果不重放、迟到结果不推进和旧节点回归。先执行 GLM 当前路径基线，再实现并验收闭环，最后运行完整门禁。真实模型只使用隔离项目/数据库与隐藏窗口，凭据从主进程本地加密目录读取并仅经子进程环境传递，不进入仓库/证据。

日志检查：复用 agent.coordination/agent.desktop、模型/节点/保存/命令/资产公共生命周期；新增控制阶段记录 review/task/node/version 身份、轮次及稳定原因，不记录反馈、目标、规则、正文、回复或密钥。日志故障不得改变业务结果。证据、终态配对、脱敏和未覆盖边界在完成后登记。

## 实施与日志自查

主控运行 body_json 增加可选 reviews/controlSteps；旧记录默认没有自动审核，不需要数据库结构迁移。审核 pending 请求在执行前持久化，只有同 scope、同请求的公共审核获得占用许可；结果必须与当前保存图签名、正式 nodeRun/nodeResult 及权威报告一致。发布等待必须对应当前 runId 和终态，禁止将上一轮成功当成本轮完成。自动审核和创建返工均计入总预算，技术失败留 pending/blocked，不自动重试；取消会终止本地等待并拒绝迟到结论，不能宣称远端已经撤回。

日志模板自查：

| 路径 | 事件/职责 | 允许信息与排除 |
| --- | --- | --- |
| 启动/继续/完成/失败 | main 的 agent.desktop 与 agent.coordination；公共 executor 的 node/workflow | project/node/task/trace/span，固定 phase/code；排除目标、正文和原始异常 |
| 审核/返工阶段 | main 的 agent.coordination.stage | 当前 request、review/reworkTask、固定 version、round、subjectCount；排除标准与反馈 |
