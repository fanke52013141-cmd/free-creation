# Agent 全面测试用例集

版本 1.0 · 策划基线 `b96faf4` · 2026-10-16 · **以下均为待执行定义，不是测试结果。**

与[总体方案](AGENT_TEST_PLAN_2026_10_16.md)配套使用。[CSV 台账](AGENT_TEST_EXECUTION_2026_10_16.csv)含实际结果、状态、缺陷、证据、执行人等空栏。所有多参数用例必须拆子记录，不可只测一个参数就把整行标为通过。

共 17 个模块、144 项定义（104 项 P0、35 项 P1、5 项 P2）。初始台账中 131 项未执行、12 项真实模型/供应商暂缓、1 项真实设备专项条件待定义。

P0：数据/权限/重复副作用/关键主路径；P1：核心组合和恢复；P2：次要兼容与体验。执行方法“单测/集成/桌面/人工/专项/真实”对应总体方案 L1–L6。数据集和 P1–P6 项目定义见总体方案第 6 节。除 AI 和真实设备专项外均使用隔离数据和确定性夹具。

现有单测和桌面脚本只表示自动化基础；每条定义须核对当前断言，不得默认已有覆盖。人工步骤、缺失故障点、长驻观测和真实质量测试需要补齐。每例最低证据为版本/runId、实际结果、关键截图或断言报告；有副作用的用例还必须留请求计数和任务/命令/资产事实摘要。

## 执行记录的填写规则

- 原始用例保持不变，执行台账按 `ID + variant` 增加子例，例如 `PAR-01 / parallel=4,cap=2`。
- “预期请求数”在启动前填写，分别计模型决策、业务生成POST、查询、下载、审核。不同计数不能合并掩盖重复生成。
- 用例失败时保留最小复现与故障现场；修复后新增复测记录关联旧记录，不覆盖第一次失败。
- 真实设备 REC-12 默认“阻塞（专项条件待定义）”；AI 组默认“暂缓”；其余默认“未执行”。状态不是产品缺陷结论。
- 本轮完整验收需覆盖定义中的全部适用参数；未执行/阻塞/暂缓项明确列入最终报告范围。
