# C2.2 生产执行命令桥

日期：2026-10-12。状态：命令意图协议与语义指纹基础已实现，**尚未接入 IPC、持久命令账本或 renderer 派发**。Agent 节点保持执行待接入。本文件承接 [生产桥审阅](09-model-probe-and-production-bridge-review.md) 与 [C2.1 资产版本](11-c2-asset-versions.md)。

## 已实现的前置协议

`src/shared/agent-flow/commands.ts` 定义严格的 node.execute v1 意图：commandId/projectId/taskId/agentNodeId/targetNodeId、expectedSemanticRevision、contractVersion、固定输入清单及 trace/span。每个输入条目明确 targetPortId，资产引用必须完整包含 assetId/versionId/sourceNodeId/sourcePortId。目标端口不可重复，全命令最多 128 个资产引用。拒绝自执行、正文、额外字段、不完整引用及非法修订。空清单只表示意图没有固定输入，是否可执行仍由正式契约校验。

`src/main/agent-flow/command-intent.ts` 计算 main 内部 SHA-256 语义指纹，来源为已保存项目图及对应 node-card 快照。正文、固定配置、媒体来源、正式端口/契约版本、固定投影/资产引用、控制/审核关系配置、workspaceProfile 与输入边变化影响指纹。节点 ID 归一排序；对象属性顺序不影响指纹，多输入的边顺序保留。当前保守包含标题；修改标题也拒绝旧意图。

graphVersion/更新时间、节点位置/尺寸、相机、运行状态、nodeRun/nodeResult 不影响指纹。不可变输入由清单固定，不能在执行时偷偷换成新产物。缺少或不匹配的图节点快照拒绝。指纹不等同自增修订号；未来如持久修订号，仍须保留相同语义裁决。

命令意图签名覆盖业务身份、契约/语义版本及固定输入；不包含 trace/span，重试可建立新诊断关联。端口清单顺序归一，每个端口内部资产顺序保留。commandId 由未来账本作为查找键，签名用来拒绝同键不同意图。

这些函数为协议基础，没有运行调用点，不读写项目/数据库、不执行节点、不派发模型，也没有新增运行日志。Schema 通过不代表任务存在、Agent 获得处理范围或目标端口合法；授权必须由下面的主进程路径完成，不能让调用者提供“可信端口”或执行许可。

## 接入顺序与职责

1. **main 接收与授权**：限制当前桌面主窗口/main frame；绑定当前项目和真实任务；从已保存 Agent config 校验允许处理的节点，不把 Skill/tool 声明当权限。读取任务状态、计算当前语义指纹、比对目标正式契约。首条对等路径选确定性数据处理节点，不开放媒体/模型副作用。
2. **固定输入准备**：按 targetPortId 解析完整资产引用，使用 C2.1 FlowAssetStore.resolveInputs 校验同项目身份及 digest；由正式注册契约检查端口存在、类型、Schema、必填性和基数。固定清单覆盖本次输入，缺项不能降级读取当前上游。保留端口内顺序和资产来源。
3. **持久占用与派发**：命令账本与目标占用由 main 管理；同 commandId 同签名返回原状态/回执，不同签名拒绝。原子保存 pending 和占用后才派发，避免副作用发生后才补记录。pending 在本轮活会话内只等待同一次派发；重启、超时或失联后的 pending 转 unknown，不自动重发。
4. **renderer 公共执行**：窄适配器只处理当前项目/目标节点；排队后再次检查项目、语义修订与正式契约，再把固定输入交给现有 executeNodeOnce。复用队列、取消、executor、输出校验、物化和诊断，不能复制一套处理逻辑。改动不得破坏原 runNodeManually 行为。
5. **保存与回执**：正式结果完成后等待保存协调器收敛。main 校验保存的运行身份/输出与此次命令相符，再将输出资产与回执做 SQLite 事务提交，保存文件与数据库之间的故障靠 pending/unknown 核对处理，不宣称二者跨介质原子事务。执行 done、画布 applied 或 toast 均不能代表回执 committed。
6. **checkpoint 推进**：只有持久 committed 回执可推进任务；失败/取消保留真实状态，unknown 停在核对点。审核/返工 gate 接入后手动与 Agent 入口共同适用，审核 v1 不能放行 v2，技术失败不能转换成“否”。

主进程必须持有真实任务与命令权威记录。renderer 回执不能自行决定 taskId、授权范围、最终提交成功或 checkpoint；C0 的 fixture 账本不能作为生产验收替代品。

## 回执与失联裁决

回执至少关联 commandId/taskId/agent/target、意图签名、执行 attempt/nodeExecutionId/runId、固定输入版本清单、输出资产版本、终态及保存/提交状态。错误只记录稳定 code 和失败阶段，不保存原始异常到诊断。

| 断点                                       | 裁决               | 后续行为                                   |
| ------------------------------------------ | ------------------ | ------------------------------------------ |
| 授权/修订/输入校验失败，尚未派发           | rejected           | 明确修复原因，旧命令不执行                 |
| pending 已持久，尚未确定 renderer 是否接受 | unknown            | 核对原命令，禁止自动重发                   |
| renderer 正在执行、取消或失联              | pending 或 unknown | 取消需真实确认；超时不是“从未执行”         |
| 产物已物化但项目保存失败/结果不明          | unknown            | 核对已有运行及保存事实，不再次执行         |
| 项目已保存但资产/回执事务未完成            | unknown            | 从已保存且匹配的运行核对提交，不能重做业务 |
| 回执已提交，但 IPC 回传丢失                | committed          | 同 ID/意图读回原回执                       |
