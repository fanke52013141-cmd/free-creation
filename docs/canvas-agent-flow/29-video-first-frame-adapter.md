# 首帧图片接入 Agent 视频调度

日期：2026-10-15。接续 [28：文生视频](28-video-agent-adapter.md)。本包为本地开发，26–29 包尚未提交/推送；不生成安装包，不安排旧项目迁移专项。

## 用户路径与实际范围

用户将一个普通图片素材节点的 `out-image` 接到 video v7 的 `in-images`，选「首帧生视频」，可另接一路 `in-text` 或填写视频节点自己的提示词。主 Agent 分派视频专业 Agent，专业 Agent 通过既有 `node.execute`、公共视频 executor 与 gateway 执行；结果未知时保留原命令与视频任务，明确核对/继续后交付一个固定视频成果节点。

仅放开 `text` 与 `first-frame`；首帧必须恰好一个固定图片版本，文本至多一个版本/一条边。首尾帧、多图 reference、音频/运动参考和提示词包暂不在 Agent 调度范围，普通手动节点继续沿现有规则。已有连线会参与手动模式推导，接线后须明确选择「首帧生视频」，不能把「参考生视频」自动认作本适配。

## 本包解决的问题

1. 图片此前不能提交为 Flow 固定输入。主进程与画布现在共用普通 image 素材输出投影，资产值保存媒体 ID、相对路径、MIME 和 SHA-256。图片来源限定当前项目媒体目录，验证索引类型、MIME、文件长度、真实路径和实际文件内容。首包上限 20 MiB，不复制图片文件；原文件丢失或被替换时明确阻断，不从别的路径猜图。
2. 一路文本的旧准入不能容纳首帧加文本。桌面准入和命令授权按端口验证，允许各一路；不扩大成任意多图。图片必须来自固定资产版本，不能把 JSON 媒体描述当图片。
3. IPC 不能仅凭 renderer 传入的媒体 ID 生图。gateway 用原命令清单回读版本，核对完整资产引用、版本摘要和首帧媒体 ID；异步媒体读取后再次对实际编码字节校验，确保发出的就是固定首帧。已有绑定任务还比较 mode/firstFrameMediaId；成功、失败、取消或未知的原任务均不因同命令恢复而重新生成。
4. 桌面验收发现媒体输入摘要不对等：renderer 过去精简媒体字段，main 对完整媒体值计算，造成原任务已成功而命令不能确认。媒体规范化收进公共 `computeInputFingerprint`，保留原手动媒体摘要语义，固定首帧另含内容摘要。回归断言两端同值且换内容摘要会改变指纹。
5. 固定图片可以通过原资产面板放到画布，仍是普通 image 节点，`out-image` 使用 pinnedOutput 与固定摘要；预览、选中、拖动和双击查看沿公共规则。媒体固定成果没有「可编辑副本」按钮；文本/JSON 原行为不变。

## 恢复、停止与限制

复用 28 包原 command/task/lease 绑定、停止持久化、unknown 占用和恢复规则。图片摘要变化时不能接回执行；先处理原资产/原任务事实，再明确创建新任务。字节读取阶段发现变化、尚无可信远端身份时仍按视频公共路径保守保留 unknown，禁止自动重发。命令准入/版本校验失败无生成副作用；不根据诊断文字判成功，不伪造远端撤回。远端事实核对沿既有官方 Ark 支持边界；其他供应商/代理没有可信核对能力时继续保留未知，不保证能自动接回。

本包没有视频内容理解/视觉审核，没有增加图片生成 Agent 目标、第二套媒体执行器或节点类型。Agent 的成果端口仍为文本/JSON，原生媒体版本通过既有结构化引用交接，视频成果节点保留视频端口。
