## 2. 核心验收场景

上帝 Agent 按用户要求构建材料节点、主 Agent、分析 Agent、整理 Agent、状态机以及所需能力/成果节点：“先分析材料，再整理成 JSON，等我选好结果后继续。”

1. 用户在主 Agent 节点输入目标，指定当前材料和允许操作的范围。
2. 主 Agent 给分析 Agent 分配任务和固定版本的最小输入，按完成条件交接给整理 Agent；缺少结构时请求上帝 Agent 或用户补齐，没有适配能力时明确说明缺口。
3. 专业 Agent 独立多步执行并调用明确能力节点，成果在画布可查看、可定位、可连接，来源关联到本次任务和运行；两个 Agent 的上下文、状态和预算分别记录。
4. 状态节点显示实际等待条件和可选成果。用户在成果节点编辑，保存新版本；在状态节点选择版本。
5. 主 Agent 读取这次选择，校验图和输入版本，执行明确的后续节点；旧成果保留来源。
6. 用户暂停控制循环，可以继续操作不受占用的其他画布节点；再次继续不重复已完成操作。
7. 保存、关闭、重开后，主 Agent、状态、成果、连线和已选择版本仍在同一张画布中；安全恢复规则生效。

C3 先以运行中场景验收 1–6，C4 增加进程重开与故障注入。真实模型验证必须明确模型、本机可用条件和实际结果；合成模型只能证明接口行为，不替代真实自主控制验收。

## 3. 不可省略的边界验收

| 条件                             | 预期行为                                                    |
| -------------------------------- | ----------------------------------------------------------- |
| 用户修改节点后，Agent 提交旧命令 | 拒绝冲突、保留用户修改、重新读取；不静默覆盖                |
| 相同执行命令因超时再次提交       | 返回原回执，只有一次业务执行                                |
| 用户拒绝候选                     | 决策持久保存，仍可继续讨论/编辑；刷新不会恢复成未处理       |
| 能力执行失败                     | 对应节点显示真实失败和可操作原因；主 Agent/状态节点可定位它 |
| 控制或状态反馈回到主 Agent       | 不被当作数据循环，也不造成自动无限派发                      |
| 用户拖动或折叠节点               | 不改变执行输入、控制范围和业务状态                          |
| 自动执行与手动运行撞到同一节点   | 只允许一个有效执行者，另一操作显示占用原因                  |
| 结果已保存而画布物化失败         | 可重试补齐同一成果节点，不丢结果、不造重复节点              |
| 重开时无法证明请求是否完成       | 显示需核对，不自动重复有副作用的调用                        |
| 本地模型缺失或离线               | 主 Agent 明确不可用原因；已有画布编辑和本地能力仍可用       |
| 加入一种新业务能力               | 通过节点扩展接入，无需修改主 Agent 的领域分支               |
