# C3.3 首包：主 Agent 顺序协调与固定成果交接

日期：2026-10-13。范围：已有画布上的主 Agent、两个专业 Agent、声明式 Flow 阶段和专业节点的人工等待。整个 C3.3 尚未完成；搭建 Agent 建图预览/事务提交、AI 审核与有界返工仍待后续。

## 画布路径

1. 创建材料、分析与整理专业 Agent，分别绑定自己的处理节点、模型、Skill 和真实输入连线。整理 Agent 可选择人机协作。专业执行能力仍限已适配的文本/JSON 与数据处理节点。
2. 主节点职责选“主控”，选择文本模型、`agent.dispatch@1` 工具和两个专业节点作为允许处理范围；通过“观察的节点”绑定一个状态机。主控不直接执行专业范围之外的处理器，不支持主控 Skill。
3. 状态机示例：`draft --flow.started--> working`；working 上 `agent.dispatched`/`agent.completed` 留在 working，`human.wait`/`flow.paused` 进入 waiting，`flow.completed` 进入 completed；`waiting --human.continue--> working`。没有声明的转换会阻断。
4. 主节点填写目标并明确启动。主模型每轮提出一个专业任务、完成条件及该节点已连接材料的最小固定引用；宿主重新核对范围和语义版本后，创建独立任务。专业任务拥有自己的 taskId、预算、上下文和 SQLite checkpoint。
5. 分析完成后，公共 Agent executor 将真实输出呈现并保存到专业节点，固定成果可查看、连接；整理节点只有在其真实数据来源已有成果时才可派发。模型的完成文字不构成资产事实。
6. 整理等待人时，主节点释放执行资源并等待。用户在整理节点选择版本、明确继续，再回主节点继续；完成必须采用选定资产，已有工具不重放。主控收尾要求全部指定专业任务真实完成，并只引用其固定资产。
7. 主节点支持“暂停派发”：当前决策/专业任务收尾后停止新派发，预算不返还；人工继续后推进。停止取消未终结专业任务并释放控制范围，不回滚已提交业务，也不宣称远端请求已撤销。

## 一致性和持久化

SQLite v15 新增主控运行、阶段事件和控制范围独占表，只有执行事实；画布节点、配置和数据边仍是唯一可编辑流程定义。一个范围只有一个协调者；两个主控不能接管同一专业节点/处理器，手动运行范围内处理器被占用检查拒绝。专业工具仍走 C2 lease/revision/保存/回执。

主模型只得到授权节点目标、固定引用和完成摘要，不读取其他专业会话、Skill 正文或检查点。专业模型只得到自身任务材料与回执。候选固定与派发复用同一份宿主快照；自动保存仅推进 graphVersion 不重复固定材料，实际语义变化仍拒绝。

主控有限循环使用 LangGraph；专业任务作为独立根运行，隔离框架 AsyncLocalStorage 的父图上下文，不能把专业任务误作主控子图而共享等待/checkpoint。状态迁移检查 revision，事件去重/冲突和状态提交同一事务；完成事件先验证全部专业任务和资产。状态机卡片显示 main 的事实，本包不开放独立状态机执行或 `out-state` 资产投影。

已完成/人工等待可以保存重开；遗留 running 的主控任务仍保守阻断核对。崩溃全部间隙、迟到矩阵、待物化补投影和模板/引用迁移归 C4。修改专业目标/输入后自动接续仍未支持，语义变化保守阻断，不能把普通恢复等同完整恢复。

## 日志自查与边界

新增 `agent.coordination.started/completed/failed` 记录开始/唯一终态，关联 project/node/task/trace/span，失败记录固定 phase/code。模型决策沿 `model.request`，错误额外记录工具调用数量和规范化结束原因。专业 executor、业务节点、C2 命令、保存和资产负责原有阶段；发布未确认另记 `agent.publication.failed`。不记录目标、完成条件、专业会话、材料、模型回复、推理、反馈或密钥。日志故障沿公共 SDK 不改变结果。

仍不支持：自动建图/结构预览提交；AI 审核、人工/纯 AI/人机协作三类返工和质量预算；专业任务并行、主控 Skill；主控内修改专业任务后的自动接续；媒体自动协调、独立状态机端口执行、完整恢复与迁移。

唯一下一步：C3.3 建图预览与事务提交，在同一张画布建立可校验的主控/专业/状态/成果关系，然后接 AI 审核和有界返工。首包通过不等于完整 C3.3 退出条件通过。
