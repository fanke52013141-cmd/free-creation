# C3.1b：画布 Agent 任务入口

日期：2026-10-13。状态：首条桌面路径、最新真实模型与完整门禁已通过；结果见开发台账。当前运行范围是**专业 Agent、文本/JSON 输入与数据处理工具**，不是全体节点的自动调度。

## 在画布中使用

1. 给材料节点填写文本或 JSON，连接到专业 Agent 的对应输入端口。把业务材料同时接到允许调用的数据处理节点的真实输入端口。
2. 打开 Agent 设置，选择“专业 Agent”、自主处理或人机协作，以及本机配置的文本模型。主控/搭建角色的自主执行仍待后续，默认角色可通过“配置专业 Agent”进入设置。
3. 勾选材料分析、JSON 整理或结果检查 Skill，启用画布节点工具，并选择允许处理的具体节点；保存配置。原版本绑定字段保留，缺失或未支持的绑定会在启动时明确拒绝。
4. 在 Agent 卡片填写目标、交付条件和处理顺序，点击“启动任务”。启动先确认项目保存，main 从保存画布派生范围和固定版本；模型不能扩大工具范围。
5. 执行时卡片展示真实任务阶段与决策次数，并提供“停止任务”。公共工作流取消同样会通知 main。取消不等于撤回已执行的业务或供应商请求；迟到结果不能推进任务。
6. 人机协作可停在人工确认；卡片提供“确认并继续”和“停止任务”。保存重开后继续从持久 interrupt 恢复。未知工具结果使用“核对并继续”，只核对原命令，有不确定性时继续等待，不换 ID 重做。
7. 完成后，Agent 的 out-text/out-json 只输出已确认回执中的成果。公共执行器将固定资产落到普通文本/JSON 节点，可查看、连接下游或创建可编辑副本。相同任务/资产版本的重复回执不重复落图；Agent I/O 面板还可按文本/JSON 端口提交经过 main 核对的版本。

Asset 节点是成果载体，Agent 卡片中的目标或讨论不是正式资产。首包不支持任意 Skill 文件导入、脚本执行、媒体自动调度、聊天修订或人工挑选替代版本。

## 执行与持久化

- Agent 的自注册 executor 通过 GatewayClient 调 main；React 只发起公共运行或明确的控制动作，不直接调用模型。Agent 使用独立协调资源槽，避免占满本地额度后等待自己调用的处理器。
- 任务 scope、目标、配置、模型身份、Skill/工具版本、直接输入和目标节点输入都从保存画布读取。文本/JSON 端口真实连线决定材料；不按标题、位置或上游类型猜测内容。未适配媒体输入/目标拒绝。
- 模型来自现有 catalog、main 密钥读取和 OpenAI-compatible factory。首次使用当前连接/模型先做两次有界工具协议探测，失败不开放运行。每次决策只有一个 SDK 动作；正文上下文和已观察资产总量有界。
- Skill 主指令使用声明的 SKILL.md 身份，参考资源列在上下文和工具 Schema 中。未声明资源仍拒绝。LangSmith/LangChain 外部 tracing 明确关闭；模型请求诊断使用既有入口。
- 业务工具继续使用 C2 账本、真实桌面 grant、公共执行器、项目保存和资产回执。派发等待有界，断开/取消/超时保持 unknown 与占用，恢复不盲目重放。
- 人工等待是 main 任务事实；公共原子节点运行在等待时返回 skipped，不伪造成功。meta.agentTask 保存画布显示快照，main 表和 checkpoint 是任务权威事实；meta.nodeRun/nodeResult 继续承载公共运行记录和正式结果。
- 项目重开时，遗留 running 任务阻断为 AGENT_SESSION_LOST，不能自动从未知副作用处继续。waiting 可校验旧语义修订后恢复；修改配置、目标或连线需先停止旧任务再启动新任务。
- 资产发布必须匹配同项目/Agent/task 的 completed 记录和固定输出版本。仅改 nodeResult 不能生成伪造资产。此核对是执行事实校验，不是目标质量审核。

## 实际验收

隐藏、隔离的 Electron 两进程路径使用实际 Agent 卡片按钮、正式 preload/IPC、模型 catalog/SDK、公共处理器、项目保存、SQLite 和固定资产。合成供应商路径覆盖 Skill/工具选择、真实直接输入、启动、两次工具、人工等待、重开继续、输出、发布以及停止决策后的迟到保护；它是测试夹具，不标为真实模型。

真实 `doubao-seed-2-1-turbo-260628` 路径已通过：Skill 渐进加载 → 两次公共处理回执 → 人工等待 → 第二进程继续 → 已观察工具不重跑 → 声明输出、固定资产和版本发布。最新成功路径诊断统计 9 次模型请求（含能力探测和恢复进程的再次探测）；报告 qa/canvas-agent-flow/C3/desktop-real/results.json。它验证连续编排和工具协议，不声称该处理器已经具备领域分析或 JSON 生成能力。

首轮真实循环曾被未声明 Skill 资源阻断；补齐资源列表、主指令身份及 Schema 后通过。密钥只用于隔离配置，临时目录退出后清理；不写入源码、项目或报告。诊断文件已扫描测试正文和实际密钥，未泄漏。

最新构建复验曾出现模型提前等待未满足两次处理，以及重复决策触发预算上限，均判失败、未伪造成功。随后在模型上下文加入由真实回执派生的明确进度摘要，并说明相同资产的不同 committed 命令分别计数、已加载资源和人工确认无需重复。最新真实复验 desktop-real-progress.log 通过，覆盖 Skill/工具设置选择、直接输入、非主窗口拒绝和完整双进程成果路径；18 项运行适配定向复验通过。该修正改善模型执行提示，不代替未来业务质量审核或保证任意目标必定成功。

## 日志自查与边界

按 LOGGING_CHANGE_TEMPLATE：新增 agent.desktop.started/completed/failed，覆盖运行、停止和配置目录操作；只允许 phase/code，携带 project/node/trace/span。正常状态读取不逐轮记日志，意外数据库读取失败最多每来源 30 秒记 agent.desktop.inspect_failed。任务创建、预算、等待、恢复、取消沿 agent.runtime；库绑定沿 skill.library，模型沿 model.request，真实节点和保存沿公共日志，不重复记录节点业务终态。正文、资源内容、密钥、供应商原始异常、请求/响应均不进入诊断。
