## 发现与修复

旧保存读取主文件失败后会回退 `.bak`，但写入仍无条件将损坏的主文件轮转到 `.bak`。若随后转正失败，原有效备份被损坏内容替换。图保存与工作台配置两条回归在旧实现均失败，见 `qa/r09-local-20261016/backup-before.log`。

两条写路径现在复用一个带阶段标记的写入函数，记录实际读取来源；来自备份时不再把不可读主文件覆盖到有效备份，回滚需要恢复时也保留备份。只接受具有当前项目身份、有效图版本及图数组的快照；两份都不可读时明确拒绝保存，不初始化空图覆盖现场。

正常主文件仍按原顺序轮转，乐观锁和进程排他保持。回滚自身失败时保留完整主/备份及剩余临时文件；重新打开可按完整已转正文件校准数据库，不承诺调用失败后文件一定回到旧版本。没有加入业务自动重试或新生成请求。

## 36 轮有界重复注入

真实 SQLite、文件和公共视频任务核对路径，下载内容及供应商协议为本地夹具：

1. 同一 unknown 任务经历查询断网、一次原成果下载、prepared 强杀。
2. 六个新进程各执行六轮：持久停止 → 明确继续原任务 → 视频文件转正 ENOSPC/EIO → 保持 unknown → 项目保存写失败 → 重开读取。
3. 项目半写、转正失败和 SQLite 写满各 12 次；其中一个进程的诊断 sink 持续抛错，业务不变。已强杀或丢失的日志不补造终态。
4. 36 轮始终只有一个任务、一次下载、零媒体发布、零生成/删除请求、零遗留持有锁；输入与备份不改写。
5. 解除故障后离线恢复唯一媒体，明确保存引用；再经三次新进程核对，仍为相同任务、文件和快照，不重发、不重复下载。

`test/r09-local-reliability.test.ts` 保留独立 `soak-report.json` 与已验证脱敏的网关 JSONL，输出进入当前验证的独立 QA 目录。未复制凭据、SQLite 或媒体。36 轮属于有界重复故障测试，不能冒充数小时压力或真实磁盘写满实验。
