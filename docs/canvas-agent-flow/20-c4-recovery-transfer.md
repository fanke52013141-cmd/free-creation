# C4 故障核对、资产补呈现与引用迁移

日期：2026-10-14。状态：文本/JSON 首批范围已验收。范围延续 C3.3 的文本/JSON/确定性处理路径；本包不增加媒体/并行 Agent 调度。

画布路径：重开中断主控 → 点击“核对执行事实” → 读取任务/命令/审核数据库和当前已保存 nodeRun/nodeResult → 未知继续阻断；事实完整则进入等待 → 必要时明确“补呈现已提交成果” → 明确继续协调。核对不请求模型，不派发业务；补呈现仅复用已提交任务/已有报告，拒绝覆盖不同的当前成果。停止仍是独立操作。

专业任务已有 reconcile 等待先只核对公共命令账本，核对成功后才给出明确继续。中断模型/不完整任务 checkpoint 不编造成功、不自动重放，保留记录与回执；不能查询的远端结果仍 unknown。可信 flow.completed 事件已提交、最终状态写入中断时，核对固定输出及所有子任务/审核后可恢复真实完成事实。

项目包新增 flow-assets.json，只携带经过完整性验证的不可变文本/JSON 资产版本。导入为新项目，重映射项目/节点/shape/binding/关系/资产/版本及嵌套 JSON 引用，复用媒体 ID/路径重映射，包括 tldrawSnapshot、nodeResult 和导演台。丢失或损坏固定版本拒绝导入；历史源节点已删除仍保留版本来源。API Key 等结构化凭据字段剔除，模型目录、任务/checkpoint、命令、审批数据库不复制；旧 nodeRun/agentTask 和审核结果不恢复为新执行/批准事实。新资产和项目/媒体在同一 SQLite 事务，目录就位后才提交可见项目；失败回滚。

缺失媒体也分配新缺失身份与路径，不读取源项目中的同名文件，不伪造媒体入库。图身份按结构化字段映射，关系 ID 不改写同名状态枚举；自由正文不按片段替换，写死旧节点 ID 的提示词需在明确启动前人工核对。导入后的模型选择与领域内容仍由用户检查，迁移不会自动执行流程。

结构模板继续只携带图配置与布局，排除媒体/运行/资产状态；导入重映射图身份，create/save 在同一数据库事务，保存失败清理新目录。旧项目包仍可导入，但带有固定引用却没有其版本数据的旧包明确拒绝，不能以外部旧数据库补齐。

真实 IPC 验收发现项目切换复用旧编辑器导致新快照未加载。CanvasPage 按 file.meta.id 重建编辑器，过渡期间旧快照只绑定旧项目身份，避免写入新项目。保存协调器忽略旧项目保存依赖的迟到成功/失败，切换后新保存不被旧响应标成完成或冲突；同项目的合并与冲突恢复保留。加载、自动保存和失败诊断复用现有公共入口，不重复添加终态。验收同时检查新画布可见节点与保存后的新身份；新编辑器与保存依赖均就绪才检查保存。
