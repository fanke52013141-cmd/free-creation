# R09 按时长运行的故障压力验收

2026-10-16。接续 [43 包](43-r09-project-flush-barrier.md)。本包增加开发验收入口，不改变正式项目保存、任务调度或节点 UI；此前工作区改动保留，不调用真实供应商或更新安装包。

## 用户路径与验收边界

目标路径：未知视频任务已下载并停在 prepared，持续停止/明确继续原任务，媒体转正与项目保存反复故障；期间始终保持一个任务、一次下载、无已发布媒体和原快照。解除故障后离线发布唯一媒体，保存引用，再经三个新进程重开，任务与媒体身份不变。正式画布的失败显示、四次 renderer 重开和明确保存重试沿用 `test:r09-local-reliability` 并随完整门禁验收；长时夹具不是一张真实画布连续运行数小时的验收。

原 36 轮夹具仍保留。本包新增 `soak-long-N`：每批新进程执行八轮，项目半写、fsync、转正及 SQLite 写满各两次；媒体 ENOSPC/EIO 交替，每六批有一批诊断 sink 持续抛错。每批独立验证任务、媒体、版本、备份、锁和诊断，不靠模型文字声明成功。供应商 GET/下载为内存协议夹具，生成/删除请求被拒绝；这不证明真实供应商取消或计费行为。

## 使用方式

```powershell
# 默认目标：故障循环 5400 秒（90 分钟），批间隔 1000ms，最多 10000 批
npm run test:r09-soak

# 三批、24 轮快速入口；达到批数上限不等于达到 60 秒目标
npm run test:r09-soak:smoke

# 自定义目标（1–86400 秒），可加 --max-epochs=10000 和 --retain-batches=16
npm run test:r09-soak -- --duration-seconds=300 --interval-ms=1000
```

每次产生独立 `qa/r09-soak/run-*`；完整门禁的环境变量 `CANVAS_QA_OUTPUT_ROOT` 仍可隔离该前缀，不接受任意 CLI 输入/输出路径。参数重复、未知参数、非整数或越界均在创建数据前拒绝。

`report.json` 持续更新 running/最终 passed、failed 或 interrupted，保留阶段、已完成批数/轮数、实际循环时长、时长目标是否达到和清理结果。`completionReason=epoch-limit` 的通过只证明已完成批次和最终恢复，`durationTargetMet=false` 明示未完成目标时长。`checkpoints.jsonl` 每批持久记录数量、锁、耗时、worker/parent RSS 与诊断丢弃计数。时长使用单调时钟，初始化和最终发布不计入故障循环目标。

## 证据容量与退出

每批先验证脱敏并归档实际 JSONL，再移除隔离数据中的已归档诊断，避免每次新进程重新扫描全部历史。默认保留最近 16 个有事件批次，每批最大 2 MiB；超限失败，不截出半条 JSON。保留数量可设 1–128；轮转时仅删除该次运行自己创建的 `batch-NNNNNN`。写入新批次时可瞬时多一批，检查点最多 10000 条。该预算不承诺整个临时 SQLite/媒体目录的硬容量，也不是生产诊断保留策略。

归档与清理会保留 `prunedBatches`、`retainedBytes`、`diagnosticDrops`；滚动诊断不是完整事件全集。prepared 强杀留下的一个 control 与一个 media.persist 缺失终态按事实登记，不补造；logger 故障没有日志时保留丢弃数，不能据此认定没有业务执行。

每个 worker 有 30 秒超时和 1 MiB stdout 上限；不复制原始 stderr/异常内容。Ctrl+C/可捕获终止信号会结束当前 worker、等待关闭后清理隔离目录，保留已完成检查点并记录 interrupted；开发调用方的取消信号在运行中终止 worker 的回归已覆盖。父进程被强制杀死、机器掉电时无法执行 finally，可能留下 running 报告和临时目录；报告 PID 只供核查，不自动推断业务成功或自动删除未知现场。本包没有恢复父运行器、清理孤儿目录或启动后台定时任务。
