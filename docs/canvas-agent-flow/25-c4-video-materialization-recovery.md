# C4 视频成果入库强杀恢复

日期：2026-10-14。接续 [供应商事实核对](24-c4-supplier-reconciliation.md)。本包只接已有视频生成任务的成果物化与离线恢复，不开放媒体 Agent 自动调度或远端撤回。

## 用户路径与事实协议

远端生成已完成，本地下载/入库中断后，用户明确接回原任务或通过原核对入口恢复；完整下载回执优先校验本地文件，不依赖已过期的供应商 URL，不重新创建计费任务。

1. 在已有 `tasks.output` 保存 v1 物化回执，固定 task/project/provider/model/node 及完整任务输入的身份摘要，包含正文/参数/素材引用、远端 ID/连接/密钥指纹；停止意图不参与不可变身份。媒体 ID 和阶段文件名由该身份派生，不再每次随机产生新媒体。
2. `reserved` 仅表示准备下载，不证明字节完整。下载完成后流式计算 SHA-256 与大小，持久化 `prepared`；未提交完整回执的文件不自动采用，即使其字节碰巧完整。
3. 根据回执校验 staging 或已转正的目标文件，大小/摘要一致才转正。冲突文件不覆盖，不删除唯一完整副本。
4. 媒体登记与 `committed` 回执在一个 SQLite 事务内提交，task.output 同时保留固定 mediaId。任务 success 更新在随后一步，任意间隙重开均可补登记或补状态，复用同一个媒体 ID。
5. 原核对入口先恢复可信本地回执，再考虑远端查询。停止意图仍阻断自动接回；下载完成后收到停止，保留 prepared 文件/回执，不发布节点成果。显式接回后恢复即可，不重新下载已验证字节。

协议复用现有 tasks/media 表，没有迁移或第二套任务数据库。媒体正文、摘要与回执是本地业务事实，不作为诊断正文输出。下载/哈希使用流，不把大视频整段读入内存。首次下载会计算并核对摘要，恢复时再校验，存在额外顺序磁盘读取成本。

## 强杀边界

| 实际切点 | 重开结果 |
| --- | --- |
| 部分下载 | reserved 保持 unknown；明确重试仅重新下载原成果，最终一个媒体 ID |
| 完整字节但 prepared 尚未提交 | 不凭文件存在宣称完成；明确重试重新下载，仍只有一个媒体 ID |
| prepared 已提交，文件未转正 | 本地校验后转正/入库，无网络、无重复下载 |
| 文件已转正，媒体事务未开始 | 校验目标文件，补媒体登记，无网络 |
| 媒体事务中强杀 | SQLite 回滚媒体/回执更新，完整文件保留，补一次事务 |
| 媒体/committed 事务已提交，task success 未更新 | 复用唯一媒体，补 success，不重新下载/入库 |
| task success 已更新，调用返回后强杀 | 原成果/身份保持，重复核对及明确重试不创建新媒体 |

父进程等待同步切点后强杀，worker 不执行业务退出清理；另起进程读取真实 SQLite/文件，两次恢复及后续显式重试结果一致。使用受控二进制内容，不证明视频解码或真实供应商计费。
