## 1. 产品与协作空间

画布是整体协作空间，也是唯一可编辑业务流程。任务、讨论、工具执行、等待、人工选择、返工和资产均可在对应节点查看和参与。长内容在节点展开视图/详情中呈现，保留节点身份与画布上下文。后台服务、运行快照、数据库和 LangGraph 为这张图服务，不另建用户维护的任务拓扑、聊天工作台或云端项目。

本地单用户 Electron，保留所有旧节点和手动操作。内部 checkpoint 和诊断按需查询，不必逐条变成节点。运行记录不代替可交付资产。

## 2. 节点体系

首版新增三个稳定类型：

| 类型    | 职责                                         | 配置与边界                                      |
| ------- | -------------------------------------------- | ----------------------------------------------- |
| Agent   | 目标驱动的多步执行、工具、Skill、自检及等待  | 职责与参与方式分别配置，独立任务/会话/输入/预算 |
| 状态机  | 声明业务阶段、事件、条件、合法迁移和人工操作 | 记录真实事实，不重复调度或直接写成功            |
| AI 审核 | 审核固定版本资产，输出是/否及反馈            | 单次审核配合受控返工，不隐藏执行上游            |

Agent 的职责为构建者（上帝 Agent）、协调者（主 Agent）、专业执行者。上帝 Agent 首版建议在画布 Agent 的构建角色中呈现，先给建图预览再提交；具体 UI 在 C1 原型验收，不建立画布外工作台。

Agent 的参与方式为人机协作和纯 AI：前者可在本节点讨论、补充、纠偏、确认和继续；后者正常任务自主运行，不强制人工交接，无法推进时明确阻塞/失败。用户主动接管有新修订。首版一个控制范围只有一个运行中的协调者，可有多个独立专业 Agent。

已有文本/JSON/图片/视频/音频/文件节点继续承载资产；纯人工使用这些节点上传、填写、编辑并提交，不调用 AI。已有 AI 对话保留简单交流，AI 处理/代码/媒体节点保留一次转换。子图补执行边界、对外端口和恢复能力。Skill 和工具是 Agent 配置与能力，不默认各新增通用节点。

## 3. 资产、结果与端口

上传、生成和人工编辑的正式内容统一称资产。资产版本记录内容/文件引用、类型与 Schema、来源节点/任务/尝试、父版本和输入版本。文本/JSON 首批接入不可变版本，媒体继续引用现有媒体记录和文件，不一次重写旧项目。

节点保存固定配置、用户正文或资产引用；正式输出由注册 projectOutputs 从已持久化状态投影。讨论消息不自动变成资产；人工提交新内容产生新版本。一次执行固定 InputManifest，后续修改不改变旧任务输入。

普通数据连接保持 `来源节点.输出端口 → 目标节点.输入端口`，校验类型、JSON Schema、基数、必填性和真实输出。控制关系、状态关系显式可见且单独保存，不进入数据 DAG。连线声明依赖，调度决定执行。移动、重命名和折叠不改变业务输入或状态。

成果先登记再物化到画布，失败可按 outputKey 补齐同一节点；文件、SQLite 和项目文件用回执/待处理记录协调，不假装一个事务。导入导出完整重映射所有引用，不携带 API Key 或活动运行；事务完成后才显示导入项目。

## 4. Skill 与工具

Skill 包采用 SKILL.md、参考资料和模板，保存版本/哈希/兼容条件/依赖。用户在本机设置导入管理，在 Agent 设置添加与启用。模型先看到名称/说明，需要时按预算读取正文与资源；任务固定所用版本。加载 Skill 不自动取得工具权限；首版不直接执行包内任意脚本。

工具统一声明 ID/版本、输入输出 Schema、允许角色/节点范围、依赖、超时、取消、幂等与诊断。流程工具读图、建图、分配/查询任务和状态；内容工具受控读取资产/Skill；业务工具调用真实能力节点、提交资产。已有工具授权内连续执行，超出范围或声明的人工交接点才等待。

每次调用经过参数、可信身份、版本、范围、预算、占用与回执校验。专业 Agent 不读取全图或其他会话。主 Agent 只协调授权范围；上帝 Agent 管理结构。初始预算建议每任务最多 12 轮决策、20 次工具、10 分钟和有界重试，C0/C3 实测调整；视频长任务另设能力时限。

## 5. AI 审核与返工

审核读取固定版本资产和明确标准。首批文本/JSON，媒体逐类通过模态/解析验收后开放。输出 JSON `review.decision@1`（passed、feedback、issues、被审核版本、标准版本和关联 ID），以及同源文本反馈。界面显示是/否，不增加独立 boolean 数据类型。

“是”仅放行已审核版本；新内容或标准要重审。“否”按显式返工负责人和策略处理：

| 主体     | 返工路径                                            |
| -------- | --------------------------------------------------- |
| 人工     | 显示反馈，等待修改并提交新版本，再审核              |
| 纯 AI    | 保留原任务/输入，加入被拒资产和反馈，新尝试修订再审 |
| 人机协作 | 在原 Agent 节点等待人讨论/调整，明确继续后修订再审  |

可以配置否后停止；默认最多 3 次返工（初审加最多 3 次复审）。用可见控制关系回到指定步骤，不建普通反向数据边。下游所有受控执行都遵守审核 gate。审核成功但不通过，与审核运行失败分开；技术失败没有有效结论，不默认放行。报告也是可查看和连接的 JSON 资产。

## 6. 框架与执行宿主

采用 LangGraph JS/TS 做任务内部有限循环、持久等待和 checkpoint，LangChain 提供消息/模型/工具组件。实际模型请求复用现有主进程网关与验证，密钥不进入 renderer、节点、报告或项目包。工具调用能力要单独实测，不能仅凭普通文本模型验证就宣称可用。

main 持有 Agent runtime，先通过可信执行桥调用现有 renderer 单一执行入口；不复制业务 executor，不恢复旧 CLI/MCP/headless。画布/宿主断开停止新派发，超时结果未知先核对。LangGraph checkpoint 是内部位置，业务命令回执才决定副作用是否发生；重开不能盲目重复。

框架和驱动版本在 C0 显式锁定并实测 Electron 打包兼容。本地模型优先，缺失时明确不可启动，普通画布仍可用；无默认云诊断、自动下载或后台付费媒体调用。

## 7. 开发顺序与验收

| 包   | 交付                                                                 | 核心退出条件                                                                        |
| ---- | -------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| C0   | LangGraph 有限循环、单步模型/工具协议、SQLite checkpoint、执行桥实验 | 隔离数据完成工具→等待→重开→继续；已完成不重复，未知结果阻断；Electron 构建/运行证据 |
| C1   | 三种新类型、参与模式、关系、契约与节点内 UI                          | 配置/身份/关系可保存重开；原节点可用，未接执行明确禁用                              |
| C2   | 资产版本/输入清单、公共命令、成果落图、确定性审核 gate               | 手动与控制输出一致；版本冲突拒绝、命令去重、资产可连接                              |
| C3.1 | Skill/工具库、纯 AI 多步执行、文本/JSON 审核                         | 真实模型工具→检查→再工具；审核反馈进入返工尝试；预算有界                            |
| C3.2 | 人机协作与人工返工                                                   | 本节点讨论/修订/等待/选择/继续；聊天不隐式执行，过期响应拒绝                        |
| C3.3 | 上帝 Agent 建图、主 Agent 与专业 Agent 交接                          | 真实最小输入与独立任务，完整示例，不伪造执行事实                                    |
| C4   | 故障恢复、迟到输出、版本 gate、模板与导入导出                        | 已完成不重放、未知请求需核对、等待恢复、ID 重映射和密钥边界                         |

贯穿示例：人工提交材料 → 纯 AI 分析 Agent → 分析资产 → 人机协作整理 Agent → JSON 资产 → AI 审核 → 是则下游处理/否则按主体返工 → 最终资产。整条路径在画布可演示、可暂停、可追溯、可重开。

每包需定向行为测试、适用节点契约/UI/Electron 验收与最终 npm run verify；不能用测试数量替代产品路径。真实模型、付费媒体、系统安装等专项单列证据，合成模型只证明接口/故障语义。使用隔离测试数据，隐藏窗口优先，必要可见窗口标“测试”并清理。
