日期：2026-10-15。接续 [运动参考](32-video-motion-reference-adapter.md)。保留工作区既有首尾帧、图片参考及运动参考改动；本包不提交/推送、不打包，不改变节点 UI 或引入云端依赖。

## 画布用户路径

在含固定图片、固定视频与 Agent 成果的项目中使用现有导出项目，再导入该 `.canvasbundle`。导入项目拥有新的项目、节点、媒体、资产和版本身份；原画布、普通端口、固定预览和成果保留，图片/视频可在新项目解码查看。运行状态回到 idle，旧任务、命令、批准与执行权威不随包恢复；导入不是原供应商任务的继续入口。

实现涉及 `src/main/store/flow-transfer.ts`、`transfer.ts` 和项目 IPC。版本解析扩展为图片/视频，限定项目内媒体 ID、相对路径、MIME 与摘要格式。导出核对数据库身份、真实文件位置和固定摘要，打包使用同一次验证的字节；缺失或被替换的固定媒体阻断导出。普通未固定媒体缺失仍沿原备份计数提示，不以其容错绕过固定版本。

导入在临时目录中验证实际文件、按扩展名重建的类型/MIME 和适用的 SHA-256，拒绝重复媒体身份、缺文件、跨项目路径、错误类型和内容变化。固定节点 pinnedOutput 必须与包内资产版本一致。复用公共媒体引用重映射，覆盖 tldrawSnapshot、nodeResult、固定版本与嵌套配置；不能回查源项目数据库填补不完整包。目录准备与数据库事务成功后才返回项目，失败清除临时或已转正目录并回滚数据库。API Key 等凭据继续剔除。

旧生成视频版本没有内容摘要时保留旧协议，不凭空补造原始内容证明：仍要求包内媒体存在并匹配身份和 MIME，但不能据此发现同 MIME 文件的历史内容替换。这类版本不能冒充已验证的运动参考，需普通视频素材重新固定。本包不是旧项目迁移专项，不引入新包版本或恢复旧执行权威。

## 日志检查模板自查

- 影响：文件、数据库、固定版本与项目切换；复用现有 project.transfer.started/committed/failed、项目打开/保存事件。媒体校验函数不重复记录终态，不调用模型或远端服务。
- 事件职责：正式项目 IPC 负责根操作开始及唯一终态，关联 traceId/spanId/projectId，operation 为 project-export/project-import；committed 仅在存储函数成功返回后记录。取消沿原对话框语义，校验失败不自动重试。
- 失败：新增 FLOW_TRANSFER_MEDIA_INVALID、FLOW_TRANSFER_MEDIA_DUPLICATE、FLOW_TRANSFER_PINNED_INVALID 进入受控错误码，沿 validation-or-transaction 阶段；IO 继续只允许既有受控存储码。无原始文件名、绝对路径、包内容或异常进入诊断。
- 脱敏：不记录媒体字节、摘要正文、Data URL、提示词、回复、模型配置或 API Key。复用诊断入口的故障隔离；logger 失败不能改变事务结果。实际桌面脚本扫描测试正文/Key/图片和视频 Data URL/MP4 前缀，并验证两次 transfer 各有唯一终态。
- 边界：异常回滚由定向测试验证，未补造强杀时不可观察终态。本包没有新增迁移中强杀、物理掉电、全部媒体解码格式、恶意媒体解码器或超大包流式化验收；既有 2GB/条目上限仍适用。诊断不作为恢复权威，不宣称完整媒体 trace 树或全链路覆盖。覆盖清单同步更新。
