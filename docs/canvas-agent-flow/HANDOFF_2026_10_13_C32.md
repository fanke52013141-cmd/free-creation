# C3.2 开发交接：协作目标修订与人工过渡

日期：2026-10-13

基线：`ab3b025dac086b951f54e5b8d864a18fad8b86be`（C3.1b）

范围：C3.2 节点内协作、人工决定和显式任务修订。

## 已交付

1. Agent 节点新增“协作”入口，所有交流和操作留在画布节点内。支持保存笔记、无工具 AI 讨论、人工接受/拒绝意见、固定版本选择和采用新目标。
2. 协作事件持久化在 SQLite v14，绑定真实 task、wait revision 和 eventId；重复事件去重，过期或异意图拒绝，最多保留 40 项。
3. 采用新目标会创建带 parentTaskId 的不可变新任务，旧任务、目标、输入、checkpoint 和回执不改写。新任务只在用户明确点击启动后执行。
4. 人工反馈和选择进入 checkpoint。拒绝会阻断原任务；接受后完成输出必须与所选 committed 资产一致，否则安全阻断。
5. main 重新核对保存画布、授权来源端口和固定版本；角色、边、配置、Skill、工具和模型权限变化不能借目标修订扩大范围。
6. 协作操作复用 `agent.desktop` 生命周期，AI 讨论复用 `model.request`；日志只记录标识、阶段、动作和稳定错误码，不记录目标、讨论、回复、资产正文或密钥。

完整行为和边界见 [15-c32-collaboration.md](15-c32-collaboration.md)。

## 接续顺序

1. 先运行最终全量门禁，确认已单独通过的双按钮几何修复与其余门禁串行执行无回归。若通过，把最终结果补记到开发台账和日志覆盖清单。
2. 单独复验真实豆包讨论。检查 AI SDK 对该模型的流式文本、推理内容和 finish reason 映射；只在获得非空、可展示文本时写入协作事件。保留现有无工具、30 秒超时、无自动重试和失败不推进业务的边界。
3. 真实讨论通过后再标记 C3.2 验收完成。不得以 C3.1b 的真实连续执行替代 C3.2 讨论验收。
4. 后续进入 C3.3：主控协调、AI 审核有界返工和状态机执行。完整崩溃恢复、模板导入导出与引用迁移继续归 C4。

## 仍未支持

- 上帝/主 Agent 自动建图与多 Agent 调度。
- AI 审核节点的通过/否决和有界返工循环。
- 状态机真实执行与跨节点控制推进。
- 运行中的远端讨论取消、完整崩溃裁决、长会话摘要/清理。
- 协作记录和固定引用的模板导入导出重映射。

本交接不包含密钥或个人模型配置。测试继续使用隔离项目、隔离数据库和隐藏窗口；不得修改个人模型目录或复制凭据到 QA 证据。
