# 视频抽帧画面审核（2026-10-15）

## 用户路径与边界

普通或固定视频的 out-video 连接 AI 审核节点 in-video，在设置中明确选择“视频抽帧画面”，填写标准与下游门禁，运行审核。未通过后人工替换负责节点的视频，提交新固定版本复审；通过后下游才可继续。关闭重开保持报告，未变输入复用原报告，不重复模型调用。

首包只审核一路固定 MP4：0.1–60 秒、至少 4 帧、最多 20 MiB。按帧索引约 10%、35%、60%、85% 选择四张真实画面，保留实际时间戳；每张 JPEG 最长边 640px、最多 1 MiB。界面明确展示抽样范围和时间。结论始终标为 sampled，不代表音轨、完整时序、未展示画面或完整视频质量。

本包不开放主控自动视频审核/自动重新生成，主控自动返工配置中的 sampled-video 明确拒绝；文本/JSON 原自动审核继续可用。没有新增节点、端口或执行器。音频理解、多路视频和并行媒体另行适配。

## 实现与完整性

- main 从已保存画布冻结唯一视频来源、版本和规则。普通视频素材包含媒体身份/路径/MIME 的绑定签名，人工替换会使旧批准失效。文件与固定版本核对项目范围、真实路径、大小、MIME 和 SHA-256；模型返回后再次核对输入与语义修订。
- 旧生成视频没有固定摘要时，只允许从同项目/来源/媒体唯一成功任务的 committed 下载回执取得摘要；没有回执不能把当前文件冒充历史版本。随后仍核对真实字节，不改写旧版本记录。
- 本地 FFprobe/FFmpeg 只读取已校验字节的临时副本，限定 mov 解复用和 file/pipe 协议、输出大小、帧数、单进程时限与统一 30 秒审核预算；支持取消，临时目录验证父目录/前缀后清理。进程参数通过数组传递，无 shell 或远端媒体读取。
- 模型须启用、声明 text.generate 支持图片且该操作验证通过，再沿原工具探测。四张真实 JPEG 和对应时间通过 SDK 多模态消息发送，不仅发送路径或摘要；发送前核对每张摘要。目录能力和工具探测不等同于真实供应商视觉理解质量验收。
- 报告仅持久化固定引用、视频与样本摘要、时间戳、抽样方法及反馈，不存图片字节。缓存重放、批准门禁再次校验视频证据；文件替换、缺失、来源/规则变化使批准失效。沿用原审核轮次、停止策略和预算。

## 日志检查

| 路径 | 事件/责任 | 关联与脱敏 |
| --- | --- | --- |
| 审核启动、缓存和失败 | 正式审核 IPC 的 agent.desktop.started/completed/failed | project/node/request/trace/span；固定 phase/code，无逐帧重复终态 |
| 抽帧/固定媒体异常 | 沿审核终态 phase=review 和稳定 FLOW_VIDEO_REVIEW_* / ASSET_VIDEO_CHANGED；内部采样错误阶段 video-review-samples | 不暴露 FFmpeg stderr、文件路径、画面、Data URL 或原始异常 |
| 多模态模型调用 | 既有 model.request.started/completed/failed，SDK 负责 | 按 requestId 配对；不写规则、反馈、推理、模型原始正文、JPEG 或凭据 |
| 保存、版本与下游 | 复用公共 asset/project/node 生命周期 | 不新增重复终态；业务结论“未通过”仍为审核执行成功 |

诊断抛错不改变业务事实的既有底座保持；脱敏门禁增加 JPEG 前缀。恢复/模型请求仍遵守原日志契约，不声称完整媒体 trace 树或远端取消验收。
