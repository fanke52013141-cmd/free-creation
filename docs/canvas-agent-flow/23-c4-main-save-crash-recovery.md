# C4 main 保存轮转强杀与遗留锁恢复

日期：2026-10-14。接续 [发布 handoff](HANDOFF_2026_10_14_C4_RELEASE.md) 的下一条路径。仅使用隔离项目、真实项目仓库和 SQLite，不请求模型。

## 行为与边界

保存仍按 `.tmp → .bak → project.json → DB` 顺序执行。独立进程在同步切点等待，父进程强杀，另起进程读取恢复；不运行退出保存或业务重放。恢复读取不会把未转正 `.tmp` 当作提交事实。

| 强杀边界 | 重开读取 | 数据库行为 |
| --- | --- | --- |
| 完整 tmp 已写入 | 旧主文件 v1 | 保持 v1 |
| 旧主文件已转 bak，新文件未转正 | 备份 v1 | 保持 v1 |
| 新文件已转正，DB 未更新 | 新主文件 v2 | 沿用现有读取校准至 v2 |
| DB 更新事务中 | 新主文件 v2 | 先验证事务回滚到 v1，再读取校准至 v2 |
| DB 已提交，写锁未释放 | 新主文件 v2 | 保持 v2 |

每条路径两次独立重开读取一致。新锁在 30 秒保护期内继续阻挡保存；测试只调整隔离锁的 mtime 模拟保护期结束。恢复后旧版本编辑仍报冲突，内容不变；重新读取后的明确新编辑才能保存并推进一次版本。

原写锁只凭 mtime 判定失效，会抢占暂停超过 30 秒的活进程。新锁写入持有 PID；保护期后仅 ESRCH（已退出）允许接管。活进程、无权限/不可确定探测、损坏或无效元数据仍阻挡。PID 重用可能延迟恢复，优先避免抢占活进程。历史空锁保留原 30 秒兼容策略；该旧格式没有可信持有者身份，不等价于新锁的存活保护。
