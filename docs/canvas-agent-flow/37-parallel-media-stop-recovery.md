## 画布用户路径

在主控 Agent 的现有设置里将“任务调度”从默认顺序执行改为“独立任务并行（最多两路）”。为两个专业 Agent 分别授权各自的视频节点，连接固定材料并绑定同一主控状态机。主控可一次批准两项就绪任务，两个视频生成同时进行，各自保留原任务、命令、固定输入、预算和成果。

某一路结果未知时，另一侧完成事实与固定成果保留；关闭重开后，在原专业节点核对并明确继续，再由主控收集。停止任务取消两侧的本地执行和后续发布，已经完成的任务记录及固定资产不会删除。未知供应商命令继续占用原目标，不能借停止重新提交。

“暂停派发”保留恢复入口，当前批次可结束后等待；“停止任务”是终止，不会通过恢复偷偷复活。核对恢复只接原任务，不重新生成。停止不等于供应商已经撤回请求。

## 实现与边界

- `maxParallelTasks` 可选，仅 1/2，旧配置仍默认 1；`dispatch_parallel` 严格两个 assignment，只有显式启用且两项就绪才向 SDK 开放。单项派发继续支持。
- main 整批校验合法就绪节点、固定输入子集、重复项、预算，以及两个写范围之间的直接/间接数据依赖。已有控制范围独占规则继续拒绝共享写目标。额外一路占用一步预算，不能通过批量派发绕过 maxSteps。
- 所有任务身份和固定输入在首个执行副作用前持久化；每路独立 LangGraph 根上下文。任务并行执行，主控收集和公开投影串行保存；单路失败不丢弃另一侧真实成果。等待收集遍历所有支路，较早的等待项不遮挡后面的已完成项。
- 显式停止读取最新专业任务事实，保留已完成一侧，其他子项取消。迟到回执不能推进主控或发布新成果；原 pending/unknown 命令锁保持。崩溃后的未确认派发意图仍阻塞核对，不能推测成功或自动重派。
- 未连任何数据边、同时带 pinnedOutput 与 flowAssetRef 的固定文本/JSON/媒体成果卡属于展示副本，不改变程序语义版本；连接后固定身份和值重新参与严格校验。普通节点、连线、配置或来源变化仍冲突。
- 两侧视频分别呈现在原有固定视频资产节点，支持预览与 out-video。主控 out-text/out-json 基数保持现有契约，最终选择一个视频成果；本包不引入两路视频合并 JSON 或新端口。
- 首包并行上限为每个主控两项独立的已适配专业任务，真实桌面路径为两路文生视频。未适配的图片/音频生成不因本包获得 Agent 权限；依赖支路仍顺序执行。没有后台新工作台或第二执行器。
