## 本轮交付

1. 新增内置模板“图片修改→后续创作”。它创建以下可见节点和真实数据依赖：

   ```text
   图片资产.out-image → 图片修改.in-image
   图片修改.out-image → 图片裁剪.in-image
   图片修改.out-image → 继续生图.in-image
   图片修改.out-image → 图片生成视频.in-image
   ```

   模板不会复制或伪造媒体。第一个“图片资产”节点是空入口；只有用户导入原图并运行图片修改节点后，三个下游节点才会取得同一份新的 `MediaAsset` 输出。

2. 修复 Electron 打包范围：`electron-builder.yml` 显式排除 `dist/**`。此前根目录保留的历史安装包会被下一次打包再次写进 `app.asar`，最终触发 4.2GB 上限；现在构建产物不会递归包含自身或旧产物。

3. 图片修改遵循模型中立规则：遮罩以标准 `prompt.mask` 发送；不按模型名称白名单或黑名单拦截。供应商是否接受图生图/遮罩，由该次真实响应确定。

## 后续增量：媒体体验与画布交互

本轮继续完善了媒体工作流的用户侧边界：

- 图片修改结果提供“裁剪图片 / 继续生图 / 修改图片 / 生成视频”四个快捷入口；它们复用统一实现，只创建下游节点和真实 `out-image → in-image` 连线。
- 图片修改可展开“对比原图”，并复用统一结果集合来切换当前输出、比较两项历史结果、删除非当前结果或清理历史；供应商失败时不改写已有输出或结果集合。
- 标注工作台提供“主体框选”和“焦点箭头”预设。预设只是可编辑配置起点，仍写入 `image-edit.config`，不会产生隐藏端口或资产。
- 用户模板与内置模板都只保留节点结构、正文、配置和端口连线；套用历史模板时也强制清空媒体字段，避免跨项目引用或复制媒体。
- 取消“选中一个节点时兼容节点发光”，删除每个节点对 selection 的监听与重算；节点首次按下会同步选中而不截获事件，可直接按住拖动。顶部类型色带由 2px 提升到 4px。

增量验证：`npm run verify` 通过（42 文件、533 项测试），`npm run test:contract` 通过（199 项），100/500/1000 节点基准通过，Electron 目录包通过。工作流面板桌面验收确认模板展示真实连线数量和“模板不复制媒体资产”提示。

## 后续增量：资产导出与批量运行稳定性

- 资产中心的“导出筛选”只导出当前筛选结果；主进程仅接受属于当前项目的 `mediaId`，使用排他写入，目标目录存在同名文件时自动添加序号，绝不覆盖用户已有文件。
- 迭代的循环体仍严格串行，但每一个实际列表项都有独立 `itemRunId`。该 ID 贯穿循环体节点的运行历史、输出数据包、媒体结果和资产来源；因此 20–100 项批量生图可以逐项定位、失败重跑和重开后追溯，且不会因共享工作流级运行 ID 被历史去重。
- 自动回归新增了逐项运行 ID 断言，并覆盖循环体真实运行历史的独立性。
