# 端口锚点稳定与节点并发运行优化方案

日期：2026-10-05。范围：用户提供的两张截图、当前 source 工作区。本文是排查结果与实施方案，尚未修改端口或执行引擎的生产行为。工作区还有其他开发改动，实施时应独立提交。

## 1. 已确认的根因与证据

### 1.1 点击蓝色输入点使绿色溯源线脱离

已在浏览器真实画布复现：创建一个视频截取节点、一个标记 artifactProducerPortId=out-audio 的音频产物、另一个视频输入节点。按下后者的蓝色输入点，前者输出圆点仍在屏幕 y=312.125，绿色溯源线起点由 y=312 变为 y=355.333，间距约 43.2px；松开又恢复。没有删除边或变更产物关系。

直接原因：

1. NodeCardView.tsx 中正式 arrow 会更新 outgoingPortIds；遍历产物溯源关系时却只更新 outgoingCounts，没有把 artifactProducerPortId 加入 outgoingPortIds。
2. DataEdgeLayer.tsx 则调用 collectNodePortConnections，该函数把正式边和产物溯源边都计入已连接输出。
3. 视频截取节点有 out-video 和 out-audio 两种输出类型。空闲时卡片错误地显示默认视频圆点；绿色音频溯源线落在中点，错误暂时被掩盖。
4. 按下蓝色视频输入会启动反向拖线。候选视频输出叠加到连线层已统计的音频输出，连线层变为两个槽位，音频位置从 h/2 移到 2h/3。卡片层没有音频已连接信息，仍只显示中间的视频圆点。260px 高度的差为 h/6≈43.33px，与实测吻合。

因此存在两个需同时处理的问题：端口连接事实不一致，以及候选显示驱动锚点重新排布。仅补一个 Set.add 可以让两层同步移动，但不能满足交互时锚点稳定的要求。

附加发现：NodeCardView 还有 portFollow 鼠标跟随状态，foundation 在伪元素上消费位移，最终 surfaces 则使用独立 port-core 并关闭伪元素。实现口径已发生漂移；本次 43px 偏差无需依赖此行为便可复现。

复现脚本：scripts/diagnose-port-concurrency.cjs。启动浏览器验收服务后运行，可用 CANVAS_QA_URL 指定服务地址；默认 http://127.0.0.1:5173。脚本只使用浏览器 mock，输出 qa/port-concurrency/evidence.json 与 port-reflow.png。该脚本断言当前缺陷可复现，不是修复后的通过门禁；实施修复后应改为验证锚点稳定和任务接纳。该复现验证相同机制，不能从截图单独恢复用户项目的全部实际连接。

### 1.2 一个节点运行时，其他节点无法启动

这主要是应用执行入口的全局限制，不是实测并发资源耗尽。

| 位置 | 当前行为 | 影响 |
| --- | --- | --- |
| engine/store.ts | 只有一份 phase、currentNodeId、进度、errors、stop/pause/resume | 默认只能表示一项前台运行 |
| executor.ts / runNodeManually | phase 非 idle 就返回“已有任务正在运行” | 不同节点、不同资源也互相阻挡 |
| canRunImageWhileVideo | 只允许当前节点为 video-depth 或 video-clay 时启动 image-gen | 普通远端 video 生成不适用，其他节点组合不适用 |
| image-gen.tsx | engineBusy 用上述规则禁用卡内生成按钮 | 尚未提交任务便被 UI 拦截 |
| runNodeTest | 任意已有运行/测试便阻断 | 设置面板测试也受全局限制 |
| 全图/局部运行 | 全局空闲检查，随后 for/await 串行运行节点 | 不相依的分支也不会并行 |
| video-conversion.ts | 主进程深度/白模共用一个转换槽位 | 是本地重任务资源限制，应与远端任务分开 |
| gateway/video.ts | 按 projectId+nodeId 拦截在途重复视频 | 应保留，避免同节点重复计费 |

浏览器无付费调用验证：模拟普通 video 节点运行，独立生图、视频截取和节点测试都返回 skipped/“已有任务正在运行”；例外函数对普通 video 为 false，对 video-depth 为 true。

不能简单删除全局判断：多个任务会覆盖 currentNodeId、停止回调、进度和错误；一个任务结束调用 endRun 会将其他任务显示为空闲。同一节点的手动运行与工作流也缺少统一执行占用检查。

## 2. 目标行为

- 点击、悬停和拖线只改变候选高亮、可见性及预览线，不移动已有端口和正式连线锚点。
- 普通视频生成与生图、配音、文本处理等独立任务，在各自资源额度允许时同时运行。
- 资源满时允许提交，显示排队原因和取消入口；其他空闲资源上的任务继续运行。
- 同一节点不可重复执行；不同节点不因全局忙而被禁用。
- 任务状态、进度、输出、取消和恢复均属于明确的运行实例。
- 工作流仍按数据依赖执行，产物溯源线继续只用于追溯，不能成为 DAG 数据输入。

## 3. 端口优化

### 3.1 统一连接事实与布局

以 node-port-layout.ts 作为唯一公共入口，生成每个节点/方向的布局结果。输入包含节点契约端口、显式动态端口、正式数据连接及产物溯源连接。NodeCardView、DataEdgeLayer、遮挡判定与拖线命中消费同一结果。

readiness 的输入可用性和契约校验仍保持独立业务含义：溯源关系可占用视觉输出点，不应变成执行依赖。

### 3.2 固定锚点槽位

建议按完整的正式端口类型组和强制动态端口预分配固定槽位。单类型居中，多类型按固定契约顺序分布。端口是否已连接、是否为候选仅控制显隐及高亮，不参与计算总槽位数。

例如视频截取节点：out-video 固定在 h/3，out-audio 固定在 2h/3；点击另一个视频输入时可以显示视频候选，但音频输出及其已有连线原地不动。同类型端口仍共享一个视觉锚点，并保留明确的实际 portId、必填/基数/schema 校验，不能把视觉分组理解为契约端口合并。

节点移动、缩放、尺寸调整及用户显式修改动态端口声明可以改变锚点；仅交互高亮不能改变锚点。页面坐标用形状页面变换统一转换，覆盖嵌套分组，再映射为 SVG 屏幕坐标。

### 3.3 保持可见圆心稳定

保留端口颜色、光晕和以圆心为中心的缩放反馈，取消圆心跟随鼠标的位移及无效的 portFollow 状态更新。拖线起点取固定锚点；视口改变时由当前页面锚点重算，避免将初始 clientX/clientY 永久当作端口位置。

## 4. 并发运行架构

### 4.1 运行实例替代全局互斥

新增运行实例注册表，包含 runId、projectId、运行范围（单节点/局部/全图/测试）、状态、独立控制令牌、节点执行实例、进度、错误及输出映射。

现有 engine phase 转为界面汇总：它可用于显示“运行中 3、排队 2”，不能用来判断其他节点能否提交。移除 isolatedImageRuns 和类型组合例外，全部入口使用同一任务接纳与节点占用逻辑。

所有入口统一接入：标题运行按钮、生图卡内生成、设置面板测试、局部工作流、全图工作流。聊天与直接能力调用也要共享其供应商资源额度，但对话顺序/历史写入仍按对话实例隔离。

### 4.2 同节点执行占用

在统一节点执行入口、实际异步工作开始前原子登记 projectId+nodeId 的占用，覆盖手动运行、工作流和测试。重复点击返回当前运行句柄，不再次提交远端请求。所有成功、失败、取消路径都释放占用，并保护“旧任务释放了新任务占用”的情况。

工作流与手动运行命中同节点：输入与配置快照相同且语义允许时可等待并消费同一次执行结果；快照不同则明确等待冲突，不静默重复计费。测试虽使用隔离副本，第一阶段也按原节点占用，后续再依据副作用能力决定是否开放同节点测试并行。

主进程保留/补齐付费请求在途去重，使 renderer 重载、重复 IPC 或另一个窗口不能绕过防重复提交。

### 4.3 资源池，而非节点类型白名单

| 资源池 | 限制范围 | 建议行为 |
| --- | --- | --- |
| 远端供应商/账号并发组 | 该账号共享的实际任务额度 | 有额度即执行，满额在该组排队；支持用户配置共享组，不能按两个连接 ID 就假定额度独立 |
| 视频远端在途任务 | 从提交成功直到远端终态 | 本地轮询等待不占 CPU/GPU 工作槽，但仍计入供应商在途额度 |
| 本地深度/白模 GPU | 同一设备重推理 | 第一阶段保留现有 1 槽位，并显示排队；显存与真机负载验证后再提供可配置并发 |
| FFmpeg/本地媒体处理 | CPU、内存及 IO | 设置可调上限，独立于远端/GPU 池；初始值需真机压力验证 |
| 上传、下载与产物落盘 | 网络与 IO | 分别限流，避免大视频下载阻塞轻量模型提交 |

区分“提交请求速率/连接数”和“供应商允许的在途任务数”；提交 HTTP 返回不代表计费任务已释放额度。429 根据 Retry-After/退避处理；超时远端状态未知时先查状态，不能直接重投计费任务。

资源池由主进程统一仲裁；renderer 展示状态，避免多个窗口各维护一份额度。任务在可执行阶段再申请所需资源，不持有 GPU 槽等待远端结果，也不在父迭代任务持有槽位后等待子任务，防止资源相互等待。

### 4.4 状态机、取消与结果隔离

状态至少表达：等待依赖、等待节点占用、排队、执行中、等待远端、成功、失败、已取消。复用现有 pending/queued/running 展示时补充明确 waitingReason，不把队列时间算为模型生成时间。

每次执行固定图边、节点配置、正文和输入值快照，并以 nodeExecutionId 标记结果。执行中编辑节点不会改变已提交请求；完成时标记输入已修改，后续重跑使用新快照。

所有更新结果/状态/产物的回调验证执行实例归属，避免旧回调覆盖新任务。删除节点后不重建原节点；已生成资产按产物保存政策保留，追溯记录注明原节点已删除。

取消只作用于所选 runId/nodeExecutionId：排队任务可直接移除；本地任务终止对应子进程并清理临时文件；远端任务区分“本地停止等待”和“服务端确认取消”。暂停默认停止该工作流派发新节点，不声称已经暂停供应商任务。

多个任务的画布结果仍通过既有保存协调器合并并落盘，继续使用项目保存事务及乐观版本检查，不能让每个任务用各自旧整图快照覆盖项目。

### 4.5 DAG 并行调度

使用依赖就绪队列：只有上游结果通过输出契约后才释放依赖，独立就绪节点可同时申请资源。汇合节点等待所需全部输入；失败只阻断依赖该失败输入的分支，其他分支继续。

跨运行的旧输出复用继续以明确的输入/配置指纹策略决定，不能把“有历史结果”当作本轮依赖已经完成。两个运行范围重叠时用统一节点占用处理；不要求因某个节点冲突而冻结整个画布。

循环第一阶段维持现有串行语义。将循环项变为独立执行上下文、输出映射、控制令牌与 itemKey 之后，才提供受资源池控制的并发批处理；不能直接对共享循环体节点做 Promise.all。

## 5. 界面规则

- 别的节点运行时，“运行/生成”按钮继续可用。仅本节点在途、输入缺失、模型不可用等真实原因禁用。
- 资源满时按钮提交进入排队，显示“等待 GPU/等待供应商额度/等待依赖”，提供取消排队；不能笼统显示“等待当前节点运行结束”。
- 卡片独立显示本任务进度；等待阶段不显示虚构的生成百分比与剩余时间。
- 顶栏汇总所有任务，并可打开列表。停止、暂停按任务范围作用；“停止全部”是单独且明确的操作。
- 某个任务完成或失败不会重置其他任务状态，也不会把其错误加到另一条工作流。

| 阶段 | 工作 | 涉及模块 | 出口条件 |

| P0 | 统一端口连接事实、固定锚点、清理圆心位移口径 | node-port-layout、NodeCardView、DataEdgeLayer、ConnectionLayer、端口 CSS | 本次复现与全部锚点测试通过 |
| P1 | 执行实例注册表、统一节点占用、主进程资源额度、独立取消/状态 | engine/store、executor、运行入口、gateway/本地媒体任务；新增运行管理与资源调度模块 | 普通视频与生图等跨节点运行不再被全局 phase 阻断 |
| P2 | 并行依赖调度、重叠子图处理、队列 UI、持久化恢复 | topology、run-plan、CanvasPage、NodeContractPanel、运行记录/任务存储 | 独立分支并行，汇合/失败/取消语义正确 |

## 7. 验收标准

端口：正式数据边/视频产物/音频产物/同时产视频和音频；从输入及输出按下、拖动、取消；50%/100%/200% 缩放；节点移动/调尺寸/嵌套分组/重开项目。静止状态端点与圆心误差目标不超过 1 个 CSS 像素；候选显隐过程中既有锚点不改变页面坐标，取消不能改变关系数据。

并发：

1. 普通视频生成运行时生图启动成功；反向启动顺序也通过。
2. 多个生图及远端视频按配置额度运行，超额可排队、可取消，不重复计费。
3. 本地深度与白模共享 GPU 槽位排队，远端图片/文本任务继续运行。
4. 同节点双击、多个入口、手动与工作流重叠只发生一次实际执行；不同项目相同节点 ID 不误锁。
5. A 完成、失败、取消或暂停均不重置 B；B 的错误与产物归属保持独立。
6. 图 A→C、B→C：A/B 在资源允许时同时运行，C 只在所需输入就绪时执行。
7. 输入编辑、节点删除、项目切换、保存冲突、关窗/重启及远端恢复不导致旧结果覆盖或重复提交。
8. 队列取消、运行失败、429、超时和异常退出释放或恢复资源占用；日志写入失败不改变执行结果。

执行单元/契约/连线/持久化测试、完整 npm run verify、真实 Electron 并发与恢复验证。先用可控延迟/错误的模拟网关验证；真实供应商额度、计费与取消能力须另行验证，不能以 mock 通过代替。

## 8. 日志影响与边界

本次仅排查和方案，不修改业务路径，不新增正式业务事件；诊断证据不含用户媒体、正文、密钥或真实请求。

端口实施属于界面派生几何，不记录逐帧或指针事件。并发实施涉及执行、网络、异步任务、取消和恢复，必须按 LOGGING_SPEC.md 补齐适用日志并更新 LOGGING_COVERAGE.md：复用 workflow/node/model/task 已有开始与唯一终态，增加必要的接纳、排队原因、派发、取消与恢复转换；携带 projectId/runId/nodeExecutionId/requestId/taskId、资源组安全 ID、排队耗时及重试次数，不记录正文、凭据或原始响应。

当前已确认的是本地代码与浏览器复现：没有调用真实收费模型，没有验证实际 GPU 显存或用户账号额度，也没有声称已经完成并发改造。P0 证据量化偏差，P1 的 UI/入口拒绝用状态注入确认；两者均需实施后做桌面回归。
