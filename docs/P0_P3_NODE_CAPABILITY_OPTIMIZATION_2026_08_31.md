# P0–P3 节点能力与协议优化交接单

> 完成日期：2026-08-31
> 基线：`f519ac3` 之后的工作区改动（待提交）
> 自动验证：`npm run verify` 通过；53 个测试文件、617 个用例。

本批不新增节点类型、不改变任何已发布端口，也不引入登录、云端项目或导演台新能力。所有新增行为都保留在现有节点配置、可见交互或协议门禁内。

## P0：协议门禁收紧

- `ACTIVE_NODE_TYPE_IDS` 与 `LEGACY_NODE_TYPE_IDS` 成为共享运行时清单，类型、注册表和测试不再各自手写节点列表。
- 可创建节点在注册时必须同时属于 `ActiveNodeTypeId`、具备 `executor`、`projectOutputs`、分类、标准尺寸与完整端口声明。
- `getNodePorts` 对 `resolvePorts` 的动态端口重新执行完整端口校验：ID、方向、名称、说明、基数、JSON Schema、Schema 注册状态和重复端口均受约束。
- 契约快照直接基于 Active 清单，`vocal-separate` 不会再遗漏；新增动态端口非法配置回归测试。

## P1：输入输出与连线反馈

- 节点卡片显示可读状态：可运行、处理中、缺少必填输入、运行失败、等待发布或已发布。
- 输入端口 tooltip 反馈必填缺失、单值连接或 many 端口的连接数量；缺失必填输入以虚线端口提示。
- 输出端口显示当前是否已有可供下游消费的正式投影，不阻止用户预先建立真实数据连线。
- 从端口拖到空白处的新建菜单继续只列兼容目标，并额外显示目标端口类型、Schema 与单/多值基数，避免“创建后才知道接错端口”。

## P2：图片生成比例与能力驱动配置

- 新增 `src/shared/image-capabilities.ts` 作为图片模型能力的单一入口。
- `image-gen` 的固定配置新增 `aspectRatio`：比例是用户的持久化意图，尺寸是当前能力表中的实际落点。
- 当前只公开已由应用请求链路稳定支持的安全组合：默认、`1:1`（1024×1024）、`3:2`（1536×1024）、`2:3`（1024×1536）。模型切换或旧 size-only 配置会归一为合法组合。
- 目前不把 `16:9` / `9:16` 伪装为所有图片服务都支持：OpenAI-compatible 端点对独立 `aspectRatio` 字段没有统一保证。确认某供应商请求格式后，只能在能力表增加精确模型条目，再将该字段透传给主进程。
- 模型、比例、尺寸、种子与参考图仍全部经现有 `image-gen` 输入端口、`props.config` 和 executor 进入运行记录；未产生隐藏输出。

## P3：视频能力与配置回退

- MiniMax H3 的模型标识使用受控规范化：大小写、空格和下划线差异都会归一为 `minimax-h3`；未登记模型仍落入保守能力集。
- 新增 `normalizeVideoGenParams`：模型切换、旧项目配置恢复和执行时会将画幅、时长、清晰度、同步音频开关归一为该模型能力表明确允许的值；H3 首尾帧模式会移除独立 ratio。
- 视频执行器不再遗漏 `generateAudio`、`seed`、`watermark` 三个已经持久化的 Seedance 参数。
- Renderer 的配置回退只改善体验，主进程仍用 `videoCapabilityIssues` 和参考素材限制二次拦截，不能绕过供应商能力。

## 验证范围与下一步

自动化已覆盖 Active 清单、动态端口、端口就绪状态、生图能力归一、视频模型 ID 归一、视频参数回退和既有执行器/连线矩阵。
