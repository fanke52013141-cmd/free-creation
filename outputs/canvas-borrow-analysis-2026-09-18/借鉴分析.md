## 4. 重点二：Agent flow / workflow —— 可借鉴清单

先说三个否证结论，避免你在错误的地方找答案：

- **infinite-canvas**：没有 agent 节点、没有 DAG 引擎、没有自动重跑下游；编排能力**全在 `canvas-agent` 的 MCP 层**（`web/src/pages/canvas/project.tsx:2305` 是唯一生成入口，手动触发）。
- **opencove**：没有 workflow engine / DAG / 调度器 / run 表；全仓 `idempoten*`、`dependsOn`、`topological`、`subagent` 零命中。它强的是**运行态观测与身份治理**。

## 6. 建议落地顺序

结合你已有的 `IA-*`（体验）与 `AG-*`（Agent 重接）计划，建议这样排：

**第一条线：生成体验收口（1–2 周量级）**

1. 统一 ResultMeta / `origin`（P1-8）+ 结果历史落库（P1-9）—— 这是"结果详情、来源跳转、继续创作"的数据前提。
2. 任务生命周期不变式：提交即落 provider task id（P0-1）+ 中断重扫分级（P0-2）+ 供应商快照与漂移保护（P0-6）+ 超时不重试（P0-7）。
3. 统一任务查询 `runs.query`（P0-3）→ 顺带产出「运行中心」UI。
4. 逐槽位重试 + 部分成功语义（P0-4）；错误归一化三件套（P1-15）。
5. （可选，但价值高）ComfyUI 一等后端：采用 `workflow.json + .config.json` 参数绑定格式（P1-13）。

**第二条线：Agent 重接骨架（先做地基，不急着接 MCP）**
